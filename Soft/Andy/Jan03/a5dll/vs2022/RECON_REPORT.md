# Разведка: код Jan03 против данных релиза

## Окружение
- Windows Server 2025, VS 2022 Build Tools (MSVC 14.44, SDK 10.0.22621), CMake 3.31 из VS, Python 3.11.
- Порт собран полностью (411/411) исправленным `build.cmd` (коммит 41081648e).
- game.db, MDF и PDB разобраны скриптами на Python по коду Jan03.
- Ресурсы проверены тестовым стендом: настоящие загрузчики Jan03 из объектов Main, вызванные на копиях файлов. Кроме того, все файлы каждой папки прогнаны статической проверкой.
- LFS: скачано всё нужное. Заглушками остались 9 файлов MySQL в `Data/masterserver/` (allowedips, bannedips, bannednames, commonstats, users — сервер их не отдаёт) и не запрошенные крупные файлы (музыка, видео, `Sounds.res`, инсталлятор MSDE и т. п.).

## a) game.db
**Jan03.** Корень — `hash_map<tableID, CDBTableBase>`. Каждая запись хранится отдельным объектом с classID, равным ID таблицы, а каждое поле — отдельным чанком с номером из `operator&`.

**Релиз** (`Complete/game.db`, 34,6 МБ):
- 155 объектов класса 0xA1843130 = `CDBTableDataStorage` (имя взято из PDB).
- Корень — `hash_map<int, CObj<CDBTableDataStorage>>` плюс связь `RPGPers2Scripts`.

Таблица самоописывающаяся:
- чанк 5 — колонки (имя в cp1251 и тип: int/bool/float/string);
- чанки 6/7/8 — имена колонок по типам;
- чанк 2 — dword'ы int и bool;
- чанк 3 — float;
- чанк 4 — wide‑строки.

Всего 1103 int, 127 bool, 285 float и 275 string колонок. По сути это снимок SQL‑таблиц, а не записи движка.

**Схема та же, упаковка другая.**
- Все 130 таблиц Jan03 есть в релизе с теми же ID, связь RPGPers2Scripts тоже. В релизе ещё 25 новых таблиц.
- У 115 таблиц есть все поля, которые читают `Import()` Jan03; даже опечатка `DamageMоd` с кириллической «о» совпадает.
- Не хватает 16 имён в 5 таблицах: 12 «CustomHead» в Nationalities (головы переделаны в новые таблицы 0x77–0x7A), RPGWeapons.AmmoTypeID, Panzerkleins.PersID, TranslatedStrings.String, RPGMineDetectors.ItemID.
- 10 шаблонных классов скриптом не разобраны.

## b) Data/A5GAME_Data.MDF
- SQL Server 2000: dbi_version 539 в загрузочной странице; имя базы «A5GAME_English (USA)».
- Содержимое — около 3 июня 2003: самые новые объекты в sysobjects от 03.06.2003, журнал LUMIGENT_PROFILER заканчивается тем же днём.
- Схема прочитана без SQL Server разбором страниц (sysobjects/syscolumns): 272 пользовательские таблицы, число строк совпало с sysindexes в 270 из 272.
- Против кода Jan03: все 130 таблиц и связь есть; 129 из 130 совпадают по полям, не хватает только `Panzerkleins.PersID`.
- `Versions/Current/res/A5GAME_Data.MDF` (ноябрь 2003) ближе к релизу: 15 полей не хватает. `Tools/Base` (март 2002) старше кода: 46 таблиц не хватает.
- Чтобы прогнать `DataImport`, базу нужно подключить к SQL Server 2000/MSDE или к 2005–2008 R2 (Express подойдёт), который обновит файл версии 539. SQL Server 2012 и новее такой файл не подключают.

## d) bin/Game.exe
- Монолитный exe от 06.08.2003 (VC 7.1), не упакован.
- 1759 имён RTTI (177 `NDb::`), в том числе `CDBTableDataStorage` и `IOLETable`.
- Указан путь к PDB `c:\Code\A5\Game\Release\Game.pdb`, age 161; совпадающего PDB нет.
- Зато в `Soft/Andy/RussianGold`, `EnglishGold` и `RussianPatch1` лежат exe с **точно совпадающими PDB** (GUID и age), RussianGold собран на 5 дней позже. В этих PDB:
  - 53 575 публичных символов и полные типы (190 508 записей TPI);
  - раскладка `CDBTableDataStorage` и `SColumnInfo`;
  - API `IOLETable` (GetInt/GetBool/GetFloat/GetString по имени, MoveNext, IsEof) и `NDatabase::Import(bool)`;
  - раскладки всех релизных классов записей. Например, `NDb::CRPGWeapon` — это поля Jan03 без `pAmmo` и с 5 новыми полями.
- Релизный `TFilesPackage::ReadHeader` принимает обе сигнатуры пакетов.

Выходит, релиз читает game.db тем же механизмом `Import()`, что и Jan03, только вместо ADO источником служит хранилище из файла.

## Два пути
**Пересобрать game.db из SQL‑базы.**
- Нужен SQL Server 2000–2008 R2. Его надо поставить на современную Windows, восстановить логин sa/simple или передать `-connect`, подключить MDF.
- Схема почти идеальна (1 поле), но содержимое — июньское 2003 года. Ссылки на ресурсы могут расходиться с августовскими файлами в Complete/.
- Ресурсы этот путь не чинит вовсе.

**Научить Jan03 читать релизный формат.**
- game.db: в ADOFake/ADOImport добавить читатель `CDBTableDataStorage` (формат описан выше и в PDB) как источник для существующего `NDatabase::Import()`. Это порядка нескольких сотен строк; 16 недостающих полей получают значения по умолчанию. Данные при этом согласованы с ресурсами, внешнего ПО не нужно.
- *.res: принимать вторую сигнатуру, как делает сам релиз.
- Terrain (65), Geometries (411), Chapters (7): добавить ветки чтения новых раскладок; типы восстанавливаются по PDB.

**Вывод: дешевле второй путь.**
- Работа над ресурсами нужна в обоих вариантах, а для game.db второй путь — небольшой код без установки SQL Server 2000-х годов.
- Данные берутся из той же версии, что и ресурсы.
- Устаревшая 2003 года сборка SQL Server на Windows Server 2025 — главный риск первого пути.
- SQL‑путь стоит держать как запасной для сверки значений.

Скрипты, тестовый стенд и полные списки таблиц и полей — в `recon/` (см. `recon/README.md`).
