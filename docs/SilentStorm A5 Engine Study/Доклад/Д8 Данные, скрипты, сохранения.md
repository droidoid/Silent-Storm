# Д8. Данные, скрипты, сохранения

← [[Д7 Правила и кампания]] · к началу [[Доклад — что забираем и куда]]

> [!summary] Суть
> Всё содержимое игры — записи в таблицах, которые ссылаются друг на друга. Моды накладываются поверх по отдельным полям. Сценарии миссий пишутся простым линейным текстом с ожиданиями, и игру можно сохранить, пока сценарий «ждёт».

## Содержимое как таблицы

Оружие, материалы, персонажи, детали зданий, шаблоны карт, тексты — всё это записи примерно в 150 таблицах. Запись ссылается на другие записи по номеру: оружие → тип патрона → материал.

Файлы ресурсов привязаны к записям самым простым способом: **номер записи и есть имя файла**. Модель с номером 1558 лежит в `Geometries/1558`. Никаких отдельных списков соответствия.

**Записи-рулетки.** Многие записи — не одна вещь, а набор вариантов с весами. «Солдат» — это рулетка из нескольких моделей; «сундук» — рулетка из нескольких наборов содержимого. Отсюда разнообразие без отдельного кода.

В оригинале таблицы жили в SQL Server, а игра получала их снимок в одном файле. Для переноса сервер не нужен: подойдут файлы или SQLite. База редактора уже переведена в SQLite конвертером `reconstruction/tools/mdf2sqlite.py`.

## Моды

Мод — папка со своим файлом таблиц и своими ресурсами. Таблицы мода накладываются поверх основных **по отдельным полям**.

> [!example] Пример
> Мод хочет сделать пистолет мощнее. В его таблице одна запись с тем же номером, что у пистолета, и в ней заполнено одно поле — «урон». Остальные поля помечены «оставить как было». Игра берёт основную запись и заменяет в ней только урон. Если основную игру обновят и у пистолета изменится вес, мод не сломается.

Ресурсы перекрываются так же просто: файл из папки мода имеет приоритет над файлом игры.

## Сценарии

Сценарий миссии — текст на скриптовом языке, написанный линейно, как рассказ:

```lua
-- условный пример в духе оригинала
CameraSet( "ВидНаВорота" )
UnitSay( officer, "Они уже здесь!" )
WaitForUI( UnitMove( officer, "Укрытие" ) )
Sleep( 20 )
StartThread( Подкрепление )
```

Здесь `WaitFor…` и `Sleep` — ожидания: сценарий засыпает и просыпается, когда событие произошло. Устроено это опросом: длинная команда возвращает номер, а ожидание спит, пока команда с этим номером ещё выполняется.

Параллельные ветки запускаются как отдельные потоки сценария. **Триггер** — пара «условие и действие»: менеджер триггеров раз за шагом проверяет условие и, когда оно выполнилось, запускает действие новым потоком.

Сценарию доступно около 220 команд: бойцы, маршруты, предметы, улики и цели, камера, звук, погода, диалоги.

## Сохранение посреди сценария

Обычная скриптовая машина не умеет сохраняться, пока сценарий ждёт: его состояние лежит во внутреннем стеке программы, который не записать в файл.

В оригинале машину переписали: всё состояние сценария — стек, вызовы, счётчик сна — хранится в обычных данных. Поэтому сохранить можно в любой момент, включая середину катсцены.

> [!example] Пример
> Офицер бежит к укрытию, сценарий ждёт на строке `WaitForUI`. Игрок сохраняется и выходит. После загрузки офицер продолжает бежать, а сценарий просыпается на той же строке и идёт дальше.

## Сохранение игры

Оригинал сохраняет «всё как есть»: весь граф объектов игры вместе с окнами интерфейса. Это удобно писать, но хрупко: стоит изменить класс, и старые сохранения перестают читаться.

Для переноса этот способ **не рекомендуется**. Идею стоит взять («сохраняться можно всегда»), а устройство сделать иначе: явное описание состояния игры, отдельное от объектов движка.

Две детали, которые стоит повторить:
- каждая посещённая зона хранится отдельным файлом и подгружается при возврате;
- в сохранении записан список активных модов, и перед загрузкой он восстанавливается.

## Реплики бойцов

События боя (убил, промахнулся, ранен, заметил мину) порождают кандидатов на реплику. Остаются кандидаты с наивысшим приоритетом, из них один выбирается рулеткой. В рулетке есть сектор «промолчать» — поэтому бойцы не комментируют каждое действие.

## Что нужно от движка

| Что | Зачем |
|---|---|
| Свои типы данных с редактором свойств | таблицы содержимого |
| Файловая система с приоритетами | моды |
| Встраиваемая скриптовая машина, которая умеет сохранять выполняющиеся сценарии | ожидания и катсцены; штатные скрипты движков этого не умеют |
| Свой слой состояния игры | сохранения |
