# Бой 2 — Боец, ранения, предметы

Спецификация ролевых правил Silent Storm (2003): характеристики и навыки бойца, опыт и перки, очки действия, здоровье и ранения, медицина, скрытность, инвентарь и предметы, магазины, сундуки, замки, мины, панцерклайны, медали, дипломатия, сложность. Источник: реконструкция исходного кода (Main\, DBFormat\) и база A5GAME.sqlite (редакторская, ноябрь 2003).

## Суть

Боец Silent Storm — это 17 «ячеек»: три характеристики (сила, ловкость, интеллект), девять навыков, очки здоровья и действия, уклонение, перехват и уровень. Навыки считаются от характеристик, а опыт лишь поднимает потолок, до которого навык дорастает, когда им пользуются (каждый выстрел, шаг, перевязка, услышанный шорох двигает свой навык на долю очка). Уровень растёт от опыта и даёт очки перков в классовом дереве из 27 способностей. Всё временное — ранения, уровень здоровья, панцерклайн, лекарства — накладывается модификаторами-множителями и прибавками, которые снимаются вместе с источником. Попадание по человеку умножается на зону тела, может вызвать критическое ранение (выбор по шкале «тяжести»), делится между настоящими и «перевязанными» очками здоровья и может оглушить. Ниже половины здоровья боец кровоточит каждый ход, бессознательный до конца миссии выбывает. Медик добавляет «перевязанные» ОЗ и лечит ранения по «сложности», стимуляторы поднимают ОЗ ценой обморока. Инвентарь — сетка 7 × 13 и две руки без учёта веса; магазин — бесплатный склад, открывающийся по рейтингу; лут и снаряжение врагов выкатываются из взвешенных «сундуков»; замки вскрываются отмычками, мины — наборами разминирования с броском по инженерии; панцерклайн — второе тело с собственными ОЗ. Сложность меняет урон, порог смерти и лечение между миссиями.

## 1. Модель бойца: характеристики и навыки

### Назначение

Каждый боец (наёмник игрока, враг, союзник, пустой панцерклайн) описывается одним набором из 17 «ячеек навыков». В этот набор входят и три первичные характеристики, и производные навыки, и расходуемые ресурсы (ОЗ, ОД), и уровень. Все боевые и небоевые проверки читают эти ячейки.

### Данные

Перечень ячеек (порядок важен — это индексы в таблицах базы и в сохранениях):

| № | Имя в коде | Смысл | Столбец в RPGClasses / RPGBaseValues |
|---|---|---|---|
| 0 | ST_MELEE | рукопашный бой | Melee |
| 1 | ST_SHOOTING | стрельба | Shooting |
| 2 | ST_THROWING | метание | Throwing |
| 3 | ST_BURST | стрельба очередями | Burst |
| 4 | ST_SNIPE | снайперская стрельба | Snipe |
| 5 | ST_STEALTH | скрытность | Stealth |
| 6 | ST_SPOT | обнаружение (наблюдательность) | Spot |
| 7 | ST_MEDICINE | медицина | Medicine |
| 8 | ST_ENGINEERING | инженерия | Engineering |
| 9 | ST_VP | очки здоровья (ОЗ, VP) | VP |
| 10 | ST_AP | очки действия (ОД, AP) | AP |
| 11 | ST_IC | уклонение (IC) | IC |
| 12 | ST_INTERRUPT | перехват хода (Interrupt) | Interrupt |
| 13 | ST_LEVEL | уровень | Lvl |
| 14 | ST_STR | сила | Str |
| 15 | ST_DEX | ловкость | Dex |
| 16 | ST_INT | интеллект | Int |

Ячейка (CDynamicSkill) хранит:

| Поле | Смысл |
|---|---|
| nBaseValue | «база» — значение, вычисленное из первичных характеристик (для самих характеристик — стартовое значение) |
| nXPValue | целая часть, заработанная опытом/тренировкой |
| fProgress | дробный прогресс к следующему +1 (0…1) |
| nMaxValue | производный предел = округление((nBaseValue + nXPValue) × произведение множителей + сумма прибавок), пересчитывается в Update |
| nValue | текущее значение (реально используется только у ОЗ и ОД) |
| modifiers | список подключённых модификаторов (слабые ссылки, владельцы — ранения, панцерклайн, лекарства) |
| bFreezedToMax | «заморожено на максимуме» |

Эффективное значение ячейки, которое читают все формулы: если ячейка заморожена или nValue > nMaxValue — это nMaxValue, иначе nValue. Все ячейки, кроме ST_VP и ST_AP, при создании бойца замораживаются — их эффективное значение всегда равно пределу. ОЗ и ОД — «расходуемые»: текущее значение может быть ниже предела.

У бойца также есть: общий накопленный опыт fXP (дробное число), массив пределов cap[17] (копия навыков из записи класса RPGClasses), флаги читов nCheats, «перевязанные ОЗ» nHealedVP, порог смерти nDeathVP, флаг потери сознания, дерево перков, ссылка на панцерклайн, «привыкание к оружию» (см. раздел 11).

Константы шкалы: N_MAX_SKILL = 140 (номинальный максимум навыка, делитель во всех формулах «навык/140»), N_MAX_VP = 250, N_MAX_DC = 300 (максимальная «сложность» критического ранения).

### Алгоритм

**Базовые значения производных ячеек** (функция GetSkillBaseStatValue, читаются эффективные значения характеристик):

| Ячейка | База |
|---|---|
| MELEE | СИЛ + 2·ЛОВ |
| SHOOTING | 20 + ЛОВ |
| THROWING | 2·СИЛ + ЛОВ |
| BURST | 2·СИЛ + ЛОВ |
| SNIPE | 2·ЛОВ + ИНТ |
| STEALTH | 5 + 2·ЛОВ |
| SPOT | 5 + 2·ИНТ |
| MEDICINE | ЛОВ + 2·ИНТ |
| ENGINEERING | ЛОВ + 2·ИНТ |
| VP | 10·(СИЛ + 5) |
| AP | 36 + 2·ЛОВ |
| IC | 5 |
| INTERRUPT | 25 |
| LEVEL | 0 |

Пересчёт баз (UpdateSkills) выполняется для ячеек 0…13 после каждого начисления опыта и после каждой тренировки характеристики. Пересчёт базы сдвигает текущее значение на ту же разницу, что и база (nValue += новая − старая), затем пересчитывает предел — поэтому рост силы не «восстанавливает» потерянные ОЗ, а прибавляет к ним прирост.

**Создание бойца из записи персонажа (RPGPers)** — порядок важен:

1. Имя = строка DisplayName, длинное имя = LongNameID; голос = 0 для мужчин, 3 для женщин (поле Voice записи при создании не читается).
2. Дерево перков создаётся только если у персонажа есть класс: дерево номер PerkTreeID класса.
3. Создаётся инвентарь.
4. Ячейки СИЛ/ЛОВ/ИНТ = значения Str/Dex/Int из записи RPGBaseValues (часть опыта 0).
5. fXP = столбец XP той же записи (у наёмников 50, у типовых врагов 0).
6. Пределы cap[i] = навыки записи класса; без класса — все 0.
7. Модель тела, панцерклайн (если персонаж сам «является» панцерклайном), оружие по умолчанию = рукопашное оружие №1 («без оружия»).
8. Оружие в руке: если карта выкатила предмет из сундука WeaponInHand — он, иначе WeaponID персонажа; кладётся в слот 1.
9. Рюкзак: если карта выкатила сундук WeaponInBackpack — его содержимое, иначе список предметов персонажа (для обойм с заданным типом патронов создаётся обойма этого типа); каждый предмет раскладывается автоматически (см. раздел 10).
10. Ячейки 0…13: база = формула выше; если в RPGBaseValues задано ненулевое значение навыка, часть опыта = заданное − база (отрицательное обрезается до 0, тогда значение = база).
11. Все ячейки, кроме VP и AP, замораживаются на максимуме.
12. Если есть класс: для каждой ячейки 0…13, у которой значение в RPGBaseValues равно 0, часть опыта = GetSkillByCap(cap[i], fXP) (см. раздел 3), значение = пределу.

Итог для наёмника с 50 опыта: уровень 1, навыки с пределом 100 получают +7, 75 → +5, 50 → +3, 25 → +1, 10 → 0 (таблица прибавок — в разделе 3).

**Боевая обёртка бойца на миссии (CUnitMission)** создаётся отдельно: для наёмника — поверх существующего бойца, для врага карты — с новым бойцом, у которого медали отключены. Обёртка при создании читает запись №1 таблиц RPGToHits, AISoundConstants, InterruptsConstants и единственную запись RPGMinesConstants; все типы ранений разрешены.

**Дальность и угол зрения бойца**: дальность 20 единиц мира (перк 83 «Far sight» умножает на Param1 = 1,25), угол обзора π рад, то есть 180° полный (перк 82 «Im a rabbit» умножает на Param1 = 1,5). Абсолютный потолок дальности зрения 40. Отдельная устаревшая таблица «дальность по позе» (лёжа 25, сидя 27, стоя 30, бег 30 клеток × шаг сетки) используется только для вывода в интерфейс (GetInfo). Сам тест видимости описан в «ИИ 3 — Геометрия и запросы.md».

### Формулы

- Эффективное значение = (заморожено или текущее > предела) ? предел : текущее.
- Предел = round((база + опыт) × ∏ fMul + ∑ fAdd), округление к ближайшему (половина — от нуля).

### Особые случаи и прихваты

- Персонажи без класса (превью «Male»/«Female» в генераторе персонажа, часть NPC) не имеют дерева перков и пределов; любой запрос перка у них — «нет».
- Значения навыков в RPGBaseValues для обычных персонажей пусты; ненулевые значения встречаются только в записях-«дельтах» панцерклайнов (22, 65–69), которые используются не как база, а как изменения навыков при надевании (раздел 16).
- Ячейка уровня тоже «заморожена» и тоже имеет базу 0 — уровень целиком состоит из «части опыта».

### Что нужно от движка-носителя

Хранение 17 ячеек с полями выше, детерминированное округление «к ближайшему» для пределов и усечение в местах, отмеченных ниже; сериализация всех полей ячейки (включая дробный прогресс).

## 2. Модификаторы навыков и характеристик

### Назначение

Временные и постоянные изменения навыков (ранения, уровень здоровья, панцерклайн, стимуляторы, отложенные эффекты) накладываются не изменением значения, а подключением объекта-модификатора к ячейке. Снятие модификатора автоматически возвращает ячейку.

### Данные

Модификатор (CSkillModifier) = {ячейка, fMul, fAdd}. По умолчанию fMul = 1, fAdd = 0. Владельцы модификаторов (только они держат «сильную» ссылку): ранение (у каждого ранения свой список), обёртка миссии (список модификаторов панцерклайна; список «временных» модификаторов — бусты ОЗ и сработавшие отложенные модификаторы). Ячейка держит только слабые ссылки.

### Алгоритм

**Подключение** (конструктор модификатора): модификатор добавляется в список ячейки. Если fAdd > 0, текущее значение сразу увеличивается: nValue = усечение(nValue + fAdd) (усечение, а не округление). Затем Update.

**Update ячейки:**
1. предел = опыт + база;
2. обходится список модификаторов; «мёртвые» (освобождённые владельцем) удаляются из списка, у живых перемножаются fMul и складываются fAdd;
3. предел = round(предел × ∏fMul + ∑fAdd);
4. если предел ≤ текущее — текущее := предел (значение только прижимается вниз, никогда не поднимается).

**Отключение** (уничтожение модификатора владельцем): модификатор ищется в списке по указателю; найден — удаляется и вызывается Update; не найден — ничего.

**Порядок наложения**: все множители перемножаются, все прибавки складываются, прибавки идут после умножения. Порядок подключения на результат не влияет.

**Время жизни**:
- модификаторы ранения живут, пока живёт ранение (снимаются при излечении, истечении, «приостановке» лекарством);
- модификатор уровня здоровья (ранение C_VP) пересоздаётся при каждом пересчёте (раздел 6);
- модификаторы панцерклайна живут, пока надет этот панцерклайн;
- буст ОЗ стимулятора — до конца миссии (длительности считаются только для передозировки, см. раздел 8);
- «отложенный модификатор» (AddPostponedModifier): хранится как {ячейка, fMul, fAdd, ходов осталось}; каждый ход счётчик уменьшается, на нуле создаётся настоящий модификатор и кладётся в список «временных» обёртки миссии — до конца миссии.

**Прочие операции над ячейкой:**
- Modify(d): текущее := min(min(предел, текущее) + d, предел) — используется при уроне;
- оператор «−=» уменьшает текущее без ограничений снизу;
- оператор «+=» увеличивает текущее с прижатием к пределу;
- SetValue(n): текущее := min(n, предел);
- Reset: текущее := предел;
- SetXPPart(n): текущее += n − опыт; опыт := n; Update.

### Формулы

Предел = round((база + опыт) × ∏fMul + ∑fAdd); при подключении с fAdd > 0: текущее := trunc(текущее + fAdd).

### Константы

Нет собственных констант; конкретные множители — в разделах 6, 7, 8, 16.

### Особые случаи и прихваты

- Множитель уменьшает именно предел; у замороженных навыков это и есть значение. У ОД уменьшение предела прижимает текущие ОД вниз немедленно, а восстановление предела текущие ОД не возвращает (они восстановятся в начале следующего хода).
- Положительная прибавка (стимулятор, панцерклайн) сразу «доливает» текущее значение, а отрицательная — нет: текущее лишь прижимается к новому пределу. Поэтому надевание панцерклайна с +ОЗ сразу добавляет ОЗ, а снятие отнимает только избыток над пределом.
- Масштабирование под сложность (раздел 20) пишет предел напрямую в обход списка модификаторов; первый же Update его стирает.

### Что нужно от движка-носителя

Список модификаторов на ячейке со слабыми ссылками и автоматической уборкой; детерминированный порядок пересчёта; RAII-семантика «удалил владельца — эффект снят».

## 3. Опыт, уровни, обучение использованием

### Назначение

Опыт (XP) — одно дробное число на бойца. Он сам по себе ничего не прибавляет к навыкам, кроме уровня: опыт поднимает «потолок», до которого навык может дорасти, а дорастает навык только использованием («обучение использованием»). Уровень растёт от опыта автоматически и даёт очки перков.

### Данные

- fXP — накопленный опыт;
- cap[i] — предел класса для ячейки i (таблица RPGClasses, приложение А);
- запись RPGBaseValues №63 «Growth speed» — делители скорости обучения по ячейкам (см. константы);
- у ячейки — целая часть опыта и дробный прогресс.

### Формулы

Обозначим LN161 = 0,476234179 (это ln 1,61) и для предела cap: K(cap) = cap / (20 · LN161) = cap / 9,52468.

1. **Навык по опыту** (используется при создании и при SetXPLevel):
   GetSkillByCap(cap, XP) = 0 при XP ≤ 0, иначе усечение( ln(1 + 0,02·XP) · K(cap) ).
2. **Опыт для уровня/значения** (пороги уровней):
   GetXPBySkill(cap, L) = 0 при L ≤ 0, иначе (2,7296^(L / K(cap)) − 1) / 0,02.
   Основание степени — 2,7296, а не e = 2,71828; поэтому функция 2 не является точной обратной к функции 1 (пороги чуть выше, ~0,4 % в показателе). Так в оригинале.
3. **Потолок обучения** (дробный, используется при тренировке):
   fCap(i) = 0 при XP ≤ 0, иначе ln(1 + 0,02·XP) · K(cap[i]) — без усечения.

Смысл: при уровне 14 (максимум класса наёмника) ln(1+0,02·712270)·K(14) ≈ 14,06, то есть потолки всех навыков примерно равны их пределу класса ровно на максимальном уровне класса.

### Алгоритм

**Начисление опыта CUnit::AddXP(x):**
1. Если у персонажа нет записи или нет строки имени (DisplayName) — опыт не начисляется вовсе.
2. x := x · (ИНТ · 0,05 + 1), где ИНТ — эффективный интеллект получателя.
3. Если взят перк 61 «Wisdom»: x := x · Param1 (1,3).
4. fXP += x.
5. Пока fXP строго больше GetXPBySkill(cap[LEVEL], уровень + 1) — уровень (часть опыта ячейки LEVEL) += 1. Равенство не повышает.
6. Прогресс ячейки уровня (для полоски в интерфейсе) = (fXP − порог(L)) / (порог(L+1) − порог(L)).
7. Пересчёт баз всех производных ячеек.
8. Если уровень вырос — очки перков += (новый − старый).

**Обучение использованием CUnit::UseSkill(e):**
1. Сначала тренируется связанная характеристика (тем же алгоритмом, рекурсивно):
   - MELEE, THROWING, BURST → СИЛ;
   - SHOOTING, SNIPE, STEALTH → ЛОВ;
   - SPOT, MEDICINE, ENGINEERING → ИНТ;
   - VP, AP, IC, INTERRUPT — без характеристики.
2. Коэффициент обучения f = 1; для навыков (e < СИЛ) при перке 60 «Skills growth faster» f = Param1 (1,1); для характеристик при перке 11 «Stats growth faster» f = Param1 (1,1).
3. Если e = LEVEL — отказ.
4. Потолок fCap = fCap(e) по формуле 3.
5. Остаток = fCap − (часть опыта ячейки + прогресс).
6. Прибавка = max(0,00001; min(остаток · f / скорость[e]; 0,1)).
7. Upgrade: если часть опыта + прогресс < fCap — прогресс += прибавка; n = усечение(прогресс); если n > 0: часть опыта += n, прогресс −= n, часть опыта := min(часть опыта, усечение(fCap)), Update, «навык вырос». Иначе ничего.
8. Если e — характеристика, пересчитываются базы всех производных навыков.
9. Если вырос навык или характеристика, боевая обёртка ставит в очередь реплику «навык вырос» (ack N_ACK_SKILL) и пишет в лог.

Следствия: за одно использование навык растёт не больше чем на 0,1 очка (то есть не быстрее одного очка за 10 использований); чем ближе к потолку, тем медленнее (прибавка пропорциональна остатку), но не меньше 0,00001; выше потолка, заданного опытом, навык не растёт никогда.

## 4. Перки: получение и дерево

### Назначение

Перки — постоянные особые способности. У каждого класса своё дерево из 27 перков (номер дерева — столбец PerkTreeID записи класса). Перк берётся за очко перка; очко даётся за каждый новый уровень.

### Данные

- RPGPerks: ID, UserName, Param1…Param3 (дробные; пустое значение читается как 0), ToolTip (строка; заголовок перка в интерфейсе — текст после «darkyellow»), IDText, иконки.
- RPGPerkTreeNodes: PerkTreeID, PerkID, ParentPerkID1…3 (родители).
- У бойца: дерево (словарь «номер перка → узел {запись, родители, взят}») и счётчик очков перков.

Соответствие деревьев классам: 1 — Солдат (классы 4 и 10), 2 — Гренадёр (3), 3 — Медик (5), 4 — Инженер (6), 5 — Разведчик (1 и 11), 6 — Снайпер (2). У классов Enemy (7) и WeakEnemy (9) PerkTreeID = −1: дерево пустое, перков нет. Полные деревья — приложение Б.

### Алгоритм

**Построение дерева** (при создании бойца с классом): обходятся все записи RPGPerkTreeNodes с нужным номером дерева; для каждой создаётся (или берётся уже созданный) узел перка, и к нему добавляются узлы всех непустых родителей (родитель тоже создаётся, если его ещё нет).

**Условие «можно взять»**: перк ещё не взят **и все** его родители взяты (логическое И, а не ИЛИ). Список доступных пуст, если очков перков нет.

**Очки перков**: +1 за каждый новый уровень при начислении опыта; при SetXPLevel — разница уровней (может быть отрицательной); счётчик не опускается ниже 0. Наёмник, созданный с 50 опыта (уровень 1), очков не имеет.

**Взятие перка игроком**: команда CCmdTakePerk; исполнитель проверяет, что перк есть в списке доступных, иначе отказ. Взятие: флаг «взят», очки −1 (не ниже 0). Команда принимается в обычном состоянии, при стрельбе со станкового оружия и при переноске тела.

**Взятие из скрипта**: Lua UnitTakePerk(unit, id) берёт перк **без проверки** родителей и очков (при 0 очков перк берётся бесплатно). Lua UnitGiveRandomPerks(unit): пока есть очки — собрать доступные, выбрать равновероятно (свежий локальный генератор), взять.

**Проверка перка HasPerk(id)**: если у бойца нет дерева — «нет»; иначе перк взят → «да» и выдаются Param1…3.

### Формулы

Нет собственных; эффекты каждого перка — приложение Б.

### Особые случаи и прихваты

- Запрос перка, которого нет в дереве, добавляет в словарь пустой элемент (побочный эффект оператора [] словаря); такие элементы пропускаются при перечислении с отладочным сообщением «Invalid perk tree» и сохраняются в сохранении.
- Перки 1–3 («[ DEBUG ]») не входят ни в одно дерево и нигде не проверяются.
- Перки 22, 38, 65 и др. имеют пустые/нулевые параметры; поведение при нуле важно (см. приложение Б: перк 4 при Param1 = 0 делает поворот бесплатным, перк 22 в оригинале из-за нуля не действовал).

## 5. Очки действия

### Назначение

Очки действия (ОД, ячейка ST_AP) — бюджет хода в пошаговом режиме. Каждое действие имеет цену (функция GetActionAP), которая списывается при его выполнении. В реальном времени ОД не тратятся.

### Данные

- Ячейка AP: база 36 + 2·ЛОВ, плюс часть опыта (предел класса AP: 20 у разведчика, 19 у солдата, 18 у гренадёра и SoldierUK, 16 у снайпера, 15 у медика и инженера, 14 у Enemy, 6 у WeakEnemy), умноженная на модификаторы ранений.
- Таблица RPGAPs (26 записей; код читает только записи 5, 9, 10, 11, 12, 13 — остальные цены зашиты в код и с таблицей не обязаны совпадать).
- Обёртка миссии хранит: nTurnCounter (счётчик ходов), nMoveInLastTurn (накопитель «пробежки» для штрафа стрельбы), eLastAction и nLastActionTimes (подряд идущие выстрелы — для бонуса пристрелки в «Бой 1»), ptLastCP (точка, где боец стоял в начале хода — для поправки на движение цели).

### Алгоритм

**Начало хода бойца** (StartNewTurn): счётчик ходов +1; счётчик попаданий по бойцу за ход := 0; текущие ОД := максимум (остаток прошлого хода **не переносится**); nMoveInLastTurn := 0; запоминается позиция. «Первый ход» = счётчик ходов < 2 (штраф первого раунда к стрельбе — «Бой 1»).

**Переход в реальное время** (StartRealTime): то же обнуление без увеличения счётчика.

**Выполнение действия** (DoAction на уровне мира): списать GetActionAP(действие); зарегистрировать действие (тренировка навыка, см. раздел 3); если боец в позе «бег», то шаг прямо добавляет 2, шаг по диагонали — 1 к nMoveInLastTurn (именно так: прямой шаг весит больше диагонального).

**Списание** SpendAP(n): в реальном времени — ничего; при читах CHEAT_AP или CHEAT_SCRIPTSEQUENCE — ничего; иначе текущие ОД −= n (без проверки снизу). **Проверка** CanSpendAP(n): в реальном времени всегда «да»; при читах — «да»; иначе текущие ОД ≥ n.

**Регистрация действия** (RegisterAction): AC_PREPARE_AND_SHOOT превращается в AC_SHOOT и обнуляет счётчик подряд идущих выстрелов; любое действие, кроме AC_END_SHOOT/AC_SHOOT/AC_BURST, тоже обнуляет его; AC_END_SHOOT увеличивает его на 1.

**Цены действий** — полная таблица в приложении Г. Порядок вычисления для «позных» действий (шаги):
1. Если поза «лёжа» и есть перк 34 — цена считается как для позы «сидя» (рекурсивно); если «сидя» и перк 35 — как для «стоя». Подстановки складываются.
2. Если боец в панцерклайне: в позе «лёжа» или «сидя» цена = 1 (немедленно, до перков переноски); иначе к базе прибавляется AddMoveAP панцерклайна.
3. База позы = (3 − поза + 1)·2: бег 2, стоя 4, сидя 6, лёжа 8.
4. Шаг с телом при перке 42 — по перку (см. приложение Б), иначе по формулам приложения Г.

**Смена позы**: бег приравнивается к «стоя» (и как исходная, и как целевая поза); коэффициент 4 (перк 7: 4 − 1); число ступеней = |исходная − целевая|; цена = 0 при нуле ступеней, иначе max(1, ступени × коэффициент).

**Реальное время**: ОД не списываются; лечение в реальном времени на каждом тике «конец хода/такт» использует половину максимума ОД (раздел 8). Сам такт реального времени — «Мир 1».

### Формулы

- Максимум ОД = round((36 + 2·ЛОВ + опыт_AP) × ∏модификаторов).
- Шаг: прямо max(1, П), диагональ max(1, trunc(П·15/10)), с телом прямо max(1, trunc(П·15/10)), с телом по диагонали max(1, trunc(П·225/100)), где П = база позы + AddMoveAP панцерклайна (вне ПК 0).
- Выстрел (GetWeaponAP): ShotAP оружия; в режимах «прицельный» и «тщательный» + TargetingAP; затем минус доля перка (15 % для навскидку/прицельного/короткой очереди при перках 15/31/10): n −= n·доля (усечение к целому при присваивании).
- Цена дополнительной пули очереди (GetWeaponBurstAP) = trunc(максимум ОД / RoF оружия), при перке 10 и короткой очереди ×(1 − 0,15), не меньше 1; при RoF = 0 — 10000 (запрет).
- Перезарядка: ReloadAP оружия (не меньше 1); перк 33 — см. приложение Б.
- Рукопашная/метание ножа: trunc(MaxAP − (MaxAP − MinAP) × навык / 140), где навык — MELEE (с перком 70 в реконструкции) или THROWING; затем перк 32/43 ×(1 − 0,25).

- Цены в таблице RPGAPs и в коде расходятся для подъёма на 1 уровень (БД 12, код 10); работает код.
- Подъём/спуск по лестнице, прыжок, поворот и т. п. имеют фиксированные цены, не зависящие от навыков.
- Боец в ПК (и сам ПК) в позе «лёжа/сидя» платит 1 ОД за шаг; на практике пилоту эти позы для ходьбы запрещены командами, а пустой ПК стоит в позе CRAWL, но сам не ходит (раздел 16).
- Реконструкция ставит нижнюю границу 1 ОД на все платные действия после скидок и превращает отрицательную цену в 1 (в оригинале скидки могли дать 0, а отрицательная цена прибавляла ОД) — см. «Отклонения».

### Что нужно от движка-носителя

Хук «начало хода бойца» с полным восстановлением ОД; единая функция цены действия, которую используют и интерфейс, и ИИ, и исполнитель; флаг «реальное время», отключающий списание.

## 6. Здоровье, приём урона, смерть, кровотечение, оглушение

### Назначение

Описывает, как боец (его RPG-сторона) принимает уже рассчитанную порцию атаки: множители зоны попадания, критическое ранение, уклонение случайного свидетеля, раздел урона между «настоящими» и «перевязанными» ОЗ, потерю сознания, смерть, кровотечение, падение с высоты, слой панцерклайна. Полёт пули, выбор зоны попадания, пробитие и бросок урона CalcStructDmg — «Бой 1»; смерть и рэгдолл на уровне мира — «Мир 1».

### Данные

- Ячейка VP: база 10·(СИЛ + 5) + часть опыта; текущее значение может уходить в минус.
- nHealedVP — «перевязанные» ОЗ: отдельный пул, который перевязка добавляет поверх текущих ОЗ. Полные ОЗ = текущие + max(0, перевязанные). Перевязанные никогда не превышают (максимум − текущие).
- nDeathVP — порог смерти (≤ 0); боец мёртв, когда текущие ОЗ ≤ nDeathVP.
- bUnconscious — флаг потери сознания (в обёртке миссии и в бойце).
- nBleedingStopAmount — сколько единиц кровотечения временно гасится (кровоостанавливающее).
- Список критических ранений (раздел 7), счётчик попаданий за ход nBulletHitThisTurn (влияет на шанс крита по этому бойцу).
- Порция атаки (CAttackPortion): nK (пробивная энергия), тип урона, границы урона, шанс крита nCrtical, тяжесть nCrticalDifficulty, атакующий, намеченная цель, тип атаки (обычная, взрывная волна, осколок, «щелчок смерти»), шанс оглушения nUnconsciousProbability, удар в спину, флаги «обойти ПК», «всегда человеческий крит», запрошенная зона eWantedHL.
- Броня человека — запись RPGArmors №1 «Human» (материал Human: порог 0, DR 0, плотность 1300).

### Алгоритм

**Приём атаки человеком (ProcessAttack, зона nUserID):**
1. Если запись персонажа сама является панцерклайном (пустой ПК, робот) — весь урон идёт в «приём урона панцерклайном» (ниже) с записью в собственные ОЗ, и результат возвращается сразу.
2. Если боец в надетом ПК и ОЗ ПК > 0 — сначала «приём урона панцерклайном» с записью в ОЗ ПК; если результат не «досталось пилоту» — конец.
3. Запомнить «был жив».
4. Если тип урона пробивает тело (таблица RPGDmgToArmors, столбец по DR материала > 0) и nK > 0:
   1. Урон = CalcStructDmg(броня тела) — бросок урона с учётом порога материала и множителей сложности (EnemyDamageMult для атак ИИ, OurDamageMult для атак игрока; «Бой 1»).
   2. Множитель зоны: голова 1,5; руки 0,7; ноги 0,85; корпус 1,0.
   3. «Щелчок смерти» (отладка): если цель в сознании и жива — шанс оглушения 100 и урон 0, иначе урон 100000.
   4. Шанс крита = nCrtical порции, тяжесть = nCrticalDifficulty.
   5. Если атакующий известен: тяжесть += случайное 1…19 столько раз, каков уровень атакующего.
   6. Если в сложности включён bHeadshotShouldKill и порция была «прицельной» в эту же зону (eWantedHL = зона): голова +90 к шансу и +150 к тяжести; корпус +10/+20; рука +35/+65; нога +25/+40.
   7. Бросок критического ранения (раздел 7). Его результат — добавочный множитель урона fCrit (0, если ранения нет).
   8. Итоговый урон = max(0, trunc((множитель зоны + fCrit) × урон)).
   9. **Уклонение случайного свидетеля**: если это не «щелчок смерти», боец **не** является намеченной целью порции и не в ПК — бросок уклонения (раздел 9, тренирует IC); при успехе урон −= trunc(IC × урон × 0,01). Намеченная цель не уклоняется вовсе (её уклонение уже учтено в шансе попадания).
   10. Доля из перевязанных: если полные ОЗ ≠ 0 — d = max(0, trunc(урон × перевязанные / полные)), иначе 0. Перевязанные −= d; текущие ОЗ: Modify(d − урон), то есть текущие уменьшаются на (урон − d).
   11. Реплики: если был жив и теперь мёртв — «смерть»; иначе если было ранение (fCrit > 0) или (урон − d) ≥ ¾ максимума ОЗ — «тяжёлое ранение».
   12. Тренировка ячейки VP.
   13. Если не мёртв — **потеря сознания**: база = шанс оглушения порции; бросок r = случайное 1…99; здоровье h = полные ОЗ / максимум ОЗ; коэффициент k = clamp((0,5 − h) × 2,5, 0, 1); шанс = round(k × база). Сознание теряется, если полные ОЗ ≤ 0, или r ≤ шанс, или это «щелчок смерти». Если мёртв — флаг сознания снимается.
5. Иначе (не пробивает) — только запись в лог.
6. В любом случае пересчитать штрафы за ранения (ранение C_VP, см. ниже).

**Шанс оглушения порции** (при её создании, GetUnconsciousProbability): база оружия (столбец UnconsciousProbability патрона или рукопашного оружия) × (1 − текущие ОЗ цели / (2 × максимум ОЗ цели)); без цели — база как есть. Итого фактический шанс = база × (1 − ОЗ₀/(2·макс)) × clamp((0,5 − h)·2,5, 0, 1): выше половины полных ОЗ оглушение невозможно, ниже 10 % — коэффициент 1.

**Приём урона панцерклайном (ProcessAttackForPK):**
1. Чит «бессмертие» — без урона (результат «неизвестно»).
2. Флаг порции «обойти ПК» (кровотечение, падение) — сразу «достаётся пилоту».
3. Рикошет: если тип урона не 0 (волна) и не 5 (луч) и бросок < RicochetProb ПК (%) — энергия порции nK := 0, урона нет.
4. Пул ОЗ: собственные ОЗ (ПК-персонаж) или ОЗ надетого ПК.
5. «Крит мимо брони»: доля пилота = 1 − CriticalResist ПК; шанс = trunc(доля × nCrtical); при успехе броска: шанс крита порции := этот шанс, границы урона × доля, результат «достаётся пилоту» (дальше идёт человеческая ветка с ослабленной порцией).
6. Если тип урона не пробивает броню ПК — урона нет.
7. Урон = CalcStructDmg(броня ПК); «щелчок смерти» — 100000.
8. ОЗ пула −= урон; если < 0 — := 0. Если ОЗ были > 0 и стали ≤ 0 — на носителя накладывается состояние «сломанный ПК» (C_PANZERKLEIN_BROKEN, раздел 16).
9. Энергия порции nK := max(nK − 1590, 0); результат: урон и «досталось пилоту», если nK > 0, иначе «поглощено ПК». Остаток энергии пролетает в пилота с той же порцией.

**Смерть и порог смерти.** Мёртв, если текущие ОЗ ≤ nDeathVP. nDeathVP = −DeathCoeff × максимум ОЗ: для бойцов игрока при высадке (DeathCoeff сложности: 1,2 / 0,7 / 0,1), для «ключевых» персонажей-улик в слотах карты — ClueDeathCoeff (3,0 / 1,5 / 0,25), обычные враги — 0 (умирают при ОЗ ≤ 0). Kill() ставит ОЗ = −4095. Между 0 и порогом боец жив, но без сознания (полные ОЗ ≤ 0).

**Потеря сознания на уровне мира.** После приёма урона мир сверяет состояние: «RPG мёртв» → смерть; «RPG без сознания» → переход в состояние «без сознания» (падение, звук смерти). Из этого состояния в миссии **не выходят**: лечить бессознательного нельзя (команда лечения отвергается), стимулятор может только ухудшить; сознание возвращается только между миссиями (раздел 8). Бессознательный не получает новых ранений с мировыми эффектами (обработчик ранений этого состояния пуст).

**Конец хода / такт реального времени** (DoRegenerations, вызывается для живого бойца):
1. Длительности бустов ОЗ −1; проверка передозировки (раздел 8).
2. Тик ранений: у временных ранений растёт счётчик ходов, истёкшие снимаются; «приостановленные» лекарством ранения ждут своего срока и затем возвращаются; «отложенные» модификаторы по истечении срока включаются (раздел 2).
3. **Кровотечение**: берётся значение первого найденного ранения «кровотечение» (fValue), полные ОЗ T = текущие + max(0, перевязанные), теоретический максимум M (база + опыт, без модификаторов):
   - если T ≤ 0 — 0;
   - урон = trunc(fValue);
   - половина = round(M × 0,5); если T < половины — урон = trunc(урон + (половина − T) × 0,1);
   - итог = max(0, урон − nBleedingStopAmount).
   Слагаемое «(половина − T)·0,1» действует **и без ранения** «кровотечение»: любой боец ниже половины здоровья теряет ОЗ каждый ход.
4. Пересчёт штрафов за ранения.
5. Если боец в ПК (или сам ПК) с RegenerationValue ≠ 0 — «перевязка» на RegenerationValue ОЗ (в пул перевязанных, предел 250) и снятие всех ранений с DC ≤ 300, включая кровотечение.

Мир: если итог кровотечения > 0 и боец не «улика без сознания» — наносится порция урона: энергия 1, тип 0, урон ровно = итог, флаг «обойти ПК», зона «корпус», без атакующего (с ней проходит вся человеческая ветка: уклонение свидетеля, доля перевязанных, потеря сознания при ОЗ ≤ 0, тренировка VP), кровавое пятно, реплика «лёгкое ранение». Если от этого боец умер — опыт за него получают враждебные игроки (раздел 3).

**Падение с высоты** (мир): при перепаде > 2,8 м урон = сумма трёх бросков случайное(0 … trunc((перепад − 2,8)·50)/4 − 1), наносится такой же порцией, как кровотечение (энергия 1, тип 0, корпус).

**Штрафы за уровень здоровья** — два независимых механизма:
1. Ранение C_VP (CVPCritical, пересчитывается после каждого приёма урона, лечения и в конце хода): процент P = trunc((перевязанные + эффективные ОЗ) × 100 / теоретический максимум); перк 5 прибавляет 25 к P (только для выбора ступени); перк 8 — если исходный P < 25, IC × 1,1. Ступени (множители ячеек AP / INTERRUPT / MELEE / SHOOTING / THROWING):

   | P | AP | INTERRUPT | MELEE, SHOOTING, THROWING | с читом 0x80: AP / INTERRUPT / остальные |
   |---|---|---|---|---|
   | > 75 | — | — | — | — |
   | 51…75 | 0,95 | 0,9 | 0,9 | 0,9 / 0,75 / 0,8 |
   | 26…50 | 0,9 | 0,75 | 0,75 | 0,8 / 0,5 / 0,6 |
   | ≤ 25 | 0,8 | 0,5 | 0,5 | 0,7 / 0,25 / 0,4 |

   Новый объект ранения всегда заменяет старый (слияние одинаковых бессрочных ранений), поэтому множители не накапливаются.
2. GetVPPenalty (множитель производного навыка стрельбы/метания/рукопашной в расчёте попадания): P2 = trunc(100 × (ОЗ + перевязанные/2) / максимум ОЗ с модификаторами); > 75 → 1,0; > 50 → 0,9; > 25 → 0,75; иначе 0,5.
   Оба штрафа действуют на стрельбу одновременно (двойной штраф).

**Оглушение** (ранение C_STUN): мир переводит бойца в состояние «оглушён», в котором отвергаются все команды; состояние проверяется каждый такт и снимается, когда ранения C_STUN больше нет. Бессрочное оглушение (MinDuration −1) держится до лечения.

**Уклонение (IC)**: GetIC = round(IC × (1 + P1 перка 40)); для взрывной волны и осколков ещё × (1 + P1 перка 39); плюс аура уклонения (перки 28/66/93) — round. Бросок: случайное 0…99 < IC.

### Формулы

- Урон по человеку = max(0, trunc((Z + fCrit) × CalcStructDmg)), Z ∈ {1,5; 0,7; 0,85; 1,0}.
- Уклонение свидетеля: урон' = max(0, урон − trunc(IC × урон × 0,01)).
- Доля перевязанных: d = trunc(урон × H / (V + H)), H := H − d, V := V − (урон − d).
- Потеря сознания: шанс = round(clamp((0,5 − (V+H)/Vmax) × 2,5, 0, 1) × база).
- Порог смерти = −DeathCoeff × Vmax.
- Кровотечение = max(0, trunc(trunc(f) + max(0, round(M/2) − T)·0,1 при T < round(M/2)) − стоп).
- Падение: ∑₃ rnd(0 … trunc((h − 2,8)·50)/4 − 1).

### Особые случаи и прихваты

- Намеченная цель не уклоняется; уклоняются только случайные свидетели (в том числе от кровотечения и падения — у этих порций нет цели). Каждое такое уклонение тренирует IC.
- Шанс оглушения дважды зависит от ОЗ (при создании порции и при приёме) — выше 50 % полных ОЗ оглушить нельзя.
- Пока полные ОЗ ≤ 0, кровотечение не идёт: бессознательный боец не истекает кровью до смерти, добить его может только новый урон.
- Кровотечение без ранения «кровотечение» существует (ниже половины здоровья).
- Из нескольких ранений «кровотечение» в разных зонах учитывается только первое в списке.
- По пустому ПК/роботу успешный «крит мимо брони» не наносит никакого урона: пилота нет.
- ОЗ ПК при уроне обрезаются на 0; проверка самоподрыва ПК на уровне мира требует ОЗ < 0 и поэтому от обычного урона не срабатывает (не подтверждено, так ли в оригинале).
- При перепаде высоты в диапазоне (2,8; 2,88) м верхняя граница броска равна 0 — генератор берёт остаток от деления на 0 (сбой; не подтверждено, так ли в оригинале).
- Бессознательного нельзя ни лечить, ни привести в чувство до конца миссии.

### Что нужно от движка-носителя

Мировой «сверщик состояния» после каждого приёма урона (смерть/потеря сознания), хук конца хода и такта реального времени для DoRegenerations, генератор случайных чисел с полуоткрытым диапазоном [a, b).

## 7. Критические ранения

### Назначение

Критическое ранение («крит») — вероятностное следствие попадания в конкретную зону тела: отдельный объект на бойце со своим типом, зоной, сроком, силой (fValue) и «сложностью» (DC, она же тяжесть). Ранение даёт модификаторы навыков, мировые эффекты (уронить оружие, оглушение, слепота) и добавочный урон в момент нанесения. Ранения лечатся медициной.

### Данные

- Таблица RPGCriticals: HitLocation (Head / Torso / Arms / Legs / Any), QueueIndex (порядок в шкале), Range (ширина полосы тяжести), MinDuration/MaxDuration (ходы; −1 — бессрочное), Value, Type. Полный список с вычисленными полосами — приложение В.
- Объект ранения на бойце: {тип, зона, срок (−1 = бессрочно), fValue, DC} + счётчик прошедших ходов + собственный список модификаторов.
- У обёртки миссии: список активных ранений; список «приостановленных» пакетов ранений {ранения, ходов до возврата}; массив состояний типов ранений (разрешён / запрещён / «перебросить» — последние два для выбора нового ранения работают одинаково: тип исключается); список «последних ранений» для мира.
- Предел тяжести игры nMaxCriticalSeverity = 300 (Lua может задать; значение < 1 означает 300).

### Алгоритм

**Шкала зоны** строится один раз (при первом броске): ранения каждой зоны сортируются по QueueIndex, начало полосы каждого = сумма Range предыдущих. Зона «Any» в бросках не участвует (только служебное «Patient»).

**Бросок крита при попадании** (GetCriticalDmgModifier; зона, шанс p, тяжесть s, флаг «всегда», атакующий):
1. Если p = 0 — крита нет (флаг «всегда» при нулевом шансе не помогает).
2. Бросок r = 0…99 — отдельный статический генератор, не общий игровой.
3. Сопротивление R = (в ПК: 1 − CriticalResist ПК, иначе 1); перк 46: R × (1 − 0,1).
4. s := min(s, nMaxCriticalSeverity).
5. Если флаг «всегда» снят и r > p × R:
   - если в сложности нет bAlwaysCritical или R < 1 — крита нет;
   - иначе (запасной крит): если атакующий известен, s := сумма бросков 1…4 по числу его уровней; крит продолжается с этой малой тяжестью.
   Условие успеха — r ≤ p·R, поэтому реальный шанс на 1 процентный пункт выше p·R.
6. Выбор ранения по зоне попадания (голова → Head, корпус → Torso, руки → Arms, ноги → Legs): из шкалы берутся только разрешённые типы; если s ≥ начала последнего разрешённого — последнее; иначе первое i ≥ 1, у которого s < начала i-го, даёт (i − 1)-е. Полосы запрещённых типов достаются предыдущему разрешённому.
7. Нет ранения — 0.
8. Добавочный множитель урона = s / 300 × (голова 2; корпус 1,5; руки 0,5; ноги 1) × R (× 0,75 при перке 47 в реконструкции; в оригинале перк 47 делил тяжесть на 1,25 — см. «Отклонения»).
9. Срок: если MinDuration > 0 — Min + случайное(0 … Max − Min − 1) (Max фактически не достигается), иначе бессрочно. DC := s. Ранение накладывается (ниже).

**Наложение ранения** (ApplyCritical):
1. Новое кровотечение обнуляет запас кровоостанавливающего (даже если оно слабее старого).
2. Для каждого имеющегося ранения (кроме «Patient», которое не сливается) — попытка слияния, только при совпадении типа **и** зоны:
   - «старое сильнее»: (старое бессрочно, либо оба срочные и у старого осталось больше ходов) **и** старое fValue > нового **и** старый DC > нового → новое отбрасывается;
   - если оставшиеся сроки равны и fValue равны — новое просто заменяет старое (даже с меньшим DC);
   - иначе новое получает срок «бессрочно», если хоть одно бессрочное, иначе max(оставшихся) со сброшенным счётчиком; fValue и DC — максимумы; заменяет старое.
   При замене старый объект уничтожается (его модификаторы снимаются), у нового выполняется «установка эффекта»; если она вернула «не хранить» — запись удаляется.
3. Если слияния не было — «установка эффекта»; если вернула «хранить» — ранение добавляется в список.

**Эффекты по типам** (установка эффекта; «мир» — что делает состояние бойца, получив тип из списка последних ранений):

В состоянии «смерть» исключаются все. В состояниях лечения, инженерии, стрельбы со станкового оружия и снайперского прицеливания часть мировых эффектов откладывается или прерывает действие (смена состояния — «Мир 1»).

**Ход времени** (в конце хода): у срочного ранения счётчик +1; если стал больше срока — ранение снимается. Ранение со сроком D держится D концов хода и исчезает на (D+1)-м.

**Приостановка** (обезболивающее, SuspendCriticals(n)): все «лечимые лекарствами» ранения переносятся в пакет на n ходов, их модификаторы снимаются. Каждый конец хода: счётчик пакета −1; пока > 0 — ранения внутри стареют как обычно (могут истечь); на нуле все оставшиеся накладываются заново через обычное наложение (эффекты, включая мировые, срабатывают повторно; кровотечение снова обнуляет кровоостанавливающее).

**Лечение ранений** — раздел 8.

### Формулы

- Шанс: крит при r ≤ p × R, r ∈ 0…99.
- Тяжесть: s = s_порции + ∑_{уровень атакующего} rnd(1…19) (+ бонус прицельной зоны) ≤ 300.
- Добавочный урон: fCrit = s/300 × k_зоны × R.
- Шанс крита огнестрела при создании порции: (попаданий по цели за этот ход + 1) × 10 (без цели-бойца — 10) + 0,4 × SNIPE (для снайперского выстрела вместо 0,4·SNIPE: SNIPE × накопленные ОД × 0,02); × (1 + перк 36); перки 38, 54, 74 — приложение Б. Тяжесть: 0,25 × SNIPE (+ накопленные ОД снайпера) × перк 44. Рукопашная: шанс max(0, 10 + 0,4 × (MELEE − 25) + CriticalBonus оружия), тяжесть = шанс × перк 44 × 0,5. Подробно — «Бой 1».

### Особые случаи и прихваты

- Выбор ранения детерминирован тяжестью; случайна только сама тяжесть (уровень атакующего, перки, прицельная зона).
- Смерть от критического ранения возможна только при тяжести ≥ 270 (голова) / 285 (корпус); предел 300 делает их достижимыми.
- Ранения «Death» не убивают бойцов игрока напрямую (только обнуляют ОЗ перед вычетом урона).
- «Lost weapon», «Accidental shot», «Damage weapon», «Death» не хранятся — после срабатывания их нельзя «вылечить», а «Damage weapon» навсегда портит оружие.
- Из-за сравнения «r ≤ p·R» при p = 10 шанс фактически 11 %.
- Бросок крита использует отдельный статический генератор (не синхронизирован с игровым).
- Повторное наложение после приостановки повторяет мировые эффекты (например, «Idle hand» снова выбросит двуручное оружие).
- В редакторской БД у всех уровней сложности bAlwaysCritical и bHeadshotShouldKill пусты (ложь); в релизной БД значения могут отличаться — не подтверждено.

## 8. Медицина, стимуляторы, лечение между миссиями

### Назначение

Медицинские предметы (таблица RPGFirstAids) применяются бойцом к соседу или к себе: перевязка (добавляет «перевязанные» ОЗ), лечение критических ранений, обезболивающие (временно убирают ранения), стимуляторы (поднимают ОЗ, грозят передозировкой), кровоостанавливающие, ремкомплекты панцерклайнов. Между миссиями отряд лечится автоматически по правилам сложности.

### Данные

Запись RPGFirstAids: ItemID, Quantity (заряды предмета), Effect (строка), RequiredSkill, SkillModifier, Duration, Power, TotalHealVP (ёмкость одного применения), APToUse (цена начала), RequiredPerkID. Строки Effect: Normal, CriticalOnly, TempRemovePenalties, BoostVP, TempStopBleeding, RemoveBleeding, NormalCriticalFirst (лечить ранение, иначе перевязать; в коде FAE_CRITICAL_FIRST), RepairPK (FAE_REPAIR_PK). Значения всех записей — приложение Е.

Предмет-аптечка хранит заряды (Quantity); одно применение (сеанс лечения) расходует **один** заряд независимо от объёма; пустой предмет убирается из руки.

### Алгоритм

**Проверка возможности** (CanDoFirstAid, для игрока и ИИ):
1. В руке аптечка с зарядами (иначе «нет снаряжения»).
2. Требования предмета — если это ремкомплект **или** у лечащего нет перка 58: навык (MEDICINE, для ремкомплекта ENGINEERING) + SkillModifier ≥ RequiredSkill, иначе «нужен навык выше»; при RequiredPerkID > 0 нужен этот перк.
3. Лечащий стоит в «целой» клетке (не промежуточной, не в бездействии).
4. Цель — не враг лечащего; жива и в сознании (кроме пустого ПК); «человек/ПК» цели совпадает с типом предмета (ремкомплект только для ПК, остальное только для людей).
5. Дистанция: по горизонтали ≤ 0,8 м (лежащая цель — 1,2 м; ПК — 1,8 м, но не ближе 0,8 м), по вертикали цель от −0,5 до +2 м относительно лечащего.
6. Есть что лечить (по типу эффекта): Normal и NormalCriticalFirst — у цели есть излечимые ранения или возможна перевязка; CriticalOnly и TempRemovePenalties — есть излечимые ранения; RemoveBleeding — есть кровотечение; RepairPK — ОЗ ПК ниже максимума; BoostVP и TempStopBleeding — всегда (можно профилактически).

«Перевязка возможна» (CUnit::CanHeal): trunc(250/140 × (MEDICINE + SkillModifier)) > перевязанных у цели **и** текущие ОЗ цели < максимума.

**Применение** (исполнитель лечения): списывается APToUse предмета (у ремкомплекта действие AC_REPAIR_PK по таблице цен стоит 0, хотя для начала требуется APToUse = 10), тренируется MEDICINE (у ремкомплекта — ENGINEERING), звучит ИИ-звук «Healing» (запись 20, радиус 2). После анимации боец переходит в состояние «лечит» до завершения.

**Начало лечения** (вход в состояние):
1. Пациенту ставится ранение «Patient» (запрещает ему ходить и т. д.).
2. Флаг «снимать кровотечение» = у лечащего перк 59; множитель длительности = P1 перка 64 (2) или 1.
3. По типу эффекта:
   - Normal: если перевязка возможна — ёмкость сеанса = TotalHealVP; иначе ищется излечимое ранение (ниже) и назначается его цена в ОД.
   - CriticalOnly: ищется ранение; цена назначается всегда (проверяется поле «зона» против «нет ранения», которое никогда не совпадает) — при пустом результате сеанс стоит 1 ОД и ничего не лечит (в БД таких предметов нет).
   - NormalCriticalFirst: есть излечимое ранение — лечить его; нет — перевязка с ёмкостью TotalHealVP.
   - TempRemovePenalties: приостановить ранения на trunc(Duration × множитель) ходов; на тот же срок отложить модификатор ОЗ ×(1 − Power/100) — после окончания действия максимум ОЗ пациента уменьшается на Power % до конца миссии («отходняк»).
   - BoostVP: буст ОЗ (ниже) с силой Power и сроком trunc(Duration × P1 перка 64 лечащего); мир сразу сверяет сознание пациента.
   - TempStopBleeding: запас кровоостанавливающего пациента += round(Power) (действует до следующего нового кровотечения, без срока).
   - RemoveBleeding: снять все кровотечения независимо от DC (медаль «вылечил ранение» на сумму DC).
   - RepairPK: если цель в ПК или пустой ПК — ёмкость = TotalHealVP.
4. Если нечего делать (ёмкость ≤ 0 и нет цены лечения ранения) — сразу обычное состояние (одноразовые препараты на этом заканчиваются).
5. В пошаговом режиме сразу выполняется шаг лечения на текущие ОД.

**Шаг лечения** (в начале — с текущими ОД; затем в конце каждого хода — с оставшимися ОД хода; в реальном времени — на каждом такте с round(0,5 × максимума ОД)):
1. Нет цели/аптечки или нечего делать — выход в обычное состояние.
2. ОД ≤ 0 — ждать следующего хода (реконструкция; см. «Отклонения»).
3. Ремкомплект: пересчитать ремонт (ниже); ёмкость −= отремонтировано; ОЗ ПК += отремонтировано; списать ОД. Не получилось — ёмкость 0.
4. Лечение ранения: списать min(остаток цены, ОД); когда остаток цены ≤ 0 — снять ранение (все ранения этого типа в этой зоне, лечимые лекарствами, или кровотечение), медаль «вылечил ранение» на сумму DC.
5. Перевязка: рассчитать (ниже), ёмкость −= объём, перевязать, медаль «вылечил рану» на объём, списать ОД; если следующий расчёт уже невозможен — ёмкость 0.
6. Ёмкость ≤ 0 и нет цены — выход.

**Расчёт перевязки** (CreateFirstAid для обычных предметов):
1. Множитель пациента m = P1 перка 24 пациента (1,5) или 1.
2. Навык S = trunc(trunc(MEDICINE) × m + SkillModifier); перк 57 лечащего: S += 15.
3. Предел перевязки L = trunc(250/140 × S).
4. Место у пациента: room = максимум − текущие − перевязанные.
5. Объём v = min(max(0, L − перевязанные), room); v = 0 → невозможно.
6. Скорость k = P1 перка 63 (1,5) только для предметов Normal, иначе 1.
7. Цена = max(1, trunc(v / max(1, S·k) × 60)); если цена больше доступных ОД — цена = ОД, v = round(ОД × S × k / 60).
8. Итог: прибавка = min(v, round(ёмкость)), предел L.

**Применение перевязки** (Heal): T = текущие + перевязанные; верх = min(максимум, текущие + L); d = max(0, min(round(прибавка), верх − T)); перевязанные += d. Перевязка не трогает текущие ОЗ — она добавляет отдельный пул.

**Ремонт ПК**: недостача = максимум ОЗ ПК − текущие ОЗ ПК (≤ 0 — невозможно); S = ENGINEERING; цена = max(1, trunc(недостача / max(1, S) × 20)); если больше ОД — цена = ОД, объём = round(ОД × S × 0,05). Ремонт идёт прямо в ОЗ ПК (Modify).

**Поиск излечимого ранения** (TryHealCritical): DC лечащего D = trunc(300/140 × (trunc(trunc(MEDICINE + P1 перка 56) × m) + SkillModifier)); первое по порядку в списке ранение, у которого (DC ранения ≤ D и оно лечимо лекарствами) или (флаг «снимать кровотечение» и это кровотечение). Цена лечения в ОД = max(1, round(DC ранения × 50 / max(1, MEDICINE) / P1 перка 62)).

**Буст ОЗ** (AddVPBoost(сила, срок)): модификатор ячейки VP с прибавкой fAdd = теоретический максимум ОЗ × сила × 0,01 (поднимает и максимум, и текущие ОЗ сразу на trunc(fAdd)); срок записывается в список сроков; проверка передозировки. Модификатор живёт до конца миссии.

**Передозировка** (CheckOverdose; при каждом бусте и в каждом конце хода после уменьшения всех сроков на 1): если ∑ 1/срокᵢ > 1 или какой-либо срок = 0 — список сроков очищается, и если боец не мёртв — он теряет сознание и его текущие ОЗ := 0. Следствие (как реализовано): действие стимулятора заканчивается обмороком, когда его срок доходит до 0; два стимулятора с остатком 1 ход — сразу обморок.

**Прерывания лечения ранениями лечащего**: «оглох», снижение ОД/навыков, обездвиживание — лечение продолжается; «случайный выстрел» — пациент получает 4 прямых удара по 1…3 ОЗ, лечение прерывается; остальные — лечение прерывается, ранение обрабатывается после смены состояния.

**Завершение сеанса**: −1 заряд аптечки (пустая убирается из руки, анимация «без оружия»); с пациента снимается «Patient»; реплика «лечение завершено», если недостача ОЗ (с учётом перевязанных) уменьшилась больше чем вдвое (для ранения — если ранения больше нет), иначе «не смог закончить».

**Лечение между миссиями** (при выходе из зоны, кроме лагеря/базы; HealOnLeaveZone):
1. Режим: если HealOnLeaveZone — «лечение», иначе если BandageOnLeaveZone — «перевязка», иначе «ничего».
2. Навык отряда S = максимум MEDICINE среди живых наёмников + GroupMedicalCoeff × среднее MEDICINE остальных живых (бессознательные считаются живыми).
3. Объём V = trunc(trunc(S × HealOnLeaveZoneCoeff) × 1,7857142686843872) (тот же коэффициент 250/140; для режима «перевязка» тоже берётся HealOnLeaveZoneCoeff — BandageOnLeaveZoneCoeff нигде не читается).
4. Для каждого наёмника: если мёртв, или без сознания при NeedCarryOutUnconscious и не вынесен с поля (не был «унесён» в переноске) — Kill(); иначе «лечение»: текущие ОЗ := max(1, min(максимум, текущие + V)), перевязанные := min(перевязанные, максимум − текущие); «перевязка»: обычная перевязка на V; «ничего» — ничего. Флаг «без сознания» снимается у всех.
5. Если живых наёмников нет — функция ничего не делает (никого не убивает).

HealOnRest (лечение отдыхом, HealOnRestCoeff) в коде есть, но нигде не вызывается.

### Формулы

- Предел перевязки L = trunc(1,7857 × S); скорость перевязки S·k/60 ОЗ за 1 ОД.
- DC лечащего = trunc(2,142857 × S'), где S' = trunc(trunc(MED + 15·[перк 56]) × m) + SkillModifier.
- Цена лечения ранения = max(1, round(DC_ранения × 50 / MED / 1,5^[перк 62])).
- Ремонт ПК: ENG/20 ОЗ за 1 ОД.
- Буст: fAdd = (база + опыт)_VP × Power / 100.
- Передозировка: ∑ 1/dᵢ > 1 или ∃ dᵢ = 0.

### Особые случаи и прихваты

- «Перевязанные» ОЗ — отдельный буфер поверх текущих, а не восстановление; в миссии он не превращается в настоящие ОЗ, но поглощает урон пропорционально и считается в процентах здоровья.
- Объём перевязки ограничен навыком медика (L), а не предметом; ёмкость предмета (TotalHealVP) ограничивает один сеанс.
- Сеанс расходует один заряд, сколько бы ни было вылечено.
- Перк 58 снимает требования к медицинским предметам, но не к ремкомплектам.
- Лечение ранения требует ОД, распределённых по ходам; лечащий всё это время «занят».
- Предмет с эффектом TempRemovePenalties после окончания уменьшает максимум ОЗ на Power % до конца миссии.
- Стимулятор поднимает ОЗ на долю **базового** максимума и по окончании срока приводит к обмороку с обнулением ОЗ (как реализовано; не подтверждено, что так в оригинальной игре).
- На тяжёлом уровне выход из зоны не лечит вовсе (HealOnLeaveZone = 0, а для перевязки берётся HealOnLeaveZoneCoeff = 0).
- Требования отмычек к навыку/перку проверяются только подсветкой в интерфейсе, у аптечек — и при применении.
- В реконструкции импорт строк «NormalCriticalFirst» и «RepairPK» в поле Effect отсутствует (поле остаётся неинициализированным), хотя код использует эти режимы; в оригинале они должны сопоставляться с FAE_CRITICAL_FIRST (7) и FAE_REPAIR_PK (6) — не подтверждено.

### Что нужно от движка-носителя

Состояние бойца «лечит» с тиком по концу хода/такту, отмена командой «отмена», канал медалей (раздел 18), хук «выход из зоны» на глобальной карте.

## 9. Скрытность, шум действий, прерывание

### Назначение

Ролевые формулы, через которые навыки STEALTH, SPOT и INTERRUPT влияют на прятки, слух и перехват хода. Сами механизмы восприятия (кто кого слышит, когда раскрывают спрятавшегося, наборы «слышимых») описаны в «ИИ 5 — Поведение, восприятие, маршруты.md» (разделы 4–5); порядок перехватов в ходе — «Мир 1». Здесь — только ролевая сторона и численные правила.

### Данные

- Навыки: STEALTH (база 5 + 2·ЛОВ), SPOT (база 5 + 2·ИНТ), INTERRUPT (база 25).
- Флаг «прячется» на обёртке миссии.
- Таблица AISoundConstants (одна запись): PrecisePositionRadius 7, ExitRadius 10, BaseProbability 50, DistanceCoeff 10, LoudSound 10, HideCoeff 0,8.
- Таблица InterruptsConstants (одна запись): BackInterruptsBase 90, InterruptsBase 50, MissedShotInterruptsBase 35, APInterruptReduction 1,0, MinInterruptAP 4.
- Таблица AISounds — радиусы шумов (полная таблица — в «ИИ 5», раздел 4).

### Алгоритм

**Спрятаться** (команда «hide»): стоит 14 ОД (зашито в код; в RPGAPs запись 14 тоже 14), тренирует STEALTH. Отказ, если боец недавно раскрыт (флаг «можно прятаться» сброшен до следующего такта), если надет ПК без CanHide (CanHide = 1 только у AlliesScout и всех ПК террористов), или если его видит хоть один враг другого игрока. Выйти из пряток — бесплатно. Вход в ПК снимает прятки.

**Вероятность раскрытия спрятавшегося** наблюдателем (GetUnhideProbability, D — расстояние в клетках):
1. Spot' = SPOT наблюдателя; при перке 25 — trunc((1 + 0,25) × SPOT).
2. База = trunc(45 − (44/30) × D).
3. Stealth' = STEALTH прячущегося; ночью при перке 75 у прячущегося — trunc((1 + 0,25) × STEALTH) (реконструкция; см. «Отклонения»).
4. U = clamp(База + Spot' − Stealth', 0, 100). Кто, когда и сколько раз бросает — «ИИ 5».

**Вероятность услышать** (GetHearingProbability; слушатель, источник, дистанция d = расстояние × 1,6 в клетках, звук с радиусом R = радиус записи AISounds (по поверхности) × глушитель):
1. Слушатель оглох (ранение Deaf) — 0.
2. Spot = SPOT слушателя; перк 20 — × 1,5 (усечение).
3. «Громкий» звук (источника нет или R ≥ LoudSound = 10): дальность H = 7 + (R − 7) × Spot / 140; в ПК с SensorRange — × SensorRange (и × 1,5 при перке 76); результат 100, если H ≥ d, иначе 0.
4. «Тихий» звук: P = 50 + (Spot + (7 − d) × 10 − STEALTH источника) × 100 / 140; если источник прячется — × 0,8; clamp 0…95. Успешно услышанный тихий звук тренирует SPOT слушателя (бросок: P > случайное 0…98).

**Шум действий** (что порождает ИИ-звук; радиусы — таблица AISounds):

| Действие | Запись AISounds | Радиус | Поправки |
|---|---|---|---|
| шаг лёжа / сидя / стоя / бегом / боком | 3 / 4 / 5 / 6 / 7 | 2 / 2 / 2 / 4 / 2 (по поверхности R1…R4) | перк 41: бег звучит как ходьба (5); перк 77: радиус ÷ 1,5 (на любом бойце, не только в ПК); в ПК — свой звук шага (только звук для игрока) |
| выстрел пистолет / ПП / винтовка / пулемёт | 8 / 9 / 10 / 11 | 40 / 50 / 60 / 70 | глушитель оружия (Silencer) — множитель радиуса |
| очередь тех же типов | 12…15 | 65 / 75 / 85 / 95 | |
| гранатомёт, миномёт | 16, 17 | 100 | |
| удар без оружия / холодным оружием | 18 / 19 | 3 / 5 | |
| лечение | 20 | 2 | |
| инженерия | 21 | 4 | |
| открыть / закрыть дверь | 23 / 25 | 4 / 5 | всегда «металлические» записи, независимо от материала двери |
| перезарядка | 26 | 2 | |
| бросить тело | 27 | 5 (по поверхности 5…7) | |
| взрыв гранаты | 30 | 100 | |

**Перехват хода** (CalcInterruptProbability; A — перехватывающий, B — тот, кого перехватывают):
1. Если текущие ОД A ≤ 4 — 0.
2. Разница навыков Δ = INTERRUPT(A) − INTERRUPT(B).
3. База: если A только что обстрелян (промах по нему) — 35 + Δ; иначе если «взаимно» (оба видят друг друга) — 50 + Δ; иначе (B не видит A, «в спину») — 90 + Δ.
4. Минус trunc(1,0 × (максимум ОД A − текущие ОД A)).
5. clamp(5, 95).
6. Проверка: r = случайное 0…99; тренируется INTERRUPT(A); сила = вероятность − r; при силе ≥ 0 перехват состоялся (сила — для упорядочивания перехватов, «Мир 1»). Фактический шанс = вероятность + 1 %.

Перк 27 даёт автоматический перехват первого хода (мир).

**Мораль и страх.** В ролевой модели бойца нет параметра морали или страха. Реакция «испуг» существует только у ИИ (порог по проценту ОЗ, «ИИ 5»).

### Формулы

- U = clamp(trunc(45 − 1,4667·D) + Spot' − Stealth', 0, 100).
- Слух громкого: H = 7 + (R − 7)·Spot/140 (≥ d → 100 %).
- Слух тихого: P = clamp((50 + (Spot + (7 − d)·10 − Stealth)·100/140)·(0,8 при прятках), 0, 95).
- Перехват: clamp(база + Δ − (ОДmax − ОД), 5, 95), база ∈ {35, 50, 90}.

### Константы

| Имя | Значение | Смысл | Источник |
|---|---|---|---|
| цена «спрятаться» | 14 ОД | | GetActionAP |
| коэффициент дистанции раскрытия | 44/30 | | GetUnhideProbability |
| база раскрытия | 45 | | GetUnhideProbability |
| множитель дистанции слуха | 1,6 | | CanHearSound |
| PrecisePositionRadius, LoudSound, BaseProbability, DistanceCoeff, HideCoeff | 7, 10, 50, 10, 0,8 | | AISoundConstants |
| потолок тихого слуха | 95 % | | GetHearingProbability |
| BackInterruptsBase, InterruptsBase, MissedShotInterruptsBase | 90, 50, 35 | | InterruptsConstants |
| APInterruptReduction, MinInterruptAP | 1,0; 4 | | InterruptsConstants |
| границы перехвата | 5…95 | | CalcInterruptProbability |

### Особые случаи и прихваты

- Каждая проверка перехвата тренирует INTERRUPT — часто проверяемый боец быстро растёт в перехвате.
- Шум двери всегда «металлический» (радиусы 4/5), даже для деревянных дверей.
- Перк 77 «Lower PK noise» работает и без панцерклайна.
- «Громкий» звук слышен наверняка в пределах дальности, «тихий» — никогда не наверняка (≤ 95 %).

### Что нужно от движка-носителя

Расстояния в клетках сетки; события «шум» от исполнителей действий; хук «враг заметил» для порядка перехватов.

## 10. Инвентарь: сетка, слоты, руки, вес

### Назначение

Инвентарь бойца — две «руки» (слоты экипировки) и рюкзак-сетка. Предметы занимают прямоугольник клеток. Отдельно — визуальная раскладка предметов на поясе формы (только отображение).

### Данные

- Рюкзак: сетка 7 × 13 клеток (ширина × высота), флаг занятости на клетку; список {позиция левого верхнего угла, предмет}.
- Слоты: SLOT_1 (0) и SLOT_2 (1); индекс активного слота (по умолчанию 0). «Активный предмет» = содержимое активного слота (может быть пустым — тогда боец бьёт рукопашным оружием по умолчанию, запись RPGMeleeWeapons №1 «без оружия»).
- Ссылка на надетый панцерклайн (меняет правила экипировки).
- Размер предмета — SizeX × SizeY записи RPGItems (поворота нет). Вес — Weight (граммы).
- Предмет «в руке у курсора» (перетаскиваемый) хранится у бойца/игрока на уровне мира, не в инвентаре.

### Алгоритм

**Можно ли положить в рюкзак в точку (x, y)**: x, y ≥ 0, x + ширина ≤ 7, y + высота ≤ 13, все клетки прямоугольника свободны.

**Поиск места** (FindPlace): перебор строк сверху вниз (y = 0…12), в строке слева направо (x = 0…6); первая подходящая позиция.

**Положить** (Place): если позиция (−1, −1) — найти место (нет места — отказ, предмет не кладётся); иначе положить в заданную точку **без проверки** (вызывающий проверяет сам); отметить клетки, добавить запись.

**Взять** (Take): найти запись, освободить клетки, удалить.

**Авторасстановка** («arrange»): копия списка сортируется по убыванию веса раскладки w = max(ширина, высота) + ширина × высота (сортировка нестабильная); все предметы вынимаются, сетка очищается; предметы по порядку кладутся первым подходящим местом. Предмет, которому места не нашлось, из инвентаря **пропадает** (на практике возможно, только если жадная укладка хуже исходной).

**Можно ли экипировать в слот** (CanEquip, одинаково для обоих слотов):
1. Обойма — нельзя; «пустышка» (предмет без игровой записи) — нельзя.
2. Надет одноместный ПК (SingleSlot, все ПК террористов) — нельзя ничего.
3. «Тип ПК-оружия» предмета: PanzerkleinWeaponType у огнестрела и рукопашного оружия, PanzerkleinWeapon у гранаты (у гранаты без записи — 0).
4. Тип ≠ 0 (оружие для ПК): можно только в ПК, у которого AllowWeaponType[тип] = 1.
5. Тип = 0 (обычный предмет): можно только **без** ПК.

**Снять из слота вручную**: нельзя, если надет одноместный ПК (его оружие несъёмное).

**Экипировать / снять** (Equip / TakeOff): без проверок (их делает вызывающий); экипировка при занятом слоте просто заменяет ссылку.

**Активировать слот**: смена индекса активного слота (цены смены предметов — приложение Г: «swap» 12 ОД, перемещения внутри инвентаря 0).

**Надевание/снятие ПК**: при надевании оружие пилота из обоих слотов уходит в рюкзак (если места нет — падает на землю рядом в случайной точке ±0,5 клетки), затем оружие ПК из его слотов переносится в слоты пилота, активен слот 1. При снятии — содержимое слотов пилота переносится в слоты ПК.

**Двуручное оружие** (TwoHanded типа оружия) занимает один слот, как и любое другое; двуручность влияет только на ранение «Idle hand».

**Вес**: используется только для физики метания (гранаты и ножи, «Бой 1») и в подсказках. Никакой перегрузки, штрафов за вес и предела переносимого веса нет; EncumbranceKoeff панцерклайна и ранение «Encumbrance» не используются.

**Отображение на теле** (только визуал): форма (RPGUniforms) задаёт 9 мест на поясе (BeltL1, BeltR1, BeltM1, BeltMediumL1/R1/L2/R2, WaistBeltL1/R1), у каждого 4 подтипа по приоритету; для каждого приоритета по очереди место заполняется моделью предмета нужного подтипа (сначала из слотов, затем из рюкзака — предмет с наибольшим SubTypePriority), неиспользованное место может получить фиксированную модель формы. Активный «тяжёлый» предмет (2HWeapon) вешается на кость оружия, кепка — если у головы нет волос, рюкзак — модель формы. Генератор раскладки сеется постоянным семенем бойца.

### Формулы

- Вес раскладки при сортировке: w = max(sx, sy) + sx·sy.

### Константы

| N_SLOTS | 2 | руки | DataConst.h |
| N_STORESLOT_DEFWIDTH × HEIGHT | 10 × 13 | окно магазина | InterfaceConst.h |

### Особые случаи и прихваты

- Перегрузки нет вообще — можно нести всё, что помещается в 7 × 13.
- Явная позиция при укладке не проверяется (выход за сетку вызывающий обязан исключить).

### Что нужно от движка-носителя

Сетка инвентаря с прямоугольными предметами без поворота, два слота рук с активным индексом, хук перестройки модели бойца при смене экипировки.

## 11. Предметы: типы, состояние, обоймы, разрядка

Создание живого предмета (CreateItem) проверяет тип наследника по порядку: оружие, обойма, граната, инженерный заряд, медпредмет, холодное оружие, миноискатель, мина, инструмент, ключ, отмычка; иное — ничего. Подсказка-предмет всегда строится из записи RPGItems №438 (0x1B6). Предмет без живого наследника на карте становится «пустышкой» (экипировать нельзя). Униформа предметом не является.

Счётные предметы (CItem) имеют количество; деление (Split) отдаёт не больше «количество − 1»; объединение Join сравнивает типы указателей (CItem* против IJoinSplit*) и поэтому **всегда отказывает** — штабелирования одинаковых предметов нет. Для патронов используется отдельное «перелить» (JoinItem).

### Алгоритм

**Оружие при создании**: режим огня — первый поддерживаемый по порядку: навскидку, прицельный, тщательный, короткая очередь, длинная очередь, снайперский. Внутренняя обойма — запись InnerClip оружия, количество патронов = InnerClipAmmoQuantity (если > 0), иначе ёмкость обоймы; тип патрона — первый по порядку таблицы RPGAmmos с тем же AmmoGroup. Ёмкость внутренней обоймы = то же количество.

**Обойма как предмет** (CreateClipItem): ёмкость = Quantity записи обоймы; тип патрона — заданный (для предметов персонажа из RPGClip4Pers) или первый подходящий по AmmoGroup; количество — заданное или полная ёмкость.

**Совместимость**: обойма подходит оружию, если AmmoGroup обоймы равен AmmoGroup внутренней обоймы оружия; «того же цвета» — если ещё совпадает AmmoColor патрона (0 обычный, 1 синий, 2 красный, 3 жёлтый).

**Поиск обоймы для перезарядки** (FindProperClip): сначала оба слота рук (по порядку), затем рюкзак (по порядку записей); первая совместимая. Если во внутренней обойме есть патроны, подходит только обойма с патронами того же цвета.

**Перезарядка** (Reload, по времени действия): если совместимых нет — отказ. Выбор цвета: если есть обойма того же цвета, что и текущие патроны, — брать только такие; иначе — любую совместимую (цвет патронов меняется). Пока внутренняя обойма не полна и находится подходящая: перелить min(нужно, есть); опустевшую обойму удалить (из слота или рюкзака); дальше — только того же цвета. Перелив в пустую обойму с другим цветом сначала меняет тип патрона.

**Зарядить конкретной обоймой** (LoadWeapon): обойма совместима (без проверки цвета); если в оружии есть патроны — сначала разрядить; затем перелить.

**Разрядка** (Unload): если патронов нет — отказ; создаётся новая обойма того же типа с тем же патроном и 0 патронами, в неё переливается min(патронов, ёмкость обоймы), она кладётся в рюкзак автоматически. Если места нет — функция всё равно сообщает успех, а патроны пропадают. Lua ItemUnload вместо этого просто уничтожает все патроны внутренней обоймы (обойма остаётся).

**Исправность оружия**: единственное «состояние» оружия — флаг «исправно». Его сбрасывает только критическое ранение «Damage weapon» в руку, когда огнестрел активен. Неисправное оружие не создаёт атак (молча); починки нет. Износа, клина, прочности предметов, деградации от использования нет.

**Привыкание к оружию** (familiarity; на бойце: «привычный» предмет — конкретный экземпляр, счётчик, текущий бонус):
- вызывается при каждой атаке с расходом патронов (один раз за выстрел/очередь, у рукопашной — каждый удар): скорость v = 1 (перк 6: 2; перк 71: v ÷ 2), предел = MaxWeaponAdaptation (100) × 1,5 при перке 87 × 2 при перке 71, множитель = WeaponAdaptationMultiplyer (0,1);
- если атакующий предмет — привычный: счётчик = min(предел, счётчик + v); иначе счётчик −= v, и при счётчике ≤ 0 привычным становится текущий предмет со счётчиком 0;
- бонус = множитель × счётчик (до +10, с перками до +20…+30) прибавляется к попаданию, только пока в руках именно привычный экземпляр.

**Оружие ПК**: оружие с PanzerkleinWeaponType ≠ 0 экипируется только в ПК, разрешающий этот тип (раздел 10, 16).

### Формулы

- Урон оружия в подсказке/атаке: мин = DmgMin патрона × DamageMod / 100; макс = DmgMin патрона × DamageModMax / 100 (DmgMax патрона не используется); пробивная энергия nK = UnitWeight патрона × InitialVelocity (подробно — «Бой 1»).
- Привыкание: бонус = 0,1 × min(предел, ∑ v).

### Константы

| Имя | Значение | Смысл | Источник |
|---|---|---|---|
| MaxWeaponAdaptation | 100 | предел счётчика привыкания | RPGToHits №1 |
| WeaponAdaptationMultiplyer | 0,1 | бонус за единицу счётчика | RPGToHits №1 |
| запись подсказки-предмета | RPGItems №438 | | CreateHintItem |
| цвета патронов | 0…3 | обычный/синий/красный/жёлтый | DataRPG.h |
| групп патронов с несколькими цветами | 2 (группа 18: цвета 0, 1, 2; группа 34: 0, 1) | остальные 36 групп — один тип | RPGAmmos |
| патроны с шансом оглушения | группы 98, 99: 80 % | остальные 0 | RPGAmmos |

### Особые случаи и прихваты

- Штабелирования нет (Join всегда отказывает); каждая обойма, граната, аптечка — отдельный предмет.
- Разрядка при полном рюкзаке теряет патроны.
- Неисправное оружие нельзя починить.
- Привыкание привязано к экземпляру: подобранный такой же автомат начинает с нуля, а смена оружия сначала «стирает» старый счётчик.
- В JoinItem проверка «не CItem» не возвращает отказ (пропущен оператор return) — при неподходящем объекте разыменование пустого указателя (не подтверждено для оригинала).

### Что нужно от движка-носителя

Фабрика живых предметов по типу записи-наследника, ссылки на конкретные экземпляры (привыкание), сериализация зарядов и патронов.

## 12. Магазины и деньги

### Назначение

«Магазин» — склад снаряжения на базе: у каждого игрока свой. Ассортимент открывается по мере роста «рейтинга» кампании и пополняется. Обмен с магазином бесплатный: цен и денег в логике магазина нет.

### Данные

- RPGStoreItems: ItemID, SideID (сторона, для которой продаётся), Rating (с какого уровня доступно), Quantity (дробное: прирост количества за уровень). В БД 189 записей: Axis (1) и Allies (2), рейтинги 1…14 и 99 (недостижимый).
- Строка склада: {тип: обычная / постоянное количество / восполняемая, рейтинг, количество (дробное), запись предмета, запись магазина, список живых предметов}.
- 8 категорий (витрин): прочее, винтовки, пистолеты, гранаты, холодное, оружие ПК, тяжёлое, пистолеты-пулемёты; у каждой своя растущая сетка 10 × 13.
- Категория предмета: у оружия — StoreType его типа оружия (RPGWeaponTypes); обойма и граната — категория первого оружия, использующего эту обойму (предпочтительно текущая витрина; иначе первое найденное; гранаты по умолчанию — «гранаты»); холодное оружие — «холодное»; прочее — «прочее».
- Цена предмета (RPGItems.Cost) читается из БД, но нигде не используется; в редакторской БД столбец пуст у всех 415 предметов.
- Деньги игрока nMoney: меняются только из Lua (PlayerGetMoney, PlayerGiveMoney — прибавляет без ограничений, PlayerTakeMoney — вычитает с прижатием к 0).

### Алгоритм

**Обновление магазина** (при открытии склада сценарной командой «показать магазин», по кнопке «arrange» на панели склада, в сетевом меню; уровень L = max(уровень техники hot-seat, максимальная сложность, достигнутая в сценарии)):
1. Для каждой записи RPGStoreItems своей стороны с Rating ≤ L, которой ещё нет на складе: новая восполняемая строка, рейтинг = Rating записи, количество = max(1, Quantity); создать trunc(количество) живых предметов.
2. Для каждой строки с записью магазина: если она восполняемая и её рейтинг < L — количество += (L − рейтинг) × Quantity записи, рейтинг := L; затем досоздать живые предметы до trunc(количество) (лишние никогда не удаляются).
3. Все витрины очищаются до 10 × 13 и раскладываются заново: каждая строка-оружие кладётся полосой: оружие в левый край ниже всего уже лежащего, справа от него — **новые** обоймы к нему: столько по ширине, сколько влезает в (ширина витрины − ширина оружия), и столько рядов, сколько обойм помещается по высоте оружия (только если предмет «принадлежит стороне»: у него нет записей магазина или есть запись этой стороны). Остальные предметы — первым свободным местом; сетка витрины растёт вниз по строке, если места нет.
4. Для оружия в руках каждого бойца отряда (оба слота, только огнестрел) — такая же полоса обойм к нему, но без самого оружия.

**Взять из магазина**: предмет убирается с витрины; в первой строке, содержащей его, количество −1. Обоймы-«довески» ни в одной строке не числятся — их можно брать сколько угодно (при следующем обновлении они появятся снова).

**Отдать в магазин**: создаётся обычная строка (рейтинг 0, количество 1) с этим предметом и кладётся в свою витрину (в указанную клетку, если подходит и витрина текущая; иначе — автоматически, а у чужой витрины ставится флаг «изменилась»).

### Формулы

- Количество восполняемой строки после обновления: max(1, Q) + ∑ (L_нов − L_стар) × Q = max(1, Q) + (L − Rating)·Q.
- Обойм-довесков к оружию: ⌊(10 − ширина оружия)/ширина обоймы⌋ × ⌊высота оружия / высота обоймы⌋.

### Константы

| Имя | Значение | Смысл | Источник |
|---|---|---|---|
| размер витрины | 10 × 13 (растёт вниз) | | RPGStore.cpp |
| категорий | 8 | | RPGStore.h |
| рейтинг 99 | недостижим | спецпредметы с Quantity 0,01 | RPGStoreItems |

### Особые случаи и прихваты

- Цены, деньги и бартер в обмене не участвуют; магазин — бесплатный склад.
- Патроны к любому оружию склада и к оружию в руках отряда бесконечны (обоймы пересоздаются при каждом обновлении).
- Количество растёт дробно: предмет с Quantity 0,14 появляется заново примерно раз в 7 уровней рейтинга.
- Сданное в магазин не восполняется и не исчезает.

### Что нужно от движка-носителя

Экран склада с вкладками-категориями, хранение строк склада в сохранении, источник «уровня рейтинга» кампании («Кампания 1»).

## 13. Сундуки и лут

### Назначение

Случайное содержимое контейнеров на карте и снаряжение врагов задаётся «сундуками»: шаблон — взвешенный набор вариантов, вариант — список предметов с количествами. Выкатывается один раз при сборке карты.

### Данные

- RPGChestTemplates (186) — шаблоны (рулетка вариантов).
- RPGChests (2455) — варианты: TemplateID, RndWeight (вес в рулетке), Flags (флаги условий варианта, как у вариантов шаблонов карт), Level (0…15).
- RPGLootInstances (4890) — строки варианта: ChestID, RPGItemID, Quantity, MaxQuantity, DifficultyID.
- RPGChestLayouts (13) — геометрия полок контейнера: ShelfHeight1…5 (ненулевые — высоты полок), VerticalLayout (предметы стоят вертикально), SafeLayout (сейф: глубина вдвое меньше и сдвиг).
- У персонажа: WeaponInHand (шаблон «в руке», задан у 52 персонажей) и WeaponInBackpack (шаблон рюкзака, 49 персонажей).

### Алгоритм

**Выкатка варианта** (CreateChest; генератор сборки карты, флаги условий карты, окно уровней [Lmin, Lmax]):
1. Подходящий вариант — валиден, его флаги совместимы с флагами карты и Level ≤ Lmax.
2. Варианты с Level ∈ [Lmin, Lmax] образуют рулетку с весами RndWeight; среди вариантов с Level < Lmin запоминается один с наибольшим Level (при равенстве — первый).
3. Есть кандидаты в окне — взвешенный случайный выбор; нет — вариант с наибольшим уровнем ниже окна; нет и его — пусто.
4. Для каждой строки варианта: количество = Quantity, а если Quantity < MaxQuantity — плюс случайное 0…(MaxQuantity − Quantity) включительно.

**Окно уровней**: Lmin = max(R − 4, 0), Lmax = R, а при R = 0 — Lmax = 100, где R — «относительный уровень» миссии = max(0, уровень врагов миссии) (уровень зоны сценария или уровень главы со случайной поправкой для случайных встреч, «Кампания 1»).

**Контейнеры на карте**: элемент карты с шаблоном сундука получает замок с твёрдостью R × 7 + 16 (запирается ли — флаг элемента); выкаченные предметы ставятся мировыми предметами внутрь контейнера: по оси, вдоль которой лежит/стоит предмет (по VerticalLayout), с долей −½, −⅙, +⅙ свободного хода по кругу (стартовая позиция цикла случайна), при наличии полок — на случайную полку; каждая единица количества — отдельный предмет в той же точке. Видимость контейнера, открывание — «Мир 3».

**Снаряжение врагов**: при сборке карты для юнита с персонажем: рюкзак = выкатка WeaponInBackpack; «в руке» = выкатка WeaponInHand, из которой обоймы переносятся в рюкзак, невалидные строки отбрасываются, а из оставшихся равновероятно выбирается одна — её предмет становится оружием в руке. Если выкатка есть, она **заменяет** WeaponID и список предметов персонажа (раздел 1).

### Формулы

- Количество строки = Quantity + rnd(0 … MaxQuantity − Quantity).
- Окно: [max(R−4, 0), R (или 100 при R = 0)].

### Константы

| Имя | Значение | Смысл | Источник |
|---|---|---|---|
| ширина окна уровней вниз | 4 | | MapBuild.cpp |
| Lmax при R = 0 | 100 | все варианты | MapBuild.cpp |
| твёрдость замка контейнера | R × 7 + 16 | | MapBuild.cpp |
| доли раскладки внутри | −½, −⅙, +⅙ (цикл с шагом 2 из 9) | | MapBuild.cpp |

### Особые случаи и прихваты

- DifficultyID строк лута (и записей «предметы персонажа» …4Pers) копируется, но нигде не проверяется — снаряжение не зависит от сложности (так в реконструкции; намерение данных — раздельные наборы для нормального и тяжёлого уровня; не подтверждено, как в оригинале).
- Если ни один вариант не подходит по окну, берётся лучший «слабее окна» — контейнер почти никогда не пуст.
- Шаблон «в руке», состоящий только из обойм, в оригинале приводил к чтению за пределами списка (реконструкция проверяет).

### Что нужно от движка-носителя

Детерминированный генератор сборки карты (одно семя на шаблон), флаги вариантов, мировые предметы внутри контейнеров.

## 14. Замки, ключи, отмычки, инструменты

### Назначение

Запертые двери, окна и контейнеры (все они — один класс объекта «дверь») открываются ключом (бесплатно для ключа) или отмычкой с проверкой инженерии. Инструменты (наборы разминирования) нужны для снятия мин и ловушек (раздел 15). Объект «дверь» как мировой объект — «Мир 3».

### Данные

- У двери: «заперта», номер ключа KeyID, твёрдость замка nLockHardness (задаются картой или скриптом; при отпирании твёрдость не сбрасывается до следующего запирания).
- RPGKeys: ItemID, KeyID (в БД: «FFight key» — ключ 1, предмет 389; «Prison Key» — ключ 98, предмет 392).
- RPGPicklocks: ItemID, APToUse, NeededEngSkill, NeededPerkID, AddToEngSkill, Quantity (заряды):

| № | Предмет | ОД | Нужна ИНЖ | Нужен перк | Прибавка | Зарядов |
|---|---|---|---|---|---|---|
| 1 | 395 «Picklock1» | 30 | 20 | — | 10 | 5 |
| 2 | 390 «Picklock2» | 30 | 60 | — | 20 | 7 |
| 3 | 393 «Picklock3» | 30 | 100 | 50 Master engineer | 25 | 10 |

- RPGTools (наборы разминирования): Charges, NeededEngSkill, NeededPerkID, CanUseForMineCleaning, SkillModifForMineCleaning:

| № | Предмет | Зарядов | Нужна ИНЖ | Нужен перк | Для мин | Модификатор |
|---|---|---|---|---|---|---|
| 1 | 387 MineClearingKit1 | 3 | 20 | — | да | 15 |
| 2 | 386 MineClearingKit2 | 5 | 50 | — | да | 20 |
| 3 | 388 MineClearingKit3 | 7 | 90 | 50 | да | 25 |

### Алгоритм

**Твёрдость замка при сборке карты** (R — относительный уровень миссии, раздел 13): контейнер — R × 7 + 16; запертая дверь без заданной твёрдости — (случайное 0…19 + 2R) × 3 − 3; иначе — значение из карты. Скрипт может запереть дверь с любыми ключом и твёрдостью.

**Можно ли открыть запертую дверь** (CanDoIt): ключ с совпадающим KeyID лежит в рюкзаке или в одном из двух слотов (пояс не проверяется) — да; иначе активный предмет — отмычка с ≥ 1 зарядом — да; иначе «заперто».

**Цена**: есть ключ — AC_USE_KEY (RPGAPs №9 = 8 ОД); иначе отмычка — её APToUse (30); незапертая дверь — 4 ОД.

**Выполнение** (Run): если дверь заперта — при наличии ключа выполняется AC_USE_KEY (ничего не тренирует), **и** (независимо) при отмычке в руке — AC_PICK_LOCK (тренирует ENGINEERING). Оба условия — двойное списание ОД (оригинальная особенность). Если дверь уже в нужном положении — конец без анимации.

**Момент анимации** (TimeLabelReached):
1. Ключ есть — замок открывается молча, ключ остаётся.
2. Иначе отмычка с зарядом: заряд списывается **до** броска; S = ENGINEERING (в реконструкции + 20 при перке 52); бросок = trunc(случайное 0…99 × S / 100) + AddToEngSkill + trunc(S / 2) — свежий локальный генератор от таймера, не игровой; опустевшая отмычка убирается из руки; если бросок < твёрдости — провал (дверь остаётся запертой и закрытой, звука нет); иначе — медаль «вскрыл замок» на твёрдость × 1,1, замок открыт.
3. Дверь открывается/закрывается; ИИ-звук открытия (23, радиус 4) или закрытия (25, радиус 5).

**Инструмент можно использовать** (CanBeUsed): заряд ≥ 1, и (перк 50 **или** (есть требуемый перк и ENGINEERING ≥ NeededEngSkill)).

**Требования отмычки** (NeededEngSkill, NeededPerkID) проверяются только подсветкой предмета красным в инвентаре; применению они не мешают. Требования инструментов проверяются при применении (CanBeUsed), медпредметов — тоже.

### Формулы

- Взлом: успех, если trunc(rnd(0…99)·S/100) + A + trunc(S/2) ≥ H (A — AddToEngSkill, H — твёрдость). Вероятность ≈ доля r, при которой r·S/100 ≥ H − A − S/2.

### Константы

| Имя | Значение | Смысл | Источник |
|---|---|---|---|
| AC_USE_KEY | 8 ОД | RPGAPs №9 | GetActionAP |
| AC_PICK_LOCK | APToUse отмычки (30) | | GetActionAP |
| AC_OPEN_CLOSE | 4 ОД | | GetActionAP |
| твёрдость контейнера | R·7 + 16 | | MapBuild.cpp |
| твёрдость двери по умолчанию | (rnd(20) + 2R)·3 − 3 | | MapBuild.cpp |
| перк 52 | +20 | | RPGPerks |

### Особые случаи и прихваты

- Ключ не расходуется и не проверяется на «требования».
- Ключ в поясе/руке перетаскивания не считается.
- Двойное списание ОД при ключе и отмычке одновременно.
- Провал взлома тратит заряд и не открывает дверь; повторять можно сколько угодно, пока есть заряды.
- Бросок взлома не воспроизводится при перезагрузке (локальный генератор от таймера).
- Твёрдость до 54 + 6R у дверей, 16 + 7R у контейнеров; при твёрдости ≤ A + S/2 взлом гарантирован.

### Что нужно от движка-носителя

Объект двери с флагом «заперта», номером ключа и твёрдостью; поиск ключа в рюкзаке и руках.

## 15. Мины и ловушки: обнаружение и разминирование

### Назначение

Мины (на клетке земли) и ловушки (граната или инженерный заряд на двери/контейнере) имеют «сложность» DC. Боец видит мину на расстоянии, зависящем от SPOT/ENGINEERING и DC; снимает её набором разминирования с броском по ENGINEERING. Взрыв мины/ловушки, цепные подрывы, мины как мировые объекты — «Мир 3».

### Данные

- RPGMinesConstants (одна запись): BaseDisarmProb 75, SpotSkillModif 20, MinerEngineerSkillModif −20, MineSpotModif 4.
- RPGMines: 6 мин (предметы 366–371), у всех APToSet = 20, Explosion = граната №16.
- У мины/ловушки: DC, позиция, модификаторы перков поставившего (урон строениям, урон по площади, «всегда крит»).
- Миноискатели: класс предмета есть, таблица RPGMineDetectors пуста — никакого бонуса к обнаружению нет (активный миноискатель только меняет анимацию).

### Алгоритм

**DC при установке бойцом**: и мина, и ловушка — ENGINEERING × (1 + 0,25 при перке 49), усечение. Для инженерного заряда-ловушки дополнительно запоминается инженерия поставившего (влияет на взрыв — «Мир 3»).

**DC ловушек карты**: если у элемента карты своя граната — R × 7 + 16; иначе — число из поля «мощность» элемента.

**Поставить ловушку** (активна граната в режиме «ловушка»; цель — дверь/контейнер, на которой нет видимой этому игроку ловушки): 30 ОД, тренирует ENGINEERING; в момент анимации — ловушка ставится, предмет убирается из руки, в руку берётся следующий такой же из рюкзака (если есть); ловушка сразу видна поставившему.

**Поставить мину** (активна мина; в клетке нет видимой мины): APToSet (20) ОД, ENGINEERING; в момент анимации: если в клетке уже есть мины (даже невидимые) — **они взрываются** (виновник — ставящий); иначе мина ставится с DC и перками, предмет убирается, берётся следующий такой же.

**Дальность обнаружения** (GetMineSpotRange(DC)): Spot' = SPOT (× 1,25 с усечением при перке 80); навык = max(Spot' − 20, ENGINEERING); дальность = max(навык − DC + 20, 0) / 4 (единиц мира, дробное деление).

**Обнаружение** (при каждом пересчёте видимости бойца, если он не ослеп): собрать мины в радиусе GetMineSpotRange(0); для каждой (кроме уже принудительно видимых): расстояние от глаз до мины ≤ GetMineSpotRange(DC мины) **и** луч видимости к точке мины, поднятой на 0,1625 и отодвинутой к наблюдателю на половину радиуса границ объекта, проходит. Новые для игрока установленные мины дают медаль «заметил ловушку» на DC × 1,1 и событие «нашёл мину» (реплика). Чит «видеть всё» показывает все мины.

**Снять ловушку/мину** (активен набор разминирования, годный для мин и пригодный бойцу; ловушка/мина видима игроку; до мины по горизонтали ≤ 1,0 м): 30 ОД, ENGINEERING; в момент анимации:
1. списать один заряд набора **до** броска (опустевший набор убирается из руки, бросок всё равно делается);
2. S = ENGINEERING (+15 при перке 51); шанс = min(75 + S − DC, 95);
3. случайное 0…99 < шанса — успех: граната/мина переходит в инвентарь бойца (или на землю), скрипт OnMineDiffusion(объект, 2); иначе — **взрыв** (виновник — разминирующий), OnMineDiffusion(объект, 1).
Модификатор набора SkillModifForMineCleaning передаётся в проверку, но в ней не используется.

**Открытие заминированной двери** взрывает ловушку (виновник — открывающий); любое попадание по заминированной двери тоже взрывает её.

### Формулы

- DC = trunc(ENG × (1 + 0,25·[перк 49])).
- Дальность = max(max(trunc(SPOT·(1 + 0,25·[перк 80])) − 20, ENG) − DC + 20, 0) / 4.
- Шанс снятия = min(75 + ENG + 15·[перк 51] − DC, 95) % (нижней границы нет — может быть ≤ 0).

### Константы

| Имя | Значение | Смысл | Источник |
|---|---|---|---|
| BaseDisarmProb | 75 | | RPGMinesConstants |
| SpotSkillModif | 20 | вычитается из SPOT | RPGMinesConstants |
| MinerEngineerSkillModif | −20 | вычитается (то есть +20) | RPGMinesConstants |
| MineSpotModif | 4 | делитель дальности | RPGMinesConstants |
| потолок снятия | 95 % | | CanClear |
| AC_TRAP_OBJECT, AC_DISARM_TRAP, AC_DISARM_MINE | 30 ОД каждое | | GetActionAP |
| дистанция снятия мины | 1,0 м | | wUnitAttackExec.h (возможно, правка реконструкции; у лечения 0,8) |
| подъём точки мины для луча | 0,1625 | | UpdateVisible |

### Особые случаи и прихваты

- Мина ставится «вслепую»: если в клетке уже лежит чужая невидимая мина, она взрывается под ставящим.
- Заряд набора тратится даже при неудаче и даже если набор опустел — бросок всё равно происходит.
- Модификатор набора для мин (15/20/25) фактически не действует.
- Неудачное снятие = взрыв.
- Медаль за снятие ловушки (MPC_DISARM_TRAP) в коде нигде не начисляется.

### Что нужно от движка-носителя

Реестр мин с позицией и DC, запрос «мины в радиусе», луч видимости к точке, событие взрыва («Мир 3»), Lua-хук OnMineDiffusion.

## 16. Панцерклайны

### Назначение

Панцерклайн (ПК) — силовой экзоскелет. Существует как отдельный «боец» (пустой ПК на карте или робот/«ПК-враг»), которого можно надеть. Надетый ПК принимает урон своим запасом ОЗ, меняет навыки пилота, ограничивает позы и оружие.

### Данные

- Panzerkleins (12 записей; полностью — приложение Е): RicochetProb, MaxVP, AddMoveAP, AddCoverIgnore, SensorRange, RegenerationValue, CriticalResist, ArmorID (у всех 22 «Middle armor», материал «PK Armor»: порог 180, DR 8, плотность 13000), EncumbranceKoeff, SelfExplosionID, AllowWeaponType1…8, LeftHandItemID, StrengthForGrenades, HasNoHead, CanHide, SingleSlot, звуки двигателя и шагов.
- Персонаж-ПК: запись RPGPers с IsPanzerkleinID — это и есть «тело» ПК (ОЗ ПК — его ячейка VP). Его запись RPGBaseValues служит «дельтами» навыков для пилота (pChangeValues): PK Axis (22), PK Sniper (65), PK Soldier (66), PK Terror (67), PK Allies (68), PK Scout (69).
- Персонаж с WearingPanzerkleinID появляется на карте уже в ПК.
- У пилота: ссылка на ПК, ссылка на ячейку ОЗ ПК, список модификаторов ПК.

### Алгоритм

**Создание ПК-персонажа**: ОЗ поднимаются модификатором +(MaxVP − текущие) до MaxVP ПК; сам ПК-персонаж «надевает себя» (тот же механизм, что для пилота). Масштабирование ОЗ/ОД под сложность и уровень к ПК-персонажам не применяется.

**Надеть ПК** (AC_ENTER_PK, 10 ОД): только если ОЗ ПК ≥ 0. Пилот выходит из пряток, встаёт на место ПК стоя; модель пилота меняется на модель ПК; оружие пилота из обеих рук уходит в рюкзак (или на землю рядом, если места нет); оружие ПК переходит в руки пилота, активен слот 1; на пилота ставится состояние C_PANZERKLEIN_AXIS (для любого ПК); список модификаторов ПК пересоздаётся: для каждой ячейки, кроме VP, с ненулевой дельтой — модификатор +дельта (отрицательные дельты пропускаются при перке 29); если ОЗ ПК < 1 — сразу «сломанный ПК».

**Снять ПК** (AC_LEAVE_PK, 6 ОД): точка выхода — 1,45 м вперёд по направлению взгляда, ближайшая позиция сетки; если она непроходима — отказ. Пилот выходит, ПК остаётся пустым в позе «присевший» (CRAWL), оружие из рук пилота возвращается в слоты ПК, состояния ПК-типа с пилота снимаются, модификаторы ПК снимаются.

**Действие ПК на пилота**:
- урон сначала по ОЗ ПК (раздел 6: рикошет, «крит мимо брони», потеря 1590 энергии);
- шаг дороже на AddMoveAP (Axis 4, Allies 3, AlliesScout 2, террористы 4); в позах «лёжа/сидя» ходить нельзя (запреты команд: нельзя ложиться и бегать, нельзя менять клетку сидя), двери сидя не открываются;
- уклонения свидетеля в ПК нет;
- сопротивление ранениям: шанс и тяжесть ранения × (1 − CriticalResist) (0,3 у большинства, 0,05 у TerrorMedic, 0,1 у босса);
- оружие: только с разрешённым типом ПК (раздел 10); одноместные ПК (террористы) — оружие несъёмное, менять экипировку нельзя;
- метание: сила броска берётся StrengthForGrenades (10) вместо СИЛ;
- слух громких звуков × SensorRange (Axis Engineer 7, босс 5, остальные 4);
- регенерация в конце хода (TerrorMedic 10, босс 5) — в «перевязанные» ОЗ пилота (или ОЗ ПК-персонажа) плюс снятие всех ранений;
- прятаться можно только в ПК с CanHide;
- запреты состояния AXIS: лечение, станковое оружие, «взять тело», ловушки, мины;
- пилот с ранением «оглушение» изображается рухнувшим ПК.

**Сломанный ПК** (ОЗ ПК стали 0 после урона > 0): состояние C_PANZERKLEIN_BROKEN — запрещены движение, стрельба, двери, перезарядка, инвентарь, переходы. Сломанный ПК больше не защищает пилота (урон идёт пилоту, пока ОЗ ПК ≤ 0).

**Ремонт**: ремкомплекты (RPGFirstAids 26 и 27: RequiredSkill 100 по ENGINEERING, перк 79, ёмкость 1000, 10 зарядов) — раздел 8.

**Самоподрыв**: если ОЗ ПК < 0 и у ПК есть SelfExplosionID (у террористов — граната 16) — взрыв; пустой ПК исчезает, пилот вываливается. Так как урон обрезает ОЗ ПК на 0, на практике это возможно только при принудительном убийстве (скрипт); не подтверждено.

### Формулы

- Модификатор пилота по ячейке i ≠ VP: +changeValues[i] (при перке 29 только ≥ 0).
- ОЗ ПК-персонажа = MaxVP записи Panzerkleins.

### Константы

| Имя | Значение | Смысл | Источник |
|---|---|---|---|
| AC_ENTER_PK / AC_LEAVE_PK | 10 / 6 ОД | | GetActionAP |
| точка выхода | 1,45 м вперёд | | CExecPanzerklein |
| потеря энергии в ПК | 1590 | | ProcessAttackForPK |
| удар рукопашной пилота в ПК | nK = 1600, может разорвать тело | | CreateAttack («Бой 1») |

### Особые случаи и прихваты

- Дельты навыков применяются как модификаторы; изменение СИЛ пилота (+1…+4) влияет на производные навыки (ОЗ, метание и т. д.) только при следующем пересчёте баз (начисление опыта или рост характеристики).
- Поле AddCoverIgnore читается (геттер есть), но нигде не используется; EncumbranceKoeff не используется.
- Ранение «AXIS» ставится для ПК любой стороны; остальные ПК-типы ранений только снимаются.
- По пустому ПК удачный «крит мимо брони» урона не наносит.

### Что нужно от движка-носителя

Смена модели и скелета бойца при надевании, перенос оружия между инвентарями, запреты поз и команд.

## 17. Переноска тел

### Назначение

Боец может поднять и нести тело (мёртвое или бессознательное, своё или чужое). Это нужно для выноса раненых (правило NeedCarryOutUnconscious), захвата пленных и сценарных задач.

### Алгоритм

1. Поднять (AC_TAKE_CORPSE, 12 ОД; запрещено при ранениях Idle hand, Blind, Motionless, Encumbrance, Patient и в любом ПК): тело не должно нести кто-то другой и не должно быть «заперто» чужой командой. Если тело в ПК — вместо подъёма пилот вываливается из ПК, ПК остаётся пустым.
2. Состояние «несёт тело»: разрешены только движение, переходы между зонами, поворот, телепорт, анимации, взятие перка, разговоры и смена позы на «стоя»; бег и другие позы запрещены.
3. Цена шага с телом: стоя прямо trunc(4·1,5) = 6, по диагонали trunc(4·2,25) = 9 ОД (перк 42: 4 и 6).
4. Учёт для кампании: свой живой (бессознательный) — «спасён»; чужой живой — «захвачен»; мёртвый — «тело взято». Если несомый умирает — отметка «жив» снимается. Спасённый бессознательный переживает выход из зоны при NeedCarryOutUnconscious (раздел 8).
5. Бросить тело — 0 ОД, ИИ-звук «Drop Corpse» (27, радиус 5…7 по поверхности); нужна свободная клетка перед собой.

### Константы

| Имя | Значение | Источник |
|---|---|---|
| AC_TAKE_CORPSE | 12 ОД | GetActionAP (RPGAPs №1 = 12) |
| шаг с телом | ×1,5 прямо, ×2,25 по диагонали | GetActionAP |

### Особые случаи и прихваты

- Нести тело можно только стоя (не бегом).
- «Поднять» тело в ПК = вытряхнуть пилота.

### Что нужно от движка-носителя

Состояние «несёт тело» с белым списком команд, прикрепление тела к носильщику, учёт спасённых для выхода из зоны.

### Алгоритм

**Очки за событие** (GetMedalPoints):

| Событие | Очки |
|---|---|
| атаковал врага / врага в ПК | 1 / 2 |
| попал во врага / в пустой ПК / во врага в ПК | 3 / 2 / 5 |
| попал в союзника | −5 |

| убил союзника / вывел ПК союзника | −50 / −30 |
| вылечил ранение | сумма DC × 1,1 |
| перевязал | объём × 1,1 |
| вскрыл замок | твёрдость × 1,1 |
| снял ловушку | DC × 1,2 |
| заметил ловушку | DC × 1,1 |
| нашёл улику | 40 (всем наёмникам отряда) |

Фактически начисляются только: улика, перевязка, лечение ранения (и кровотечения), вскрытие замка, обнаружение мины/ловушки. Боевые события собираются в «сессию атаки», но функция их начисления в оригинальной игре не вызывается ни откуда (так и в реконструкции); «снял ловушку», «убил», «вывел ПК» не начисляются нигде.

**Начисление** (AddMedalPoints): если медали бойца отключены — ничего. Для каждой медали, которая копит очки, не получена и не «будет выдана» (и если медаль «только в России» — текущая зона российская: краткое описание зоны начинается с «R»/«r»):
1. очки += очки события;
2. если текущий шанс 0: при очках ≥ PointsNeededToStart — очки −= порог, шанс := StartingProbability, бросок;
3. иначе при очках ≥ PointsNeededToAdd — очки −= порог, шанс += AddToProbability, бросок.
Бросок: случайное 0…99 (локальный генератор) ≤ шанса → «будет выдана». За одно событие — не более одного броска на медаль (избыток очков остаётся).

**Выдача** (при выходе из зоны, кроме лагеря/базы): «будет выдана» → «получена», «только что получена»; медали, у которых она — предыдущая, начинают копить очки.

### Формулы

- Шанс получить при броске = (шанс + 1) % (сравнение ≤ при броске 0…99).

### Константы

См. таблицы выше.

### Особые случаи и прихваты

## 19. Дипломатия

### Назначение

Отношения между игроками миссии (до 16): враг, нейтрал, союзник. По ним решается, кто в кого стреляет, кто кого видит как угрозу, кто может лечить кого, кто получает опыт.

### Данные

- Состояния: DS_ENEMY = 0, DS_NEUTRAL = 1, DS_ALLY = 2.
- Матрица: 16 масок (32 бита) — у игрока i состояние к игроку j хранится в битах 2j…2j+1. Сам к себе — всегда союзник.
- Запись Diplomacies (на вариант шаблона карты): Diplomacy1…16 — маски игроков 0…15 (41 запись в БД).
- У каждого боевого юнита — своя копия маски его игрока.

### Алгоритм

1. Загрузка с вариантом карты: маски берутся из записи Diplomacies варианта; затем каждый игрок становится союзником сам себе. Нет записи — все маски 0, то есть **все враги всем** (кроме себя).
2. Юниты карты получают маску своего игрока (персональный столбец Diplomacy юнита в v1.x игнорируется).
3. Изменение (скрипт SetDiplomacy): меняется состояние игрока 1 к игроку 2 (только в одну сторону) в глобальной матрице и в масках всех юнитов игрока 1. Нельзя изменить отношение к самому себе.
4. Установка маски игрока целиком: маска + «союзник сам себе», копируется всем его юнитам.

### Особые случаи и прихваты

- Отношения несимметричны: A может считать B врагом, а B — A союзником.
- Пустая маска = враждебность ко всем.
- Лечить врага нельзя; опыт за убийство даётся только при отношении «враг».

### Что нужно от движка-носителя

Хранение 2-битной матрицы 16 × 16, копия маски в юните, Lua-доступ.

## 20. Сложность

### Назначение

Уровень сложности — одна запись DifficultyConstants (1 Easy, 2 Normal, 3 Hard), выбранная при создании кампании (без выбора — запись 1); её можно сменить по ходу (ChangeDifficulty). Поля влияют на силу ИИ, урон, смерть, лечение между миссиями, сохранение, интерфейс задач. Полная таблица значений и мест применения — приложение Д.

### Алгоритм (ролевые поля)

1. **Создание ИИ-юнита карты**: уровень = max(0, уровень врагов миссии + относительный уровень юнита на карте + AIUnitsLevel). Для не-ПК: сначала предел ОЗ := round(текущие ОЗ × AIVPCoeff), предел ОД := round(текущие ОД × AIAPCoeff) (текущие прижимаются к новым пределам), затем SetXPLevel(уровень). SetXPLevel заново вычисляет пределы всех ячеек из базы и опыта, поэтому у юнитов **с классом** масштабирование ОЗ/ОД стирается (у бесклассовых — остаётся, пока что-то не вызовет пересчёт ячейки). Так в реконструкции; в оригинале (по комментарию реконструкции) масштабирование тоже пишется напрямую в предел — значит, вероятно, и там теряется; не подтверждено.
2. **Порог смерти**: бойцы игрока — DeathCoeff; персонажи-улики в слотах — ClueDeathCoeff (раздел 6).
3. **Урон по телу**: атакующий-ИИ — × EnemyDamageMult, атакующий-игрок — × OurDamageMult (только по материалу «Human»).
4. **Критические ранения**: AlwaysCritical (запасной крит), HeadshotShouldKill (бонусы прицельной зоны к шансу/тяжести крита, весовой множитель зоны в попадании и в рукопашной).
5. **Удар в спину рукопашной**: навык × BackstabMeleeMult; к обеим границам урона + навык × BackstabMinDamageMult × (½ без оружия) × 5/7; BackstabMaxDamageMult не читается.
6. **Выход из зоны**: HealOnLeaveZone, BandageOnLeaveZone, HealOnLeaveZoneCoeff, GroupMedicalCoeff, NeedCarryOutUnconscious (раздел 8).
7. **Случайные встречи**: поправка уровня = trunc((∑₁₀ rnd(0 … max(1, 2·RE) − 1)) / 10) − RE; при RE = 3 — от −3 до +2 («Кампания 1»).

### Особые случаи и прихваты

- BandageOnLeaveZoneCoeff и BackstabMaxDamageMult, HealOnRestCoeff не используются; ShowAllClueIcons в реконструкции не читается.
- На тяжёлом уровне лечения между миссиями нет вовсе.
- В функции PlaceTemplate (размещение шаблона из скрипта) уровень врагов задаётся равным AIUnitsLevel и затем AIUnitsLevel прибавляется ещё раз.

### Что нужно от движка-носителя

Глобальная запись сложности, доступная из расчёта урона, создания юнитов, экрана задач и правил сохранения.

## 21. Читы и отладочные переключатели

### Назначение

Флаги читов хранятся на бойце (битовая маска) и меняют ролевые правила. Включаются консолью (для всех юнитов активного игрока через команду мира) или скриптом (UnitCheat, GroupCheat — любой бит, включая безымянные).

### Данные

| Бит | Имя | Как включить | Действие |
|---|---|---|---|
| 1 | CHEAT_GODMODE | консоль «godmode 1», Lua | лучи атак игнорируют бойца; урон ПК не наносится |
| 2 | CHEAT_SEEALL | «seeall 1» | видит всех юнитов и все мины, предметы без лучей |
| 4 | CHEAT_TELEPORT | «teleport 1» | телепорт (флаг фактически не проверяется исполнителем телепорта) |
| 8 | CHEAT_AP | «cheat_ap 1» | ОД не тратятся, любые действия по карману |
| 16 | CHEAT_SCRIPTSEQUENCE | скриптовые ролики | ОД не тратятся, ИИ выключен |
| 32 | CHEAT_NOAI | Lua | ИИ юнита не действует |
| 64 | CHEAT_TOHIT | Lua | бросок попадания всегда 1 (почти всегда попадание) |
| 128 | (без имени) | только Lua UnitCheat/GroupCheat | «жёсткие» ступени штрафов за ранения (раздел 6) |

Прочие консольные команды, меняющие правила: «setxplevel [ally/enemy] N» — SetXPLevel(N) для своих или чужих юнитов; «getitem» — выдать предмет; «summonunit»/«unsummonunit»; «surrender» — завершить миссию; привязки «click_of_death» (атака «щелчок смерти»: огромный урон или гарантированное оглушение живой цели), «explode», «explosion»; «cheat_showall» — показать всё в интерфейсе. Скрипт может принудительно задать шанс попадания юнита (UnitSetToHit; −1 — выключить) и предел тяжести крита (SetMaxCriticalSeverity).

### Особые случаи и прихваты

- Бит 128 (жёсткие ранения) нигде в коде не включается автоматически — только скриптом.
- В реальном времени ОД не тратятся и без читов.

### Что нужно от движка-носителя

Битовая маска читов на бойце, консольные переменные, Lua-доступ.

## Все прихваты списком

- [ ] Все ячейки, кроме ОЗ и ОД, «заморожены на максимуме»: их значение всегда равно пределу.
- [ ] Модификатор с положительной прибавкой сразу доливает текущее значение (усечением), с отрицательной — только прижимает к пределу.
- [ ] Пересчёт базы при росте характеристики сдвигает текущее значение на разницу баз (ОЗ не восстанавливаются).
- [ ] Производные навыки пересчитываются лениво — только при начислении опыта или росте характеристики (изменение СИЛ в ПК видно не сразу).
- [ ] Пороги уровней считаются с основанием 2,7296 вместо e — функция «опыт → навык» и «уровень → опыт» не взаимно обратны.
- [ ] Повышение уровня требует опыта строго больше порога.
- [ ] Опыт не поднимает навыки, только их потолок; навык растёт только от использования (кроме SetXPLevel).
- [ ] За одно использование навык растёт не более чем на 0,1 очка (минимум 0,00001).
- [ ] Каждое использование навыка тренирует и связанную характеристику; реплика «навык вырос» звучит и при росте одной характеристики.
- [ ] ОД тренируются каждым шагом, ОЗ — каждым попаданием, IC — каждым броском уклонения, перехват — каждой проверкой.
- [ ] Опыт умножается на (1 + 0,05 × ИНТ получателя).
- [ ] Боец без строки имени (DisplayName) не получает опыт.
- [ ] Награда за убийство делится на число бойцов отряда, но не больше чем на 6 (при отряде > 6 общий пул растёт).
- [ ] Добивание бессознательного опыта не даёт; опыт дают убийство или первое выведение из строя.
- [ ] Смерть от кровотечения даёт опыт всем враждебным игрокам.
- [ ] Номер подсказки (Sequence) выдаётся как опыт всему отряду при её показе.
- [ ] Перк берётся, только если взяты все родители (И, не ИЛИ); Lua UnitTakePerk не проверяет ничего.
- [ ] Наёмник на 1-м уровне при создании не имеет очков перков.
- [ ] Запрос отсутствующего перка добавляет пустой элемент в словарь дерева.
- [ ] ОД в начале хода восстанавливаются полностью, остаток не переносится.
- [ ] В реальном времени ОД не тратятся вовсе.
- [ ] При беге прямой шаг добавляет 2 к счётчику «пробежки», диагональный — 1.
- [ ] Цена подъёма на 1 уровень: в коде 10, в таблице RPGAPs 12 (работает код); большая часть RPGAPs не читается.
- [ ] Перки 34 и 35 складываются: лёжа оплачивается как стоя.
- [ ] В ПК шаг лёжа/сидя стоит 1 ОД (позы запрещены командами).
- [ ] Ремонт ПК (AC_REPAIR_PK) по таблице цен стоит 0 ОД, для начала требует 10.
- [ ] Ключ и отмычка одновременно — двойное списание ОД.
- [ ] Намеченная цель не уклоняется; уклоняются только случайные жертвы, включая жертв кровотечения и падения.
- [ ] Урон делится между текущими и перевязанными ОЗ пропорционально.
- [ ] Шанс оглушения нулевой выше 50 % здоровья и учитывает ОЗ дважды.
- [ ] Бессознательный в миссии не приходит в себя, лечить его нельзя.
- [ ] Порог смерти бойцов игрока ниже нуля (−1,2 / −0,7 / −0,1 × макс. ОЗ), у врагов — 0.
- [ ] При полных ОЗ ≤ 0 кровотечение прекращается (бессознательный не истекает кровью).
- [ ] Ниже половины теоретического максимума ОЗ боец кровоточит и без ранения: trunc((половина − T) × 0,1) за ход.
- [ ] Из нескольких кровотечений учитывается только первое в списке.
- [ ] Кровоостанавливающее действует бессрочно до появления нового кровотечения и гасит и «низкое здоровье».
- [ ] Два штрафа за ранения к стрельбе: ступени ранения C_VP (по перевязанным полностью) и GetVPPenalty (перевязанные пополам).
- [ ] Перк 5 сдвигает только ступени штрафов (+25 к проценту), но не порог перка 8.
- [ ] Ранение выбирается детерминированно по тяжести; случайна только тяжесть.
- [ ] Тяжесть крита растёт с уровнем атакующего (+1…19 за уровень) и обрезается на 300.
- [ ] Условие крита «бросок ≤ шанс»: шанс фактически на 1 % больше.
- [ ] Бросок крита идёт отдельным статическим генератором.
- [ ] Запрещённые типы ранений отдают свою полосу предыдущему разрешённому типу.
- [ ] Ранение «Death» не убивает бойца игрока напрямую, а обнуляет ОЗ перед вычетом урона; мировой эффект «смерть» не вызывается.
- [ ] «Damage weapon» навсегда ломает огнестрел, починки нет.
- [ ] Новое ранение того же типа и зоны с тем же сроком и силой просто заменяет старое (даже с меньшим DC).
- [ ] Повторное наложение ранений после действия обезболивающего повторяет мировые эффекты.
- [ ] Обезболивающее после окончания срока снижает максимум ОЗ на Power % до конца миссии.
- [ ] Стимулятор поднимает ОЗ на 150–300 % базового максимума, а по истечении срока вызывает обморок с ОЗ = 0 (передозировка при сроке 0).
- [ ] Передозировка: ∑ 1/срокᵢ > 1.
- [ ] Перевязка добавляет отдельный пул, ограниченный 1,7857 × навык медика, а не ёмкостью предмета.
- [ ] Один сеанс лечения тратит один заряд аптечки независимо от объёма.

## Примеры

### Пример 1. Рост навыка «Стрельба» за миссию

Солдат (класс 4: предел Shooting 100, предел ЛОВ 1; характеристики 8/8/4), опыт fXP = 1500 (уровень 5: порог 1472,1 < 1500 ≤ 2963,9), часть опыта Shooting = 30, прогресс 0. База Shooting = 20 + ЛОВ 8 = 28, навык = 58. За миссию сделано 80 одиночных выстрелов (AC_SHOOT), опыт за миссию не менялся.

1. Потолок обучения: K(100) = 100 / 9,52468 = 10,4990; fCap = ln(1 + 0,02 × 1500) × 10,4990 = ln 31 × 10,4990 = 3,43399 × 10,4990 = 36,0536.
2. Выстрел 1: остаток = 36,0536 − 30 = 6,0536; прибавка = max(0,00001; min(6,0536 / 20; 0,1)) = 0,1. Прогресс 0,1.
3. Пока остаток ≥ 2,0 (то есть до части опыта 34), каждый выстрел даёт ровно 0,1: при вычислениях в одинарной точности сумма десяти 0,1 даёт 1,0000001, так что +1 очко на выстрелах 10, 20, 30, 40 (навык 59, 60, 61, 62).
4. С части опыта 34 остаток 2,0536 − прогресс, прибавка = остаток / 20 < 0,1: очко 35 приходит на 54-м выстреле (навык 63).
5. Дальше прибавка падает (0,039 на 60-м, 0,014 на 80-м выстреле); к 80-му выстрелу прогресс 0,789. Следующее очко (36 ≤ trunc(fCap) = 36) — ещё через десятки выстрелов; 37 недостижимо, пока не вырастет опыт.
6. Каждый выстрел тренирует и ЛОВ: fCap(ЛОВ) = ln 31 × 1/9,52468 = 0,3605; прибавка = 0,3605/100 ≈ 0,0036, прогресс за 80 выстрелов ≈ 0,20 — ЛОВ не растёт (часть опыта не может превысить trunc(0,3605) = 0).
7. Каждое повышение ставит реплику «навык вырос».

Итог: за миссию Shooting 58 → 63; при наборе опыта (например, убийство врага 5-го уровня класса Enemy одним солдатом: 133,5 × (1 + 0,05 × 4) = 160,2 опыта) потолок fCap поднимется до ln(1 + 0,02 × 1660,2) × 10,499 ≈ 37,1, и рост ускорится.

### Пример 2. Попадание в голову с критическим ранением

Атакующий — боец 5-го уровня, SNIPE = 25, без перков, обычный (не снайперский) выстрел из винтовки. Цель — враг, по которому в этом ходу уже было одно попадание (счётчик 1); текущие ОЗ 85, перевязанные 10, теоретический максимум 120; сложность Normal (бонусов прицельной зоны нет).

1. Создание порции: шанс крита = (1 + 1) × 10 = 20, + 0,4 × 25 = 10 → 30; тяжесть = trunc(25 × 0,25) = 6.
2. Луч попал в голову («Бой 1»); бросок урона CalcStructDmg = 30.
3. Множитель зоны 1,5. Тяжесть += 5 бросков 1…19 (уровень 5): 12 + 3 + 17 + 9 + 15 = 56 → 62 (≤ 300).
4. Бросок крита: r = 17 (статический генератор), шанс × сопротивление = 30 × 1 → 17 ≤ 30 — крит есть.
5. Шкала головы: 0–39 Graze, 40–79 Temporarily Deaf → тяжесть 62 выбирает «Temporarily Deaf» (ID 34).
6. Добавочный множитель = 62 / 300 × 2 (голова) × 1 = 0,4133.
7. Срок: MinDuration 2 + rnd(0…2) → пусть 3 хода. Ранение {голова, Deaf, срок 3, Value 1, DC 62} накладывается: слияния нет, эффект — запись в «последние ранения»; шанс услышать у цели теперь 0.
8. Урон = trunc((1,5 + 0,4133) × 30) = trunc(57,4) = 57. Цель — намеченная, уклонения нет.
9. Доля перевязанных: trunc(57 × 10 / 95) = 6 → перевязанные 4; текущие ОЗ: 85 − (57 − 6) = 34; полные 38.
10. Реплика «тяжёлое ранение» (был крит). Тренировка VP цели. Оглушение: шанс патрона 0 → нет.
11. Ранение уровня здоровья: P = trunc((4 + 34) × 100 / 120) = 31 → ступень 26…50: ОД × 0,9, перехват × 0,75, рукопашная/стрельба/метание × 0,75.
12. «Глухота» держится 3 конца хода и снимается на 4-м.

Если бы атакующий был снайпером 14-го уровня с прицеливанием (тяжесть около 270+), выпала бы «Death» (270+): ОЗ цели := 0 и множитель урона 1,5 + 270/300 × 2 = 3,3.

### Пример 3. Перевязка и кровотечение за несколько ходов

Медик с MEDICINE 40 (без перков, 50 ОД) перевязывает солдата: теоретический максимум ОЗ 130, текущие 50, перевязанные 0, ранение «Bleeding» в корпус (Value 5, DC 100, бессрочное). Предмет — First Aid Kit (RPGFirstAids №1: ёмкость 100, 0 ОД на начало, модификатор 0, 5 зарядов).

Ход 1, медик:
1. Перевязка возможна: trunc(1,7857 × 40) = 71 > 0 перевязанных, 50 < 130. Ёмкость сеанса 100.
2. Расчёт: L = 71; место = 130 − 50 − 0 = 80; объём v = min(71, 80) = 71; цена = trunc(71 / 40 × 60) = 106 > 50 → цена 50, v = round(50 × 40 / 60) = 33.
3. Перевязано 33 (перевязанные 33), ёмкость 67, потрачено 50 ОД. Проверка продолжения: ещё можно (v = 38) — медик остаётся в состоянии «лечит».

Конец хода 1, солдат: кровотечение: полные T = 50 + 33 = 83 ≥ половины round(130/2) = 65 → урон 5. Доля перевязанных trunc(5 × 33 / 83) = 1 → перевязанные 32, текущие 46 (T = 78).

Ход 2, медик (в конце его хода, 50 ОД): v = min(71 − 32, 130 − 46 − 32) = min(39, 52) = 39; цена trunc(39/40 × 60) = 58 > 50 → v = 33; перевязано 33 (перевязанные 65, T = 111), ёмкость 34.

Конец хода 2, солдат: T = 111 → урон 5; доля trunc(5 × 65 / 111) = 2 → перевязанные 63, текущие 43 (T = 106).

Ход 3, медик: v = min(71 − 63, 130 − 43 − 63) = 8; цена max(1, trunc(8/40 × 60)) = 12; перевязано 8 (перевязанные 71 — предел медика), ёмкость 26; дальше v = 0 → сеанс окончен, аптечка теряет 1 заряд (осталось 4), с солдата снимается «Patient», реплика «лечение завершено».

Дальше солдат теряет 5 ОЗ каждый ход (при T < 65 — больше: например, при T = 45 урон = 5 + trunc((65 − 45) × 0,1) = 7). Остановить: Haemostatic Powder (+5 к «кровоостанавливающему» → урон 0, пока не появится новое кровотечение) или вылечить ранение: при Haemostatic Forceps (+10) DC медика = trunc(2,142857 × 50) = 107 ≥ 100 — можно; цена = round(100 × 50 / 40) = 125 ОД (три хода по 50, 50, 25).

### Пример 4. Взлом замка

Инженер с ENGINEERING 45, в руке Picklock2 (AddToEngSkill 20, 7 зарядов, 30 ОД). Дверь заперта без заданной твёрдости на карте с R = 5: твёрдость = (rnd(20) + 10) × 3 − 3; выпало 7 → 48.

1. Команда «открыть»: ключа нет, в руке отмычка с зарядами → можно; цена 30 ОД; списывается, тренируется ENGINEERING.
2. Момент анимации: заряд списан (осталось 6). Бросок r = 0…99 (локальный генератор).
3. Число = trunc(r × 45 / 100) + 20 + trunc(45 / 2) = trunc(0,45 r) + 42.
4. Успех при числе ≥ 48, то есть trunc(0,45 r) ≥ 6 ⇔ r ≥ 14. Шанс успеха 86 %, провала 14 %.
5. Пусть r = 30: 13 + 42 = 55 ≥ 48 — замок открыт, дверь открывается, медаль «вскрыл замок» + 48 × 1,1 = 52,8 очка, ИИ-звук открытия (радиус 4).
6. При r = 10: 4 + 42 = 46 < 48 — провал: заряд потерян, дверь заперта, звука нет; можно пробовать снова (ещё 30 ОД).

С перком 52 (+20): в реконструкции S = 65 → число = trunc(0,65 r) + 20 + 32 ≥ 52 — успех всегда; в оригинале +20 к итогу: trunc(0,45 r) + 62 — тоже всегда. Для контейнера на той же карте твёрдость 5 × 7 + 16 = 51 (успех при r ≥ 20, шанс 80 %).
