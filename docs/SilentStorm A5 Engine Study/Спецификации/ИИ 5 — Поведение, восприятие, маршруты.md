# ИИ 5 — Поведение, восприятие, маршруты

Источник: `reconstruction\Main` (aiReaction*, aiReactions*, aiGuard/Defence/Assassin/Fear/ScriptReaction*, aiScriptLogic*, aiThreatTracker*, aiEvent*, aiUnitState*, aiRoute*, aiRouteLogic*, aiRouteMisc*, aiTaskCommand*, aiWaypoint*, AILog*, aiLogic*, aiUnit.cpp, aiCommander.cpp, aiMisc.cpp, RPGUnitMission.cpp, wUnitSounds.h, wMain.cpp/wUnitServer.cpp в части шума и обнаружения, script*.cpp), база `A5GAME.sqlite`, библиотеки `Complete\Scripts\*.l`.

## Суть

У каждого юнита под управлением ИИ есть три слоя. Нижний — **память об угрозах**: три списка (враги, которых вижу; «подозреваемые», о которых узнал косвенно; союзники, зовущие на помощь) и список уже найденных трупов. Память меняется только событиями: увидел, потерял из виду, услышал, мимо пролетела пуля, рядом взорвалась граната, нашёл тело, начался ход. Средний слой — **реакция** (режим поведения): ровно одна на юнита — «обычная», «караульный», «оборона из укрытия», «убийца-подкрадывающийся», «отступление», «страх/гражданский», «скриптовая», «пустая». Реакция не действует сама: когда память изменилась, она один раз просыпается, смотрит на текущего врага/подозреваемого/союзника и **ставит юниту логику** — либо боевую (её описывают другие спецификации), либо маленький готовый сценарий из шагов маршрута («добеги и осмотрись», «обойди с фланга», «подними тревогу»). Третий слой — **маршрут**: патруль по путевым точкам из редактора или из Lua; он живёт в отдельном слоте, встаёт на паузу, пока работает логика реакции, и продолжается после неё. Скрипты миссий переключают реакции, задают маршруты и телепортируют юнитов через набор Lua-функций.

## Термины и единицы

| Термин | Значение |
|---|---|
| Метр (м) | Мировая единица расстояния между «контрольными точками» (CP) юнитов. Все константы памяти угроз и реакций (2.5, 5, 8, 9, 30 …) — в метрах. |
| Тайл | Шаг сетки проходимости, `FP_GRID_STEP = 0.625` м. Расстояние «в тайлах» = метры × 1.6. В тайлах заданы радиусы звуков в БД и все формулы слуха и раскрытия спрятавшихся. |
| AP | Очки действия. «Волна на N AP» — все клетки, достижимые за N AP в заданной позе. |
| Поза движения (EPose) | CRAWL=0 (ползком), CROUCH=1 (пригнувшись), WALK=2 (шагом), RUN=3 (бегом). |
| Поза клетки | CM_LAY=0, CM_CROUCH=1, CM_STAND=2, CM_INACTIVE=3 (переходная точка пути: дверь, лестница). |
| Направление | 0..7, шаг 45°: 0 — вправо, 2 — вверх, 4 — влево, 6 — вниз (константы DIR_* из Constants.l). |
| Сегмент | Один тик мира. ИИ «думает» каждый третий сегмент. |
| RT / TBS | Реальное время / пошаговый режим. |
| CanFight | Юнит жив, в сознании, способен действовать. Почти все правила применяются только к таким юнитам. |
| ПК | Панцеркляйн (силовой костюм). Юнит в ПК не бегает, не приседает, не прячется (если костюм не разрешает), не пугается. |
| Враг / не-враг | Определяется дипломатией: `DS_ENEMY` либо всё остальное (союзник и нейтрал считаются «не-врагом»). |
| Логика | Объект, выдающий юниту мировые команды (идти, смотреть, стрелять). Бывает боевая (Attack, Defence, Guard, Retreat, AfterCombat — см. спецификации по тактике) и маршрутная (список шагов). |
| Реакция | Объект-режим, выбирающий логику. Один на юнита. |
| Недействительная клетка | Служебное значение позиции `0xFDFFFFFF` (оба старших бита позы = 1): «места нет». |
| «Та же клетка» | Сравнение позиций по маске `0x1FEFFFF` — без учёта направления, позы и признака движения. |

Случайные числа: `rnd(n)` — целое 0..n−1; `rnd(a,b)` — целое a..b−1.

## 1. Каркас реакций и слоты логики

### Назначение
Определяет, когда ИИ юнита «передумывает» и как новая логика уживается с патрульным маршрутом и скриптовыми сценами.

### Данные (на юнита)
| Поле | Смысл |
|---|---|
| `pReaction` | Текущая реакция (одна). |
| `pLogic` | Слот боевой/ситуативной логики, которую ставит реакция. |
| `routes[0]` | Обычный маршрут (патруль с карты или из скрипта). |
| `routes[1]` | Маршрут сцены (действует только пока мир в режиме скриптовой последовательности). |
| `state` | Память угроз (раздел 2), с флагом «изменилась». |
| `nHideProbability` | Шанс спрятаться перед проверкой подозрительного места, %; при создании берётся из сложности. |
| `disabledShootModes` | Запрещённые режимы огня (использует реакция обороны). |
| `nNonFreezeCounter` | Счётчик «дёрганий» ИИ (защита от зависания хода). |

### Алгоритм: цикл обдумывания
1. Командир ИИ каждый сегмент увеличивает счётчик `nAILag`; когда он превысил 2, обнуляет его, пересобирает списки своих/чужих и выполняет «сегмент ИИ». То есть ИИ думает **каждый 3-й сегмент**; выдача команд юнитам тоже происходит только на этом тике.
2. Сегмент ИИ не выполняется, если ИИ выключен глобально (консольная переменная `game_noai`) или мир в режиме сцены.
3. Для каждого своего юнита, которым ИИ вправе управлять (юнит принадлежит ИИ-игроку и CanFight): проверка видимых трупов (раздел 6), затем пересчёт производных полей памяти (текущий враг, ближайший подозреваемый, ближайший союзник, проверка испуга).
4. В TBS, если сейчас не ход этого игрока, — дальше ничего.
5. **Постановка в очередь.** Для каждого своего управляемого юнита: если флаг «память изменилась» поднят — флаг сбрасывается, все ещё не исполненные команды этого юнита выбрасываются из очереди командира, текущая мировая команда отменяется, реакция добавляется в очередь обновлений (без дублей).
6. В TBS, если сейчас проигрывается действие (анимация), — ждать.
7. **Из очереди берётся и обновляется ровно одна реакция за тик.** Реакция в `Update()` либо ставит логику, либо заменяет себя другой реакцией.
8. Пока очередь реакций не пуста или у кого-то ещё поднят флаг изменения, командир **не выдаёт новых команд** никому (кроме времени сцены).

### Правила слотов
- **Какая логика активна:** в режиме сцены — только `routes[1]`; иначе `pLogic`, если он есть; иначе `routes[0]`.
- **Поставить логику (SetLogic):** запрещено в режиме сцены и для юнита, которым ИИ не управляет или который не CanFight. Сначала отменяется мировая команда; если стояла старая логика — она снимается, а маршрут, если был на паузе, возобновляется. Затем, если новая логика не пустая, маршрут ставится на паузу и логика занимает слот. `SetLogic(пусто)` = «вернуться к маршруту».
- **Поставить реакцию (SetReaction):** `SetLogic(пусто)`, запомнить реакцию, **поднять флаг «память изменилась»** (поэтому новая реакция гарантированно получит `Update` на одном из ближайших тиков), увеличить счётчик дёрганий. Немедленного `Update` нет.
- **Поставить маршрут (SetRoute):** разрешено только ИИ-юниту либо любому юниту во время сцены. Отменяет мировую команду, выбрасывает боевую логику, кладёт маршрут в слот, соответствующий текущему режиму (сцена / обычный).
- **Логика закончилась:** командир на каждом тике проверяет активные логики; у закончившейся: если это маршрут — слот маршрута очищается, иначе `SetLogic(пусто)`. В обоих случаях поднимается флаг изменения → реакция передумывает. Логика не считается законченной, пока у юнита ещё висит мировая команда.
- **Начало сцены:** `SetLogic(пусто)`, обычный маршрут на паузу, слот сцены очищается. **Конец сцены:** `SetLogic(пусто)`, маршрут сцены на паузу (он больше не возобновится), обычный маршрут — `Resume`, флаг изменения поднят.
- **`UnitKeepMoving` (ContinueRoute):** переносит маршрут из «чужого» слота в слот текущего режима (после конца сцены — из слота сцены в обычный), возобновляет его и снимает боевую логику. Нужен, чтобы актёр дошёл до точки после `EndSequence`.

### Пауза и продолжение маршрута
Пауза — счётчик (вложенные паузы складываются). При паузе маршрутная логика **откатывается к ближайшему предыдущему шагу «идти к точке»** и помечает «продолжить, а не перейти дальше»; при возобновлении этот шаг выполняется заново, то есть юнит возвращается на прерванный отрезок патруля и идёт к той же путевой точке.

### Константы
| Имя | Значение | Смысл |
|---|---|---|
| период ИИ | 3 сегмента | Частота обдумывания и выдачи команд. |
| реакций за тик | 1 | Сколько реакций обновляется за один тик ИИ. |
| зацикливание, мягкий порог | 16..30 повторов | Юнит получает команды, стоя в той же клетке с тем же AP: с вероятностью 25 % на каждую выдачу текущая мировая команда отменяется. |
| зацикливание, жёсткий порог | ≥ 31 повтор | Логика принудительно завершается. |
| порог «возможное зависание» | 5000 | Общий счётчик выданных команд, либо счётчик + 200 × счётчик дёрганий любого юнита: при превышении в TBS ход ИИ принудительно заканчивается. В RT счётчики обнуляются каждый тик. |

### Особые случаи и прихваты
- Если команда, взятая из логики, по проверке выполнимости даёт результат хуже «нет цели» (не хватает AP, нет пути и т. п.), она отбрасывается, а логика помечается «ход окончен» до следующего хода.
- После каждой реальной команды командир добавляет команду «продолжить»; если юнит простаивает, но у него висит недовыполненная команда и (в TBS) хватает AP, логика выдаёт одно «продолжить» с приоритетом над собственной очередью.
- В TBS перед тем, как двигать нового юнита, командир шлёт интерфейсу подсказку «сейчас пойдёт этот юнит ИИ» (камера).
- Порядок обхода юнитов: следующий — **ближайший к предыдущему** (а не по списку), каждый посещается один раз за круг.

### Что нужно от движка-носителя
Очередь мировых команд на юнита с отменой; признаки «выполняет действие», «есть незавершённая команда», «хватает AP продолжить»; режим сцены; события смены хода.

## 2. Память угроз (SAIUnitState)

### Назначение
Хранит, что юнит знает о противнике, и выводит из этого три «текущие цели» и флаг испуга, на которые смотрят реакции.

### Данные
| Поле | Смысл |
|---|---|
| `enemies` | Подтверждённые враги (вижу сейчас). Для каждого хранится позиция на момент добавления. |
| `possibleEnemies` | Подозреваемые: знаю, что есть, но не вижу. Тоже с позицией. |
| `allies` | Союзники, **позвавшие на помощь** (не все союзники!). |
| `knownCorpses` | Уже замеченные тела. |
| `pEnemy` | Текущий враг — «самый опасный». |
| `pPossibleEnemy` | Ближайший подозреваемый. |
| `pAlly` | Ближайший звавший союзник. |
| `bScared` | Испуган. |
| `bHelpCalled` | Уже поднимал тревогу. |
| флаг «изменилась» | Будит реакцию. У каждого из трёх списков свой грязный флаг и счётчик блокировки. |

### Правила списков
- **Добавить врага:** только если он CanFight, по дипломатии враг и его ещё нет в списке **с той же позицией**. Если он есть, но сдвинулся, — запись обновляется, список помечается изменённым.
- **Добавить подозреваемого:** то же, плюс его не должно быть среди подтверждённых врагов. Повторное сообщение о подозреваемом, который с тех пор **переместился**, считается изменением (реакция сработает снова); о стоящем на месте — нет.
- **Добавить союзника:** не сам юнит, CanFight, не враг, ещё не записан с той же позицией.
- **Удаление** из списка сразу обнуляет и соответствующую «текущую цель», если это была она (без подъёма общего флага).
- **Пересчёт (каждый тик ИИ):** если изменился список врагов — выбрать текущего врага; если подозреваемых — ближайшего подозреваемого; если союзников — ближайшего союзника; при смене любой из трёх целей поднимается общий флаг. Затем проверка испуга.
- Два пути доставки события: **прямой** (от мира и от тревоги) — изменение сразу помечает списки грязными; **под блокировкой** (когда реакция сама «потребляет» контакт) — изменения списков выполняются, но грязные флаги не ставятся, чтобы реакция не разбудила сама себя.

### Выбор текущего врага («самый опасный»)
1. Среди подтверждённых врагов (CanFight) найти ближайшего; собрать **кластер** — всех, чьё расстояние отличается от минимального меньше чем на 1.5 м (враг заметно ближе сбрасывает кластер).
2. Внутри кластера выбрать того, по кому собственное лучшее оружие юнита даёт **наибольший шанс попадания** при текущем AP (запрос к инвентарю ИИ — интерфейс тактической части). Первый кандидат побеждает «пусто».

Ближайший подозреваемый и ближайший союзник выбираются просто по расстоянию до их **реальной текущей** позиции.

### Условие испуга (CheckScared)
Проверяется каждый тик, пока юнит не испуган и не поднимал тревогу. Юнит становится испуганным, если одновременно:
1. есть текущий враг;
2. юнит не в ПК;
3. здоровье (VP) меньше половины максимума **или** подтверждённых врагов больше двух;
4. в радиусе 9 м нет ни одного другого боеспособного не-врага (любого игрока, включая людей).

Флаг испуга **сам никогда не снимается**; его снимает только событие «помощь позвана» (и тогда юнит больше никогда не пугается).

### Забывание
| Что | Когда исчезает |
|---|---|
| Подтверждённый враг | Умер/потерял сознание; в RT — как только потерян из виду (переходит в подозреваемые); в TBS — в начале хода владельца, если его нет в списке видимых (переходит в подозреваемые); при побеге «поднять тревогу» юнит сам вычёркивает врага. |
| Подозреваемый | Стал видимым (переходит во враги); умер; «потреблён» реакцией Караульный, Страх или Отступление после того, как они на него отреагировали. **Обычная реакция подозреваемого не потребляет** — она будет гоняться за ним снова и снова (см. 3.1). По времени подозреваемые не забываются. |
| Союзник | Умер/потерял сознание любой не-враг; «потреблён» обычной реакцией или караульным после реакции на зов. |
| Труп | Никогда (каждое тело вызывает событие один раз). |

### Начало хода (PrepareEnemies)
В начале хода игрока-владельца (и при старте игры): все боеспособные враги из собственного списка видимости юнита становятся подтверждёнными врагами (и вычёркиваются из подозреваемых); прежние подтверждённые, которых там нет, — переходят в подозреваемые.

### Константы
| Имя | Значение | Смысл |
|---|---|---|
| ширина кластера | 1.5 м | Допуск «примерно так же близко» при выборе цели. |
| порог ранения | 50 % VP | Условие испуга. |
| порог численности | > 2 врагов | Условие испуга. |
| радиус поддержки | 9 м | Есть ли рядом кто-то из своих. |

### Что нужно от движка-носителя
Список видимых юнитов на юнита; дипломатия между юнитами; функция «лучший шанс попадания моим оружием по цели».

## 3. События ИИ

### 3.1. Внутренние события (изменяют память)
| Событие | Действие над памятью |
|---|---|
| Начало хода | PrepareEnemies (см. выше). |
| Обновить | Поднять общий флаг изменения. |
| Помощь позвана | Если юнит испуган или ещё не звал: `bHelpCalled = да`, `bScared = нет`, поднять флаг. |
| Враг | Убрать из подозреваемых, добавить во враги. |
| Враг потерян | Только в RT: убрать из врагов, добавить в подозреваемые. В TBS ничего (сделает начало хода). |
| Возможный враг | Добавить в подозреваемые, поднять флаг. |
| Возможный враг снят | Убрать из подозреваемых. |
| Враг умер | Убрать из врагов и из подозреваемых. |
| Союзнику нужна помощь | Добавить в союзники. |
| Союзник потерян | Убрать из союзников. |
| Труп | Если тело ещё не известно: запомнить; **убийцу** этого тела (записывается на теле в момент первой смерти/потери сознания) добавить в подозреваемые. |

Событие доставляется только юниту, который жив, CanFight и принадлежит ИИ-игроку.

### 3.2. Мировые события и кто их поднимает
| Мировое событие | Кто и когда поднимает | Что делает слушатель (каждый ИИ-юнит) |
|---|---|---|
| Увидел нового врага | Пересчёт видимости юнита: враг CanFight попал в список видимых, а в прошлый пересчёт его там не было. | Наблюдатель — не враг мне, цель — мой враг. Если наблюдатель я сам → «Враг». Если наблюдатель — другой юнит **не дальше 5 м** от меня и цель не я → «Возможный враг» (сосед показал). |
| Потерял врага из виду | Пересчёт видимости: юнит был виден и перестал (поднимается без проверки дипломатии). | Только если наблюдатель я → «Враг потерян». |
| Услышал врага | Генерация шума (раздел 4), слушатель услышал источник-врага. | Только если слушатель я и источник — мой враг → «Возможный враг». |
| Услышал союзника | Генерация шума: слушатель услышал не-врага, и базовый радиус звука в БД > 30 (то есть выстрелы и взрывы). | Слушатель я, источник не враг и не я → «Союзнику нужна помощь». |
| Пуля | Пуля закончила полёт (луч от первой до последней точки трассы, с длиной). | См. 3.3. |
| Взрыв гранаты | Взрыв с известным метателем. | Если **метатель** (не точка взрыва!) ближе 30 м ко мне: метатель-враг → «Возможный враг»; иначе, если метатель не я → «Союзнику нужна помощь». |
| Атака по юниту | Юнит начал атаку по цели. | Атакующий — не враг мне и не я, цель — мой враг, и я **вижу атакующего** → цель становится «Возможным врагом» (вижу, куда стреляет товарищ). |
| Юнит умер / потерял сознание | Смерть или отключка. | Не я: если он мой враг → «Враг умер», иначе → «Союзник потерян». |
| Передача управления | Ход перешёл к игроку (в т. ч. при прерываниях). | Если это мой игрок → «Начало хода». |
| Старт игры | Начало миссии. | «Начало хода» безусловно. |
| Юнит раскрыт (перестал прятаться) | Скрытность снята чужим обнаружением. | Если раскрыт я → «Обновить» (реакция передумает). |

### 3.3. Пуля, пролетевшая рядом
1. `d` = вектор от начала трассы до меня; `t` = проекция `d` на направление выстрела.
2. Если `t` > длина трассы + 2.5 м — мимо (пуля не долетела до меня).
3. Перпендикулярное расстояние от меня до луча должно быть **< 2.5 м**. (Проверки «`t` ≥ 0» нет: юнит позади стрелка в пределах 2.5 м от линии тоже реагирует.)
4. Стрелок — мой враг → «Возможный враг» (стрелок). Это и есть реакция на выстрел из невидимой позиции.
5. Стрелок не враг: если ближайшая цель пули — мой враг → «Возможный враг» (эта цель); иначе → «Союзнику нужна помощь» (стрелок).

### Константы
| Имя | Значение | Смысл |
|---|---|---|
| радиус «сосед увидел» | 5 м | Передача увиденного врага ближайшим товарищам. |
| коридор пули | 2.5 м | Поперёк трассы и за её концом. |
| радиус гранаты | 30 м | От метателя до слушателя. |
| порог «громкого своего» | радиус звука > 30 тайлов | Свой шум, на который сбегаются. |

## 4. Слух и шум

### Назначение
Любое действие юнита (шаг, выстрел, перезарядка, открывание двери, лечение, взрыв) порождает «ИИ-звук». Каждый другой боеспособный юнит на карте (любого игрока) проверяет, услышал ли он.

### Данные
Запись звука из таблицы `AISounds`: базовый радиус `Radius`, пять радиусов `R1..R5` по типу поверхности, флаг «не зависит от поверхности». Описатель конкретного шума: запись + индекс типа поверхности + коэффициент глушителя (глушитель оружия для выстрела, поправка перка «тихий шаг» для шагов, иначе 1.0). Эффективный радиус `R` = (базовый радиус, если звук не зависит от поверхности, иначе радиус по типу поверхности; **усекается до целого**) × коэффициент глушителя.

Константы слуха — единственная запись `AISoundConstants`:

| Поле БД | Значение | Смысл |
|---|---|---|
| PrecisePositionRadius | 7 | «Радиус точной позиции», тайлы. Базовая дальность слуха и точка отсчёта вероятности. |
| ExitRadius | 10 | Дальше этого расстояния (тайлы) источник выпадает из «слышимых». |
| BaseProbability | 50 | Базовый шанс услышать тихий звук, %. |
| DistanceCoeff | 10 | Сколько «очков навыка» стоит один тайл расстояния. |
| LoudSound | 10 | Радиус, начиная с которого звук считается громким. |
| HideCoeff | 0.8 | Множитель шанса, если источник прячется. |

Радиусы из `AISounds` (тайлы):

| ID | Звук | Radius | R1..R4 (по поверхности) | Класс |
|---|---|---|---|---|
| 3 | Ползком | 2 | 2 / 2 / 3 / 3 | тихий |
| 4 | Пригнувшись | 2 | 3 / 3 / 4 / 5 | тихий |
| 5 | Шагом | 2 | 3 / 4 / 5 / 6 | тихий |
| 6 | Бегом | 4 | 4 / 5 / 6 / 7 | тихий |
| 7 | Стрейф | 2 | 3 / 3 / 4 / 5 | тихий |
| 8 / 9 / 10 / 11 | Выстрел: пистолет / ПП / винтовка / пулемёт | 40 / 50 / 60 / 70 | — | громкий |
| 12 / 13 / 14 / 15 | Очередь: пистолет / ПП / винтовка / пулемёт | 65 / 75 / 85 / 95 | — | громкий |
| 16, 17 | Базука, миномёт | 100 | — | громкий |
| 18 | Удар без оружия | 3 | — | тихий |
| 19 | Удар холодным оружием | 5 | — | тихий |
| 20 | Лечение | 2 | — | тихий |
| 21 | Инженерное дело | 4 | — | тихий |

R5 у всех записей равен 0.

### Алгоритм: генерация шума
Источник должен быть CanFight. Для каждого другого боеспособного юнита-слушателя:
1. `D` = расстояние между CP × 1.6 (тайлы).
2. Если `D` > ExitRadius (10) — слушатель вычёркивает источник из своего набора «слышимых».
3. Проверка «слышу ли» (ниже). Если нет — слушатель стирает запомненную звуковую метку этого источника; конец.
4. Если да: слушатель запоминает метку звука с клеткой источника; источник вносится в набор «слышимых»; в TBS, если слушатель — юнит человека, а источник — юнит ИИ и не виден, камера показывает место звука.
5. Если источник — враг слушателя → событие «услышал врага». Иначе, если **базовый** радиус записи > 30 → «услышал союзника».
6. Если источник — враг из другого игрока, прячется, и слушатель геометрически видит его (с учётом сектора обзора) → **источник раскрывается** (прятки сняты), видимость пересчитывается.

### Алгоритм: «слышу ли»
1. Слушатель не CanFight → нет.
2. Если у слушателя критическое ранение «глухота» — он сначала очищает весь набор слышимых.
3. Источник уже в наборе слышимых → да (без броска).
4. Источник в списке видимых слушателя → да (вижу — значит слышу).
5. Иначе бросок: `P` = вероятность (ниже) при `D`; услышал, если `P > rnd(99)` (то есть бросок 0..98). Если услышан **тихий** звук — слушателю засчитывается применение навыка «наблюдательность» (Spot растёт от использования).

### Формула вероятности
`Spot` = навык наблюдательности слушателя; при наличии перка обострённого восприятия (id 0x14) умножается на коэффициент перка (усечение до целого). `MAX = 140` (максимум навыка).

- Глухой слушатель → 0.
- **Громкий звук** (нет источника или `R ≥ LoudSound`): дальность слуха `H = PPR + (R − PPR) × Spot / 140`. Если слушатель в ПК с ненулевой «дальностью сенсоров» — `H` умножается на неё, и ещё на коэффициент перка 0x4c, если он есть. Результат: 100, если `H ≥ D`, иначе 0. То есть громкий звук слышен **наверняка** в пределах дальности и никогда — за ней.
- **Тихий звук**: `P = Base + (Spot + (PPR − D) × DistanceCoeff − Stealth_источника) × 100 / 140`; если источник прячется — `P × HideCoeff`; зажать в **0..95**. Потолок 95 — тихий звук никогда не слышен гарантированно.

С числами из БД: `H = 7 + (R − 7) × Spot/140`; `P = 50 + (Spot + (7 − D) × 10 − Stealth) × 100/140`.

### Набор «слышимых» (CAudibleSet)
Список юнитов, чьи звуки слушатель сейчас слышит. Пополняется при услышанном звуке и при **потере врага из виду** (потерянный боеспособный враг автоматически считается слышимым и оставляет звуковую метку на месте исчезновения). Чистится по расстоянию (> 10 тайлов при следующем шуме источника), при глухоте, и метки стираются для юнитов, которых слушатель сейчас видит. Набор используется: (а) для слуха без броска; (б) для раскрытия спрятавшихся (раздел 5); (в) маршрутом обхода — «слышу ли я врага сейчас» (раздел 9.6); (г) Lua-функцией `UnitIsHearUnit`.

### Особые случаи и прихваты
- Глушитель уменьшает `R`. Если `R` падает ниже 10, выстрел переходит в класс **тихих**: вместо жёсткой дальности начинает работать вероятность со Stealth стрелка и потолком 95 %.
- Радиус по поверхности усекается до целого до умножения на глушитель.
- Для «своих» реакцию вызывают только громкие звуки с базовым радиусом > 30: все выстрелы, очереди, взрывы. Шаги своих никого не тревожат.
- Слышат все, в том числе юниты игрока (для них это метка звука на экране).

### Что нужно от движка-носителя
Вызов «шум» из исполнителей движения, стрельбы, перезарядки, дверей, лечения, падения тела, взрывов с типом звука и поверхности; навыки Spot/Stealth; критическое ранение «глухота».

## 5. Прятки и раскрытие спрятавшихся

### Назначение
Юнит может «спрятаться» (режим скрытности). Спрятавшийся не попадает в список видимых врага, пока тот его не раскроет.

### Когда можно спрятаться
Команда «спрятаться» принимается, если: (1) у юнита взведён флаг «могу прятаться» (сбрасывается при любом раскрытии и взводится заново в начале следующего «быстрого хода»/такта времени); (2) если юнит в ПК — костюм это разрешает; (3) **ни один боеспособный враг любого другого игрока сейчас его не видит**.

### Вероятность раскрытия
`U = clamp( int(45 − (44/30) × D) + Spot' − Stealth', 0, 100 )`, где `D` — расстояние в тайлах; `Spot'` — наблюдательность смотрящего, умноженная на (1 + коэффициент перка «лучшее обнаружение»), если он есть; `Stealth'` — скрытность прячущегося (ночью, при наличии у него перка «ночная маскировка», умножается на (1 + коэффициент) — см. раздел «Отклонения»).

### Алгоритм 1: при пересчёте видимости наблюдателя
Для каждого врага, которого наблюдатель геометрически видит и который прячется:
1. Бросок делается, только если враг **слышим** наблюдателю или ещё не числится в его списке «спрятался у меня на виду». (За молчащим, уже замеченным-как-спрятавшийся бросок не повторяется.)
2. Бросок: `r = rnd(0,100)`. Если `r ≥ U` **и** враг не слышим — остаётся спрятанным. Иначе раскрыт (с событием «юнит раскрыт»). Следствие: **слышимый спрятавшийся в прямой видимости раскрывается всегда**.
3. Оставшийся спрятанным заносится в список «спрятался у меня на виду» и в список видимых не попадает.

### Алгоритм 2: в начале каждого быстрого хода / такта времени
Для каждого прячущегося юнита и каждого боеспособного врага из других игроков, который его геометрически видит: бросок `rnd(0,100) < U` → раскрыт. Достаточно одного успеха.

### Алгоритм 3: шумом
См. раздел 4, шаг 6: услышанный врагом, находящимся в прямой видимости, раскрывается без броска.

### Последствия раскрытия
Режим пряток снят; флаг «могу прятаться» сброшен до следующего такта; раскрытый ИИ-юнит получает событие «Обновить» (его реакция передумывает — например, «убийца» сдаётся).

## 6. Обнаружение трупов

### Алгоритм (каждый тик ИИ, для живого боеспособного ИИ-юнита)
1. Собрать юнитов в радиусе **удвоенной дальности зрения** от глаз (дальность зрения — базово 20 м, с поправками перков и ночного зрения; итого обычно 40 м).
2. Для каждого: это не я; он **не CanFight** (мёртв или без сознания); его ещё нет в моих известных трупах; он **не враг** мне (вражеские тела игнорируются); геометрическая проверка «тело видно» (лучи к точкам тела с учётом дальности и сектора обзора) пройдена.
3. Поднять событие «Труп»: тело запоминается, **убийца тела становится подозреваемым** — и обычная реакция побежит проверять **текущее** место убийцы.

### Прихваты
- Юнит без сознания считается «трупом» наравне с мёртвым.
- Опция сложности `AICheckCorpses` это обнаружение **не выключает** (она управляет другим — обходом лежащих союзников, раздел 9.6).
- Тело, которое несут на плечах, видимо тогда же, когда виден несущий.

### 7.1. Обычная реакция (Normal)

**Данные:** `bWasCombat` — был ли бой.

**Алгоритм Update** (лестница приоритетов; первое сработавшее правило завершает обновление):

| № | Условие | Действие |
|---|---|---|
| 1 | Испуган **и** есть текущий враг | См. «Испуг» ниже. |
| 2 | (подготовка) | `проверять_подозреваемого` = есть ближайший подозреваемый. Если есть и текущий враг: подозреваемый интересен, только когда он ближе **трети** расстояния до врага (`dist(враг) × 1/3 > dist(подозр.)`). Если собственная клетка юнита недействительна — не проверять. |
| 3 | Можно применить Оборону (7.3) | Заменить себя реакцией Обороны, передав себя как «предыдущую». |
| 4 | Можно применить Убийцу (7.4) | Заменить себя реакцией Убийцы. |
| 5 | `проверять_подозреваемого` | Построить сценарий «проверить врага» (9.6) к **текущей реальной позиции** подозреваемого, бегом, с передачей самого подозреваемого. Если сценарий построился — поставить и закончить. Иначе — дальше. |
| 6 | Есть текущий враг | Если текущая логика ещё не «атака» — поставить логику атаки (существующая атака не пересоздаётся). `bWasCombat = да`. |
| 7 | Есть звавший союзник и своя клетка действительна | Сценарий «проверить врага» к текущей позиции союзника, бегом, без цели. Если построился — поставить, союзника вычеркнуть из памяти (один зов — один забег), `bWasCombat` не трогать. |
| 8 | `bWasCombat` | Поставить логику «после боя» с разрешённым сбором трофеев; `bWasCombat = нет`. |
| 9 | иначе | `SetLogic(пусто)` — стоять / вернуться к маршруту. |

**Испуг (правило 1):**
1. **Тревога.** Если боеспособных не-врагов под управлением ИИ на карте больше одного (считая себя) и `rnd(100) < 40` — попытаться построить сценарий «тревога» (раздел 8). Если построился: поставить его, вычеркнуть текущего врага из своей памяти (событие «Враг умер» самому себе), закончить.
2. **Отступление.** Искать точку бегства (9.8) от всех известных врагов и подозреваемых: не ближе 5 м вперёд по направлению «от толпы», достижимую бегом за 30 AP. Нашлась — заменить себя реакцией Отступления к этой точке.
3. **Загнан в угол.** Точки нет — заменить себя Караульным с радиусом 12 AP и без анимации.

**Логика «после боя»** (интерфейс; принадлежит тактической части): по приоритету перезарядка → лечение → сбор трофеев (если разрешён) → «выйти из неактивной позы/подойти». Если делать нечего — логика завершается, но в TBS только после того, как юнит получил свежий ход (то есть держится минимум один ход); в RT — сразу.

**Прихваты:**
- Подозреваемый не «потребляется»: когда сценарий проверки закончится (или прервётся), реакция проснётся и построит новый забег к **новому текущему** месту подозреваемого. Обычный юнит преследует до тех пор, пока не увидит цель или пока та не умрёт.
- Правило трети: рядом шумит невидимый враг, а видимый далеко — юнит бросит видимого и пойдёт на шум.
- Бросок тревоги повторяется при каждом обновлении, пока юнит испуган, враг есть и отступление/караул ещё не выбраны (на деле один раз — следующим же шагом реакция заменяется).

**Константы**
| Имя | Значение | Смысл |
|---|---|---|
| шанс тревоги | 40 % | При испуге и наличии хотя бы одного своего. |
| мин. дальность бегства | 5 м | Проекция на направление «от врагов». |
| бюджет бегства | 30 AP | Волна бегом. |
| радиус караула «в углу» | 12 AP | |
| правило трети | 1/3 | Приоритет подозреваемого над видимым врагом. |

### 7.2. Караульный (Guard)

**Данные:** анимация простоя; зона (множество клеток); радиус зоны в AP; пост (позиция); `bWasCombat`.

**Алгоритм Update:**
1. Если зоны ещё нет: пост = текущая позиция; зона = все клетки, достижимые **шагом** от поста за `радиус` AP. Не удалось построить — ничего не делать в этот раз.
2. Снять маршрут юнита навсегда (`SetRoute(пусто)`).
3. Если можно применить Оборону — заменить себя Обороной (с возвратом к караульному).
4. Если есть текущий враг — `bWasCombat = да`.
5. `гнаться_за_подозреваемым` = есть подозреваемый; если есть и враг — только когда `dist(подозр.) < dist(враг) × 1/3`.
6. Если гнаться: сценарий «проверить позицию» (9.5) подозреваемого **изнутри зоны**, поза — пригнувшись. Построился — поставить, подозреваемого вычеркнуть (потреблён), перейти к шагу 8.
7. Иначе по порядку:
   - есть враг → если текущая логика не «караульная боевая» — поставить её (бой, не выходя из зоны; интерфейс тактики);
   - иначе есть звавший союзник → «проверить позицию» союзника изнутри зоны, пригнувшись; если поставлено — союзника вычеркнуть;
   - иначе `bWasCombat` → логика «после боя» **без сбора трофеев**; `bWasCombat = нет`;
   - иначе, если юнит не на клетке поста и путь к посту существует и стоит > 0 AP → сценарий «дойти до поста» шагом, конечная поза — стоя.
8. Хвост: если у юнита сейчас есть логика — убрать особую анимацию простоя; если логики нет и анимация задана — включить её.

**Прихваты:** караульный никогда не покидает зону (все проверки — из клеток зоны); трофеи не собирает; зона и пост фиксируются при первом обновлении, а не при создании реакции (юнит, которого скрипт сначала переставил, караулит новое место). Радиус 0 — зона из одной клетки: юнит только поворачивается и приседает.

**Радиусы:** из БД (`RoamingRadius`) для размещённых; 4 — умолчание `UnitSetGuardLogic`; 8 — после Отступления; 12 — «загнан в угол».

### 7.3. Оборона из укрытия (Defence)

**Идея:** стрелок с коротким оружием находит рядом клетку, где враг его не видит, и соседнюю «огневую» клетку; дальше «танцует»: выскочил — пострелял — спрятался, каждый раз оставляя AP на возврат.

**Выбор пары клеток (GetCoveredPosition):**
1. Волна на **18 AP пригнувшись** от позиции юнита (без учёта временных блокировок клеток другими юнитами).
2. Кандидаты в укрытие: клетки волны, кроме собственной, с позой «пригнувшись», которые **враг не видит** из своей текущей позиции (враг виртуально разворачивается к клетке; его реальные дальность и сектор зрения). Каждому кандидату задаётся направление на врага.
3. Ищется путь (пригнувшись) от юнита сразу ко **всем** кандидатам; укрытие = конец найденного пути (то есть ближайшее по стоимости).
4. Огневая клетка: идём по этому пути **с конца к началу** и берём первую клетку (не укрытие, поза «пригнувшись»), из которой **юнит видит врага**; ей задаётся направление на врага. Не нашли — пары нет.

**Проверка годности пары (все условия обязательны):** юнит CanFight; не в ПК; **не прячется**; обе клетки — действительные и допустимые как цель движения; первое огнестрельное оружие в инвентаре — **пистолет или пистолет-пулемёт**; переход укрытие→огневая пригнувшись стоит > 0 AP; ни одна из клеток не занята другим объектом; стоять уже на огневой клетке допустимо только при наличии врага; при наличии врага: враг не видит укрытие **и** из укрытия не виден враг (полное укрытие); если есть подозреваемый — юнит не должен видеть его со своего места.

**Вход:** из Обычной (правило 3) и Караульного (шаг 3), когда есть текущий враг, пара найдена и годна. При создании реакция планирует пару заново и запоминает `цена` = AP перехода укрытие→огневая.

**Алгоритм Update:**

| Состояние | Условие | Действие |
|---|---|---|
| План умер | пара не годна и есть предыдущая реакция | Разрешить режимы огня «прицельный» и «длинная очередь»; вернуть предыдущую реакцию. |
| (общее) | иначе | Запретить режимы «прицельный» и «длинная очередь» на время танца. |
| В укрытии | до укрытия 0 AP | Сценарий «стрейф к огневой клетке» (пригнувшись). |
| На огневой | до огневой 0 AP; `AP > цена` и `AP ≠ AP_прошлого_раза` | Запомнить AP; поставить боевую логику обороны (стрелять с этой клетки, сохранив `цена` AP — интерфейс тактики). |
| На огневой | иначе | «Нырнуть»: стрейф к укрытию; плановый запас AP = max(0, AP − стоимость пути). |
| В пути | `AP > 2 × цена` | Стрейф к огневой. |
| В пути | иначе | «Нырнуть» в укрытие. |

Реакция получает следующее обновление, когда поставленная логика завершается.

**Прихваты:** сравнение с «AP прошлого раза» — защита от вечного цикла на огневой клетке без траты AP; запрет дорогих режимов огня — чтобы хватало AP на возврат; стрейф (боком, не отворачиваясь от врага) вместо обычной ходьбы; годится только пистолет/ПП — стрелки с винтовками и пулемётами никогда не танцуют.

**Константы:** волна 18 AP; порог «богат» 2 × цена; служебное «цена неизвестна» 0xFFFF.

### 7.4. Убийца (Assassin)

**Условие входа (из Обычной, после Обороны):** юнит CanFight; не в ПК; первое огнестрельное — пистолет или ПП; есть цель (текущий враг, иначе подозреваемый); расстояние до цели **> 5 м**; `rnd(0,99) < AssassinProbability` сложности; юнит уже прячется **или** движок принимает команду «спрятаться» (никто из врагов его не видит).

**Алгоритм Update:**
1. Если запомненная жертва исчезла или не CanFight — взять текущего врага, иначе подозреваемого; никого нет → сдаться.
2. Если это не первый проход и юнит **уже не прячется** → сдаться (раскрыли).
3. Если первый проход и юнит ещё не прячется → поставить сценарий «спрятаться» (один шаг) и ждать.
4. Иначе (спрятан): расстояние до жертвы < 5 м → сдаться (Обычная реакция на следующем тике атакует в упор). Иначе найти точку подхода; не нашлась → сдаться. Если расстояние ≥ 10 м — сценарий «проверить врага» (обход с фланга, 9.6) к точке подхода **ползком**, без цели; если < 10 м — сценарий «дойти до точки» ползком, конечная поза ползком. Сценарий не построился → сдаться.
5. «Сдаться» = заменить себя новой Обычной реакцией. В конце каждого прохода «первый проход» снимается.

**Точка подхода:** волна на **14 AP бегом вокруг жертвы**; перебор клеток в порядке волны; годятся клетки «по мою сторону» от жертвы (скалярное произведение (жертва − клетка)·(жертва − я) > 0); для первой такой клетки, где **шанс жертвы услышать** заданный шум передвижения с расстояния (клетка↔жертва, тайлы) **меньше 15** — ответ «есть ли у меня путь туда ползком»; если шанс ≥ 15 — следующая клетка.

**Прихват «шанс быть услышанным»:** для оценки берётся запись звука с ID 3 и типом поверхности 0, без глушителя. В комментариях исходника она названа «звук бега», но в БД запись 3 — «Crawl» (радиус 2); запись «Run» имеет ID 6. Что именно грузилось в оригинале — не подтверждено; по данным БД оценивается шум ползка, что согласуется с тем, что юнит действительно ползёт. Формула — «тихий звук» из раздела 4 (со Stealth убийцы и множителем 0.8, так как он прячется).

**Константы:** порог дистанции 5 м; порог «далеко» 10 м; волна 14 AP; порог слышимости 15 %.

### 7.5. Отступление (Retreat)

**Данные:** точка отхода.

**Алгоритм Update:**
1. Снять маршрут навсегда.
2. Расстояние до точки < 0.5 м → заменить себя Караульным (радиус 8 AP, без анимации).
3. Иначе: есть текущий враг → боевая логика отступления к точке (интерфейс тактики). Иначе есть подозреваемый → сценарий «посмотреть на место» (повернуться к нему, ждать 3 с) и вычеркнуть подозреваемого.
4. Если после этого у юнита нет никакой логики → сценарий «дойти до точки» бегом, конечная поза пригнувшись, допускается неточный путь (дойти как можно ближе).

Возврата в Обычную реакцию нет: отступивший юнит остаётся караульным на месте отхода до конца миссии (или до вмешательства скрипта).

### 7.6. Страх / гражданский (Fear)

**Параметры:** `bUseCover` — искать невидимое место; `bRoaming` — в покое бродить; `nRadius` — радиус блуждания в AP.

**Алгоритм Update:**
1. Есть текущий враг: если `bUseCover` — искать «безопасное место» (9.8); не нашли или без укрытий — искать «точку бегства» (мин. дальность 1 м, бюджет 20 AP). Нашли: если это та же клетка, где стоит юнит, — сценарий «осматриваться пригнувшись» (зацикленный); иначе — «дойти до точки» бегом, конечная поза бегом. Закончить.
2. Есть подозреваемый: сценарий «посмотреть на место», вычеркнуть подозреваемого и **сжечь реальные AP юнита, оставив ровно стоимость поворота** — юнит только оборачивается и больше ничего не делает в этот ход. Закончить.
3. Никого: если не `bRoaming` — «осматриваться пригнувшись»; иначе — блуждание вокруг текущей клетки в радиусе `nRadius`.

Маршрут эта реакция не снимает.

### 7.7. Скриптовая (Script)

Реакция при каждом обновлении ставит юниту **новую** скриптовую логику. Логика при запросе команды:
1. Если ход не сдан и хук ещё не вызывался в этом окне — вызвать Lua-функцию `OnUnitNeedCommand(unit)`, запомнить номер сегмента.
2. Через **5 сегментов** после вызова: если у командира игрока этого юнита нет ожидающих команд — «ход сдан» до начала следующего хода игрока; в любом случае окно закрывается, и следующий запрос снова вызовет хук.
3. «Ход окончен» = «ход сдан» или обычные условия конца хода.

Счётчик сегментов увеличивается событием мира «сегмент»; «ход сдан» сбрасывается событием «новый ход игрока».

### 7.8. Пустая (Empty)
Ничего не делает. Ставится при включении чита `CHEAT_NOAI` на юнита (функция библиотеки `UnitAIMode(unit, false)`).

### 7.9. Переходы между реакциями

| Из | В | Условие |
|---|---|---|
| Обычная | Оборона | Есть враг, найдена годная пара клеток. |
| Обычная | Убийца | Условия 7.4. |
| Обычная | Отступление | Испуган, тревога не выпала/не построилась, точка бегства найдена. |
| Обычная | Караульный (12) | Испуган, точки бегства нет. |
| Караульный | Оборона | Есть враг, найдена годная пара. |
| Оборона | предыдущая (Обычная или Караульный) | Пара перестала быть годной. |
| Убийца | Обычная (новая) | Нет жертвы; раскрыт; подошёл ближе 5 м; нет точки подхода; сценарий не построился. |
| Отступление | Караульный (8) | Дошёл до точки (< 0.5 м). |
| любая | любая | Скриптом (раздел 11); `CHEAT_NOAI` вкл → Пустая, выкл → **Обычная** (прежний тип не восстанавливается). |

## 8. Тревога

### Назначение
Испуганный юнит, у которого есть свои на карте, может вместо отступления сбегать к ближайшему товарищу и «рассказать» о враге.

### Алгоритм
1. Условие и бросок — в Обычной реакции (7.1): не менее одного другого ИИ-не-врага на карте и 40 %.
2. **Куда бежать:** ближайший (по прямой) боеспособный не-враг под управлением ИИ, кроме себя. Берутся клетки в сфере радиуса 2 м вокруг него, из них одна случайная. Если до неё нет пути бегом — тревоги не будет (переход к отступлению).
3. **Сценарий:** сменить позу на «бегом» → идти к клетке → повернуться к клетке → ждать 1 (в TBS — до следующего хода) → шаг «тревога».
4. Сразу после постановки сценария паникёр вычёркивает врага из своих списков — иначе реакция на следующем же тике вернула бы его в бой.
5. **Шаг «тревога»** (если и паникёр, и враг ещё CanFight): каждому боеспособному ИИ-юниту-не-врагу **в радиусе 5 м** от паникёра (включая его самого) — событие «Возможный враг» с этим врагом, прямой доставкой. Затем сам паникёр получает «Помощь позвана»: испуг снят, второй раз он не пугается и не бегает.
6. Получатели на ближайшем тике срабатывают как на подозреваемого: обычные бегут проверять текущее место врага, караульные — смотрят из зоны, гражданские — оборачиваются.

### Константы
| Имя | Значение |
|---|---|
| шанс | 40 % |
| радиус выбора места у товарища | 2 м |
| радиус оповещения | 5 м |
| пауза перед оповещением | Wait(1) |

### Прихваты
Сообщается не место, а сам враг — оповещённые идут туда, где враг находится **на момент построения их сценария**. Если враг умер, пока паникёр бежал, тревога ничего не делает (и «Помощь позвана» не ставится).

## 9. Маршруты, путевые точки и готовые сценарии

### 9.1. Путевая точка и маршрут

**Путевая точка:** имя; мировая точка; клетка сетки (при загрузке точка «прилипает» к ближайшей **изначально проходимой** клетке — клетки под закрытой дверью и временно занятые тоже годятся; для «трёхмерных» точек, флаг `Is3DPoint`, строится позиция полёта); список команд точки.

**Команды точки:** `POSE(поза)`, `WAIT(время)`, `DIR(направление)`; `GOTO` существует в перечислении, но в списке команд точки не обрабатывается (переход создаётся автоматически). Умолчания команды: тип POSE, поза «шагом», время 0, направление «вверх».

**Маршрут:** упорядоченный список путевых точек. В БД: 2306 точек, 1207 имён, 130 групп юнитов; поле `Formation` у всех групп пустое.

### 9.2. Разворачивание маршрута в шаги
Для каждой путевой точки по порядку:
1. Вычислить места строя: текущие позиции всех юнитов группы передаются функции сети путей «построиться вокруг точки» (интерфейс поиска пути); берётся место, выпавшее этому юниту. Для одиночки группа состоит из него одного. **Строй считается один раз — в момент назначения маршрута**, от позиций юнитов в этот момент.
2. Шаг `Goto(место)`.
3. Команды точки по порядку: POSE → шаг «сменить позу»; DIR → «повернуться»; WAIT → «ждать».
4. Если маршрут групповой (в группе больше одного юнита) → шаг «синхронизация» с барьером этой точки.

Зацикливание: запрошенное зацикливание действует, только если точек больше одной; логика маршрута с менее чем двумя шагами никогда не зациклена. Для группового маршрута число барьеров должно равняться числу точек, иначе маршрут не создаётся.

### 9.3. Исполнение (логика маршрута)
Состояние: список шагов, номер текущего шага (−1 до старта), флаг зацикливания, флаг «продолжить текущий».

Когда очередь команд логики пуста:
1. Если текущий шаг закончен (или ещё не начинали): вызвать у него «шаг закончен», перейти к следующему (в зацикленном маршруте после последнего — к нулевому), вызвать «шаг начат».
2. Сбросить «продолжить текущий»; запросить у текущего шага следующую мировую команду и поставить в очередь.
3. Незацикленный маршрут, у которого шаги кончились, завершается.

«Шаг закончен»: у юнита нет висящей команды, не стоит флаг «продолжить», и сам шаг сообщает о конце (обычный шаг — когда выдал все свои команды; «ждать» и «синхронизация» — по своим условиям). «Ход окончен» для маршрута: общие условия конца хода либо текущий шаг требует ждать (ожидание, барьер).

### 9.4. Шаги (семейство команд маршрута)

| Шаг | Что делает |
|---|---|
| Goto(место, стрейф?) | Если юнит сейчас не в позе «бегом» и не в ПК — сначала команда «режим стрейфа = да/нет», затем команда «идти по пути к месту». |
| Сменить позу | Юнит в ПК: позы выше «пригнувшись» заменяются на «шагом» (ПК не бегает). Команда «желаемая поза», затем — если клетка действительна — переход в эту позу на месте. |
| Сменить желаемую позу | То же, но переход на месте выполняется только для ПК; остальные примут позу при следующем движении. |
| Повернуться(направление) | Команда «смотреть» из текущей клетки в заданном направлении. |
| Посмотреть на место(клетка) | В момент исполнения вычисляет ближайшее из 8 направлений от текущей клетки к целевой и поворачивается. |
| Ждать(N) | При старте шага запоминает «сейчас + N секунд» и номер хода. В RT ждёт до срока; **в TBS ждёт, пока номер хода не сменится, независимо от N**. Юнит с недействительной клеткой не ждёт. Пока ждёт — «ход окончен». |
| Блуждать(центр, радиус AP) | Волна от центра на радиус AP; случайная клетка волны; идти туда, конечная поза — стоя. |
| Спрятаться | Если юнит CanFight, ещё не прячется, **игрок №0 (человек) ему враг** и движок принимает команду — команда «спрятаться». |
| Тревога(враг) | См. раздел 8. |
| Особая анимация простоя | Включает юниту заданную анимацию простоя. |
| Синхронизация(барьер) | См. 9.7. |

### 9.5. Готовые сценарии (фабрики)

| Сценарий | Условие создания | Шаги | Цикл |
|---|---|---|---|
| Посмотреть на место | юнит жив | Посмотреть на место; Ждать(3) | нет |
| Дойти до точки (поза движения, конечная поза, неточный путь?) | есть путь в позе движения | Посмотреть на место; Желаемая поза; Goto без стрейфа; Сменить позу на конечную | нет |
| Стрейф к точке | есть путь | Желаемая поза; Сменить позу; Goto **со стрейфом** | нет |
| Осматриваться (поза) | юнит жив | Сменить позу; «оглядывание» с параметром 6 | да |
| Блуждание (центр, радиус) | юнит жив | Блуждать; «оглядывание» с параметром 2 | да |
| Спрятаться | юнит жив | Спрятаться | нет |
| Проверить позицию (зона, место, поза) | см. ниже | см. ниже | нет |
| Проверить врага (место, поза, цель) | см. 9.6 | см. 9.6 | нет |
| Тревога | см. 8 | см. 8 | нет |

**«Оглядывание» (параметр n):** число взглядов = `lo + rnd(hi − lo)`, где `lo = max(n − 2, 0)`, `hi = max(n + 1, 1)`, не меньше 1 (для 6 → 4..6 взглядов; для 2 → 1..2). Каждый взгляд: Повернуться(`rnd(7)`), Ждать(`rnd(5) + 1`). Опционально перед этим — «Сменить позу: шагом».

**«Пойти и проверить» (вспомогательный набор):** Посмотреть на место; Желаемая поза бегом/шагом; Goto; опционально «оглядывание» (со сменой позы на шаг, параметр 6); Сменить позу: шагом.

**«Проверить позицию»** (используют Караульный): 
1. С шансом `nHideProbability` % — шаг «Спрятаться».
2. Найти **точку наблюдения**: волна бегом на текущий AP юнита; среди клеток волны, лежащих в зоне, из которых видно проверяемое место (юнит развёрнут к нему, его дальность и сектор зрения), взять клетку с **наибольшей стоимостью пути** (смотреть с самого дальнего доступного края; при равенстве — первая).
3. Если точка найдена и до неё есть путь бегом: Посмотреть на место; Сменить позу на заданную; с шансом `nHideProbability` % ещё раз «Спрятаться»; Goto(точка).
4. Если точка **не найдена** и у юнита нет текущего врага: Посмотреть на место; Сменить позу: пригнувшись (кроме ПК); Повернуться в направлении на место со случайной поправкой −1/0/+1, зажатом в 0..7.
5. Если хоть что-то набралось — добавить Ждать(6). Иначе сценарий не создаётся.

### 9.6. Обход с фланга («проверить врага», round-up)

**Создание:** с шансом `nHideProbability` % — шаг «Спрятаться». `слышу` = цель передана и она в моём наборе слышимых. Затем строится набор обхода с признаком «проверять своих» = **не** `слышу`. Если набор добавил хоть один шаг — добавить Ждать(6) и создать сценарий, иначе сценария нет.

**Признак «обходить лежащих своих»** = «проверять своих» **и** опция сложности `AICheckCorpses`.

**Планирование трёх точек (GetRoundUpPlaces):**
1. `dist` = расстояние от меня до места врага. Поза движения: бегом (ПК — шагом).
2. Если обходим лежащих своих: собрать центры всех **не боеспособных союзников** (именно `DS_ALLY`) в сфере с центром в середине отрезка «я—враг» и радиусом `dist/2 + 5` м.
3. **Близко (`dist < 8` м):** фланг = стоп = моя позиция, атака = место врага. План отвергается только если обходим своих и какая-то из трёх точек ближе 4 м к лежащему союзнику.
4. **Далеко:** `бюджет = int(dist × 1.6)`; для атаки не больше 20 AP, для фланга не больше 25 AP.
   - **Точка атаки:** волна от **клетки врага** на бюджет атаки; случайный перебор без возврата; годится клетка с позой «пригнувшись» (ПК — «стоя»), из которой, развернувшись к врагу, я вижу его место. Нет такой — план не удался.
   - Путь от меня к точке атаки; на нём берётся точка с индексом `int(длина × 0.33333334)` — **«треть пути»**.
   - **Точка фланга:** волна от «трети пути» на бюджет фланга; случайный перебор; годится клетка, лежащая **с той же стороны от оси «я → враг», что и точка атаки** (скалярное произведение перпендикулярной составляющей вектора «я → атака» на вектор «я → клетка» > 0). Нет — план не удался.
   - **Точка остановки:** путь от меня к флангу; первая на нём переходная клетка (поза CM_INACTIVE — **дверь или лестница**); если таких нет — сама точка фланга.
   - Если обходим своих: план отвергается, когда путь «я → фланг» или путь «конец первого пути → атака» проходит ближе 4 м от лежащего союзника.

**Набор шагов (RouteAddRoundUp):**
1. Посмотреть на место врага.
2. Если план удался:
   - «низкая поза» = пригнувшись (ПК — шагом), «поза переброски» = бегом (ПК — шагом); обе не выше запрошенной позы сценария (для убийцы обе — ползком);
   - Посмотреть на место врага (ещё раз);
   - если точка остановки не моя клетка: Желаемая поза = поза переброски; Goto(остановка) — **добежать до двери/лестницы**;
   - Сменить позу на низкую; Goto(фланг) — **дальше крадучись**;
   - если цель жива и нашлась **точка передышки** (ниже): если она не моя клетка — [если просматриваемых точек было ≤ 3 и `rnd(0,100) < 40` → Ждать(1)]; Goto(передышка); Ждать(1). Затем, если юнит не в ПК, — Повернуться от точки передышки к врагу;
   - Goto(атака); Посмотреть на место врага.
3. **Хвост — всегда, даже если план не удался:** Ждать(2 или 3, поровну); «оглядывание» с параметром 6; Сменить позу: шагом.

**Точка передышки (GetRestoreAPPoint):** путь от фланга к атаке просматривается **с конца**; возвращается первая точка, которую враг (виртуально развёрнутый к ней, его дальность и сектор зрения) **не видит**; подряд идущие точки одной клетки считаются один раз; если просмотрено 20 видимых точек — передышки нет. Смысл: остановиться на последнем невидимом для врага месте перед выходом на огневую, дождаться нового хода (Ждать(1) в TBS = до следующего хода, AP восстановятся) и выйти с полным запасом AP.

**Константы**
| Имя | Значение | Смысл |
|---|---|---|
| ближняя дистанция | 8 м | Ближе — без обхода. |
| бюджет атаки / фланга | min(dist×1.6, 20) / min(dist×1.6, 25) AP | Волны. |
| доля пути | 1/3 | Откуда ищется фланговая точка. |
| радиус «лежит свой» | 4 м | Обход тел союзников. |
| запас сферы поиска тел | +5 м | |
| шанс паузы перед передышкой | 40 % при ≤ 3 просматриваемых точках | |
| предел просмотра | 20 точек | |
| финальное ожидание | 6 | |

### 9.7. Группы и барьер синхронизации
- На каждую путевую точку группового маршрута создаётся общий объект-барьер; у каждого юнита в конце шагов точки стоит шаг «синхронизация», зарегистрированный в барьере как участник.
- Когда шаг становится текущим, он «голосует». Когда число проголосовавших ≥ числа участников — все участники разблокируются, список голосов очищается.
- Заблокированный шаг: «не закончен» и «ход окончен» — юнит стоит на точке и ждёт остальных.
- При завершении шаг снова взводит блокировку (для следующего круга зацикленного маршрута).
- Участник, который **умер или потерял сознание**, вычёркивается из барьера, чтобы группа не ждала его вечно.
- Итог: группа идёт от точки к точке «гармошкой» — все собираются на точке (каждый на своём месте строя), и только потом идут дальше.

### 9.8. Точки бегства и безопасные места

**Направление «от толпы»:** для каждого известного боеспособного противника в пределах 15 м — единичный вектор на него с весом `16.666666 / (расстояние + 1.6666666)`; сумма нормируется; берётся обратное направление.

**Клетки по направлению:** волна бегом на заданный бюджет AP от своей клетки; для каждой клетки `f` = проекция смещения на направление; требуется `f ≥ 0` и `минимум ≤ f ≤ 4095`; клетка попадает в конус, если боковое отклонение `< 0.40 × f`. Если конус пуст — берётся одна клетка с наибольшим `f` (если была хоть одна в полосе).

**Точка бегства:** случайная клетка конуса. Параметры: Обычная — минимум 5 м, 30 AP; Страх — минимум 1 м, 20 AP.

**Безопасное место** (Страх с укрытиями): волна бегом на текущий AP, но **не меньше 28**; выкидываются все клетки, которые видит хоть один известный противник (он виртуально разворачивается к клетке; его дальность и сектор зрения); берётся **первая** оставшаяся в порядке волны (ближайшая по стоимости).

**Волна достижимых клеток (общая):** на время расчёта юниту подставляется нужная поза; временные блокировки клеток другими юнитами игнорируются; из результата убираются клетки с позами «лёжа» и «переходная» и клетки, непроходимые вовсе или «нельзя лежать».

### 9.9. Маршруты с карты и из скриптов
- При размещении юнита с карты: есть путевые точки → зацикленный маршрут; иначе по типу (таблица в разделе 7). Обычный часовой без точек не получает ничего и просто стоит.
- Скриптовые маршруты ставятся в тот же слот позже и вытесняют размещённые.
- Маршрут из одной точки (`UnitMoveToWaypoint`, `GroupMoveToWaypoint`, хвост `UnitSetToWaypoint`) не зациклен и завершается по приходе; завершение будит реакцию.

### Что нужно от движка-носителя
Поиск пути с позой; волна достижимости со стоимостями; «ближайшее из 8 направлений от клетки к клетке»; «построить группу вокруг точки»; геометрическая проверка видимости точки из позиции с дальностью и сектором; команды: путь, взгляд, желаемая поза, стрейф, спрятаться, отмена, продолжить, телепорт.

## 10. Журнал плана (AILog)

### Назначение
Боевой планировщик (тактическая часть) просчитывает ход на **виртуальной копии** юнита: позиция, AP, HP, инвентарь, патроны. Каждое намеченное действие — запись журнала с тремя операциями:

| Операция | Смысл |
|---|---|
| Commit | Применить действие к виртуальной копии (как будто оно выполнено). |
| RollBack | Вернуть копию в состояние до действия. |
| GetCommands | Выдать мировые команды для реального исполнения. |

Планировщик пробует вариант: Commit → оценка → RollBack; выбранная цепочка превращается в команды. Каждая мировая команда юнита оборачивается в «задать команду юниту».

### Записи

| Запись | Commit | RollBack | Команды |
|---|---|---|---|
| Перемещение (откуда, куда, поза; умолч. бегом) | позиция = «куда» | позиция = «откуда» | Желаемая поза; путь к цели с сохранением позы |
| Выстрел (цель, часть тела) | — | — | Стрелять по объекту |
| Удар в ближнем бою (враг, оружие, часть тела) | — | — | Та же команда «стрелять по объекту» |
| Выстрел в точку | — | — | Стрелять по тайлу |
| Лечение (пациент) | — | — | Лечить (если пациент существует) |
| Покинуть ПК | — | — | Выйти из ПК (только если юнит всё ещё в ПК) |
| Надеть ПК (костюм) | — | — | «Взять тело» с костюмом как целью |
| Занять орудие | — | — | Желаемая поза: бегом; занять орудие |
| Покинуть орудие | — | — | Выйти из орудия |
| Начать снайперский выстрел (враг, часть тела) | — | — | Стрелять по объекту |
| Копить снайперские AP (сколько) | — | — | Копить AP прицеливания |
| Отменить действие | — | — | Отмена (не обёрнута) |
| Перезарядка (оружие) | следующая обойма становится текущей и убирается из запасных | — | Перезарядить |
| Трата AP (сколько) | AP = max(0, старое − трата) | старое AP | нет |
| Трата HP (сколько) | HP = старое − трата | старое HP | нет |
| Трата патронов (обойма, сколько) | остаток = max(0, старое − трата) | старое | нет |
| Смена оружия (новое) | текущий предмет = новое | текущий = старое | Старое из слота 1 в рюкзак; (если новый предмет существует) упорядочить рюкзак, новое из рюкзака в слот 1, сделать слот 1 активным |
| Подобрать предмет (предмет на земле, поза) | добавить в виртуальный инвентарь | — | Желаемая поза (ПК: выше «пригнувшись» → шагом); упорядочить рюкзак; переместить с земли в рюкзак |
| Выбросить предмет | убрать из виртуального инвентаря | — | Предмет ищется в рюкзаке, затем в двух слотах; в руку → на землю; если был в рюкзаке — упорядочить |
| Бросок гранаты (точка, граната) | убрать гранату, рука пуста | вернуть (см. отклонения) | Стрелять по тайлу |
| Бросок ножа (враг, нож) | убрать нож, рука пуста | вернуть (см. отклонения) | Стрелять по объекту, часть тела — «любая» |
| Смена режима огня | режим = новый (на реальном предмете оружия) | режим = старый | Команда смены режима |
| Спрятаться | — | — | Спрятаться |

Маршрутные сценарии (раздел 9) журналом не пользуются — их шаги выдают команды напрямую.

### 11.2. Маршруты, группы, перемещение

### 11.4. Как этим пользуются дизайнеры (по таблице `Scripts`)

Частота вызовов во всех 113 скриптах: `UnitMoveToWaypoint` 266, `GroupMoveToWaypoint` 59, `UnitSetToWaypoint` 43, `SetDiplomacy` 39, `UnitSetRetreatLogic` 25, `CreateRoute` 19, `GroupSetRoute` 18, `UnitKeepMoving` 18, `PlayerGiveTurn` 14, по 12 — `UnitSetNormalLogic`, `UnitSetGuardLogic`, `UnitRoaming`; `UnitHide` 11; `UnitSetHideProbability` 4; `UnitSetScriptLogic` 3.

**Пример 1 — штурмовые группы по маршрутам (скрипт «GCom»):**
```
Assault1Route = CreateRoute( "Assault1WP1", "Assault1WP3", "Assault1WP4" )
GroupSetRoute( Assault1, Assault1Route, nil )
```
Группа идёт по трём точкам без зацикливания, собираясь на каждой.

**Пример 2 — «отступление» как способ согнать юнитов в точку (скрипт «GVip»):**
```
UnitCancelAction( unit )
UnitSetRetreatLogic( unit, "GeneralsHideout" )
```
Закомментированная строка рядом показывает, что раньше стоял `UnitMoveToWaypoint`: реакция отступления надёжнее — юнит бежит к точке, отстреливаясь, и становится там караульным.

**Пример 3 — снайпер в засаде (скрипт «RRBridge»):**
```
UnitSetSkill( GetUnit( "sniper" ), ST_STEALTH, 50 )
UnitSetHideProbability( GetUnit( "sniper" ), 100 )
UnitHide( GetUnit( "sniper" ) )
```
Снайпер спрятан с самого начала и перед каждой проверкой места снова прячется со 100 % шансом.

**Пример 4 — передача агента под ИИ в роли неподвижного наблюдателя (скрипт «ECct»):**
```
UnitSetPlayer( ourag, 3 )
UnitAIMode( ourag, false )
UnitSetGuardLogic( ourag, 0 )
```
Радиус 0 — зона из одной клетки.

**Пример 5 — босс под управлением скрипта (скрипт «FF2»):** группе ставится `UnitSetScriptLogic`; решения принимаются в `OnStartTurn( player )` (стрельба, гранаты, перелёты `UnitFlyToWaypoint`), а `OnUnitNeedCommand( unit )` лишь выставляет флаг — пятисегментное окно используется как «дай скрипту время, иначе сдай ход».

**Пример 6 — мирные жители (скрипт «GTFact»):** `UnitSetFearLogic( GroupGetUnit( Civilians, i ) )` в цикле по группе.

## 13. Реакция ИИ на отдельные ситуации (сводка)

| Ситуация | Что происходит |
|---|---|
| Найден труп своего | Убийца → подозреваемый → Обычная: обход с фланга к текущему месту убийцы; Караульный: осмотр из зоны; Страх: обернуться. |
| Выстрел из невидимой позиции | Пуля в коридоре 2.5 м → стрелок подозреваемый; громкий выстрел в пределах слышимости → то же через слух. Дальше — как выше. |
| Враг пропал из виду | RT: сразу в подозреваемые; TBS: в начале своего хода. Пропавший автоматически считается «слышимым» и оставляет метку. Обычная реакция идёт в обход к его текущему месту; так как он «слышим», обход лежащих своих не включается. |
| Двери и лестницы | В обходе с фланга юнит бежит только до первой двери/лестницы на пути, а дальше идёт пригнувшись. Открывание дверей на пути — дело исполнителя движения (вне среза); двери шумят (радиусы 2–5). |
| Мины | В разобранных файлах реакции ИИ на мины нет: обнаружение мин (по навыку, с проверкой прямой видимости) служит только отображению, медалям и реплике «замечена ловушка». Учёт мин при выборе пути — не установлено (вне среза). |
| Сосед увидел врага | Юниты в 5 м от увидевшего получают подозреваемого. |
| Свой стреляет рядом / свой бросил гранату ближе 30 м / слышен громкий звук своего | «Союзнику нужна помощь» → Обычная бежит к нему обходом; Караульный смотрит из зоны. |
| Юнита раскрыли из пряток | Событие «Обновить» → реакция передумывает. |
| Юнит сидит за пулемётом, а реакция поставила сценарий | См. «Отклонения» (вставка «выйти из орудия»). |

## 14. Все прихваты ИИ списком

- [ ] ИИ думает каждый 3-й сегмент; за тик обновляется только одна реакция.
- [ ] Пока хоть у одного юнита «память изменилась», никому не выдаются новые команды.
- [ ] Изменение памяти отменяет текущую команду юнита и чистит его очередь.
- [ ] Реакция просыпается только от изменения памяти или завершения логики — не по таймеру.
- [ ] Новая реакция не обновляется сразу, а на следующем тике (через поднятый флаг).
- [ ] Маршрут живёт в отдельном слоте: пауза на время боевой логики, возобновление после.
- [ ] При паузе маршрут откатывается к последнему шагу «идти» и повторяет его.
- [ ] В режиме сцены работает только слот маршрута сцены; `SetLogic` запрещён.
- [ ] Следующий юнит для хода — ближайший к предыдущему.
- [ ] Антицикл: 16–30 повторов «та же клетка, то же AP» — 25 % отмены команды; 31 — конец логики.
- [ ] Антизависание хода: порог 5000, вес дёрганий юнита ×200.
- [ ] Цель — не ближайший, а лучший по шансу попадания из кластера ±1.5 м от ближайшего.
- [ ] Память хранит позицию контакта; повторный сигнал о сдвинувшемся контакте — новое событие.
- [ ] Подозреваемые не забываются по времени.
- [ ] Обычная реакция не «потребляет» подозреваемого — преследует бесконечно.
- [ ] Идя проверять подозреваемого, ИИ берёт его **реальную текущую** позицию, а не место, где слышал/видел.
- [ ] Правило трети: подозреваемый важнее видимого врага, если он втрое ближе.
- [ ] Испуг: < 50 % VP или > 2 врагов, и никого своего в 9 м; ПК не пугается.
- [ ] Испуг не проходит сам; после тревоги юнит не пугается никогда.
- [ ] Тревога: 40 %, бежит к ближайшему своему, оповещает всех в 5 м, сам забывает врага.
- [ ] Оповещённые получают самого врага (не место).
- [ ] Загнанный в угол испуганный становится караульным с радиусом 12 AP.
- [ ] Отступивший становится караульным (радиус 8) и в обычный режим не возвращается.
- [ ] Караульный снимает свой маршрут навсегда и не выходит из зоны.
- [ ] Караульный смотрит на подозрительное место с самой дальней по стоимости клетки зоны.
- [ ] Караульный не собирает трофеи, обычный — собирает.
- [ ] Оборона только для пистолетов и ПП; запрещает прицельный режим и длинную очередь.
- [ ] Оборона: укрытие — ближайшая по пути клетка, которую враг не видит; огневая — последняя клетка пути к укрытию, откуда врага видно.
- [ ] Оборона: выход на огневую, только если AP > 2 × цена возврата; стрельба с резервом AP на возврат.
- [ ] Оборона: защита от холостого цикла сравнением AP с прошлым разом.
- [ ] Убийца: только пистолет/ПП, дистанция > 5 м, шанс из сложности, нужно суметь спрятаться.
- [ ] Убийца ползёт по клеткам, где шанс быть услышанным < 15 %, и только «со своей стороны» от жертвы.
- [ ] Убийца: дальше 10 м — фланговый обход ползком, ближе — прямой подход; ближе 5 м — сдаётся в обычный режим для атаки.
- [ ] Раскрытый убийца сразу сдаётся.
- [ ] Гражданский при подозрении только оборачивается: его AP сжигаются до стоимости поворота.
- [ ] Гражданский с укрытиями бежит на ближайшую клетку, которую не видит ни один известный враг (бюджет не меньше 28 AP).
- [ ] Бегство — в конус 40 % от направления «от взвешенной толпы» (вес 16.67/(d+1.67), учёт до 15 м).
- [ ] Выключение `CHEAT_NOAI` всегда ставит Обычную реакцию, даже если раньше была другая.
- [ ] Скриптовая логика: хук раз в окно, 5 сегментов ожидания, затем сдача хода.
- [ ] Пуля: коридор 2.5 м, без проверки «впереди стрелка».
- [ ] Граната: расстояние меряется до метателя, а не до взрыва (30 м).
- [ ] Сосед в 5 м от увидевшего врага узнаёт о нём.
- [ ] Вижу, как свой стреляет по моему врагу, — враг становится подозреваемым.
- [ ] Свой шум тревожит только при базовом радиусе звука > 30.
- [ ] Громкий звук слышен детерминированно; тихий — вероятностно, потолок 95 %.
- [ ] Глушитель может перевести выстрел в «тихие» (R < 10) — тогда включаются Stealth и вероятность.
- [ ] Слышимого и видимого слышу без броска; глухой каждый раз забывает всех слышимых.
- [ ] Услышанный тихий звук прокачивает Spot.
- [ ] Потерянный из виду враг автоматически «слышим».
- [ ] Слышимый спрятавшийся в прямой видимости раскрывается всегда.
- [ ] За молчащим спрятавшимся, уже «замеченным», повторный бросок не делается.
- [ ] Спрятаться нельзя, пока видит хоть один враг; после раскрытия — пауза до следующего такта.
- [ ] Шаг «Спрятаться» в сценариях срабатывает, только если человек-игрок №0 — враг юниту.
- [ ] Труп = мёртвый или без сознания не-враг; подозреваемым становится убийца.
- [ ] Поиск трупов — в радиусе двойной дальности зрения.
- [ ] Обход: добежать до первой двери/лестницы, дальше пригнувшись.
- [ ] Обход: фланговая точка — от «трети пути», со стороны точки атаки.
- [ ] Обход: передышка на последней невидимой для врага точке, Ждать(1) = до нового хода.
- [ ] Обход: если врага не слышно и сложность позволяет — не ходить ближе 4 м от лежащих союзников.
- [ ] Обход: ближе 8 м — без манёвра, прямо на место.
- [ ] После любой проверки — пауза 2–3, 4–6 случайных взглядов, поза «шагом», затем Ждать(6).
- [ ] Случайный взгляд берёт направления 0..6 — направление 7 не выпадает никогда.
- [ ] «Ждать(N)» в пошаговом режиме = «до смены хода», N игнорируется.
- [ ] Строй группы считается один раз при назначении маршрута.
- [ ] Барьер: группа собирается на каждой точке; мёртвые и потерявшие сознание вычёркиваются.
- [ ] Маршрут из одной точки не зацикливается, даже если просили.
- [ ] Стрейф включается перед движением, только если юнит не бежит и не в ПК.
- [ ] ПК: позы выше «пригнувшись» заменяются на «шагом»; проверяется «стоя» вместо «пригнувшись».
- [ ] Волна достижимости игнорирует временные блокировки клеток юнитами.
- [ ] Путевая точка прилипает к ближайшей изначально проходимой клетке (в т. ч. под закрытой дверью).
- [ ] Телепорт идёт через команды «отмена → телепорт → продолжить» и ставит маршрут из одной точки.
- [ ] Караульный с карты получает «ожидание 3000» в маршруте, но маршрут снимается первым же обновлением реакции.

## 15. Пример

### Пример 1. Часовой слышит выстрел за 15 тайлов
Условия: часовой (в БД `Sentry`, Обычная реакция, без маршрута), Spot = 50, вооружён ПП; герой игрока в 15 тайлах (9.4 м), не виден, стреляет из пистолета без глушителя в другого юнита. Сложность Normal.

1. Выстрел порождает шум «Pistol Shot», `R = 40`.
2. Для часового `D = 9.375 × 1.6 = 15` тайлов. `D > 10` — герой вычёркивается из слышимых (его там и не было).
3. «Слышу ли»: не в слышимых, не в видимых → бросок. Звук громкий (40 ≥ 10): `H = 7 + (40 − 7) × 50/140 = 18.8` тайла ≥ 15 → вероятность 100 → услышал (бросок 0..98 всегда меньше 100).
4. Часовой запоминает метку звука, герой попадает в слышимые; герой — враг → событие «услышал врага» → «Возможный враг» → герой в списке подозреваемых, список помечен изменённым.
5. Ближайший тик ИИ (не позже чем через 3 сегмента; в TBS — в ход ИИ): пересчёт → ближайший подозреваемый = герой → флаг «память изменилась».
6. Постановка в очередь: команды часового отменены, реакция в очереди; на этом же или следующем тике — `Update`.
7. Лестница: не испуган (врага нет). Подозреваемый есть, врага нет → проверять. Оборона — нет (нужен текущий враг). Убийца: ПП подходит, дистанция 9.4 > 5, бросок 10 %; допустим, не выпал.
8. Сценарий «проверить врага» к текущей позиции героя, бегом: бросок «спрятаться» 30 %; герой в слышимых → обход лежащих своих выключен; `dist = 9.4 ≥ 8` → планируется обход: точка атаки — случайная клетка в 15 AP от героя, откуда его место видно пригнувшись; «треть пути»; фланг; остановка у первой двери.
9. Часовой бежит до двери, пригнувшись идёт на фланг, встаёт на невидимой точке передышки, (в TBS ждёт следующего хода), выходит на точку атаки, смотрит на место героя.
10. Если по дороге герой попал в поле зрения → событие «Враг» → реакция: Оборона (у часового ПП; если рядом есть годное укрытие) либо логика атаки. Если не увидел — пауза 2–3, 4–6 взглядов, Ждать(6); сценарий завершается → реакция снова видит подозреваемого → новый обход к новому месту героя.

Вариант с глушителем (коэффициент, например, 0.2): `R = 8 < 10` → звук тихий. `P = 50 + (50 + (7 − 15) × 10 − Stealth) × 100/140`; при Stealth героя 40 это 50 + (−70) × 0.714 = 0 → не услышан. Но если пуля пролетит ближе 2.5 м от часового — он всё равно получит стрелка в подозреваемые.

### Пример 2. Раненый бандит поднимает тревогу
Условия: Обычная реакция, VP 40 % от максимума, видит одного врага; ближайший свой — в 14 м за углом; ещё двое своих стоят рядом с тем.

1. Пересчёт памяти: враг есть, VP < 50 %, в 9 м никого из своих → `bScared = да`, флаг поднят.
2. `Update`: испуган и есть враг. ИИ-не-врагов на карте 4 > 1; бросок `rnd(100) < 40` — выпало 23 → тревога.
3. Ближайший свой — в 14 м; в сфере 2 м вокруг него выбирается случайная клетка; путь бегом есть.
4. Сценарий: поза «бегом» → Goto → повернуться → Ждать(1) → Тревога. Бандит вычёркивает врага из памяти (иначе тут же вернулся бы в бой).
5. Бандит добегает. В TBS «Ждать(1)» держит его до следующего хода.
6. Шаг «Тревога»: враг ещё жив → трое своих в пределах 5 м (и сам бандит) получают «Возможного врага». Бандит получает «Помощь позвана»: испуг снят навсегда.
7. Следующий тик: у всех четверых подозреваемый → Обычные реакции строят обходы к текущему месту врага (каждый со своими случайными точками атаки и фланга — получается охват с разных сторон).

Если бы бросок не выпал: поиск точки бегства (≥ 5 м от врагов, 30 AP бегом) → реакция Отступления → по приходе Караульный с радиусом 8.

### Пример 3. Оборона из укрытия
Условия: бандит с пистолетом, 40 AP, видит врага в 12 м; рядом угол стены.

1. `Update` Обычной: не испуган. Проверка Обороны: волна 18 AP пригнувшись; клетка за углом врагу не видна; путь к ней 9 AP; предпоследняя клетка пути (у самого угла) видит врага → пара (укрытие, огневая), переход между ними 3 AP = `цена`. Оружие — пистолет; клетки свободны; из укрытия враг не виден → годна.
2. Реакция заменена Обороной (Обычная сохранена как «предыдущая»). Следующий тик — `Update` Обороны: запрещены прицельный режим и длинная очередь. Юнит «в пути»: `40 > 2 × 3` → стрейф к огневой клетке (6 AP), остаётся 34.
3. Сценарий закончен → `Update`: «на огневой», `34 > 3`, отличается от прошлого → боевая логика обороны: стреляет, оставляя 3 AP.
4. Логика закончена (AP ≈ 3–5) → `Update`: «на огневой», AP не больше цены либо равно прошлому значению → нырок: стрейф в укрытие, плановый AP = max(0, AP − 3).
5. Новый ход, 40 AP → событие «начало хода» → `Update`: «в укрытии» → стрейф к огневой → стрельба → нырок.
6. Враг сместился, укрытие стало простреливаться → пара не годна → режимы огня разрешены, возвращена Обычная реакция; на следующем тике она либо найдёт новую пару, либо перейдёт к атаке.

### Пример 4. Патруль группы из трёх по четырём точкам (`GroupSetRoute(g, r, TRUE)`)
1. Создаётся 4 барьера. Для каждого юнита строится список: для точки k — `Goto(место юнита в строю у точки k)`, команды точки (например, POSE пригнувшись, WAIT 5), `Синхронизация(барьер k)`.
2. Все трое идут к точке 1. Первый пришедший выполняет команды точки и встаёт на барьер («ход окончен»). Когда проголосовал третий — барьер открывается всем, группа идёт к точке 2.
3. Один юнит слышит врага → его реакция ставит обход → маршрут на паузе, откат к `Goto` текущей точки. Двое других дойдут до барьера и будут ждать.
4. Юнит вернулся (логика кончилась, врага нет) → маршрут возобновлён, он заново идёт к той же точке, голосует — группа двигается дальше.
5. Если бы он погиб — вычеркнут из всех барьеров (см. оговорку в «Не установлено»).

## 16. Отклонения реконструкции от оригинала

Перечислено то, что автор реконструкции пометил как исправления или упрощения; при переносе «как в оригинале» это нужно учитывать.

| Где | Что сделано в реконструкции | Оригинал |
|---|---|---|
| Обновление реакции из очереди | Перед `Update` перепроверяется, что юнитом всё ещё можно управлять (жив, под ИИ). | Проверки не было: реакция мёртвого/оглушённого могла выполниться. |
| Вероятность раскрытия, перк «ночная маскировка» | Перк усиливает Stealth прячущегося и только ночью. | Помечено как «исправленная ошибка оригинала»: в оригинале перк работал иначе (на стороне наблюдателя и в любое время суток — по описанию в комментарии). |
| Логика маршрута, юнит за пулемётом | Перед командами движения/поворота/позы/стрейфа/пряток вставляется «выйти из орудия». | В оригинале сценарий мог быть поставлен юниту за орудием, и его команды отвергались («ошибка оригинального ИИ»). |
| Командир: «стационарный простой» | Юнит в переходной позе, чей зацикленный маршрут состоит только из ожиданий/поворотов/смен позы/блуждания с радиусом 0, пропускается при обходе и не держит ход. | Вероятно добавка реконструкции (в комментариях нет ссылки на оригинал) — не подтверждено. |
| `CreateRoute` | Не-строковый аргумент превращается в пустое имя. | В оригинале — падение. |
| Караульный, возврат на пост | Условие «не на клетке поста». | В оригинале — «клетка поста сейчас не свободно проходима для юнита». |
| Обход, лежащие союзники | Берётся центр тела. | В оригинале — первая контрольная точка тела (разница меньше метра). |
| Журнал: бросок гранаты / ножа | Добавлен RollBack (возврат предмета). | В оригинале отката у этих записей нет. |
| Журнал: «копить снайперские AP» | Команда «копить всё». | В оригинале — точное количество AP. |
| Журнал: смена оружия | Дополнительная проверка, что у нового предмета есть запись в БД. | В оригинале — только проверка существования предмета. |
| Убийца | Защитный возврат в Обычную, если у юнита пропал игровой объект. | В оригинале проверки нет. |
| «Проверить позицию», случайная поправка направления | Записана как `rnd(3) − 1`. | Эквивалентно оригиналу (−1/0/+1). |
| Трекер событий | Отдельный объект, принадлежащий юниту. | В оригинале — базовая часть самого ИИ-юнита; поведение то же. |
| Старый стек «контролей» (менеджер AI/SCRIPT, прерываемый/непрерываемый) и обход задач `CTask` | Сохранены рядом как наследие ранней версии кода. | В релизе их роль выполняют слоты маршрутов; в предшественнике у маршрута была случайная задержка старта 1–20 с и «оглядывание» 3–5 взглядов с ожиданием 1–5 с и направлениями 0..7 — в релизе этого нет. |
| Выбор пары клеток в Обороне | Чтение конца пути без проверки на пустой путь — намеренно сохранённая ошибка оригинала (на практике не срабатывает). | Так же. |

## 17. Не установлено

1. Какой именно звук использует Убийца для оценки слышимости: комментарий говорит «бег», данные БД для ID 3 — «ползок». Способ индексации записей (по ID или по порядку) в загрузчике не проверялся.
2. Поле `FearUseToHit` у юнитов на карте (287 нулей, 13 единиц): загружается в описание юнита, но в разобранных файлах нигде не читается.
3. Возможная блокировка барьера группы: если погибший был последним непроголосовавшим, оставшиеся уже проголосовали, а условие «все проголосовали» перепроверяется только при новом голосе. По коду выглядит как зависание группы на точке до вмешательства скрипта; в игре не подтверждено.
4. Точная функция «построить группу вокруг точки» (как распределяются места строя) — в части поиска пути; поле `Formation` групп в БД пусто.
5. Где хранятся команды путевых точек (POSE/WAIT/DIR) — в данных карты, не в SQLite; единицы времени WAIT в данных карты (секунды по коду шага) не сверялись с реальными картами.
6. Реакция ИИ на мины при выборе пути и открывание/обход дверей при движении — вне среза.
7. Бросает ли событие «юнит раскрыт» раскрытие шумом (значение умолчания соответствующего параметра не проверялось); раскрытие взглядом — бросает.
8. Что именно делает юнит-караульный с параметром «ждать 3000» — секунды это или миллисекунды в замысле дизайнера; по коду шага это 3000 секунд, но маршрут всё равно снимается реакцией.
9. Коэффициенты перков 0x14 (восприятие) и 0x4c (сенсоры ПК) и значение «дальности сенсоров» костюмов — данные RPG-части.
10. Внутреннее устройство боевых логик (атака, оборона с резервом AP, караульная, отступления, «после боя») и их условия завершения — в спецификациях по тактике; здесь использован только интерфейс.
11. Частота вызова выдачи команд командиром относительно сегмента мира (кто и когда вызывает) — вне среза; установлено только, что решение принимается на тике со сброшенным счётчиком задержки.
