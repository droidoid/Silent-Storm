# Мир 2 — Здания и разрушение

Спецификация разрушаемых зданий Silent Storm (2003): модель данных здания, конструктивные части и их варианты, карта стен и твёрдых тел, решётка прочности, входы урона, структурная схема (стыки и стержни), алгоритм обрушения, пересборка меша из кусков, последствия разрушения, создание здания и заранее разрушенные руины, отладочный просмотр.

## Суть

Здание в Silent Storm — не модель, а набор «конструктивных частей» (кусков стен по 1,25 м, плит перекрытий, лестниц, крыш), расставленных автором в редакторе по сетке. Каждая часть разбита на маленькие куски (до 22 на блок 1,25 × 1,25 м × 1 этаж). Центры кусков — узлы общей трёхмерной «решётки прочности» с шагом 0,625 м по всем трём осям; в каждом узле хранится один байт — очки прочности куска (HP). Пуля или взрыв отнимают HP у узла; узел с HP = 0 считается разрушенным, его кусок исчезает из модели, ИИ-карты и коллизий.

После разрушения узла запускается «статика»: из уцелевших кусков строится структурная схема — граф «стыков» (узлов решётки) и «стержней» (рёбер длиной в один шаг решётки). Трёхпроходный алгоритм определяет: какие стыки опираются на землю напрямую или через «распор» между противоположными опорами (проход 1); какие куски висят в воздухе, не связаны с опорой вообще (проход 2 — они рушатся тихо, без эффектов); какой вес давит на каждую опору и какие изгибающие моменты возникают в её горизонтальных связях (проход 3 — вес «стекает» к опорам случайными блужданиями с фиксированным зерном случайности). Стык, на который давит больше предельного давления материала, ломается; связь, в которой момент больше предельного момента материала, ломается вместе с соседним куском. После каждой поломки схема пересчитывается — по одной итерации за тик мира, пока здание не успокоится; тогда схема выбрасывается.

Видимая модель здания пересобирается только для «частей» (этаж × квадрат 2 × 2 тайла), где что-то изменилось: из заранее нарезанных по кускам мешей берутся уцелевшие куски, стыки стен подрезаются плоскостями (Т-образные, Г-образные, на 45°, по толщине), внутренние грани между соседними кусками удаляются, копланарные полигоны упрощаются; результат кешируется по ключу «геометрия + маска видимых кусков + код подрезки». ИИ-карта получает два представления каждого блока: «слитое» (для видимости и укрытий) и «раздробленное» по кускам (чтобы попадание пули знало номер узла).

## Термины и единицы

| Термин | Значение |
|---|---|
| Тайл (игровой тайл) | 0,625 м (`FP_GRID_STEP`). Координаты x, y фрагментов здания и узлов решётки — в тайлах. |
| Строительный тайл, блок, субблок | 2 × 2 игровых тайла = 1,25 × 1,25 м в плане, высота — 1 этаж. Размеры конструктивных частей (`SizeX`, `SizeY`) заданы в блоках. |
| Этаж | 2,5 м (`WALL_HEIGHT`). Делится на 4 «плоскости» решётки по 0,625 м (`PLANE_DIST = WALL_HEIGHT/4`). Координата z фрагмента — в этажах, допускается половина (промежуточный этаж: дробная часть 0,5). |
| Узел решётки (воксел) | Точка решётки прочности с целыми координатами (x, y — тайлы, z — плоскости, z = 4·этаж + плоскость). Хранит 1 байт. |
| Кусок (piece) | Фрагмент ИИ-геометрии конструктивной части с собственным номером, объёмом и списком «стыков». Центр куска — узел решётки. |
| Хеш куска (piece hash) | 7 младших бит номера куска: x (биты 0–1), y (биты 2–3), z (биты 4–6); значения 1..3 / 1..5 (координаты внутри блока +1). 0 = «целый блок». |
| Хеш субблока (part hash) | Биты 7–9 — x, 10–12 — y, 13–15 — z номера субблока внутри многоблочной части (тоже с +1). Пример: 9344 = субблок (1,1,1), целый; 9366 = субблок (1,1,1), кусок (2,1,1). |
| Пулевой хеш узла | `GetPieceHash`: ((z+16+4) << 16) \| ((y+4) << 8) \| (x+4) — номер, который ИИ-карта возвращает при попадании в раздробленный кусок. |
| Часть здания (SPart) | Единица перерисовки: (этаж, x/2, y/2) — один этаж над квадратом 2 × 2 тайла. Упакована в 32 бита: этаж 6 бит со знаком, x и y по 13 бит со знаком. |
| Фрагмент (SBuildFragment) | Запись чертежа здания: ссылка на шаблон конструктивной части, позиция, поворот, слой, материалы, пятна. Стена — по одному фрагменту на каждый субблок; сплошной объект — один фрагмент на всю часть. |
| Слой (layer, fragment ID) | `тип << 16 \| номер`. Типы (`ELayer`): 0 перекрытия, 1 промежуточные перекрытия, 2 сплошные объекты, 3 промежуточные сплошные, 4 комнаты, 5 прямоугольники, 6 стены (`LID_WALLS`), …, 13 подвал (`LID_CELLAR`). |
| Стык (junction) | Вершина структурной схемы; находится в узле решётки. «Заполненный» стык — центр куска; «незаполненный» — точка соединения кусков (узел, где куска нет). |
| Стержень (rod) | Ребро схемы длиной ровно 1 шаг решётки вдоль одной оси. Левый конец — нижний (для вертикальных), затем меньший y, затем меньший x. |
| HP узла | 0 — пусто/разрушено; 1..253 — прочность; 254 — `N_CELLAR` (подвал/низ колонны, неуязвим); 255 — `N_INDESTRUCTIBLE` (неразрушим). |
| Float2Int | Округление к ближайшему (режим FPU по умолчанию, половинки к чётному). |
| SRand | ЛКГ Microsoft: зерно = зерно·214013 + 2531011; `Get(n)` = ((зерно >> 16) & 0x7FFF)·n / 0x8000; `GetFloat(a,b)` = a + Get(0xFFFF)·(b−a)/0xFFFF. |
| Рулетка | Выбор варианта из шаблона по весам: накопленные суммы, `GetFloat(0, сумма)`, двоичный поиск сектора; при нулевой сумме — вариант 0. |

## 1. Модель данных здания

### Назначение
Чертёж здания (`CBuildInfo`) — неизменяемое описание того, что поставил автор. Один чертёж на вариант шаблона карты (`TemplVariants.ID`); он лежит в ресурсном пакете `Buildings` под ключом = ID варианта. Все игровые структуры (карта стен, решётка прочности, модель, схема) строятся из чертежа + зерна случайности конкретного экземпляра здания.

### Данные
`CBuildInfo` (теги сериализации в скобках):
- `wallFragments` (2), `solidFragments` (3) — списки фрагментов стен и «сплошных» объектов (перекрытия, лестницы, крыши, колонны, камины);
- `roomMap` (4) — по одному двумерному массиву байт на этаж (номер комнаты на тайл, 0 = вне комнат), размер (nMaxX+2) × (nMaxY+2) — с полосой в 1 тайл по краю;
- `spots` (5) — проецируемые пятна (декали) автора;
- `nMaxY` (6), `nMaxX` (7) — размер в игровых тайлах; `nMinFloor` (8), `nMaxFloor` (9) — диапазон этажей;
- `ladders` (10) — лестницы-стремянки;
- `cellar` (11) — двумерная маска «здесь дыра в рельефе под подвал» (true = дыра);
- `lgroups` (12) — группы слоёв;
- `nMaxSpotID` (13), `nMaxLadderID` (14), `nMaxFragmentID` (15) — счётчики следующего свободного ID.

Фрагмент `SBuildFragment`:

| Поле | Смысл |
|---|---|
| `nConstructionPartID` | ID шаблона конструктивной части (`ConstructionPartTemplates.ID`); конкретный вариант выбирается рулеткой при каждом построении. |
| `nSubBlockID` | хеш субблока (для стены — какой из субблоков многоблочной части; для сплошного — 0 или (1,1,1)). |
| `ptPos` | x, y — в игровых тайлах (угол субблока, то есть узел решётки); z — в этажах, промежуточный этаж = целое + 0,5. |
| `nRotationID` | 0/1/2/3 = 0°/90°/180°/270°. |
| `nFragmentID` | слой: `тип << 16 \| номер слоя`. |
| `nObjectFlags` | флаги встроенного объекта; бит `OF_OPEN` = 1 — дверь/окно стоит открытой. |
| `materials[8]` | «сырые» смешанные материалы на 8 слотов (4 для первой геометрии, 4 для второй): список слоёв {проекция NORMAL/PROJECTION_X/Y/Z, ID шаблона материала (`MaterialTemplates`), масштаб, сдвиг, поворот}. |
| `spots` | ID пятен, наложенных на фрагмент. |
| `nID` | номер фрагмента. |

Пятно `SProjectedSpot`: начало, нормаль, размер, поворот, ID шаблона материала, ID, маска материалов (бит n установлен — на геометрию с материалом n пятно не накладывается).

Стремянка `SLadder`: ID; позиция (x, y в тайлах, z — начальный этаж; поворот); высота в этажах; высоты начальной и конечной точек; сторона, с которой можно лезть (вперёд/назад/влево/вправо). Обработка стремянок — «Карта 1» и «ИИ 1».

Группа слоёв `SLayerGroup`: список слоёв и список этажей. Используется для объединения слоёв и этажей при определении приоритетов сплошных блоков (раздел 3).

### Алгоритм загрузки
1. Читается ресурс; при исключении — пустой чертёж и отладочное сообщение.
2. Если `roomMap` пуст — создаётся (nMaxFloor − nMinFloor + 1) нулевых слоёв размером (nMaxX+2) × (nMaxY+2).
3. Счётчики ID: следующий ID = текущее значение, если оно в (0; 100000], иначе 1 (защита для «старых шаблонов»); после выдачи счётчик = выданный + 1.

### Смешанный материал фрагмента
Для каждого слота: перебрать слои; слой с ID шаблона ≤ 0, несуществующим шаблоном или невалидным выбранным материалом пропускается; материал выбирается рулеткой шаблона материалов. Если не осталось ни одного слоя — подставляется один слой «NORMAL, масштаб 1, сдвиг 0, поворот 0» с материалом по умолчанию из конструктивной части для этого слота, а если его нет — материал с ID 7 (`N_DEF_MATERIAL_ID`).

### Поворот на 90°
Все повороты внутри здания дискретны (`SDiscretePos`): поворот применяется к x, y точки, z не меняется, затем прибавляется сдвиг.

| Поворот | (x, y) → |
|---|---|
| 0 | (x, y) |
| 1 (90°) | (−y, x) |
| 2 (180°) | (−x, −y) |
| 3 (270°) | (y, −x) |
| 4 (FLIP) | (x, y) — поворот не выполняется |

Смена знака делается инверсией знакового бита (может давать −0,0 — безвредно). Обратное преобразование: вычесть сдвиг и повернуть на обратный угол (90 ↔ 270).

### Особые случаи и прихваты
- Стены хранятся по одному фрагменту на субблок, сплошные — по одному на всю часть; поэтому многоблочная дверь — это несколько фрагментов с разными `nSubBlockID`.
- Чертёж разделяется всеми экземплярами здания (кеш ресурсов); при создании здания карта ПЕРЕЗАПИСЫВАЕТ в нём `nMinFloor`/`nMaxFloor` (раздел 5) — изменение общего ресурса.

### Что нужно от движка-носителя
Формат хранения чертежа (ассет), детерминированный ГСЧ `SRand` и рулетка вариантов, независимые от платформы.

## 2. Конструктивные части и их данные в БД

### Назначение
Конструктивная часть — элемент «конструктора» зданий: кусок стены, плита перекрытия, лестница, крыша. В базе хранится шаблон (`ConstructionPartTemplates`) и его варианты (`ConstructionParts`, поле `TemplateID`); вариант выбирается рулеткой по `RndWeight` с зерном экземпляра здания — поэтому одинаковые чертежи дают визуально разные здания (разная кладка, сколы, окна).

### Основные субблоки (приоритет)
Бит (y·5 + x) маски установлен ⇒ субблок (x, y) НЕ основной (`N_SUBPARTS` = 5 — ширина строки маски). Приоритет субблока (x, y) части:
- `SP_PRIMARY` = 2 — если он основной;
- `SP_SECONDARY` = 1 — если основной хотя бы один из 4 соседей внутри части (x±1 в пределах [0; SizeX−1], y±1 в пределах [0; SizeY−1]);
- `SP_LOW` = 0 — иначе.

В базе: 0 (843 варианта — все субблоки основные), 7335 (39 вариантов 3×3, основной только центр (1,1); края — вторичные, углы — низкие), 15663 (3 варианта 4×3 — основные (1,1) и (2,1)). Это крыши/плиты, которые должны перекрывать соседние элементы своим центром.

### Куски ИИ-геометрии
У каждой ИИ-геометрии (ресурс `AIGeometries`, см. «ИИ 3») есть словарь кусков «номер → {вершины, треугольники, объём, стыки}». Для строительных частей номер куска = хеш субблока | хеш куска. Кусок с хешем 0 — целый субблок (используется, пока субблок не тронут); кусок с номером 0 — вся часть.

Внутри субблока узлы решётки имеют локальные координаты x, y ∈ {0,1,2}, z ∈ {0..4}; куском может быть только узел с нечётной суммой x + y + z: при чётном z — середины рёбер (1,0), (0,1), (2,1), (1,2); при нечётном z — углы и центр (0,0), (2,0), (1,1), (0,2), (2,2). Итого 4 + 5 + 4 + 5 + 4 = **22 позиции**. Узлы с чётной суммой — «точки соединения» (на них лежат незаполненные стыки).

Стык куска — точка в локальных координатах субблока и флаг «земля». Пример реальных данных — тонкая стена «w01AI» (геометрия 238), 7 кусков в плоскости y = 0:

## 3. Карта стен и твёрдых тел

### Назначение
`CSolidAndWallMap` — производная от чертежа и зерна структура «что где стоит»: (а) какие субблоки сплошных частей реально присутствуют (с учётом приоритетов, перекрытий и групп слоёв), (б) нижний этаж под каждым тайлом, (в) какие стены сходятся в каждом узле сетки (для подрезки стыков). Используется построением модели, HP, схемой. Сохраняется только ссылка на чертёж и зерно; содержимое пересчитывается лениво при первом обращении (и при изменении чертежа в редакторе).

### Данные
- `solidMap`: словарь «ID группы подрезки → карта узлов» (`CNodeMap<SSolidElement>` размером [этажи nMinFloor..nMaxFloor] × (nMaxX+2) × (nMaxY+2)); элемент = список `SFragmentPos` + приоритет.
- `SFragmentPos`: указатель на фрагмент, выбранный вариант части, `nSubPos` — начало субблока (тайлы, этажи), индекс фрагмента, хеш субблока (x+1, y+1, z+1).
- `bottom`: двумерный массив float (nMaxX+2) × (nMaxY+2), изначально 0, — минимальный z (этаж) сплошных блоков над тайлом.
- `wallGrid`: карта узлов `SGridNode` того же размера; в узле 4 списка стен по направлениям 0 — влево (−x), 1 — вверх (+y), 2 — вправо (+x), 3 — вниз (−y).
- `neighbs[i]` для каждого фрагмента стены i: выбранный вариант части, указатели на левый и правый узлы.
- Элемент стены в узле `SGridElement`: фрагмент, индекс фрагмента, длина 2 (тайла), толщина, высота (SizeZ), группа подрезки, сторона (LEFT — это начало части, RIGHT — конец).

### Алгоритм пересчёта
1. Очистить всё; `rand` = SRand(зерно экземпляра).
2. Хеш групп слоёв: для каждой группы с ≥ 2 слоями каждый её слой → первый слой группы. Хеш групп этажей (ключ — первый слой группы, для групп с ≥ 1 слоем): для i ≥ 1 этаж floor[i] → floor[0].
3. **Сплошные** — по порядку фрагментов i:
   1. Создать вариант части (рулетка `rand`); нет шаблона/варианта — пропустить.
   2. Сдвиг поворота (в тайлах): 90° → (2·SizeY, 0); 180° → (2·SizeX, 2·SizeY); 270° → (0, 2·SizeX); 0° → 0.
   3. Для каждого субблока (l по x, k по y, m по z): начало субблока pos = повернуть (2l, 2k, m) поворотом фрагмента + ptPos фрагмента + сдвиг поворота.
   4. Угол хранения spos: повернуть (1,1,0) без сдвига; если x результата < 0 — spos.x = pos.x − 1, иначе pos.x; так же для y. То есть spos — левый нижний тайл занятого квадрата 2 × 2.
   5. Группа подрезки = группа слоя фрагмента (из шага 2) или сам ID слоя; карта группы создаётся по образцу при первом обращении.
   6. Этаж хранения nZ = spos.z, но если у группы есть сцепка этажей и для spos.z задан общий этаж — берётся он. (Обращение к словарю этажей создаёт в нём пустые записи — побочный эффект.)
   7. Координата вне карты — пропуск (проверка по линейному индексу, см. прихваты).
   8. Приоритет pr субблока (l, k) (раздел 2). В ячейке (nZ, spos): если приоритет ячейки > pr — пропуск («здесь уже более важный блок»); если pr > приоритета ячейки — список ячейки очищается; приоритет ячейки = pr; фрагмент дописывается в список. Равные приоритеты копятся (рисуются оба).
   9. `bottom` под spos = min(bottom, spos.z) (если spos внутри по верхним границам).
   10. Три остальных тайла квадрата: повернуть (1,0), (1,1), (0,1) поворотом фрагмента, прибавить spos; вне карты — пропуск (с ASSERT); `bottom` = min; если приоритет той ячейки < pr — поднять его до pr и очистить её список (сам фрагмент туда НЕ дописывается).
4. Карта стен: размер как у сплошных; `neighbs` по числу стен.
5. **Стены** — по порядку фрагментов i: создать вариант (тот же `rand`, продолжение последовательности), запомнить в `neighbs[i]`; узел = wallGrid(этаж = z фрагмента, усечение; x; y). Нет такого узла — стена не регистрируется. Правый узел и индексы списков по повороту:

| Поворот | Правый узел | Список в левом узле | Список в правом узле |
|---|---|---|---|
| 0° | (x+2, y) | 2 (+x) | 0 (−x) |
| 90° | (x, y+2) | 1 (+y) | 3 (−y) |
| 180° | (x−2, y) | 0 (−x) | 2 (+x) |
| 270° | (x, y−2) | 3 (−y) | 1 (+y) |

   Элемент кладётся в левый узел, только если субблок фрагмента — первый по x (x хеша = 1, сторона LEFT), и в правый узел — только если последний (x = SizeX, сторона RIGHT). Внутренние стыки многоблочной стены не регистрируются. Указатели левого/правого узлов запоминаются всегда.

### Особые случаи и прихваты
- Проверка «внутри карты» считает линейный индекс (этаж·W·H + y·W + x) и сравнивает с размером массива: x за правым краем «заворачивает» на следующую строку, y за краем — на следующий этаж. Ошибочно принятые координаты не отсекаются.
- Нижняя граница `bottom` начинается с 0, поэтому у здания без подвала она 0 везде; отрицательна только под подвальными блоками.
- Приоритет «вытесняет» более слабые фрагменты не только в своей ячейке хранения, но и в трёх соседних тайлах своего квадрата: крыша-«центр» с основным субблоком срезает под собой углы соседних крыш.
- Правый узел стены берётся без проверки границ.

### Что нужно от движка-носителя
Ничего особенного: плотные 3D-массивы и хеш-таблицы; важно сохранить порядок обхода фрагментов (он задаёт последовательность ГСЧ).

## 4. Решётка прочности: узлы, 22 куска, маска, HP

### Назначение
`CBuildingGrid` — единственное сохраняемое состояние разрушения здания: байт HP на каждый узел решётки. Всё остальное (модель, ИИ-представление, схема) выводится из решётки + чертежа.

### Данные

| Поле (тег) | Смысл |
|---|---|
| `net` (2) | трёхмерный массив байт: по x — 2 + 2·nMaxX, по y — 2 + 2·nMaxY, по z — (nMaxFloor − nMinFloor + 1)·4 + 1 |
| `nDZ` (3) | сдвиг z: −nMinFloor·4; доступ `net[z + nDZ][y][x]` |
| `ptBoxMin` (4), `ptBoxMax` (5) | (0, 0, nMinFloor·2,5) и (nMaxX, nMaxY, (nMaxFloor+1)·2,5) |
| `rooms` (6) | соответствия (этаж, локальная комната) → глобальный номер (в релизе не заполняется) |
| `seed` (7) | зерно экземпляра; при создании = `GetTickCount()` |
| `bStabilityUpdate` (8) | считать ли статику (по умолчанию true; отладочный переключатель) |
| `nBaseFloor` (9) | абсолютный этаж, на котором стоит здание |
| `box` (10) | 6 плоскостей коробки (перед, зад, лево, право, верх, низ) |
| `nCutFloor` (11) | этаж среза (для редактора), при создании = nMaxFloor |
| `visibleLayers` (12), `bOnlyCutFloorVisible` (13) | видимость слоёв в редакторе |
| `updatedParts` (14) | «грязные» части здания (SPart), ждущие перестройки |
| `pSchema` | структурная схема (только пока здание «активно»; не сохраняется) |
| `brokenSpots` | узлы, разрушенные с эффектами с прошлого тика (не сохраняется) |

Координаты узла: x, y — игровые тайлы от начала здания (узел x лежит в x·0,625 м локальной системы здания), z = 4·этаж + плоскость, высота z·0,625 м. Узлы с z = 4·k — уровни перекрытий: верхний ряд стены этажа k−1 и плиты этажа k попадают в одни и те же узлы.

Значения узла: 0 — пусто/разрушено; 1..253 — HP; 254 — `N_CELLAR`; 255 — `N_INDESTRUCTIBLE`.

### 27-битная маска видимых кусков субблока (`dwParts`)
Бит куска с локальными координатами (x, y, z), x, y ∈ 0..2, z ∈ 0..4: если x + y + z чётно — бита нет (это не кусок); иначе бит = x + 3·y + 9·⌊z/2⌋. Уровни z = 0 и 1 делят группу битов 0–8, z = 2 и 3 — 9–17, z = 4 — 18–26 (биты 18, 20, 22, 24, 26 никогда не ставятся). Значение 0xFFFFFFFF — «субблок цел».

Распаковка маски в номера кусков: для каждой группы g = 0, 1, 2 (смещение 9g, z0 = 2g): биты 0..8 группы дают куски с хешами (1,1,z0+2), (2,1,z0+1), (3,1,z0+2), (1,2,z0+1), (2,2,z0+2), (3,2,z0+1), (1,3,z0+2), (2,3,z0+1), (3,3,z0+2) соответственно (с добавлением хеша субблока). Значение 0xFFFFFFFF распаковывается в один номер — хеш субблока (целый кусок).

«Раздробить» целый субблок (`SplitOptimized`): если список содержит ровно один номер и это хеш субблока без кусочных бит — заменить его на все 22 номера в порядке z = 1..5: при нечётном z (1, 3, 5) — (2,1), (1,2), (3,2), (2,3); при чётном (2, 4) — (1,1), (3,1), (2,2), (1,3), (3,3). Иначе список не меняется.

### Вычисление маски видимых кусков (`SetSolidVisibleParts`)
Вход: начало субблока (тайлы, z — этажи), поворот, решётка, флаг «всегда по кускам», ИИ-геометрия (может отсутствовать).
1. Если ИИ-геометрии нет — проверяются все 22 позиции (при чётном z — 4 середины рёбер, при нечётном — 4 угла и центр).
2. Иначе — перебираются куски геометрии; учитываются только куски этого субблока (хеш субблока совпадает) и не целые (хеш куска ≠ 0); позиция = (x−1, y−1, z−1).
3. Позиция → узел решётки: повернуть (x, y) поворотом фрагмента, прибавить (ptPos.x, ptPos.y), z узла = Float2Int(4·ptPos.z + z). Если узел не разрушен — бит ставится; флаг «все целы» = И по всем проверенным.
4. Если все целы и не просили «по кускам» — маска = 0xFFFFFFFF (рисовать целым мешем).

### HP узлов (`BuildingHP`)
1. Сброс решётки: если статика включена — все узлы 0; иначе все узлы (и пустые тоже) = 253, HP по материалам не считаются, и на этом всё (отладочный режим: здание без статики, все позиции «целы»).
2. Для каждого фрагмента каждой ячейки сплошной карты (все группы) — для первой и второй геометрии, если у них есть ИИ-геометрия, — начислить HP субблоку (начало = `nSubPos`, хеш = хеш субблока).
3. Для каждой стены — то же с `ptPos` и `nSubBlockID` фрагмента.
4. Начисление одному субблоку: список номеров = раздробить хеш субблока (22 номера); преобразование: поворот фрагмента, сдвиг (ptPos.x, ptPos.y, 4·ptPos.z). Для каждого номера:
   - куска нет в геометрии, но есть в дополнительных связях → узел (x−1, y−1, z−1) после преобразования получает +1 HP; иначе — ничего;
   - кусок есть: если `nDR` материала брони части > 0 — HP = 2 · `nVP` · объём куска (NaN → 10), к узлу прибавляется ⌈HP⌉; иначе узел объявляется неразрушимым (255).
5. Прибавление: узел = min(253, текущее + прибавка); прибавка — БАЙТ (см. прихваты); координаты вне решётки игнорируются.
6. Позже при первом построении схемы узлы всех «нижних» и «подвальных» стыков получают 254 (раздел 7).

### Формулы
- HP куска: `HP = ⌈2 · VP · V⌉`, V — объём куска (м³), VP — `RPGMaterials.VP`.
- Узел, общий для нескольких кусков (стык двух соседних стен, верх стены и плита над ней), получает сумму их HP, но не больше 253.

### Константы

| Имя | Значение | Смысл | Источник |
|---|---|---|---|
| `N_MAX_HP` | 253 | потолок HP | BuildingGrid.cpp |
| `N_CELLAR` | 254 | подвал/низ колонны — неуязвим | BuildingGrid.cpp |
| `N_INDESTRUCTIBLE` | 255 | неразрушим | BuildingGrid.cpp |
| `DESTROY_LIM` | 255 | урон «уничтожить наверняка» | BuildingGrid.h |
| `PLANE_DIST` | 0,625 м | шаг плоскостей по z | BuildingGrid.cpp |
| `MIN_NODE_DIST` | 0,625 м | шаг узлов по x, y | BuildingGrid.cpp |
| `ZSHIFT` | 16 | смещение z в пулевом хеше (+4 запаса) | BuildingGrid.h |
| множитель HP | 2 | HP = 2·VP·V | MakeBuilding.cpp |
| HP при NaN | 10 | | MakeBuilding.cpp |
| HP виртуального куска | 1 | | MakeBuilding.cpp |

### Особые случаи и прихваты
- Прибавка HP передаётся как байт: ⌈HP⌉ > 255 при компиляторе MSVC превращается в младший байт (263 → 7). Кусок толстой (0,3 м) кирпичной стены: 2·650·0,2015625 = 262,03 → 263 → **7 HP** вместо 253. Поведение вытекает из типа параметра; в бинарнике оригинала не проверено, но тип параметра оригинальный.
- Материалы с `DR` ≤ 0 (не только −1!) делают узел неразрушимым: Glass, Grass, Cloth, Human (DR = 0) так же, как Ground/Unbreakable/Item (DR = −1). В схеме «землёй» объявляются только материалы с DR < 0.
- Порядок важен: неразрушимый узел (255), которому ПОТОМ прибавят HP другого куска, становится обычным узлом с 253 HP (255 + x обрезается до 253). Если же неразрушимость пришла последней — узел остаётся 255.
- Размер решётки по x, y вдвое больше нужного (2 + 2·nMaxX узлов при ширине nMaxX тайлов); «коробка» `ptBoxMax` = nMaxX в МЕТРАХ, хотя здание шириной nMaxX·0,625 м — коробка в 1,6 раза шире здания (влияет только на отсечение взрывов).
- `GetSize` с ошибкой: третьей строкой снова пишет x вместо z (в игре не используется).
- `Point2Part`: этаж = (z−1)/4, для отрицательных (z−1)/4 − 1 с усечением деления к нулю — для z−1 = −4, −8… получается на этаж ниже правильного; x/2, y/2 тоже с усечением.
- Позиция может попасть в узел, где куска нет (пустой, HP 0) — он считается разрушенным.

### Что нужно от движка-носителя
Компактный 3D-массив байт на здание; событие «решётка изменилась» (номер версии), на которое подписаны модель, ИИ-представление и освещение.

## 5. Создание здания при сборке карты

### Назначение
Превратить вариант шаблона с чертежом здания в экземпляр: решётку прочности с HP, карту стен и твёрдых тел, встроенные объекты (двери, окна, камины), список этажей, положение, а затем применить авторские «взрывы», заранее делающие руины. Обход дерева шаблонов, слои ИИ, рельеф и стремянки — «Карта 1»; здесь — только то, что касается здания.

### Алгоритм `CreateBuilding` (для каждого узла дерева шаблонов, где у варианта есть чертёж)
1. Если чертежа нет, или нет ни одного фрагмента, или nMaxX = nMaxY = 0 — здание не создаётся.
2. Запомнить позицию шаблона (`mpos`) и точку выравнивания (центр здания).
3. Создать решётку (её зерно = `GetTickCount()` — экземпляры одного чертежа выглядят по-разному) и карту стен и твёрдых тел с тем же зерном.
4. `brnd` = SRand(зерно решётки). Временно nMinFloor = 100, nMaxFloor = −100.
5. Встроенные объекты (механизм для дверей, окон, каминов — в этой базе им пользуются только 7 вариантов: камины и трубы): сначала по всем сплошным фрагментам, потом по всем стенам:
   1. Вариант части — рулетка `brnd` С ФЛАГАМИ карты (может отличаться от варианта, выбранного картой стен — там флагов нет и последовательность ГСЧ другая).
   2. nMaxFloor = max(nMaxFloor, int(z + 0,5) + SizeZ) (усечение к нулю: для z = −1 даёт 0 + SizeZ); nMinFloor = min(nMinFloor, ⌊z⌋).
   3. Объект создаётся, только если у варианта есть встроенный объект, а для стен (SizeY = 0) — только у фрагмента первого субблока (хеш (1,1,1)).
   4. Позиция: локально (0,625·x, 0,625·y, 2,5·z) + 0,625·сдвиг поворота (только у сплошных: 90° → (2·SizeY, 0), 180° → (2·SizeX, 2·SizeY), 270° → (0, 2·SizeX); у стен и неповёрнутых — 0), повернуть на угол здания, прибавить позицию здания. Этаж = этаж здания + ⌊z⌋; угол = угол здания + угол фрагмента; масштаб 1; «открыт» = флаг `OF_OPEN`. Дальше это обычный объект мира (двери/окна/ловушки — «Мир 3»).
6. Если min/max не изменились — 0. Значения ЗАПИСЫВАЮТСЯ в общий чертёж.
7. Решётка: `Setup(nMaxX, nMaxY, nMinFloor, nMaxFloor, (0,0))` (повороты в расчёте размеров не учитываются — комментарий автора «CRAP»).
8. HP (раздел 4).
9. Далее (обход дерева): базовый этаж решётки = этаж шаблона; для каждого относительного этажа от nMinFloor до nMaxFloor ВКЛЮЧИТЕЛЬНО добавляется «этаж здания» (относительный, абсолютный). Так как nMaxFloor = верх + SizeZ, в список попадает и этаж над крышей.
10. Мёртвый код: `CreateGrids` перебирает сплошные фрагменты первого субблока, катит вариант со своим (временным) ГСЧ и ничего не делает.

### Положение
После обхода дерева и подгонки высот к рельефу: матрица здания = масштаб 1, перенос (позиция шаблона + высота рельефа в точке выравнивания), поворот на угол шаблона вокруг z. Локальная система здания — метры; узел решётки (x, y, z) лежит в точке (0,625·x, 0,625·y, 0,625·z).

### Авторские разрушения («руины на загрузке»)
Источники:
- записи таблицы `Explosions` (поля Power, PosX, PosY — тайлы, Floor, DeltaZ; радиус не хранится → 10);
- элементы шаблона (`FinalElements`), чей объект — RPG-предмет 189 «Explosion» (размещаемый объект 1221): поля Power, Radius, ObjStageDelta, ObjRadius.

Позиция: (0,625·PosX, 0,625·PosY, 2,5·Floor) повернуть на угол родителя + позиция родителя, z += DeltaZ, затем подгонка к рельефу («Карта 1»).

Применение (в конце сборки карты, после установки матриц зданий): для каждого взрыва, для КАЖДОГО здания карты — `Explode(матрица здания, эпицентр, (int)Power, Radius)` (раздел 6). Затем, если ObjStageDelta > 0 и ObjRadius > ε, всем объектам карты ближе ObjRadius/0,625 к эпицентру (сравнение квадратов расстояний в метрах) прибавляется ObjStageDelta к стадии разрушения.

Схемы в этот момент ещё нет — удаляются только узлы; обрушение висящих кусков случится при создании мира (раздел 11: до 99 итераций сразу, остаток — уже в игре).

### Данные из БД
- `Explosions` — 21 запись; мощности 3…2000 (чаще 1000), радиус всегда 10.
- Элементы «Explosion» — 1040 штук; Power: 5000 (421), 800 (260), 1000 (170), 500 (107), пусто (41), 100 (17), 200 (14), 10000 (3), 300, 250, 0 (по 2), 400 (1). Radius: 1 (458), 2 (329), 3 (91), 5 (43), пусто (39), 15 (24), 6 (16), 4 (10), 10 (7), 0 (7). ObjStageDelta/ObjRadius в основном 0/0 (918), встречаются 1–3 / 0,5–7.

### Особые случаи и прихваты
- Мощность взрыва-элемента — float, в решётку передаётся с усечением до int; пустое поле → 0 → взрыв ничего не делает (порог 50).
- Подгонка высоты: z взрыва += высота рельефа в «точке выравнивания». У элементов «Explosion» внутри шаблона здания эта точка — центр здания (та же поправка, что у самого здания); у записей таблицы `Explosions` точка выравнивания не инициализируется (в структуре нет значения по умолчанию) — поправка берётся по мусорным координатам (билинейная выборка карты высот; результат не определён).
- Таблицы старого формата зданий (`Walls` 919 записей, `WallModels` 101, `Floors` 70, `FloorModels` 23, `SolidObjects` 129, `SolidModels` 149, `IntermediateFloors` 6, `IntermediateSolids` 29, `Rooms` 6) импортируются, но кодом зданий не используются — здания строятся только из ресурса `Buildings` и `ConstructionParts`.
- Радиус в формуле решётки делится пополам (раздел 6): авторский «Radius 2» разрушает сферу радиусом 1 м.
- Радиус стадий объектов переводится в тайлы, но сравнивается с метрами: фактический радиус в 1,6 раза больше.
- Каждый взрыв применяется ко всем зданиям карты; отсечение — коробкой решётки (которая в 1,6 раза шире здания).
- Встроенный объект может быть взят из ДРУГОГО варианта, чем нарисованная часть (разные потоки ГСЧ и учёт флагов).
- Перезапись `nMinFloor/nMaxFloor` в общем чертеже: при повторном использовании того же варианта (вторая копия здания на карте) уже лежат пересчитанные значения — результат тот же, поэтому вреда нет, но размеры `roomMap` были посчитаны по старым.

## 6. Входы урона

### Назначение
Все способы уменьшить HP узла решётки. Здание не знает, «чем» его ударили: на вход приходит либо готовый структурный урон в конкретный узел, либо сфера взрыва.

### 6.1. Попадание в кусок (пули, осколки, нож, удар взрывной волны по кускам)
1. Трассировка пуль, осколков и воксельного взрыва идёт по ИИ-карте с флагом `TS_FRAGMENTED` и попадает в «раздробленные» корпуса здания: у каждого куска собственный пользовательский номер = пулевой хеш узла (раздел 14). Броня корпуса = броня конструктивной части.
2. Попадание пересылается часть здания → здание → RPG-объект здания: `ProcessAttack(мир, номер, порция атаки, направление, броня)`.
3. Координаты узла = разбор номера: x = (номер & 0xFF) − 4, y = ((номер >> 8) & 0xFF) − 4, z = ((номер >> 16) & 0xFF) − 16 − 4.
4. Урон = `CalcStructDmg(мир, броня, 0)` — структурный урон порции атаки против материала брони (формула — «Бой 1»: случайный урон в диапазоне порции, поправка на пробитие против `Threshold` материала, множители порции; множители сложности к зданиям не применяются — только к материалу «Human»).
5. `DamageSpot(узел, урон, с эффектами)`. Если узел разрушен — вернуть урон (здание запускает цикл обновления, раздел 11); иначе вернуть 0 и ничего не перестраивать (HP просто уменьшился).
6. Направление удара не используется; накопление урона (`nAccumulated`) не используется — каждый удар считается отдельно.

### 6.2. `DamageSpot` — единственная точка уменьшения HP
1. Узел вне решётки → «не разрушен».
2. Узел 0 (пусто), 255 или 254 → «не разрушен» (неуязвим, урон не применяется).
3. HP = max(0, HP − урон).
4. Если стало 0: пометить грязными 27 частей вокруг узла (смещения −1..+1 по всем осям, раздел 12); увеличить версию решётки (модель, ИИ, освещение перечитают её); если у решётки сейчас есть схема — отметить стык этого узла разрушенным (вместе со всеми его стержнями); если просили эффекты — добавить узел в список `brokenSpots`. Вернуть «разрушен».

### 6.3. Сферический взрыв по решётке (`Explode`)
Вход: матрица здания, эпицентр (мир), мощность P (int), радиус R.
1. Если P ≤ 50 (`MIN_ADDITIVE_DMG`) — ничего.
2. r² = (R/2)² — повреждаются только узлы в сфере ПОЛОВИННОГО радиуса.
3. Эпицентр переводится в локальную систему здания обратной матрицей.
4. Отсечение коробкой: если расстояние от центра до любой из 6 плоскостей коробки > R — выход. Иначе пересечение: ptMin = max(коробка.min, центр − R), ptMax = min(коробка.max, центр + R) по каждой оси.
5. Диапазон плоскостей: minPl = max(−nDZ, Float2Int((ptMin.z − box.min.z)/0,625 − nDZ)) (это просто округлённое z/0,625), maxPl — так же для ptMax.z. Диапазон узлов по x: minX = ⌊(ptMin.x − box.min.x)/0,625⌋ (усечение), maxX — так же; по y — так же.
6. z первой плоскости пересчитывается точно: z = minPl·0,625 (через этаж и остаток).
7. Перебор: плоскости от minPl до maxPl ВКЛЮЧИТЕЛЬНО (z += 0,625); y от minY до maxY НЕ включая (y начинается с ptMin.y, шаг 0,625); x от minX до maxX НЕ включая (x начинается с ptMin.x).
8. Для каждой точки: s = |центр − (x,y,z)|² (квадрат расстояния, м²); если s ≤ r² — `DamageSpot(узел, урон)` без эффектов, где урон = (int)(P · k), k = 1 при s < 1, иначе 1/s.

Формула урона: `урон = ⌊P · min(1, 1/d²)⌋`, d — расстояние до эпицентра в метрах (обратный квадрат, полный урон ближе 1 м), только для d ≤ R/2.

Источники вызова:
- авторские взрывы при сборке карты (раздел 5) — с авторским R;
- `CBuilding::Explode(эпицентр, P)` — R = √P; после него сразу перестраиваются грязные части и запускается цикл обновления. Вызывается из `CWorld::Explode`, который в этом коде используют только отладочная команда «explode» (мощность 100 в точке выбранного бойца) — и тот же мировой взрыв добавляет эффект 51, звук 63, волну по траве, будит обломки в сфере радиусом 15 м и проверяет устойчивость (сторож устойчивости — «ИИ 3»). Боевые гранаты повреждают здание через 6.1 (воксельный взрыв, «Мир 3»), а не через эту функцию.

### 6.4. Разрушение схемой
Схема ломает узлы через `DamageSpot(узел, 255, эффекты)` (раздел 10): 255 > 253, поэтому любой обычный узел гарантированно разрушается; неуязвимые (254/255) — нет.

### Константы

| Имя | Значение | Смысл | Источник |
|---|---|---|---|
| `MIN_ADDITIVE_DMG` | 50 | порог мощности взрыва по решётке (строго больше) | BuildingGrid.cpp |
| радиус в `Explode` | R/2 | реально повреждаемая сфера | BuildingGrid.cpp |
| ослабление | 1/d² при d² ≥ 1 м² | d² — квадрат расстояния | BuildingGrid.cpp |
| R для мирового взрыва | √P | | wBuilding.cpp |
| отладочный взрыв | P = 100 | команда «explode» | wUnitExec.cpp |
| эффект / звук мирового взрыва | 51 / 63 | | wMain.cpp |
| сфера пробуждения обломков | 15 м | | wMain.cpp |

### Особые случаи и прихваты
- В отборе по сфере x и y берутся не по положению узла, а от `ptMin` с шагом 0,625: проверяемая точка смещена относительно узла на дробную часть (до +0,625 м), а урон считается по этой смещённой точке. z — точный.
- Последний столбец и строка (maxX, maxY) не обрабатываются, последняя плоскость (maxPl) — обрабатывается.
- Ослабление — обратный квадрат расстояния без «мягкого» перехода: ближе 1 м — полная мощность. Для P = 1000 узел в 2 м получает ⌊1000/4⌋ = 250, в 3 м — 111, в 4 м — 62, в 5 м — 40 (при R = 10 сфера 5 м). Авторский взрыв P = 5000 с Radius 2 уничтожает всё в сфере 1 м (5000 > 253).
- Взрыв не трогает узлы 254/255 и пустые; урон без эффектов (пыль/звук не создаются).
- Попадание, не уничтожившее узел, не вызывает никакой перестройки и не запускает статику.

### Что нужно от движка-носителя
Трассировка, умеющая вернуть «номер куска» попадания (уникальный ID на узел решётки); обратная матрица здания.

## 7. Построение структурной схемы

### Назначение
Из УЦЕЛЕВШИХ на момент построения кусков собрать граф стыков и стержней с весами, пределами прочности, признаками «земля», «низ колонны», «стена подвала». Схема строится заново каждый раз, когда здание «просыпается» (раздел 11), и выбрасывается, когда оно успокоилось.

### Данные стыка (`CJunction`)

| Поле | Смысл |
|---|---|
| ID | индекс в массиве стыков |
| координаты | целые координаты узла решётки |
| соседи[6] | стержень и сторона по направлениям XP=0 (+x), XM=1 (−x), YP=2 (+y), YM=3 (−y), UP=4, DN=5 |
| устойчивость | STABLE, UNSTABLE, FREE, UNSTABLE_NOTFREE, UNKNOWN, UNINITIALIZED, UNKNOWN_MOMENT |
| вес | собственный вес (добавляется при создании стыка) |
| моменты[4] | по горизонтальным направлениям XP, XM, YP, YM |
| давление | сумма долей веса, опирающихся на этот стык |
| предельные давление и момент | максимум по всем частям, чьи стержни касаются стыка |
| флаги | биты 0–10 — «стрелы» по направлениям (раздел 8); 1<<16 ЗЕМЛЯ, 1<<17 СТЕНА ПОДВАЛА, 1<<18 БЛОКИРОВКА, 1<<19 ПРОВЕРЕН_НА_СВОБОДУ, 1<<20 ЗАПОЛНЕН, 1<<21 РАЗРУШЕН, 1<<22 ФРОНТ_ВОЛНЫ, 1<<23 НИЗ |
| родители | ID заполненных стыков, протянувших стержень к этому (у незаполненных) |
| волна | номер текущей волны, направление прихода, номер шага |
| опорные волны | список номеров волн, дошедших до стыка, и сумма их весов |

Постоянные флаги (переживают сброс): ЗЕМЛЯ, СТЕНА ПОДВАЛА, ЗАПОЛНЕН, НИЗ.

Стержень (`CRod`): два стыка (левый, правый), «вертикальный», счётчик блокировок (не больше 2 — «ёмкость» стержня для волн), «разрушен».

### Алгоритм `MakeBuildingSchema`
1. Резерв памяти: стыков — 15·(число стен) + 9·(число сплошных фрагментов), стержней — 22·стены + 12·сплошные.
2. Маска стен подвала (ниже).
3. Для каждой группы подрезки, каждой ячейки, каждого фрагмента сплошной карты: добавить куски первой геометрии и (если есть) второй геометрии, если у геометрии есть ИИ-геометрия.
4. Для каждой стены, у которой есть вариант и броня: так же для первой и второй геометрий.
5. Для каждого стыка с флагом НИЗ или СТЕНА ПОДВАЛА — узел решётки := 254 (неуязвим навсегда, сохраняется).

Добавление кусков субблока (сплошного или стены):
1. Маска видимых кусков по текущей решётке «всегда по кускам» (раздел 4) и отдельная маска видимых «виртуальных» кусков (записи дополнительных связей этого субблока, узел не разрушен).
2. «Земля» = z фрагмента ≤ 0 (нулевой этаж и ниже; промежуточный 0,5 — уже не земля).
3. Преобразование: поворот фрагмента, сдвиг (x, y, 4·z).
4. Для каждого видимого куска (кроме целого):
   - вес = объём куска · `Weight` материала брони части;
   - позиция = (x−1, y−1, z−1);
   - стыки: если для куска есть запись дополнительных связей — позиция + каждый вектор связи, флаг земли = «земля» И локальный z стыка = 0; иначе — стыки куска из файла, флаг земли = «земля» И флаг стыка;
   - стыки и позиция преобразуются;
   - «стена подвала» = маска стен подвала в (x, y) позиции, только если z ≤ 0;
   - `AddNode(броня, позиция, стена подвала, вес, стыки)`.
5. Для каждого видимого виртуального куска, который не добавлен как настоящий и принадлежит этому субблоку: стыки = позиция + векторы связей (земля — как выше), вес = 0,1·`Weight` (комментарий автора «CRAP — объём для виртуального куска»), `AddNode`.

`AddNode(броня, точка, стена подвала, вес, стыки)`:
1. вес := вес · 0,1.
2. Для каждого стыка: `AddRod(броня, {точка, заполнен, вес, стена подвала}, {стык, не заполнен, вес 0, без флага подвала}, флаг земли стыка)`.
3. Если стержень получен: тот конец, что не заполнен, получает родителя — заполненный конец.

`AddRod(броня, край L, край R, земля)`:
1. Упорядочить: если z(R) < z(L) — поменять; иначе если y(R) < y(L) — поменять; иначе если x(R) < x(L) — поменять (стержни осевые единичной длины, поэтому это корректный порядок «нижний/меньший — левый»).
2. Найти стыки по хешу координат (хеш: z<<24 | y<<16 | x).
3. Если оба стыка есть и у левого уже есть стержень в направлении к правому — стержень существует: поставить флаг ЗАПОЛНЕН концам, если край заполнен, а стык ещё нет; пределы прочности обоим концам; вернуть существующий стержень. Вес не добавляется.
4. Нет левого стыка — создать: флаги ЗЕМЛЯ = «земля», СТЕНА ПОДВАЛА (с ней и ЗЕМЛЯ) = флаг края, ЗАПОЛНЕН = флаг края; устойчивость = STABLE для земли, иначе UNKNOWN; проверка хеша земли; вес += вес края.
5. Нет правого — создать так же, но ЗЕМЛЯ = «земля» И z(L) = z(R) (у вертикального стержня земля — только нижний конец).
6. Обоим концам — пределы прочности по броне.
7. Новый стержень; левый стык получает соседа (стержень, сторона LEFT), правый — (стержень, RIGHT).

Хеш земли (в каждой колонке x, y только один «земляной» стык):
1. Стык не «земля» — ничего.
2. Если в колонке уже есть стык и он — стена подвала ИЛИ ниже нового: новый (если он сам не стена подвала) теряет «землю» (становится UNKNOWN); конец.
3. Иначе прежний теряет «землю» и «низ»; новый получает «низ» и записывается в колонку.

Добавление соседа к стыку:
- Вертикальный стержень, стык — нижний конец: направление UP; если верхний конец — «земля», нижний становится «землёй» (STABLE), а верхний теряет «землю», если он не стена подвала.
- Вертикальный, стык — верхний конец: направление DN; если стык — «земля», нижний конец становится «землёй», а сам стык теряет её (если не стена подвала).
- Горизонтальный — направление по разности координат.

Итог: «земля» стекает вниз по вертикальным цепочкам к самому нижнему стыку (флаг НИЗ при этом не переносится).

Пределы прочности (`SetDestroyLimits`):
- брони нет → давление 40, момент 140 (перезапись);
- если `DR` материала < 0 → поставить флаг ЗЕМЛЯ (устойчивость не меняется);
- давление = max(текущее, `UltimatePressure`), момент = max(текущее, `UltimateMoment`) (начальные значения 0).

Маска стен подвала (`MarkCellarWalls`), массив (Xc+2) × (Yc+2), где Xc × Yc — размер маски подвала чертежа; nX = min(Xc, X нижней границы), nY = min(Yc, Y нижней границы):
- края: walls[0][x] = cellar[0][x], walls[nY][x] = cellar[nY−1][x] (x < nX); walls[y][0] = cellar[y][0], walls[y][nX] = cellar[y][nX−1] (y < nY);
- внутри (1 ≤ x < nX, 1 ≤ y < nY): узел — стена подвала, если подвальность тайла (x,y) отличается от любого из тайлов (x−1,y), (x,y−1), (x−1,y−1), ИЛИ если «нижний этаж» `bottom` в (x,y) отличается от любого из этих же трёх соседей.

То есть стены подвала — узлы на границе ямы под зданием и на перепадах нижнего уровня; такие стыки — вечные опоры.

### Формулы
- вес заполненного стыка = 0,1 · V · ρ (V — объём куска, ρ — `RPGMaterials.Weight`); виртуального — 0,1 · 0,1 · ρ.
- предел давления/момента стыка = max по частям, касающимся стыка.

### Константы

| Имя | Значение | Смысл | Источник |
|---|---|---|---|
| множитель веса | 0,1 | в `AddNode` | BuildingSchema.cpp |
| вес виртуального куска | 0,1·ρ (до множителя) | | MakeBuilding.cpp |
| пределы без брони | 40 / 140 | давление / момент | RodJunction.cpp |
| резерв | 15/9 стыков, 22/12 стержней | на стену / сплошной фрагмент | MakeBuilding.cpp |
| хеш стыков | z<<24 \| y<<16 \| x | ключ поиска | BuildingSchema.h |
| `NLOCKS` | 2 | сколько раз волна может пройти стержень | rod.h |

### Особые случаи и прихваты
- **Правило низа колонны**: при КАЖДОМ построении схемы узлы всех стыков «низ» и «стена подвала» становятся 254. Так как первая схема строится при создании мира, нижний ряд кусков стен нулевого этажа (середины рёбер на уровне z = 0) и куски плиты пола нулевого этажа становятся неуязвимыми ещё до первого выстрела — фундамент никогда не исчезает. Авторские взрывы при сборке карты (раньше схемы) могут их разрушить.
- Значение 254 ставится и в узлы, где куска нет (точки соединения) — «пустой» узел становится «целым»; видимости это не меняет.
- Вес добавляется только при СОЗДАНИИ стыка: узел, общий для двух кусков (угловой кусок двух соседних стен, верх стены + плита), несёт вес только первого добавленного куска; если стык сначала появился как незаполненный конец, а потом совпал с куском — ни веса, ни флага ЗАПОЛНЕН он не получит (флаг ставится только в ветке «стержень уже существует»).
- Неразрушимый материал (DR < 0) получает флаг ЗЕМЛЯ после проверки хеша земли и без смены устойчивости: до первого сброса схемы такой стык остаётся UNKNOWN и опорой не служит; кроме того, «земля» стекает вниз, и неразрушимый стык над другим стыком теряет её.
- Хеш стыков создаёт пустые записи при каждом поиске.
- Узлы на краях ямы подвала, лежащие выше z = 0, стеной подвала не считаются.

### Что нужно от движка-носителя
Динамические массивы со стабильными индексами (в коде — векторы с резервом, ссылки по индексам), хеш-таблица по целочисленным координатам.

## 8. Пересчёт схемы (Recalc): три прохода

### Назначение
Одна итерация статики: определить устойчивость всех стыков, распределить вес по опорам, сломать перегруженное. Возвращает «что-то сломалось».

### Порядок `Recalc(решётка)`
1. Очистить список волн. (Проверка артефактов — пустая функция.)
2. Проход 1 — устойчивость (`ComputeStability`).
3. Проход 2 — поиск свободных (`FindFree`, раздел 9).
4. Проход 3 — моменты и давления (`ComputeMoments`, раздел 9).
5. Если решётки нет (отладочный просмотр) — вернуть false (ничего не ломать).
6. Правила разрушения (раздел 10). Если что-то сломано — увеличить версию решётки. Вернуть признак.

### Подготовка (`Start`, один раз после построения)
Индексы стыков сортируются по z по возрастанию (`std::sort`, порядок внутри слоя не определён — на результат прохода 1 не влияет, так как процесс монотонный и доводится до неподвижной точки).

### Проход 1 — устойчивость, послойно снизу вверх
Для каждого слоя z (только неразрушенные стыки):
1. Вертикальная устойчивость каждого стыка слоя:
   - уже STABLE — оставить;
   - не «земля» и нет живого стержня вниз → UNSTABLE;
   - «земля» без стержня вниз → оставить как есть;
   - есть стержень вниз и нижний сосед STABLE → STABLE (иначе оставить, обычно UNKNOWN).
2. Повторять, пока что-то меняется: каждый STABLE-стык слоя «стреляет» в 8 направлениях по порядку: XP, XM, YP, YM, XPYP, XMYP, XMYM, XPYM.

Выстрел стыка J в направлении d:
1. Если у J уже есть «стрела» d — вернуть «без изменений».
2. Поставить J стрелу d.
3. Осевое d: если у J есть живой стержень в d — выстрел передаётся соседу на том конце в том же направлении (рекурсивно, стрела летит по прямой, пока есть стержни и пока не встретит стык, уже имеющий стрелу d).
4. Диагональное d (например, XPYP): сосед ищется в два шага — если у J есть стержень XP, берётся стержень YP соседа по XP; ИНАЧЕ, если есть стержень YP, берётся стержень XP соседа по YP. Если найденный стержень жив — выстрел продолжается в стык на его конце (тоже по диагонали).
5. Пересчитать устойчивость J по стрелам: STABLE, если есть пара противоположных стрел: (XP и XM) или (YP и YM) или (XPYP и XMYM) или (XMYP и XPYM). Вернуть «изменилось», если устойчивость изменилась у J или у кого-то по цепочке.

Смысл: стрела d в стыке означает «где-то в стороне, противоположной d, по непрерывной цепочке стержней этого же слоя есть устойчивый стык». Стык между двумя устойчивыми опорами на одной прямой (или диагонали) — устойчив: так держатся пролёты, перемычки над проёмами, балки. Стрелы распространяются только горизонтально, внутри слоя; на следующий слой устойчивость переходит только по вертикальным стержням (шаг 1).

### Константы

| Имя | Значение | Смысл |
|---|---|---|
| направления | XP 0, XM 1, YP 2, YM 3, UP 4, DN 5, XPYP 7, XMYP 8, XMYM 9, XPYM 10 | номер = номер бита стрелы |
| противоположные | XP↔XM, YP↔YM, UP↔DN | таблица `oppositeDirs` |

### Особые случаи и прихваты
- Диагональ ищется «сначала по x, потом по y»; если сосед по x есть, но у него нет стержня по y, путь «сначала по y» не пробуется.
- Стрела ставится и самому стреляющему (он уже устойчив).
- Устойчивость никогда не «понижается» внутри прохода: стрелы сбрасываются только при сбросе схемы.
- Альтернативный рекурсивный вариант (`ComputeStabilityR`) и «прямой угол» (`HasRightAngle`) в коде закомментированы — мёртвый код.

## 9. Поиск свободных узлов и распространение моментов

### Проход 2 — `FindFree`
Для каждого стыка массива (в порядке индексов, ВКЛЮЧАЯ разрушенные — их устойчивость устаревшая) с устойчивостью UNSTABLE или UNKNOWN:
1. Обход в глубину `CheckFree` от стыка: устойчивый или уже UNSTABLE_NOTFREE сосед → ответ «STABLE» (в область не входит); заблокированный или уже проверенный стык → «UNKNOWN»; иначе стык входит в область, помечается «проверен», результат «UNSTABLE», затем обходятся все 6 соседей по живым стержням (обход идёт по ВСЕМ соседям, даже после найденной опоры), и если кто-то ответил «STABLE» — результат «STABLE».
2. Всем стыкам области, у которых устойчивость UNSTABLE или UNKNOWN, присваивается: UNSTABLE_NOTFREE, если область касается устойчивого стыка, иначе FREE.

Итог: каждый неустойчивый стык либо «висит, но держится» (связная область касается опоры), либо «свободен» (кусок, полностью оторванный от опор).

### Проход 3 — `ComputeMoments`
Цель: каждому неустойчивому стыку найти опоры, на которые давит его вес, и распределить вес между ними; опорам — накопить давление и моменты.

1. Источники волн. Для каждого STABLE-стыка S (в порядке индексов): список «рёбер» = направления 0..5, для которых НЕТ (живой стержень с устойчивым соседом) — то есть сюда попадают и направления без стержня вообще. Если список пуст — S ничего не испускает. Вес волны w = 1 / (длина списка). Для каждого направления списка, где стержень жив: создаётся волна №k = {источник S, вес w, направление «назад к S»}, и она продвигается по стержню (см. «продвижение»), шаг = −1.
2. ГСЧ = SRand(зерно 1) — одно и то же при каждом пересчёте (результат детерминирован).
3. Шаги волн: n = 0, 1, 2… Пока на шаге было хоть одно продвижение: для каждого стыка из текущего списка фронта — обработка фронта (ниже); затем текущий список очищается и меняется местами со следующим.
4. Моменты: каждый неразрушенный неустойчивый стык раздаёт свой вес (раздел ниже).

Продвижение волны по стержню (со стороны s): если у стержня уже 2 блокировки — отказ; иначе блокировка +1; стык на другом конце получает флаг ФРОНТ_ВОЛНЫ, номер волны, направление движения и номер шага; он добавляется в следующий список фронта (возможны повторы; если на стыке уже была волна, номер перезаписывается).

Обработка фронта стыком J на шаге n:
1. Если у J нет флага фронта, или его номер шага = n, или J устойчив — ничего.
2. Записать волну J в список опорных волн J; сумма весов += вес волны.
3. Кандидаты: направления 0..5 с живым стержнем, кроме направления «назад» (противоположного направлению прихода), у которых сосед сейчас НЕ фронт волны и у стержня осталась ёмкость (пробная блокировка с откатом).
4. Если кандидатов < 2 — снять с J флаг фронта; иначе J остаётся фронтом и добавляется в следующий список (на следующем шаге он снова запишет ту же волну и снова ответвится).
5. Нет кандидатов — конец. Иначе выбрать кандидата: индекс = `rand.Get(число кандидатов)`; продвинуть ту же волну по выбранному стержню (с текущим n).

Раздача веса (`ComputeMoment`) стыком J:
- J устойчив — ничего.
- Опорных волн нет и J не FREE → J := UNKNOWN_MOMENT (отладочное сообщение «Cant compute momemnt»); его вес никуда не идёт.
- Иначе для каждой записи списка опорных волн (запись = волна {S, w, направление}): доля = вес(J) · w / (сумма весов записей J); у источника S вызывается «добавить момент».

Добавить момент в S (доля m, точка массы P, направление волны): Δ = P − S (в узлах решётки); направление первого шага волны d = противоположное записанному:

| d | изменение |
|---|---|
| XP | момент[XP] += Δx · m |
| XM | момент[XM] −= Δx · m |
| YP | момент[YP] += Δy · m |
| YM | момент[YM] −= Δy · m |
| UP, DN | моментов нет |

Давление S += m во всех случаях.

### Формулы
- вес волны от опоры S: w = 1 / N, N — число направлений из 6, где нет устойчивого соседа (включая направления без стержня);
- доля веса стыка J, приходящаяся на запись волны: m = W_J · w / Σw (сумма по всем записям J, с повторами);
- давление опоры: p_S = Σ m (по всем записям всех стыков, указывающим на S);
- момент опоры по направлению первого шага d: M_d = Σ m · (±Δ_d), плечо — проекция на ось d в узлах решётки (0,625 м), знак «+» для масс дальше по направлению d.

### Константы

| Имя | Значение | Смысл | Источник |
|---|---|---|---|
| зерно ГСЧ волн | 1 | фиксированное при каждом пересчёте | BuildingSchema.cpp |
| `NLOCKS` | 2 | ёмкость стержня | rod.h |
| `WEIGHT_EPSILON` | 5e−5 | объявлена, не используется | RodJunction.cpp |

### Особые случаи и прихваты
- Вес волны «разбавляется» отсутствующими стержнями: опора с одним неустойчивым соседом и пятью пустыми направлениями даёт волну весом 1/6 — но так как доли нормируются у получателя, это влияет только на соотношение между опорами.
- Стык, оставшийся фронтом, записывает одну и ту же волну на каждом шаге, пока может ветвиться: опоры, чьи волны «задержались» в стыке, получают большую долю его веса.
- Плечо считается по прямой проекции от опоры до массы, а не по пути волны; масса «позади» направления волны даёт отрицательный вклад.
- Вес стыков UNKNOWN_MOMENT теряется (отладочная проверка сравнивает сумму весов UNSTABLE_NOTFREE с суммой давлений и печатает расхождение в процентах — только в отладочной сборке).
- FREE-стыки тоже раздают вес, если волны до них дошли (волна по стержню не проверяет, свободен ли сосед), но области FREE по определению не связаны с опорами, поэтому обычно волн у них нет.
- Порядок обработки и выбор ветви зависят от порядка индексов стыков (порядок построения) и фиксированного ГСЧ: при той же схеме результат всегда тот же.

## 10. Правила разрушения и удаление стыков и стержней

### Алгоритм (конец `Recalc`)
Для каждого стыка массива по порядку индексов (включая разрушенные):
1. FREE → «разрушить стык» без эффектов; если удалось — «изменено».
2. STABLE:
   1. Вычисляется ⌊√HP узла⌉ (округление) — значение не используется.
   2. Если давление > предельного давления — «разрушить стык» С эффектами; если удалось — «изменено» и к следующему стыку.
   3. Для каждого горизонтального направления XP, XM, YP, YM: если |момент| > предельного момента — «разрушить стык» на другом конце стержня этого направления (если стержень жив) С эффектами; если удалось — «изменено» и стержень этого направления разрушается.
3. Остальные состояния (UNSTABLE_NOTFREE, UNKNOWN_MOMENT…) — ничего.

«Разрушить стык» J (с флагом эффектов):
1. J — «земля» или «стена подвала» → нельзя (false).
2. `DamageSpot(узел J, 255, эффекты)`; если узел действительно разрушен, решётка сама помечает J разрушенным в схеме.
3. J заполнен (кусок): если узел разрушен — J разрушается (повторно, безвредно); вернуть результат шага 2.
4. J не заполнен (точка соединения): если у него нет живых стержней — вернуть результат шага 2. Иначе найти «ближайший заполненный»: перебрать родителей по порядку, пропуская разрушенных; первый НЕустойчивый — он; если все живые устойчивы — последний из них. Нашёлся — его узел получает `DamageSpot(…, 255, эффекты)`; если узел разрушен — родитель разрушается; стержни между родителем и J разрушаются; вернуть результат. Не нашёлся — false.

(Параметр «глубина» > 5 → false — рекурсии в живом коде нет.)

Разрушение стыка (флаг РАЗРУШЕН): разрушаются все его живые стержни, очищаются родители и опорные волны.

Разрушение стержня: флаг «разрушен»; для каждого живого конца — «проверка вертикальной цепочки»: если у стыка жив стержень вверх И вниз, но нет ни одного живого горизонтального — стык помечается РАЗРУШЕННЫМ (узел решётки НЕ трогается) и оба вертикальных стержня разрушаются (без каскада: их другие концы уже имеют разорванную вертикаль).

Сброс схемы (после итерации, в которой что-то сломалось), только для неразрушенных: стыки — повторная инициализация (флаги кроме постоянных стираются, устойчивость = STABLE для «земли», иначе UNKNOWN, моменты и давление 0, опорные волны очищены, шаг −1); стык без живых стержней получает флаг РАЗРУШЕН; стержни — блокировки := 0.

### Формулы
- поломка опоры: p_S > P_ult (давление больше предельного давления);
- поломка связи: |M_d| > M_ult (по каждому из 4 горизонтальных направлений).

(Закомментированный вариант: p > 2·P_ult/3 + P_ult/3 · round(√HP)·10/255 — зависимость от HP узла была задумана, но отключена; аналогичная заготовка `P_ult/3` есть и у момента, тоже не используется.)

### Особые случаи и прихваты
- **Тихие и громкие поломки**: оторванные куски (FREE) убираются без пыли и звуков; поломки от перегрузки опоры и от излома связи идут в очередь эффектов (раздел 14).
- Разрушение точки соединения бьёт по соседнему куску: так «излом связи» в стыке-точке превращается в выпадение реального куска.
- Стык, исключённый проверкой вертикальной цепочки или сбросом (нет стержней), продолжает существовать в решётке (кусок виден). На следующей итерации у него устаревшая устойчивость: если UNKNOWN/UNSTABLE — проход 2 объявит его FREE (стержней нет) и он будет тихо разрушен; если он успел стать UNSTABLE_NOTFREE или STABLE — останется висеть до следующего «пробуждения» здания, когда схема строится заново.
- Изолированный кусок (все соседи выпали) пропадает тихо через одну итерацию после соседей.
- Неуязвимые узлы (254/255) не разрушаются, даже если стык «сломан»: функция вернёт false и итерация не считается изменившей здание.
- Разрушение в схеме меняет решётку во время обхода, поэтому стыки с большими индексами в той же итерации видят уже частично разрушенную схему (порядок индексов влияет на результат).

## 11. Ритм итераций и жизненный цикл схемы

### `UpdateBuildingStability(здание, решётка, карта, N = 1)`
1. Загрузить чертёж; нет — false.
2. Счётчик итераций = −1, предел = N − 1.
3. Если у решётки нет схемы: построить (раздел 7), отсортировать стыки, прикрепить к решётке; счётчик += 1; если счётчик = предел — вернуть true (построение съело весь бюджет).
4. Пока «изменено»: «изменено» = `Recalc`; если изменено — сброс схемы; счётчик += 1; если счётчик = предел — прервать.
5. Если последний пересчёт ничего не изменил — схема отцепляется от решётки и уничтожается. Вернуть «изменено» (true = здание ещё двигается).

В лог пишется время построения и число итераций.

Режимы:
- при создании объекта здания в мире: N = 100 → построение + до 99 пересчётов за один вызов; если здание и после этого не успокоилось — включается игровой цикл обновления (ниже);
- в игре: N = 1 → один вызов = либо построение схемы, либо один пересчёт;
- отладочная команда «checkStability»: N = 1 для всех зданий.

### Игровой цикл обновления объекта здания (каждый сегмент мира, 50 мс)
Состояние: счётчик сегментов `nSegemntCnt` (−1 = выключен), флаг «идёт статика», счётчик удержания действия `nActionCnt` (−1 = выключен), удерживаемый счётчик действия мира.

«Включить обновление» (при разрушении узла попаданием, при `Explode`, при неуспокоившемся здании на создании мира): счётчик сегментов := 0; захватить счётчик действия мира с задержкой 10 («Мир 1»).

Каждый сегмент:
1. Эффекты разрушения (раздел 14) — всегда первыми.
2. Если счётчик сегментов = 0 — перестроить грязные части (раздел 12).
3. Если счётчик ≥ 0 и после увеличения стал 5:
   - счётчик := −1, «идёт статика» := нет, удержание := 0;
   - если статика включена: вызвать `UpdateBuildingStability` (N = 1). Если true — счётчик := 0, «идёт статика» := да, удержание := −1. Если false — перестроить грязные части.
4. Иначе, если счётчик ≥ 0 и «идёт статика»: `UpdateBuildingStability` (N = 1); если false — счётчик := −1, «идёт статика» := нет, удержание := 0, перестроить грязные части.
5. Если удержание ≥ 0 и после увеличения стало 30 — отпустить счётчик действия, удержание := −1.

Временная диаграмма после попадания, разрушившего узел (сегмент = 50 мс):

| Сегмент | Что происходит |
|---|---|
| 1 | дыра видна сразу (перестройка частей), счётчик 1 |
| 2–4 | ожидание (счётчик 2–4) |
| 5 | счётчик 5 → построение схемы (весь бюджет), счётчик 0, «идёт статика» |
| 6 | перестройка частей; пересчёт №1 |
| 7–9 | пересчёты №2–4 (модель НЕ перестраивается) |
| 10 | счётчик 5 → пересчёт №5; если ещё двигается — счётчик 0 |
| 11 | перестройка частей, пересчёт… |

Итого во время обрушения: пересчёт каждый сегмент (20 в секунду), перестройка модели — каждый 5-й сегмент (4 раза в секунду); после успокоения — финальная перестройка, схема выброшена, мир «занят» ещё 30 сегментов (1,5 с).

|---|---|---|---|
| итераций при создании мира | 100 (1 построение + 99 пересчётов) | | wBuilding.cpp |
| итераций за сегмент в игре | 1 | | MakeBuilding.h |
| задержка перед первой статикой | 5 сегментов (0,25 с) | | wBuilding.cpp |

### Особые случаи и прихваты
- Схема не сохраняется: после загрузки сохранения обрушение «досчитывается» заново — если здание сохранили в движении, схема будет построена с нуля (по текущей решётке) при следующем включении обновления.
- Схема строится из уцелевших кусков: удалённые ранее стыки (например, «висящие» после проверки вертикальной цепочки) получают второй шанс быть признанными оторванными.
- Повторное попадание во время обрушения перезапускает счётчик сегментов, но не сбрасывает «идёт статику»: пересчёты продолжаются с существующей схемой (решётка уже отметила новый разрушенный стык).
- Попадание, не разрушившее узел, вообще не включает обновление.
- Отладочный переключатель `bStabilityUpdate` = false: решётка заливается 253, HP не считаются, статика не запускается — здание разрушается только непосредственно.

### Что нужно от движка-носителя
Тик фиксированной длины (50 мс), механизм «мир занят, не передавать ход» (счётчик действия), бюджет одной итерации на здание за тик.

## 12. Пересборка меша здания

### Назначение
Из решётки, чертежа и карты стен построить описание видимой модели, разбитое на «части здания» (этаж × квадрат 2 × 2 тайла), и перестраивать только изменившиеся части.

### Данные
`SBuildingInfo`: словарь «часть здания → этаж-описание» (`SStoreyInfo`: этаж, список сплошных фрагментов, список стен). Фрагмент описания: номер (индекс фрагмента; у второй геометрии — 0x20000000 | индекс), броня части, `SClipInfo`, пятна.

`SClipInfo`: геометрия, хеш субблока, позиция (тайлы, этажи), поворот, 4 смешанных материала, 32-битное поле `nClip` (у стены — код подрезки; у сплошного то же место называется «соседи» и не заполняется), маска видимых кусков `dwParts`.

Держатель описания (`CBuildingInfoHold`): ссылки на решётку, чертёж, карту стен и флаг «всегда по кускам». У объекта здания два держателя: обычный (целые субблоки рисуются одним мешем) и «раздробленный» (`bSplitParts`); второй в этом коде только создаётся и обновляется, никем не читается (назначение не подтверждено).

### Алгоритм построения (`MakeBuilding`, полная или выборочная)
1. Обновить карту стен; `rand` (зерно перезадаётся на каждый фрагмент), `randStart` = SRand(зерно решётки).
2. Выборочная перестройка — удалить из описания перестраиваемые части; полная — очистить всё.
3. Этаж среза = этаж среза решётки (в игре = nMaxFloor, раздел 18).
4. Сплошные: по группам подрезки, по ячейкам (этаж, y, x), по фрагментам ячейки. Пропуск: нет фрагмента, ⌊z⌋ > этажа среза, слой фрагмента скрыт. Иначе:
   - описание: позиция = начало субблока, геометрия = первая геометрия варианта, поворот, хеш субблока;
   - зерно `rand` = `randStart.Get(0x6000)` + `randStart.Get(0x6000)`·0x6000 (две выборки на фрагмент — ВСЕГДА, даже если часть не перестраивается);
   - часть здания = (⌊z⌋, cx/2, cy/2 с усечением к нулю), где (cx, cy) = позиция + поворот(1,1) — центр квадрата блока;
   - если часть перестраивается — добавить фрагмент в её список сплошных.
5. Стены: если скрыт слой стен (тип 6, номер 0) — конец. По каждой стене i (вариант берётся из карты стен): пропуск без варианта/геометрии или выше среза; код подрезки (раздел 13); зерно — так же 2 выборки; часть = (⌊z⌋, cx/2, cy/2 с усечением), где (cx, cy) = позиция + поворот(1,0) — середина стены; добавить в список стен части.
6. Добавление фрагмента:
   1. Нет геометрии — пропуск.
   2. Маска видимых кусков (раздел 4) по ИИ-геометрии первой геометрии (при флаге «всегда по кускам» целые субблоки тоже разбиваются).
   3. Материалы слотов 0..3 — из сырых материалов фрагмента 0..3 (раздел 1) тем же `rand`.
   4. Добавить фрагмент; пятна фрагмента: по каждому ID пятна найти пятна чертежа с этим ID, выбрать материал по шаблону (`rand`) и запомнить.
   5. Если есть вторая геометрия — добавить второй фрагмент: та же позиция, та же МАСКА кусков (посчитанная по первой геометрии), подрезка 0, материалы из сырых 4..7 и слотов по умолчанию 4..7, номер 0x20000000 | индекс, без пятен.

### Выборочная перестройка
1. При разрушении узла решётка помечает «грязными» 27 частей вокруг узла (раздел 4: часть узла = (⌊(z−1)/4⌋…, x/2, y/2)).
2. Объект здания раз в цикл (раздел 11) забирает список и очищает его; держатель перестраивает только эти части (если чертёж изменился — всё).
3. Для каждой грязной части: если после перестройки её нет в описании (все фрагменты исчезли) — объект части здания удаляется (исчезает из рендера и ИИ); иначе — обновляются счётчики фрагментов и рассылается «часть изменилась» (рендер пересоздаёт меши части, ИИ перерегистрирует куски, раздел 14).
4. Новые части при выборочной перестройке не появляются (их создают полная перестройка `Update`/`UpdateAllParts`, используемые редактором и при входе в зону).

### Рендер части (`NGScene::CBuilding::Build`)
Для каждой стены части:
1. Позиция в метрах: (0,625·x, 0,625·y, 2,5·z), поворот фрагмента, матрица здания.
2. Группа (этаж) = бит этажа (этаж части + базовый этаж здания).
3. Окклюдер: если у геометрии есть ИИ-геометрия и материал слота 0 непрозрачный или самосветящийся — дополнительный меш-окклюдер из ИИ-кусков (видимые номера кусков, раздел 4).
4. Для каждого слота материала 0..3 с непустым материалом: ключ кеша {ID геометрии, слот, маска кусков, хеш субблока, код подрезки}; если в ресурсе геометрии нет части с номером слота — пропуск; клиппер стены из общего кеша; пользовательский номер меша = (номер фрагмента XOR (слот << 20)) | 0x40000000; для каждого пятна, у которого бит слота в маске не установлен, — декаль, спроецированная на результат клиппера.

Для каждого сплошного фрагмента — то же, но: группа этажа учитывает «подвал» (узел решётки в центре блока, z = 4·этаж, равен 254 и этаж < 0 → самый нижний этаж рендера `N_MIN_FLOOR`); клиппер сплошного (без подрезки); пользовательский номер без 0x40000000.

### Кеш клипперов
- Кеши: клипперы стен (кеш №116), клипперы сплошных (№124), исходные меши по кускам (№122), чертежи (№108).
- Ключ: {ID геометрии, номер части геометрии = слот материала, маска кусков, хеш субблока, код подрезки}; сравнение — побайтно всей структуры, хеш = (маска << 16) ^ (слот << 12) ^ ID.
- Одинаковые сегменты стен с одинаковыми уцелевшими кусками и одинаковыми стыками используют один и тот же подрезанный меш.

### Особые случаи и прихваты
- Две выборки `randStart` на каждый фрагмент делаются до проверки «перестраивается ли часть», поэтому материалы фрагментов не «прыгают» при выборочной перестройке; но пропуск фрагментов по этажу среза или скрытому слою (редактор) сдвигает последовательность — материалы следующих фрагментов меняются.
- Вторая геометрия получает маску кусков первой.
- У сплошных поле `nClip` не инициализируется, а входит в ключ кеша — фактически ключи сплошных могут не совпадать между одинаковыми фрагментами (лишние копии в кеше). Не подтверждено, что так было в оригинале, но код тот же.
- Пустая маска (все куски разрушены) всё равно даёт фрагмент в описании — клиппер вернёт пустой меш; часть удаляется только когда в ней не осталось ни одного фрагмента.

### Что нужно от движка-носителя
Возможность пересобирать статический меш отдельной части без пересборки всего здания; общий кеш мешей по ключу; стабильные пользовательские номера мешей для декалей.

## 13. Коды обрезки стен и клиппер

### Назначение
Стены — сегменты по 1,25 м с выступом 0,05 м за концы. В углах, Т- и Х-образных стыках, при стыке стен разной толщины выступы надо срезать, чтобы не было «зубцов» и z-конфликтов. Срез вычисляется один раз при построении описания и кодируется 8 битами на каждый конец.

### Упаковка кода подрезки стены (`nClip`, 32 бита)
- биты 24–31: длина в тайлах = 2;
- биты 16–23: ID толщины стены (1/2/3);
- биты 8–15: код левого конца;
- биты 0–7: код правого конца.

Код конца (8 бит): бит 0 — «стыкуемая стена перпендикулярна», биты 1–2 — ID толщины стыкуемой стены (0 = не резать), бит 3 — «стыкуемая стена сверху» (top), биты 4–7 — «скрытые стороны» (левая, правая, верх, низ).

### Алгоритм вычисления кода конца (`GetWallClipInfo`)
Вход: узел конца стены (левый или правый), сама стена.
1. Узла нет — 0.
2. Найти направление «своей» стены в узле: первое i = 0..3, в списке которого есть эта стена (i — направление от узла вдоль стены). Не найдено (внутренний стык многоблочной стены) — 0.
3. Для каждого другого непустого направления: fW = максимальная толщина стен в нём (любых групп); «в группе» = есть стена той же группы подрезки; если «в группе» — записать (направление, fW) в список ширин. Самая толстая стена своей группы подрезки во всех направлениях — «главная встречная» (строго большая толщина; при равенстве остаётся найденная первой в порядке 0..3).
4. Нет встречной своей группы — код 0.
5. ID толщин: встречной (In) и своей (Own).
6. Встречная — «внутренняя» (сторона INTERNAL) — код (In, не перпендикулярно). В текущем коде сторона INTERNAL не назначается — ветка мёртвая.
7. **Особый случай трёх и более стен одной толщины**: если In ≤ Own и в списке ширин больше 2 записей, посчитать записи, чья ширина в точности равна своей толщине; если таких > 2:
   - противоположное направление (i+2) mod 4: если там есть стена (первая в списке) той же группы — скрыть свою сторону: левую, если своя стена начинается в этом узле (сторона LEFT), иначе правую;
   - вернуть код (Own, не перпендикулярно, без top, скрытые стороны).
8. Иначе: если (i − i_встречной) нечётно — перпендикулярно; top = таблица[i][3 + (i − i_встречной)].
   Если чётно (встречная — продолжение по прямой) — не перпендикулярно; при равных толщинах: если стороны совпадают — ничего; иначе если своя сторона LEFT — скрыть левую, иначе — правую.
9. Если In < Own — In := 0 (о более тонкую стену не режем).
10. Код = (скрытые стороны << 4) | (top << 3) | (In << 1) | перпендикулярно.

Таблица top (строка — своё направление i, столбец — разность i − i_встречной от −3 до +3):

| i | −3 | −2 | −1 | 0 | +1 | +2 | +3 |
|---|---|---|---|---|---|---|---|
| 0 (влево) | 1 | 0 | 0 | 0 | 0 | 0 | 0 |
| 1 (вверх) | 0 | 0 | 0 | 0 | 1 | 0 | 0 |
| 2 (вправо) | 0 | 0 | 0 | 0 | 1 | 0 | 0 |
| 3 (вниз) | 0 | 0 | 0 | 0 | 1 | 0 | 0 |

Комментарий автора: top = «встречная перпендикулярна и лежит в положительной полуплоскости Y» (в локальной системе своей стены).

### Плоскость среза (`GetClipPlane`)
Локальная система стены: x — вдоль стены от 0 до L = 0,625·2 = 1,25 м, y — по толщине (стена ±w/2), z — вверх. Сохраняется часть полигонов, где n·p ≥ d.
1. In = 0 → не резать.
2. Перпендикулярно:
   - In = Own (одинаковые толщины) — срез под 45°: левый конец: top → n = (1/√2, −1/√2, 0), d = 0; не top → n = (1/√2, 1/√2, 0), d = 0. Правый конец: top → n = (−1/√2, 1/√2, 0), d = −L/√2; не top → n = (−1/√2, −1/√2, 0), d = −L/√2;
   - In > Own (встречная толще) — срез по оси на грани встречной: левый n = (1,0,0), d = w_in/2; правый n = (−1,0,0), d = −(L − w_in/2);
   - иначе — не резать.
3. Не перпендикулярно (продолжение или особый случай): левый n = (1,0,0), d = 0 (x ≥ 0); правый n = (−1,0,0), d = −L (x ≤ L) — просто срезать выступ.

Биты скрытых сторон клиппер НЕ читает — они только делают ключ кеша разным.

### Клиппер стены (по шагам)
1. Распаковать видимые куски; взять их полигоны из меша, нарезанного по кускам (ресурс геометрии, раздел 4 «Geometries»), и сложить.
2. Срез левой плоскостью, затем правой (если есть): для каждого полигона — обход рёбер; вершина сохраняется, если d − n·p ≤ 0; на пересечении ребра с плоскостью создаётся новая вершина с линейной интерполяцией позиции, нормали, касательных, текстурных координат и цвета (нормаль и касательные перенормируются); одинаковые новые вершины переиспользуются (точное совпадение всех полей); полигон из ≤ 2 вершин отбрасывается.
3. Удалить пары встречных полигонов (внутренние грани между соседними кусками): позиции «свариваются» по сетке 1/4096 м; индексы каждого полигона циклически сдвигаются, чтобы начинаться с наименьшего сваренного индекса; два полигона с одинаковым числом вершин, одинаковым первым индексом и обратным порядком остальных — удаляются ОБА.
4. Оптимизация вершин: позиция → сетка 1/4096 м; нормаль и касательные → 1/16384; текстурные координаты → 1/65536; одинаковые после квантования вершины сливаются, неиспользуемые выбрасываются.
5. Разбить полигоны по плоскостям: плоскость полигона — по первой невырожденной тройке подряд идущих вершин, квантованная (нормаль и d — 1/4096).
6. Для каждой плоскости — упрощение копланарных полигонов (до двух проходов, второй — если первый что-то нашёл): полигоны триангулируются; для каждой вершины строятся «секторы» (угол между входящим и выходящим ребром каждого треугольника вокруг неё, в базисе плоскости). Вершина «внутренняя», если её секторы сцепляются в одну цепочку (полный круг) — либо в одну незамкнутую цепочку, концы которой лежат на одной прямой (разворот ровно π с допуском 0,001) — «граничная на прямой». Внутренняя вершина сливается с одной из вершин-соседей, если ни один треугольник вокруг неё не меняет ориентацию (знак векторного произведения относительно нормали; нулевая площадь не может стать ненулевой); граничная — только с одним из двух концов своей прямой. Слияния повторяются, пока возможно; затем индексы переписываются по таблице слияний.
7. Ещё раз удалить встречные пары и оптимизировать вершины; результат — меш.

Клиппер сплошного: шаги 1, 3, 4 (без среза и без упрощения).

### Особые случаи и прихваты
- Вторая геометрия части (заборы) не подрезается (код 0).
- Срез «по прямой» к более тонкой стене не делается: толстая стена своим выступом закрывает торец тонкой.
- При Т-стыке трёх одинаковых стен все три режутся ровно по узлу (не под 45°), особый случай 7.
- Х-стык (четыре одинаковые стены): у каждой стены в списке ширин 4 записи, все равны — особый случай; противоположное направление занято → скрыта своя сторона; все четыре режутся по узлу; центральный квадрат толщина × толщина закрывают две коллинеарные стены (каждая — свою половину), поперечные стены входят внутрь них.
- «Половина толщины»: при стыке с более толстой перпендикулярной стеной срез проходит по её грани — на расстоянии w_in/2 от узла (0,05 / 0,1 / 0,15 м для толщин 0,1 / 0,2 / 0,3).
- Стены разных групп подрезки не влияют друг на друга (заборы, решётки, особые элементы с собственным номером группы).
- Базис плоскости для секторов: ось X = (1,0,0) × n (или (0,1,0) × n, если |(1,0,0)·n| > 0,7), ось Y = X × n, обе нормированы и квантованы до 1/16384.

### Что нужно от движка-носителя
Ассет геометрии, разрезанный по кускам (номер куска → полигоны), и CPU-сборка меша; можно заменить на заранее посчитанные варианты, но коды подрезки и ключи кеша нужны те же.

### 14.2. Перестройка частей
Раздел 12: грязные части пересобираются; пустые части удаляются; изменённые рассылают обновление.

### 14.3. Перерегистрация в ИИ-карте (часть здания → ИИ)
Для каждой стены части:
1. Матрица = матрица здания × перенос (0,625·x, 0,625·y, 2,5·z) × поворот фрагмента; список номеров кусков = распаковка маски; дискретная позиция для пулевых хешей = (x, y, 4·z) с поворотом фрагмента; этаж ИИ = абсолютный этаж этажа здания.
2. Флаги ИИ (`GetMask`): Damage → TS_FRAGMENTED | TS_COVER, иначе TS_VIRTUAL; Vision → TS_VISION, если прозрачность материала ≠ 1, плюс TS_VISION_SOLID при прозрачности > 0; Passability → TS_PASS_BLOCKER | TS_WEAPON_BLOCKER; ItemBlocker → TS_ITEM_BLOCKER; LadderPart → TS_LADDER_PART.
3. Геометрия неповреждаемая (Damage = 0): один набор корпусов со всеми флагами, пользовательский номер у всех кусков = номер фрагмента | 0x40000000.
4. Повреждаемая: (а) «слитое» представление — текущий список номеров (целый субблок одним куском или уцелевшие куски), флаги без TS_FRAGMENTED, номер = номер фрагмента | 0x40000000; (б) «раздробленное» — список, раздробленный на 22 номера (если субблок цел), флаг только TS_FRAGMENTED, номер каждого куска = пулевой хеш его узла (позиция куска (x−1, y−1, z−1) → поворот → + (x, y, 4·z) фрагмента).

Для сплошных — то же, но в (а) номер — номер фрагмента БЕЗ 0x40000000 (у неповреждаемых — с ним).

`FixSmallPieceID` (слияние кусков объёмом ≤ 0,01 м³ с ближайшим крупным соседом в кубе 3×3×3: минимальное расстояние, при равенстве — меньший объём) в коде отключён ранним `return` — номер куска не меняется.

### 14.4. Декали и освещение
- Следы пуль, кровь, пятна на зданиях привязаны к держателю описания здания и пользовательскому номеру меша (фрагмент, слот). Когда часть пересобирается и меш с тем же номером создаётся заново, менеджер декалей повторно накладывает на новый меш все декали этого номера («восстановление декалей»); если исходный меш (узел клиппера) сменился — декаль проецируется заново.
- Любое изменение статической геометрии сцены сбрасывает кеш динамического освещения (выборки окружающего света по точкам) и кешированные позиции световых групп (сдвигаются в 1e30, чтобы пересчитаться); кеш также очищается, если в нём больше 500 записей.

### 14.5. Прочее
- Мировой взрыв (`CWorld::Explode`) будит обломки в сфере 15 м и вызывает проверку устойчивости объектов; падение предметов, трупов и мин, у которых исчезла опора, делает «сторож устойчивости» по изменениям ИИ-карты («ИИ 3», «Мир 3»).
- Попадание, разрушившее узел, держит мир «занятым» (раздел 11).

Две формы коллизии на блок (слитая для видимости/укрытий/проходимости, по кускам для попаданий), события «геометрия изменилась» для навигации и освещения, система декалей с переносом на пересобранный меш.

## 15. Амбиент комнат и освещение

### Назначение
Задумано: внутри комнаты свет — смесь «локального» (комнатного) и «глобального» (уличного) амбиента пропорционально доле разрушенных стен и потолка комнаты: чем больше дыр, тем светлее внутри.

### Алгоритм (`CLightCalcer`, в этом коде НЕ подключён — создание закомментировано)
1. Значение = локальный амбиент.
2. По глобальному номеру комнаты найти (этаж, локальная комната) в решётке; слой карты комнат = этаж − nMinFloor; нет такого — выход.
3. Для каждого тайла (i, j) карты комнат без краевой полосы, принадлежащего комнате: узел p = (i−1, j−1, 4·этаж − 1);
   - всего += 2; разрушено += [p разрушен] + [p + (0,0,4) разрушен];
   - если тайл на границе комнаты (хотя бы один из (i,j−1), (i−1,j), (i−1,j−1) — другая комната): всего += 3; разрушено += [p+(0,0,1)] + [p+(0,0,2)] + [p+(0,0,3)].
4. Доля f = разрушено / всего (если всего = 0 — оставить локальный).
5. Амбиент = f · глобальный + (1 − f) · локальный.

Локальный амбиент комнаты = сумма цветов «окружающего света» контейнеров, стоящих в здании (`ptAmbientColor` модели объекта; собирается при сборке карты в `SMapBuilding::lights`, все в комнату 0).

### Особые случаи и прихваты
- Создание `CLightCalcer` в коде вида закомментировано, номера комнат здания не заполняются (`WriteLightRooms` пуст, глобальные номера всегда 0) — в этой версии механизм неактивен.
- Узлы, где куска никогда не было, считаются «разрушенными» (HP 0), поэтому даже у целой комнаты доля разрушенного не 0.
- Группа этажа рендера: бит этажа (этаж части + базовый этаж); сплошной блок в подвале (этаж < 0, узел центра = 254) рисуется как этаж −3 (`N_MIN_FLOOR`) — не срезается камерой.

## 16. Дискретные позиции и вспомогательные структуры

- `SDiscretePos` — сдвиг + поворот (0..3, FLIP = 4); правила — раздел 1. Матрица: перенос и поворот на 0/90/180/270° (FLIP — 0°), умноженная слева на внешнюю матрицу, если она задана.
- `RotationIDToAngle`: 0/1/2/3 → 0/90/180/270; иначе 45 (с ASSERT). `AngleToRotationID`: угол mod 360 → 0..3; иначе FLIP.
- `CNodeMap<T>`: плотный массив [этаж][y][x], индекс = (этаж − min)·W·H + y·W + x; проверка координат — по линейному индексу (раздел 3).
- `SPart`: (этаж 6 бит, x 13 бит, y 13 бит, все со знаком) в одном 32-битном слове; хеш = само слово.
- Пулевой хеш узла: раздел «Термины»; допустимые x, y ∈ [−4; 251], z ∈ [−20; 235].
- Хеш стыков схемы: z<<24 | y<<16 | x (без смещения — отрицательные координаты перекрываются старшими битами, коллизии ключа разрешаются таблицей); хеш колонки земли: y<<16 | x.

## 17. Отладочный просмотрщик схемы

Команда «viewSchema» (повторно — убрать): для каждого здания строится НОВАЯ схема по текущей решётке (с побочным эффектом: узлы низа и стен подвала получают 254), сортировка, один пересчёт без решётки (только устойчивость, свободные и моменты, без поломок).
- Стыки — сферы радиуса 0,15 м в точках (0,625·x, 0,625·y, 0,625·z) × матрица здания. Цвет: перегружен (давление > предела) и не земля/подвал — жёлтый (0,9; 0,9; 0); FREE — белый; STABLE: заполненный (0,2; 0,1; 0), незаполненный (0,3; 0,2; 0,1), земля — чёрный, стена подвала (0,30; 0,35; 0,30); UNKNOWN — серый 0,6; UNSTABLE — (0,7; 0,1; 0,1); UNKNOWN_MOMENT — (1; 1; 0,1); прочие (UNSTABLE_NOTFREE) — (1; 0,3; 1).
- Стержни — цилиндры радиуса 0,03 + 0,004·√M·k, где M — максимум |момента| двух концов по этому стержню, k = 5/√Mmax (или 1, если Mmax ≈ 0); цвет белый, если связь сломана у левого конца, иначе (0,05; 0,25; 0,3).
- В отладочный вывод: максимальный момент, максимальное давление, число стыков и стержней, суммарный вес.

Команда «checkStability» — одна итерация статики для всех зданий (N = 1).

## 18. Срез этажей

- В игре срез этажей — дело камеры и рендера («Мир 1»): у кусков здания маска этажа, рендер скрывает этажи выше среза. Решётка здания хранит свой «этаж среза» = nMaxFloor и в игре его не меняет.
- В редакторе (режим WYSIWYG): клавиши «этаж выше/ниже» меняют этаж среза сцены на ±1 и копируют его в решётку здания; чертёж помечается изменённым, мир обновляет срез. Построение описания (раздел 12) ПРОПУСКАЕТ фрагменты с ⌊z⌋ > этажа среза — они не попадают ни в модель, ни в ИИ (в редакторе срез физический, а не только визуальный). При открытии здания срез = максимальный этаж.
- Видимость слоёв (редактор): список видимых слоёв (пустой = все видимы); скрытые слои сплошных пропускаются, скрытый слой стен (тип 6, №0) убирает все стены. Флаг «видим только этаж среза» хранится, но построением не читается.

## 19. Сохранение и загрузка

Сохраняется:
- решётка целиком (теги 2–14, раздел 4), включая грязные части и зерно (зерно определяет варианты частей и материалы — поэтому здание после загрузки выглядит так же);
- карта стен и твёрдых тел — только ссылка на чертёж и зерно (содержимое пересчитывается);
- держатели описания — ссылки и флаг; само описание пересчитывается;
- объект здания: счётчик действия, `SMapBuilding` (вариант, матрица-узел, решётка, карта, этажи, точка выравнивания), RPG-объект (ссылка на решётку), части, счётчики сегментов и удержания, «идёт статика», исходная матрица, «без ИИ»;
- часть здания: SPart, родитель, счётчики фрагментов, «без ИИ».

Не сохраняется: структурная схема, список `brokenSpots`, вычисленные описания и меши.

Загрузка: если здание было сохранено во время обрушения («идёт статика» = да), то при первом сегменте `UpdateBuildingStability` найдёт решётку без схемы, построит её заново и продолжит. Тонкость сериализации решётки: в оригинале у решётки нет поля матрицы (матрица живёт в `SMapBuilding` и передаётся во `Explode` параметром) — иначе номера тегов сдвигаются.

## Все прихваты списком

- [ ] Решётка — 1 байт на узел, узлы через 0,625 м по всем осям; 4 плоскости на этаж, верх этажа k и низ этажа k+1 — одни и те же узлы.
- [ ] Куски только в узлах с нечётной суммой локальных координат: 22 позиции на блок, «шахматная» решётка; точки с чётной суммой — только точки соединения.
- [ ] HP куска = ⌈2·VP·V⌉; узел, общий для нескольких кусков, суммирует их HP (потолок 253).
- [ ] Прибавка HP передаётся байтом: ⌈HP⌉ > 255 заворачивается (толстая кирпичная стена: 263 → 7 HP на угловой кусок).
- [ ] DR ≤ 0 → узел 255 (неразрушим), включая стекло/траву/ткань (DR = 0); «землёй» в схеме становится только DR < 0.
- [ ] 255 + прибавка → 253: неразрушимый узел, которому позже прибавили HP, становится обычным.
- [ ] 254 (низ колонны/стена подвала) ставится при каждом построении схемы; первая схема строится при создании мира → фундамент (нижний ряд стен нулевого этажа и пол нулевого этажа) неуязвим с начала миссии, но авторские взрывы при сборке карты его разрушить могут.
- [ ] 254 ставится и в пустые узлы-точки соединения.
- [ ] При отключённой статике (`bStabilityUpdate` = false) решётка заливается 253 и HP не считаются.
- [ ] Структурная схема строится только из уцелевших кусков и выбрасывается, как только итерация ничего не сломала; не сохраняется.
- [ ] Статика учитывает только вес ВИСЯЩИХ частей: у полностью опёртого здания давления и моменты нулевые, стена не «раздавливает» себя.
- [ ] Устойчивость по «стрелам»: стык устойчив, если на одной прямой/диагонали по обе стороны есть устойчивые стыки, соединённые непрерывными стержнями того же слоя; только горизонтально, слой за слоем снизу вверх.
- [ ] Диагональ ищется только «сначала x, потом y», если сосед по x есть.
- [ ] Свободные области (без связи с опорой) убираются тихо; перегрузка и излом — с пылью и звуком.
- [ ] Распределение веса — случайные блуждания волн от опор с ГСЧ, у которого зерно всегда 1 (детерминированно); ёмкость стержня — 2 прохода; фронт, который может ветвиться, остаётся фронтом и повторно записывает ту же волну.
- [ ] Вес волны = 1/(число направлений без устойчивого соседа, считая пустые направления).
- [ ] Плечо момента — проекция на ось первого шага волны от опоры до массы, в узлах решётки (0,625 м), со знаком.
- [ ] Ломается: давление > `UltimatePressure` (у опоры), |момент| > `UltimateMoment` (связь по направлению); HP узла в правилах поломки не участвует (формула с HP закомментирована).
- [ ] Поломка точки соединения разрушает «ближайший» родительский кусок (первый неустойчивый, иначе последний живой) и режет стержень между ними.
- [ ] Стык с живыми вертикальными стержнями, но без горизонтальных, после разрушения соседнего стержня удаляется из схемы без разрушения узла (кусок остаётся висеть до следующего построения схемы или до признания свободным).
- [ ] Стыки без стержней удаляются при сбросе схемы; на следующей итерации, если их устойчивость устарела как UNKNOWN, — тихо уничтожаются.
- [ ] Вес стыка добавляется только при его создании: второй кусок в том же узле (угол соседних сегментов, верх стены + пол) свой вес теряет.
- [ ] «Земля» стекает вниз по вертикальным стержням при построении; неразрушимый материал получает флаг «земля» без смены состояния и становится опорой только после первого сброса.
- [ ] Стены подвала — узлы z ≤ 0 на границе ямы подвала или перепада «нижнего этажа»; вечные опоры.
- [ ] Ритм: дыра видна сразу; первая статика — через 5 сегментов (0,25 с); затем по одной итерации на сегмент, перестройка модели каждые 5 сегментов; после успокоения мир «занят» ещё 30 сегментов.
- [ ] При создании мира — до 99 итераций сразу; неуспокоившееся здание продолжает рушиться уже в игре.
- [ ] Попадание, не разрушившее узел, ничего не перестраивает.
- [ ] Обрушение, уложившееся в 4 итерации, появляется на экране одним скачком (перестройка модели только каждые 5 сегментов и в конце).
- [ ] У записей `Explosions` точка выравнивания по рельефу не инициализирована.
- [ ] Консоль из тонкой кирпичной стены держится до 2 блоков (2,5 м), на 3-м ломается по моменту у корня (пример 3).
- [ ] Мировой `Explode`: радиус = √P, но реально повреждается сфера R/2; урон P/d², полный ближе 1 м; порог P > 50; x, y точек отбора смещены от узлов на дробную часть `ptMin`; последний столбец/строка не обрабатываются.
- [ ] Боевые гранаты бьют здание не через `Explode`, а через попадания воксельного взрыва в куски (6.1).
- [ ] Коробка решётки в 1,6 раза шире здания (метры вместо тайлов) — влияет только на отсечение взрывов.
- [ ] Авторские взрывы применяются ко всем зданиям карты; мощность усечена до int; Radius делится пополам; радиус стадий объектов в 1,6 раза больше задуманного (тайлы против метров).
- [ ] Каждое здание получает зерно `GetTickCount()` → варианты частей и материалы разные при каждой генерации карты, но сохраняются в сейве.
- [ ] Встроенный объект (дверь/камин) выбирается отдельным потоком ГСЧ и с флагами — может принадлежать другому варианту части, чем нарисованный.
- [ ] Материалы фрагментов: две выборки `randStart` на каждый фрагмент до проверки выборочной перестройки → материалы стабильны при перестройке частей (но не при срезе этажей в редакторе).
- [ ] Перестраиваются только 27 частей вокруг разрушенного узла; пустая часть удаляется целиком (из рендера и ИИ).
- [ ] Два представления в ИИ-карте: слитое (видимость, укрытия, проходимость) и раздробленное (только TS_FRAGMENTED, номер = координаты узла) — пуля сразу знает, в какой узел попала.
- [ ] У слитого представления номер стены = фрагмент | 0x40000000, у сплошного — без флага (у неповреждаемых геометрий — с флагом).
- [ ] Вторая геометрия получает маску кусков первой и не подрезается.
- [ ] Подрезка стен: 8 бит на конец; 45° при одинаковой толщине и перпендикулярной встречной, по грани встречной — если она толще, по торцу сегмента — для продолжения/трёх одинаковых стен; о тонкую стену не режется; «скрытые стороны» в коде клиппера не используются, но входят в ключ кеша.
- [ ] Клиппер сваривает по сетке 1/4096 м, удаляет встречные пары полигонов (внутренние грани), упрощает копланарные полигоны, квантует нормали 1/16384 и UV 1/65536; результат кешируется по ключу {геометрия, слот, маска, субблок, код}.
- [ ] У сплошных поле кода в ключе кеша не инициализировано.
- [ ] Пыль — эффект 945 «BlockDestruct» на каждый узел; звуков — max(1, N/10) из 7 фиксированных ID; порядок вызовов ГСЧ: сначала звук, потом точка.
- [ ] Декали на здании переживают перестройку части (переносятся на новый меш по пользовательскому номеру).
- [ ] Изменение статической геометрии сбрасывает кеш динамического освещения (и он чистится сам при > 500 записях).
- [ ] Амбиент комнат по доле разрушенных узлов реализован, но не подключён; номера комнат здания не заполняются.
- [ ] Подвальная плита (этаж < 0, центр = 254) рисуется на этаже −3 и не срезается камерой.
- [ ] Редактор: срез этажей физически выкидывает фрагменты выше среза из модели и ИИ.
- [ ] `FixSmallPieceID` (слияние кусков < 0,01 м³) отключён ранним `return`.
- [ ] Индексная проверка «внутри карты» в карте стен/сплошных пропускает «завёрнутые» координаты.
- [ ] Ошибки, не влияющие на игру: `GetSize` пишет x дважды; `Point2Part` для отрицательных z, кратных 4, ошибается на этаж; `CreateGrids` — мёртвый цикл; `IsBroken` вычисляет неиспользуемый √HP.
- [ ] Рекурсия обхода свободных областей и выстрелов не ограничена глубиной (риск переполнения стека на огромных зданиях).

Объёмы кусков — из ресурса `AIGeometries.res`. ### Пример 1. HP одного куска кирпичной стены
- Середина сегмента (локально (1,0,2)), V = 0,059375 м³: HP = ⌈2 · 650 · 0,059375⌉ = ⌈77,1875⌉ = **78**.
- Нижний/верхний кусок (1,0,0)/(1,0,4), V = 0,0296875: ⌈38,59⌉ = **39**.
- Угловой кусок (0,0,1), V = 0,0546875: ⌈71,09⌉ = 72. На стыке двух соседних сегментов этот узел общий: 72 + 72 = **144**.
- Узел на уровне перекрытия над серединой сегмента: верх стены нижнего этажа 39 + низ стены верхнего этажа 39 = 78; если над этим местом лежит ещё и кирпичная плита пола (кусок плиты V = 0,0836219 → ⌈108,7⌉ = 109), узел получает 78 + 109 = 187.
- Тот же угловой кусок у кирпичной стены 0,3 м (геометрия 240, V = 0,2015625): 2·650·0,2015625 = 262,03 → ⌈⌉ = 263 → передаётся байтом → **7** (и 14 на стыке двух сегментов) — см. прихваты.
- Вес куска в схеме: середина 0,1 · 0,059375 · 1600 = 9,5; угол — 8,75; низ/верх — 4,75.
- Сколько попаданий: при структурном уроне попадания 40 (условное число; формула — «Бой 1») середина разрушается со 2-го попадания (78 → 38 → 0), общий угловой узел — с 4-го (144 → 104 → 64 → 24 → 0). Пока узел не разрушен, ничего не перестраивается.
- Нижний кусок нулевого этажа (z = 0) после построения первой схемы — 254 и неуязвим.

### Пример 2. Опора под пролётом в 3 блока
Конструкция (порядок фрагментов): A — стена нулевого этажа на x = 0..2; E — на x = 8..10; U1…U5 — стена первого этажа на x = 0..2, 2..4, 4..6, 6..8, 8..10. Над проёмом x = 2..8 (три блока, 3,75 м) висит стена второго яруса.

HP узлов: ряд z = 4 (уровень перекрытия): над A и E — 78 (39 + 39), над проёмом — 39 (только низ верхней стены); колонна x = 2 (общие углы A/U1/U2): z = 1, 3 — 72, z = 5, 7 — 144. Схема при создании мира: 79 стыков, 134 стержня, суммарный вес 298,5; неуязвимыми (254) стали (0,0,0), (1,0,0), (2,0,0), (8,0,0), (9,0,0), (10,0,0) — низ стен.

**До выстрела**, проход 1: слой z = 0 — «земля»; слои 1–3 устойчивы по вертикали в колоннах A и E; слой z = 4: стыки над A и E устойчивы по вертикали; (2,0,4) стреляет по +x — стрела XP пролетает по стыкам (3..10,0,4); (8,0,4) стреляет по −x — стрела XM пролетает по (7..0,0,4). Стыки (3..7,0,4) получают пару XP + XM → STABLE. Слои 5–8 — устойчивы по вертикали от слоя 4. Итерация ничего не ломает, схема выбрасывается. Пролёт держится как балка на двух опорах; давлений и моментов нет.

**Выстрел** (гранатой, все узлы сразу): разрушены углы и середина опоры E: (8,0,1), (10,0,1), (8,0,3), (10,0,3) (по 72 HP) и (9,0,2) (78). Нижний кусок (9,0,0) — 254, уцелел. Через 5 сегментов строится новая схема: 72 стыка, 118 стержней.

**Итерация 1.**
- Проход 1: (2,0,4) стреляет по +x, но встречной стрелы XM нет (опоры справа больше нет): у (5,0,4) только стрела XP → UNSTABLE; так весь ярус x = 3..10, z = 4..8, и обрывок (9,0,3) над разрушенной опорой. (9,0,1) устойчив — стоит на неуязвимом нижнем куске.
- Проход 2: всё неустойчивое — одна связная область, касающаяся колонны x = 2 → 41 стык UNSTABLE_NOTFREE общим весом 146,0.
- Проход 3: опоры-источники — 5 стыков колонны x = 2 на z = 4..8; у каждого неустойчивый сосед только по +x; «рёбра» без устойчивого соседа: XP, YP, YM (и UP у верхнего (2,0,8)) → веса волн 1/3, 1/3, 1/3, 1/3, 1/4. Волны прошли за 16 шагов. Пример раздачи: стык (9,0,6) (середина U5, вес 9,5) записал волны №2, №4, №0, №2 (сумма весов 1/3 + 1/4 + 1/3 + 1/3 = 1,25): опоре (2,0,6) достаётся 9,5·(2/3)/1,25 = 5,07, моменту XP добавляется 5,07 · (9 − 2) = 35,5; опоре (2,0,8) — 1,9, опоре (2,0,4) — 2,53.
- Итог по опорам: (2,0,4) давление 46,96, момент XP 223,6; (2,0,5) 17,39 / 37,9; (2,0,6) **52,99** / **283,4**; (2,0,7) 13,85 / 26,9; (2,0,8) 14,81 / 82,2. Сумма давлений = 146,0 = вес висящей части.
- Поломки (в порядке индексов стыков): (2,0,4): момент XP 223,6 > 140 → разрушается сосед по +x — кусок (3,0,4) (с пылью и звуком), стержень режется; (2,0,6): давление 52,99 > 50 → сам (2,0,6) — точка соединения, поэтому рушится его «ближайший заполненный» родитель: первые родители (2,0,5), (1,0,6), (2,0,7) устойчивы, первый неустойчивый — (3,0,6) → он разрушается.

**Итерация 2.** Остатки опираются на 3 стыка: (2,0,5) давление 37,24 / момент 195,5; (2,0,7) **59,0** / 296,9; (2,0,8) 35,5 / 147,3. Ломаются: связь (2,0,5)→+x (кусок (4,0,5) через точку (3,0,5)), сама опора-кусок (2,0,7) (давление), связь (2,0,8)→(3,0,8).

**Итерация 3.** Весь ярус x = 3..10 больше не связан с колонной → FREE; 16 «тихих» удалений (без пыли и звука; точки соединения удаляются через своих родителей).

**Итерация 4.** Ничего не меняется → схема выброшена. От пролёта остался обрубок над A ((2,0,8) — NOTFREE, держится); над E — только нижний кусок и точка (9,0,1). По времени (раздел 11): выстрел → сегмент 1 — видна дыра в опоре; сегмент 5 — построение схемы; сегменты 6, 7, 8 — итерации 1–3; сегмент 9 — итерация 4 «без изменений», схема выброшена и модель перестроена: всё обрушение появляется на экране одним скачком через 0,45 с после выстрела (промежуточная перестройка в сегменте 6 шла ДО итерации 1 и ничего нового не показала).

### Пример 3. Консоль и проверка момента
Конструкция: A — стена нулевого этажа на x = 0..2; над ней стена первого этажа U1 (x = 0..2) и продолжение в воздух U2, U3, U4 (по 1,25 м каждое).
- Вылет 1 блок (U1, U2): висящая часть — 10 стыков, вес 4,75 + 9,5 + 4,75 + 8,75 + 8,75 = 36,5. Опоры (2,0,4..8): давления 5,28 / 7,48 / 14,35 / 8,44 / 0,95; моменты XP 7,46 / 12,58 / **22,38** / 10,63 / 0,95. Максимум 22,4 < 140 — держится. (Если бы весь вес лёг на одну опору: Σ m·плечо = 4,75·1 + 9,5·1 + 4,75·1 + 8,75·2 + 8,75·2 = 54 — тоже держится.)
- Вылет 2 блока: вес 73,0; максимальный момент 66,6 (опора (2,0,4)), максимальное давление 22,5 — держится.
- Вылет 3 блока (3,75 м): вес 109,5; моменты опор 68,5 / 32,4 / **163,5** / 41,4 / 75,2; давление (2,0,6) 38,3. Проверка: |163,5| > 140 → у опоры (2,0,6) ломается связь по +x — кусок (3,0,6) разрушен. Дальше нагрузка перераспределяется на оставшиеся опоры: итерация 2 — (2,0,7) давление 55,4 > 50 → разрушен; итерация 3 — (2,0,4) давление 77,3 > 50 → рушится кусок (3,0,4); итерация 4 — (2,0,5) давление 80,7 → разрушен; итерация 5 — весь вес 95,25 на (1,0,8): давление 95,25 > 50 → разрушен; итерация 6 — консоль FREE, тихо удаляется.

Вывод: кирпичная тонкая стена держит консоль до 2 блоков (2,5 м); 3 блока ломаются у корня — сначала по моменту, затем «домино» по давлению.

### Пример 4. Стыки стен и коды подрезки
Все стены 0,1 м (ID толщины 1), группа подрезки 0. Узел N; в списках N: направление 2 (+x) — стена A, начинающаяся в N (сторона LEFT); направление 0 (−x) — стена B, кончающаяся в N (сторона RIGHT); направление 1 (+y) — стена C, начинающаяся в N (поворот 90°, LEFT).

**Т-стык трёх одинаковых стен.**
- A (i = 2): другие направления 0 (B, 0,1) и 1 (C, 0,1); главная встречная — первая найденная, направление 0. Список ширин {(2;0,1), (0;0,1), (1;0,1)} — 3 записи, In = 1 ≤ Own = 1 → особый случай; ширин, равных 0,1, — три (> 2); противоположное направление 0 занято стеной B той же группы → скрыть левую сторону (A начинается в N) → код = (1 << 4) | (1 << 1) = 0x12 = 18. Полный `nClip` A (правый конец свободен): 0x0201_1200.
- B (i = 0): встречная — направление 1 (C); особый случай; противоположное направление 2 (A) занято → скрыть правую сторону → код (2 << 4) | 2 = 0x22 = 34 (младший байт `nClip` B).
- C (i = 1): встречная — направление 0 (B); особый случай; противоположное направление 3 пусто → код 2.
- Плоскости: у всех In ≠ 0 и «не перпендикулярно» → A: x ≥ 0, C: x ≥ 0 (в своих системах), B: x ≤ 1,25. Все три стены обрезаны ровно по узлу; выступы 0,05 м убраны, торец C прячется внутри толщины A/B.

**Г-угол (только A и C).**
- A (i = 2): встречная — C (направление 1); записей 2 → не особый случай; 2 − 1 = 1 нечётно → перпендикулярно; top = таблица[2][3+1] = 1. Код = (1 << 3) | (1 << 1) | 1 = 11. Плоскость: левый конец, top, одинаковые толщины → n = (0,7071; −0,7071; 0), d = 0 — остаётся x ≥ y: внутренняя грань (y = +0,05) кончается в x = 0,05, внешняя (y = −0,05) продлена до x = −0,05.
- C (i = 1): встречная — A (направление 2); 1 − 2 = −1 → перпендикулярно; top = таблица[1][2] = 0. Код = 3. Плоскость n = (0,7071; 0,7071; 0), d = 0 — остаётся x + y ≥ 0 в системе C (у C ось y смотрит в мировое −x, то есть в сторону A). Получается чистый угол «в ус» 45°.

**Тонкая стена упирается в толстую (0,3 м, ID 3), проходящую насквозь** (B1 слева и B2 справа — толстые, C — тонкая вверх):
- C: встречная — B1 (направление 0, первая из двух равных 0,3); In = 3 > Own = 1 → особого случая нет; 1 − 0 нечётно → перпендикулярно, top = таблица[1][4] = 1; In не меньше Own → код = (1 << 3) | (3 << 1) | 1 = 15. Плоскость: In > Own → n = (1,0,0), d = 0,5·0,3 = 0,15 → тонкая стена начинается от грани толстой.
- B1 (i = 0, конец RIGHT): встречная — сначала C (0,1), затем B2 (0,3 > 0,1) → направление 2; ширин 0,3 в списке две (не > 2) → не особый случай; 0 − 2 чётно → продолжение; толщины равны, стороны разные (RIGHT против LEFT), своя RIGHT → скрыть правую; код = (2 << 4) | (3 << 1) = 38 → срез x ≤ 1,25.
- B2 (конец LEFT): код = (1 << 4) | (3 << 1) = 22 → срез x ≥ 0. Толстая стена не прерывается тонкой (о тонкую не режут), её сегменты стыкуются встык.

### Пример 5. Авторский и отладочный взрыв по решётке
- Запись `Explosions` №4: Power 1000, радиус 10 → повреждается сфера 5 м. Узел в 2 м от эпицентра: ⌊1000/4⌋ = 250 → разрушает любой обычный узел (≤ 253); в 3 м — 111 (середина тонкой кирпичной стены, 78, — разрушена; угол на стыке, 144, — остаётся 33); в 5 м — 40.
- Элемент «Explosion» Power 5000, Radius 2 → сфера 1 м, урон 5000 → вырезается всё, кроме 254/255.
- Отладочная команда «explode» (P = 100, R = √100 = 10 → сфера 5 м): урон 100 ближе 1 м, 25 в 2 м, 11 в 3 м — тонкая стена в упор теряет середину (78 < 100) и низ/верх (39), углы на стыках (144) выживают.

## Отклонения реконструкции от оригинала

В файлах среза нет блоков, помеченных [FORK]. Комментарии автора реконструкции в этих файлах описывают ПРИВЕДЕНИЕ кода к оригиналу (и здесь принято как оригинальное поведение): решётка без поля матрицы (сдвиг тегов сериализации), флаг подвала у каждого края стержня отдельно (раньше флаг вызова «перекрашивал» в землю всех соседей подвального узла), `Destroy` с флагом эффектов, восстановленная функция пыли и звуков обрушения с таблицей 7 звуков, `Explode` с матрицей параметром. Отличия, которые остаются:
1. `CWorld::RestoreRuntimeCaches` (wMain.cpp): после загрузки сохранения реконструкция пересчитывает описания зданий (`UpdateInfo` обоих держателей), а при повторном входе в зону вызывает полное `Update` здания (перестройка всех частей и включение цикла обновления). По комментарию автора, оригинальный путь загрузки здания не трогает.
2. Формат исходных вершин мешей: в этом дереве `SLoadVertex` хранит нормали несжатыми и упаковывает их при загрузке (в релизе — уже упакованные); результат тот же.
3. Загрузчик ИИ-геометрии читает релизный формат (чанк 13 — заранее посчитанные сферы вместо BSP-деревьев) — на здания не влияет.
4. Отладочный вывод времени построения схемы и числа итераций в системную консоль (с HTML-тегом размера шрифта) — косметика.

## Не установлено

1. Заворачивание ⌈HP⌉ > 255 при передаче байтом (MakeBuilding.cpp, `AddNodeHP` → `CBuildingGrid::AddHP(const SPoint3&, BYTE)`): следует из типа параметра и поведения компилятора MSVC, в бинарнике оригинала не проверено.

7. Что делает ИИ-карта с номерами кусков, которых нет в геометрии (раздробление целого субблока даёт все 22 номера) — предположительно пропускает («ИИ 3», не проверено).

9. Объёмы и стыки кусков взяты из ресурсного пакета `AIGeometries.res` установленной игры (чанк 4 каждой геометрии); значения плотностей и пределов — из редакторской базы ноября 2003 года (в релизной `game.db` могут отличаться отдельные ячейки).
