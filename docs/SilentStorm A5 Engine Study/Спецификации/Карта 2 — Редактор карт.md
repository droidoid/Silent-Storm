## Суть

Редактор карт Silent Storm (MapEdit) — MFC-приложение, внутри которого крутится настоящий игровой движок: 3D-окно рисует зону тем же рендером и теми же загрузчиками, что и игра, а редактор подменяет игровой мир «миром редактора» без игровой логики. Дизайнер работает с **вариантом шаблона** — прямоугольником W × H тайлов по 0,625 м: лепит рельеф кистями, рисует стены ломаной по осям (они сами режутся на модульные детали и поворачиваются внутренней стороной внутрь), заливает плиты перекрытий и крыш, красит стороны деталей материалами, клеит декали, перетаскивает из деревьев базы объекты, персонажей и другие шаблоны (вложенные шаблоны показываются выбранным вариантом вместе с их рельефом и зданиями), ставит вейпоинты и маршруты, сохраняет камеры. Каждая правка мгновенно пишется — либо в SQL-базу контента (объекты, юниты, вложенные шаблоны, пятна, вейпоинты, свойства всех записей), либо в бинарные файлы по ID варианта (постройка, рельеф, вейпоинты, маршруты) — при записи файлы чистятся от удалённого и некорректного. Модель выделения едина для всех сущностей: 32-битный userID в коллизии, задержка 0,2 с перед переносом, CapsLock — привязка к тайлу, Shift — поворот, Z — высота, Ctrl — добавление и шаг 45°. Есть неограниченная отмена правок 3D-окна, системный буфер обмена между этажами и зонами, создание нового шаблона из выделения, 2D-план для стен/полов/комнат/рельефа, декларативная схема из 79 деревьев базы с инспектором свойств, экспорт ресурсов из Maya и мягкое предупреждение о совместном редактировании.

## Термины и единицы

| Термин | Значение |
|---|---|
| Тайл | Узел/клетка сетки 0,625 м (`FP_GRID_STEP`). Позиции фрагментов, юнитов, вейпоинтов, объектов в базе — в тайлах; позиции вложенных шаблонов в памяти — в метрах (угол), в базе — центр в тайлах. |
| Строительная клетка | 2 × 2 тайла = 1,25 м; единица `SizeX`/`SizeY` детали. |
| Этаж | 2,5 м (`WALL_HEIGHT`). Полуэтаж — z = этаж + 0,5 (промежуточные слои). Четверть этажа = 0,625 м — шаг переноса по высоте. |
| Единица высоты рельефа | 1/64 м (`FP_TERRAIN_H_SCALE`), 16 бит без знака. |
| Шаблон / вариант | Запись `Templates` (размер W × H тайлов, папка) / запись `TemplVariants` (содержимое). Зона — шаблон верхнего уровня. |
| Вложенный шаблон (подшаблон) | Запись `Rects` в варианте: ссылка на шаблон, центр, поворот, этаж, `DeltaZ`, атрибуты-требования. |
| Деталь | Запись `ConstructionPartTemplates` (с вариантами `ConstructionParts`): модуль здания; `SizeY = 0` — стена, иначе плита/сплошной блок. Во фрагмент пишется ID шаблона детали; вариант выбирается случайно по `RndWeight`. |
| Фрагмент | Элемент постройки `SBuildFragment` (стена — один 2-тайловый подблок детали; плита — деталь целиком). Хранится в файле `Buildings\<ID варианта>`. |
| Подблок | Номер 2-тайлового куска детали `GetPartHashID(1+k, 1, 1)` = (1+k)·2⁷ + 2¹⁰ + 2¹³ (сдвиги, объединённые побитовым «или»). |
| Слой | ID = тип·65536 + номер (сдвиг типа на 16 бит, «или» номер); типы `LID_*` (перекрытия 0, промежуточные 1, сплошные 2, промежуточные сплошные 3, комнаты 4, … стены 6, тайлы 7, высоты 8, альфа 9, трава 10, …). |
| userID | 32-битная метка пикируемого объекта: тип кисти·2²⁴ + номер (сдвиг на 24 бита, «или» номер; раздел 4). |
| Мир редактора | `CEditorWorld` — реализация игрового интерфейса мира без игровой логики, только показ и пиккинг. |
| WYSIWYG | Режим 3D-окна, в котором правится зона (`CWysiwyg`); противоположность — просмотрщик (`CMapViewer`). |
| Расстановка | `CPlacement` — представление варианта для 2D-вида. |
| Пин | ID варианта вложенного шаблона, выбранного для показа в текущем сеансе (не хранится). |
| Каталог экспорта | Корень бинарных данных игры (`W:\complete\` по умолчанию); каталог исходников — `W:\Art\ForComplete\`. |
| Округление `Float2Int` | Округление к ближайшему (режим FPU по умолчанию). «Целая часть» в тексте — отбрасывание дроби (к нулю). |
| Углы | Поворот деталей — код 0…3 (0°/90°/180°/270°); объекты/юниты/шаблоны — градусы (float), положительный — против часовой стрелки на плане с осью Y вверх. |

## 1. Архитектура: MFC-окно со встроенным игровым циклом и рендером

### Назначение
Редактор — это не отдельный «редакторский» движок, а игровой движок, встроенный в MDI-окно MFC. Всё, что видит дизайнер в 3D-окне, рисует тот же рендер, те же загрузчики зданий, рельефа и объектов, что и в игре; редактор лишь подменяет игровой мир «миром редактора» и подаёт в игровой цикл свои «интерфейсы» (экраны) вместо игровых.

### Данные
- Приложение `CTEditApp` (файл `MapEdit.cpp`): активный элемент `activeItem` = {номер дерева-таблицы, ID записи, ID варианта, список свойств, указатель на «расстановку» `CPlacement`}; активный этаж `nActiveFloor` (целое, −2…4); флаги `bInputActive`, `bGameActive`, `bShadows`, `bCameraReset`, `bRealtimePreview`; глубина сбора вложенных шаблонов для 2D-вида `nMaxTreeDepth` (из реестра `TemplateDepth`, по умолчанию 0); история переходов «назад/вперёд» по парам (таблица, запись).
- Главное окно `CMainFrame` — «workbook» из MDI-окон: `GRID_VIEW` (старый 2D-вид шаблона на клеточной сетке, `ChildView`), `GAME_VIEW` (3D-окно `CGameView`), `PARAMS_VIEW` (параметры), `UI_VIEW`, `CHAPTER_VIEW`, `SCENARIO_VIEW`, `GLOBALMAP_VIEW`, `DIPLOMACY_VIEW`; плюс пристыкованные панели: деревья ресурсов (базы данных), инспектор свойств `PropView`, «быстрый просмотр» иконки, список слоёв, панель кисти здания (`WysiwygBar`), панель рисования (`PaintBar`), панель выбора варианта.
- 3D-окно `CGameView` владеет устройством Direct3D 8, DirectInput (буфер 128 событий), звуком FMod; при создании регистрирует каталог ресурсов `<рабочий каталог>\res`, запускает поток фоновой загрузки ресурсов, импортирует игровую базу (`UpdateGameDB`), читает `.\cfg\autoexec.cfg` и включает секцию привязок `mapeditor`.
- Интерфейсы игрового цикла, которые подставляет редактор:
  - `CMapViewer` (`iMapEditor.cpp`) — «просмотрщик» отдельного ресурса: модели, текстуры, материала (куб и сфера рядом), геометрии с показом AI-геометрии, анимации (с маркерами точки выстрела), частиц, звука, предмета, персонажа, головы, объекта по стадиям разрушения, детали здания, контейнера, интерфейса и т. д.; плюс режим `VIEW_PLACEMENT` — полный случайный прогон сборки карты, как в игре («Roll»).
  - `CWysiwyg` (`IWysiwyg.cpp`) — собственно редактор зоны «что видишь, то и получаешь» поверх мира редактора `CEditorWorld`.
  - `CICAIView` — просмотр AI-карты (сетки проходимости) текущего мира.
  - `CICMapEditBeginMission` — запуск миссии прямо из редактора (кнопка «Run game»).
- Мир редактора `CEditorWorld` (`wEditor.cpp`) реализует игровой интерфейс мира `IWorld`, но почти все игровые методы — заглушки (нет игроков, ходов, дипломатии, взрывов). Он держит: рельеф `CEditorTerrain`, одно «главное» здание зоны (сетка здания + карта стен/сплошных + информация о постройке), списки показываемых объектов (фрагменты-«замороженные» меши, объекты зоны, юниты, лестницы, вейпоинты, пятна, «пустые» сплошные блоки, вложенные шаблоны), оси начала координат, AI-карту (для пиккинга) и сеть путей.

### Алгоритм
1. Запуск (`InitInstance`): ключ реестра `Software\Nival Interactive\A5 MapEdit\`; если сохранённая версия ≠ `"0.050"` — раскладка окон сбрасывается; параметр командной строки `-clean` сбрасывает её всегда, `-nogamedb` отключает загрузку игровой базы (3D-окно тогда ничего не рисует). Рабочий стол обязан быть в 32-битном цвете, иначе выход с сообщением. Открывается сокет совместного редактирования (раздел 22). Соединение с базой: при неудаче — окно выбора сервера базы, выбор сохраняется в профиле `DB`; отказ — выход. Текущий каталог ставится в каталог экспорта. Загружаются деревья ресурсов и менеджер шаблонов, создаются браузеры, восстанавливается раскладка, показывается «совет дня».
2. Игровой цикл крутится из `OnIdle` MFC: каждый второй вызов простоя (счётчик `RENDER_DELAY` = 1) выполняется один шаг `StepApp(активен, главное окно активно)`. «Активен» = при включённом «Realtime preview» — когда активное MDI-окно есть 3D-окно, иначе — когда у 3D-окна есть фокус ввода. Если шаг вернул «ложь», в очередь ставится команда снять верхний интерфейс. Перед шагом прокачиваются сообщения DirectInput.
3. Фокус: щелчок левой/правой в 3D-окне, получение фокуса — `bInputActive = bGameActive = истина`; потеря фокуса — ложь. Нажатие Alt (системные клавиши) перехватывается главным окном и возвращает фокус 3D-окну.
4. Выбор элемента в дереве (`SetActiveItem`): запись в историю, «сохранить всё», освобождение старых свойств; если уходили с шаблона — закрыть «расстановку» (`ClosePlacement`); у элементов «с вариантами» (шаблоны, детали зданий и т. п.) заполняется панель вариантов и активируется сохранённый или первый вариант; иначе вызывается обработчик дерева (`pSelectCb`), который переключает набор окон и подаёт в цикл нужный интерфейс. Затем два шага цикла с ожиданием, пока фоновые запросы файлов не опустеют. Для шаблона — `OpenPlacement` (захват общей зоны, раздел 22).
5. Открытие варианта шаблона: окна PARAMS + (если включён 2D-вид) GRID + GAME; кэш «расстановок» вложенных шаблонов собирается рекурсивно до глубины `nMaxTreeDepth` (берётся первый вариант каждого вложенного шаблона); в 3D-окне — `SetRootPlacement`: в режиме WYSIWYG создаётся интерфейс `CWysiwyg` с камерой над центром шаблона, иначе — `CMapViewer` в режиме полной сборки.
6. Начальная камера над шаблоном (`GetBestCameraPos`): l = целое(0,625 · max(ширина, высота)); высота z = 4 + (l сдвиг вправо на 1) / tg 17,5°, не меньше 5; якорь — центр шаблона; тангаж −89°, рыскание 0. Обратите внимание: l обрезается до целого метра и делится пополам целочисленно. При «camera_reset» внутри WYSIWYG та же формула считается без обрезки: l = 0,5·max(ширина, высота в метрах).
7. Создание WYSIWYG-интерфейса: мир редактора строится вызовом `CreateRandom(вариант)` с флагом «облегчённо»; сцена в «быстром режиме»; направленный свет и амбиент берутся из настроек освещения редактора (раздел 15); камера «Maya» со скоростью из реестра (по умолчанию 1,0); создаются: модель выделения, кисть материалов, кисть рельефа, маршруты, анимация камеры, перетаскивание; плоскость отсечения этажей ставится на максимальный этаж мира. Ближняя/дальняя плоскости 0,1 / 200 м, угол обзора `N_FOV` = 35°.
8. Шаг WYSIWYG-интерфейса: обновить анимацию камеры; мир рендерится через тот же `IRenderGame`, что и в игре; дважды пускается луч из курсора — один только по рельефу, второй по всему; кисть рельефа получает точку на рельефе; модель выделения получает объект под курсором (если не зажат Alt); обрабатывается клавиатурный сдвиг/поворот; очищающий цвет (0,55; 0,55; 0,55); поверх рисуются рамки выделения и сетка; в режиме «последовательность» (`ME_SEQUENCE_MODE`) — киношные полосы сверху и снизу высотой 111 пикселей на 768 (текстура 3135).
9. Частичные обновления сцены (вместо полной пересборки): мир копит три списка «грязных» прямоугольников — геометрия рельефа, текстура рельефа, трава (инвалидация травы автоматически инвалидирует и текстуру). В `UpdateWorld` при наличии грязных прямоугольников заново строится информация о рельефе (`BuildTerrain` с глубиной вложенности = глубина подшаблонов + 1), затем перестраиваются только эти регионы (метры переводятся в тайлы умножением на 1/0,625 с отбрасыванием дроби). Если изменился список дыр/стен подвалов (при включённом показе дыр) — рельеф пересоздаётся целиком. Изменение геометрии рельефа требует синхронизации AI-карты. Пока дизайнер тащит объект мышью, обновление рельефа выключено (если не включён параметр `ME_INSTANT_TERRAIN`) и делается один раз при отпускании кнопки.
10. Отдельные точечные обновления по событиям: `UpdateObject(id)`, `UpdateUnit(id)`, `UpdateSubTemplate(userID)`, `UpdateWaypoints`, `UpdateLadders`, `UpdateWallSpot`, `UpdateBuilding`, `UpdateFakeSolids`, `UpdateCutFloor`. Каждое ищет объект в своём списке по ID; если запись базы исчезла — удаляет его из сцены; если не нашёл — считает объект «только что добавленным» и создаёт. После каждого — синхронизация AI-карты (пиккинг идёт по ней).
11. Выравнивание по рельефу (`bTerrainAlign`): если в информации о постройке нет ни одного фрагмента стены и ни одного сплошного фрагмента, каждый объект ставится на высоту рельефа в своей точке; иначе вся зона поднимается на одну постоянную высоту — высоту рельефа в центре шаблона (здание стоит ровно). Флаг пересчитывается в каждом `UpdateWorld`; при его смене вся сцена обновляется.
12. Связь MFC → движок идёт через очередь событий ввода: пункты меню и диалоги не трогают мир напрямую, а кладут именованное событие (`NInput::PostEvent("new_waypoint")` и т. п.) и при необходимости прокручивают цикл; интерфейс `CWysiwyg` ловит событие по имени через `CBind`. Обратная связь — через объект пользовательских настроек (`GetUserSettingsSetup().SendMessage`): выбор, правка, обновление списка слоёв.
13. Диалоги из контекстного меню открываются не из обработчика, а через таймер 10 мс («если вызывать диалог из этого обработчика, возникают глюки»).

### Особые случаи и прихваты
- Мир редактора поднимает зону с постройкой на высоту рельефа в центре шаблона, а «пустую» зону (только рельеф и объекты) кладёт на рельеф поточечно (п. 11).
- Сетка здания создаётся с запасом по 10 этажей вверх и вниз и на 2 тайла шире зоны, чтобы не пересоздавать её при каждом мазке.
- Режим полной сборки (`VIEW_PLACEMENT`) строит мир через обычный игровой `CreateRandom` с параметрами сборки из реестра (`REG_MAPBUILD_ARG`, строка через запятую) — это «как в игре», включая случайный выбор вариантов вложенных шаблонов.
- «Run game» отказывается запускать шаблон меньше 9×9 тайлов («Too small map»); создаётся глобальная игра с одним игроком.
- Опция `ME_SWITCH_SYSCOLORS` пересчитывает системные цвета Windows через приближённое sRGB→линейное преобразование (f ≤ 0,1047 → f/4, иначе ((f+0,1466)/1,1466)^2,4) на время активности редактора и восстанавливает при деактивации — чтобы интерфейс выглядел так же, как в «линейном» рендере.

### Что нужно от движка-носителя
Возможность запустить игровой мир в «редакторском» режиме без игровой логики; рендер в окно редактора; луч-пиккинг по коллизионной/AI-геометрии с пользовательским 32-битным ID на каждом объекте; частичная перестройка ландшафта по прямоугольнику; очередь именованных событий между UI и миром.

## 2. Документ редактора: зона, шаблон, вариант, этажи; открытие и сохранение

### Назначение
Определить, что дизайнер «открывает» и что «сохраняет»: в редакторе нет файла-документа, есть **вариант шаблона** из базы, собранный из записей таблиц и нескольких бинарных файлов.

### Данные
- Единица редактирования — вариант (`TemplVariants.ID`) шаблона (`Templates`): размер W × H тайлов (тайл 0,625 м), набор свойств варианта (раздел 18). Зона — это обычный шаблон верхнего уровня (тот же формат, что у дома, леса или комнаты).
- Содержимое варианта: записи `Rects` (вложенные шаблоны), `FinalElements` (объекты), `Units`, `TerrainSpots`, `Waypoints` (+ файлы), `RoomParams`, «старые» `Explosions`; файлы `Buildings\<ID>` (постройка), `Terrain\<ID>` (рельеф), `Waypoints\<ID>`, `Units\<ID>`/`Groups\<ID>` (маршруты).
- В памяти 2D-вида — «расстановка» `CPlacement`: прямоугольники, юниты, объекты, взрывы по этажам −10…10 (`MIN_FLOOR`…`MAX_FLOOR`), планы стен и полов по (тип, этаж, слой), комнаты, ссылка на загрузчик рельефа.
- Этажи: 2,5 м каждый; кнопки на панели — этажи −2, −1, 0, 1, 2, 3, 4 (активный этаж приложения); полуэтаж — +0,5 для промежуточных слоёв (раздел 7); плоскость отсечения этажей в 3D (`cut floor`) — отдельный счётчик (Num +/−), при открытии = максимальный этаж мира.

### Алгоритм
1. **Открыть**: выбрать шаблон в дереве «Templates» → в панели вариантов появляются его варианты (по одной кнопке на вариант) → активируется ранее активный вариант (если есть) или первый. Открытие варианта: «сохранить всё», освободить предыдущую расстановку, проверить совместное редактирование и записать себя в `SharedMaps` (раздел 22), загрузить расстановку, собрать кэш вложенных шаблонов для 2D, создать WYSIWYG-мир и подать его в 3D-окно (раздел 1). Заголовок окна 2D-вида: «<имя>: W x H».
2. **Сохранить**: явного действия нет — каждое изменение пишется сразу (раздел 19). Команда «Save all» (`OnFileSaveall`) лишь дописывает отложенные изменения записей деревьев и шаблонов; данные 2D-слоёв рельефа сохраняются при закрытии вида, смене шаблона и по их собственным уведомлениям.
3. **Закрыть**: при переходе к другому элементу или выходе — удалить свою строку из `SharedMaps`, освободить расстановку.
4. **Проверить в игре**: «Update game»/«Roll» — переимпорт базы и пересборка вида; «Run game» — запуск миссии на этом варианте прямо в окне (шаблон не меньше 9 × 9); режим `VIEW_PLACEMENT` (WYSIWYG выключен) показывает зону собранной так, как её соберёт игра (со случайным выбором вариантов вложенных шаблонов и параметрами сборки из настроек).

### Особые случаи и прихваты
- 2D-вид может быть выключен (настройка `REG_SHOW2DVIEW`); тогда расстановка не грузит прямоугольники/юниты/объекты (они нужны только 2D-виду), а WYSIWYG работает напрямую с базой.
- История «назад/вперёд» хранит пары (дерево, запись), а не варианты.

### Что нужно от движка-носителя
Открытие «уровня» как набора записей и файлов по ID варианта; мгновенная запись правок; режим «собрать как в игре» для проверки случайности.

## 3. Режимы, панели, слои и кисти

### Назначение
Общее состояние инструментов, разделяемое 2D-видом и 3D-окном: режим, активный слой и его кисть, этаж, поворот, размер пера, наборы материалов, видимость слоёв, параметры.

### Данные
- **Режимы** (`EEditMode`): `EM_SELECT` (выделение и постановка), `EM_GEOMETRY` (кнопка есть, обработки в 3D нет), `EM_MATERIAL` (покраска), `EM_RECTANGULAR_SELECTION`, `EM_ZOOM` и `EM_PAN` (только 2D), `EM_FILL` (заливка в 2D-слоях тайлов/подвала), `EM_ERASE` (стирание), `EM_SELECTMATERIAL` (пипетка — кладётся на «стек» поверх текущего режима и снимается после взятия материала; глубина стека 1).
- **Режим переноса** (`EMoveMode`): XY или Z (кнопки панели); есть также XZ, YZ, X, Y, Z, но используются только XY и Z.
- **Слой** — ID = тип << 16 | номер. Список слоёв 2D-вида по умолчанию: «Sub templates», «Units», «Objects», «Walls» (одиночные), «Cellar», «Floors», «Intermediate floors», «Solids» (скрыт), «Intermediate solids» (скрыт), «Texture», «Height map», «Terrain holes», «Alpha», «Rooms», «Grass» (скрыт), «Terrain color map», «Terrain spots» (скрыт). Слои перекрытий, сплошных, травы и пятен рельефа могут быть множественными (номер слоя). Видимость слоёв управляет и 3D: фрагменты невидимого слоя не рисуются и не пикируются; рельеф виден, если видим хоть один из слоёв высот, тайлов, цветовой карты.
- **Кисть слоя**: выбранная запись дерева (деталь, тайл, трава, материал пятна…) — у каждого слоя своя; выбор в дереве при активном слое ставит кисть. Для слоёв без 2D-элемента (вейпоинты, камеры, объекты) кисть хранится в таблице «слой → ID».
- **Поворот** — комбобокс 0/90/180/270 на панели рисования.
- **Перо** — 1, 2, 3 (`SetBrushSize` 0/1/2): 2D — квадраты 1×1, 2×2, 5×5 тайлов; 3D — круги радиусом 0,3 / 0,7 / 3,0 м.
- **Сетка** — показ (реестр `GRID_SEC`), шаг = 0,625 × `GridInterval`, высота сетки 0 или (минимальная высота рельефа + активный этаж × 2,5) при `GridSnap`, опущена на 0,02 м.
- **Параметры** (`Params` в реестре, значение — биты float):

| параметр | имя в реестре | умолчание | смысл |
|---|---|---|---|
| `ME_SUBTEMPLATE_ALPHA` | SubtemplateAlpha | 0,2 | прозрачность ящиков вложенных шаблонов |
| `ME_SWITCH_SYSCOLORS` | SwitchSysColors | 0 | перекраска системных цветов Windows |
| `ME_OBJECTS_SHOWGROUND` | ObjectsShowGround | 0 | плита-«земля» под объектом в просмотрщике (куб модели 1411, 10 × 10 × 1) |
| `ME_SHOW_AISPHERES` | ShowAISpheres | 1 | показывать сферы масс AI-геометрии |
| `ME_DEF_ANIM_MODEL` | DefAnimModel | −1 | модель для просмотра анимаций |
| `ME_INSTANT_TERRAIN` | InstantTerrainPreview | 0 | перестраивать рельеф во время перетаскивания |
| `ME_GRASS_DENSITY` | GrassDensity | 0 | текущая плотность кисти травы |
| `ME_GRID_INTERVAL` | GridInterval | 1 | шаг сетки в тайлах (0…16) |
| `ME_LOCK_SELECTION` | LockSelection | 0 | замок выделения |
| `ME_KBDMOVE_SPEED` | KmdMoveSpeed | 1 | скорость клавиатурного сдвига |
| `ME_GRID_SNAP_2FLOOR` | GridSnap | 0 | сетка на высоте активного этажа |
| `ME_SEQUENCE_MODE` | SequenceMode | 0 | киношные полосы и окно 4:3 |
| `ME_ANIM_SHOWFLAGS` | AnimShowFlags | 1 | окно флагов анимации |
| `ME_TERRAIN_SHOWHOLES` | ShowHoles | 0 | показывать дыры рельефа в 3D |
| `ME_PERS_FACEGENCAMERA` | FaceGenCamera | 0 | камера лица для персонажа |
| `ME_SCRIPT_SYNAXCOLORING` | SyntaxColouring | 1 | подсветка Lua |
| `ME_SHOW_OBJ_BROWSER` | ShowObjBr | 0 | браузер стадий объекта |
| `ME_SHOW_CUSTOMFRAME` / `_WIDTH` / `_HEIGHT` | ShowCustomFrame … | 0 / — / — | рамка иконки предмета |

### Алгоритм
1. Выбор активного слоя в списке слоёв (2D) определяет, что делает щелчок в обоих видах: строительный слой — постановка/заливка деталей; слой рельефа — кисть рельефа; «Sub templates», «Units», «Objects» — расстановка; «Spots» — слой новых пятен рельефа. Если активного слоя нет — считается «Floors» 0.
2. Смена активного этажа (кнопки −2…4): событие «active_floor_changed» (сетка перерисовывается) и пересборка 2D-вида; плоскость отсечения в 3D не меняется.
3. «Set game aspect ratio» — подогнать высоту окна под 4:3 и переключить режим «последовательность» (кадры для роликов).
4. Добавление слоя — диалог со списком типов (одиночные типы, которые уже есть, не предлагаются; «Alpha» добавляется вместе с картой высот); удаление слоя — с подтверждением (не все типы можно удалять).

### Особые случаи и прихваты
- `GridInterval` = 0 допустим (зажим 0…16), но тогда шаг сетки 0 и цикл рисования сетки не завершится (зависание) — не подтверждено, что так было в оригинале, но код именно такой.
- Сетка рисуется вложенным циклом по (x, y) и выводит каждую линию многократно (по разу на каждый шаг другой оси).
- `EM_GEOMETRY` — кнопка без обработчика в 3D.

### Что нужно от движка-носителя
Единое состояние инструментов (режим, слой, кисть, этаж, поворот, размер), параметры редактора с сохранением между сеансами.

## 4. Модель выделения: userID, выбор мышью, привязка, перенос, поворот, удаление

### Назначение
Единая модель «выделил — потащил — повернул — удалил — скопировал» для всех сущностей зоны: фрагментов здания, объектов, юнитов, вейпоинтов, лестниц, вложенных шаблонов, пятен на стенах и на рельефе.

### Данные
**userID.** Каждый пикируемый объект сцены несёт 32-битный ID: `userID = тип << 24 | номер`, номер — младшие 24 бита. Типы (`EBrushType`, битовые маски, чтобы складываться в «маску выделения»):

| тип | код | номер в младших битах |
|---|---|---|
| `BT_GEOMETRY` | 0x1 | индекс фрагмента; у стен дополнительно бит 0x40000000 (в самом userID фрагментов здания тип не кодируется — их узнают по классу объекта «здание»); бит 0x20000000 — «вторая геометрия» |
| `BT_SUBTEMPLATE` | 0x2 | ID записи прямоугольника вложенного шаблона |
| `BT_TEXSPOT` | 0x4 | «ID пятна» = тип (стена/рельеф) + индекс + ручка (центр/углы) |
| `BT_WAYPOINT` | 0x8 | ID вейпоинта |
| `BT_OBJECT` | 0x10 | ID записи `FinalElements` |
| `BT_WALLSPOT` | 0x20 | (маска выделения: выбрано пятно на стене) |
| `BT_LADDER` | 0x40 | ID лестницы внутри информации о постройке |
| `BT_TERRAIN` | 0x80 | — (попадание в рельеф: у треугольника рельефа нет владельца) |
| `BT_MATERIAL` | 0x100 | — |
| `BT_UNIT` | 0x200 | (юниты узнаются по классу объекта) |
| `BT_TERRHOLE` | 0x400 | — |

Индекс фрагмента: `userID & ~0x60000000` (срезаются два служебных бита); стена — если установлен 0x40000000, тогда индекс относится к массиву стен, иначе к массиву сплошных/полов.

**Выделенный объект** (`CSelectedObj`) умеет: равенство с (объект, userID) и с «ID выделения»; отложенное удаление; рамку (текущую и «движущуюся»); дискретность сдвига (в тайлах), поворота (в градусах), высоты (в четвертях этажа); начало/ход/конец переноса с откатом; поворот и поворот вокруг точки; двойной щелчок; сведения для панели свойств (тип, ID кисти, ID объекта, позиция, поворот, этаж); копирование в буфер. Классы: `CFragmentSel` (фрагмент здания), `CObjectSel` (объект), `CUnitSel`, `CWaypoint`, `CLadderSel`, `CSubTemplateSel`, `CSpotSel` (пятно на стене), `CTerrSpot` (пятно на рельефе).

**Модель выделения** (`CSelection`): список выделенных; действие текущего перетаскивания (`A_MOVE`, `A_MOVE_Z`, `A_ROTATE`, `A_FILL`, `A_RECTSEL`); тайл и высота под курсором в момент нажатия; прямоугольник рамочного выделения; время последнего выбора; размер мира в тайлах; накопленный клавиатурный сдвиг и поворот.

### Алгоритм
**Пиккинг.** Луч из камеры через курсор (`MakeProjectiveRay`, FOV 35°) трассируется по AI-карте мира (в ней все видимые объекты и вспомогательные меши с userID) — получается список интервалов. Список сортируется: два вложенных шаблона сравниваются функцией `CompareSubtemplates` (выше этаж — раньше; иначе по вложенности прямоугольников: если ни один не содержит хотя бы двух углов другого — порядок не меняется, иначе раньше идёт тот, у которого меньше углов другого внутри, т. е. внутренний); если только один из пары — вложенный шаблон: при активном слое «подшаблоны» он идёт первым, иначе — последним (после всего, кроме рельефа). Затем берётся первый интервал, у которого расстояние вдоль оси взгляда (t · (направление луча · направление на центр экрана)) больше ближней плоскости 0,1 м. Пиккинг выполняется дважды на каждый кадр и щелчок: только по рельефу и по всему.

**Щелчок левой кнопкой** (только если окно в фокусе, курсор строго внутри клиентской области и не зажат Alt) — по режиму редактирования:
- `EM_SELECT`: если активный слой — слой рельефа, щелчок уходит кисти рельефа (раздел 14). Иначе без Ctrl — «выбрать» (см. ниже); с Ctrl — добавить/убрать объект к выделению (если выделение пусто и в активном слое выбрана кисть — ничего, начнётся заливка `A_FILL`).
- `EM_MATERIAL`: снять выделение, покрасить материалом (раздел 12). `EM_SELECTMATERIAL`: «пипетка» — взять материал с поверхности и вернуться в предыдущий режим (стек режимов).
- `EM_ERASE`: только для слоёв рельефа — стирание кистью.
- `EM_RECTANGULAR_SELECTION`: без Ctrl снять выделение.
- Остальные режимы: снять выделение.
Затем (если щелчок не ушёл кисти рельефа) модель выделения получает «кнопка нажата».

**Выбрать объект** (`Select`): если под курсором ничего — снять выделение. Если объект уже выделен (для пятна при этом запоминается, за какую ручку схватили), с Ctrl (и без Shift) — переключить его членство; без Ctrl, если не выделен — заменить выделение им. Двойной щелчок = второй щелчок по уже выделенному объекту менее чем через 0,4 с после предыдущего щелчка; вызывает действие объекта: фрагмент — окно свойств фрагмента (материалы, флаги); объект — переключение «открыто/закрыто» (двери, окна, сундуки, раздел 11); юнит, вейпоинт, лестница — окно правки; вложенный шаблон — переход к его записи в дереве.

**Определение действия при нажатии** (`GetAction`): в режиме выделения на слое рельефа — всегда «перенос»; Shift — поворот; режим «рамка» — рамка; выделение было пусто, режим «выделение» и нет Ctrl — рамка; выделение было пусто, режим «выделение» и Ctrl — заливка (`A_FILL`, раздел 6); клавиша Z — перенос по высоте; иначе перенос. Действие пересчитывается каждый кадр; если оно сменилось посреди перетаскивания (нажали/отпустили Shift или Z), текущий перенос завершается, а для переноса — сразу начинается новый с «уже прошедшей» задержкой.

**Задержка начала переноса.** После выбора объект можно тащить только через `START_MOVE_TIME` = 0,2 с; при отпускании раньше перенос не фиксируется. Это защищает от случайного сдвига при щелчке.

**Перенос мышью** (`Move`): плоскость переноса — горизонталь на высоте центра рамки выделения (в этажах: z центра / 2,5) или на активном этаже, если выделение пусто; плоскость поднимается на высоту рельефа в центре шаблона. Тайл под курсором при нажатии запоминается; смещение = (тайл под курсором − тайл нажатия). Режимы сдвига: `MM_XY` (по плоскости) и `MM_Z` (по высоте: смещение = высота точки луча над точкой нажатия минус высота в момент нажатия). Квантование: если максимальная «дискретность сдвига» среди выделенных > 0 — смещение округляется до целых тайлов; дискретность по высоте (в четвертях этажа = 0,625 м) — если CapsLock включён и дискретность 0, берётся 1; смещение по высоте округляется до кратного. Затем смещение зажимается так, чтобы рамка выделения не вышла за карту (`CheckPos`, с допуском 1e-5). Каждому выделенному передаётся смещение и флаг «по тайлам» = CapsLock (кроме режима Z). Дискретности по типам (сдвиг в тайлах / поворот в градусах / высота в четвертях этажа): фрагмент здания 1 / 90 / 4; лестница 1 / 90 / 0; юнит 1 / 0 / 0; объект, вложенный шаблон, вейпоинт, пятна 0 / 0 / 0. Берётся максимум по выделению: если в выделении есть хоть один фрагмент, вся группа сдвигается по целым тайлам и поворачивается кратно 90°.

**Правила переноса по типам:**
- Фрагмент здания: при ходе — смещение переводится в целые тайлы с ограничением карты (`CheckTilePos`: округлить смещение до тайла, не дать дальнему углу рамки выйти за ширину/высоту, ближнему — меньше 0); при завершении — x, y отбрасыванием дроби в тайлы, z = min(4, целое(dz / 2,5)) этажей. Если сдвиг ненулевой — позиция меняется, min/max этаж постройки расширяется, перестраиваются затронутые куски сетки здания, пишется отмена «смена позиции».
- Объект: с CapsLock позиция = целая часть (отбрасывание) новой позиции в тайлах; без — свободно (дробные тайлы). Высота — `fDZ` + смещение; этаж пересчитывается по центру рамки: этаж = пол(центр z / 2,5), `fDZ` уменьшается на разницу этажей × 2,5, этаж ≤ 4. x, y зажимаются в [0, ширина]×[0, высота] тайлов. Сразу пишется в базу (`FinalElements`: позиция, `fDZ`, этаж, поворот); при ошибке записи — откат.
- Юнит: позиция всегда в целых тайлах (округление), этаж = min(4, этаж + dz / 2,5), x, y зажимаются в [0, ширина]×[0, высота]; запись в базу `Units` при завершении.
- Вейпоинт: позиция в целых тайлах (округление); сохраняется в отдельный файл вейпоинта (раздел 15).
- Лестница: всегда с привязкой к тайлу (округление); высоты начала и конца сдвигаются на dz; если |высота начала| > 2,5 — этаж лестницы сдвигается на целое число этажей, высоты корректируются; позиция зажимается в карту; отмена для лестниц не пишется.
- Вложенный шаблон: с CapsLock — по целым тайлам (отбрасывание); высота: `fDZ` += dz; если `fDZ` ≥ 1,26 — этаж += ceil(fDZ/2,5), если `fDZ` < −1,24 — этаж += floor(fDZ/2,5), `fDZ` уменьшается соответственно; этаж ≤ 4; рельеф под шаблоном пересчитывается при отпускании кнопки.

**Поворот мышью** (Shift + тащить): угол = −0,7 × (смещение курсора по вертикали в пикселях), градусы; если у выделенных есть «дискретность поворота» — угол округляется до кратного ей. Каждый выделенный поворачивается вокруг центра рамки выделения, запомненного при нажатии. Объекты/юниты/шаблоны: угол = исходный + поворот, с Ctrl — `45 · целое((исходный + поворот)/45)`. Фрагменты здания: угол отбрасыванием приводится к кратному 90 (отрицательный → 360 + угол); центр вращения округляется до тайла; позиция фрагмента поворачивается вокруг центра, из неё вычитается сдвиг привязки для нового поворота (для деталей с ненулевой глубиной: 90° → (2·sy, 0), 180° → (2·sx, 2·sy), 270° → (0, 2·sx), где sx, sy — размеры детали в «строительных» клетках по 2 тайла; если исходный поворот 90/270 — sx и sy меняются местами); код поворота складывается. Лестница — поворот кратно 90. Во время поворота рисуется квадратная рамка (большая из полуширин по x, y).

**Клавиатура.** Клавиши «selection_move_x/y/z» и «selection_rotate» дают оси: первый шаг при включённом CapsLock — сдвиг на 0,8 × 0,625 м по знаку оси (гарантированно «перескочить» в соседний тайл), далее — смещение = ось × `ME_KBDMOVE_SPEED` (зажато в 0,01…100); поворот = 20 × ось. Начало/конец клавиатурного переноса и поворота оборачиваются одной группой отмены. Команда «rotate» — мгновенный поворот выделения на 90°. «move_selection» — перенести выделение так, чтобы центр рамки совпал с точкой, введённой в панели.

**Рамочное выделение** (`A_RECTSEL`): прямоугольник от тайла нажатия до текущего (в плоскости активного этажа); выбираются строго внутри прямоугольника (границы не включаются) и только на этаже пол(активный этаж): объекты (если видим слой объектов), пятна рельефа (если видим их слой), вложенные шаблоны (по точке-углу, если видим слой), юниты, стены (по точке начала фрагмента, если видим слой стен) и пятна на стенах (по точке-началу, без проверки этажа; начало пятна в метрах сравнивается с рамкой в тайлах — ошибка оригинала), сплошные фрагменты (если видим их слой). Вейпоинты рамкой не выбираются. Выделение, бывшее до нажатия, сохраняется и дополняется; пересчёт — только если прямоугольник изменился больше чем на 0,01 (сумма квадратов разностей координат). Рисуется пунктиром (штрих 0,2 м) на высоте активного этажа + 0,1 м.

**Выделить всё**: стены и сплошные фрагменты видимых слоёв (а также фрагменты без слоя −1 и со «слоем» > 100), объекты (если слой видим), пятна рельефа видимых слоёв, вложенные шаблоны и юниты (если их слои видимы), все вейпоинты. Лестницы собираются в список, но функция принудительного выделения список лестниц не обрабатывает — лестницы не выделяются (и выпадают из выделения при его дополнении рамкой). Пятна на стенах не включаются.

**Удаление** (`DeleteSelected`): одной группой отмены для каждого выделенного — «отложенное удаление»: фрагмент здания не вынимается из массива, а помечается `nConstructionPartID = −1` (индексы остальных не сдвигаются; чистка — при запекании, раздел 19); объект, юнит, вложенный шаблон — удаляются из базы и обнуляются в списке варианта; лестница — вынимается из массива; вейпоинт — удаляется из дерева вейпоинтов и его файл; затем, если удалялось здание, информация о постройке сериализуется и главное здание пересоздаётся (скрыть/показать). Выделение очищается.

**Замок выделения** (`ME_LOCK_SELECTION`, пункт меню): пока включён, «снять выделение» ничего не делает (удобно при переходах между окнами).

**Подсказка вставки.** Пока выделение пусто, активен строительный слой, режим «выделение» и в слое выбрана деталь — под курсором рисуется желтоватая рамка (цвет (1; 1; 0,7)) будущей детали в её активном повороте, привязанная к тайлу и зажатая в карту.

**Рисование выделения.** Рамка выделенного — каркас ящика цвета (0,6; 1; 0,7), расширенного на 0,01 м; у фрагментов здания — ещё «основная» рамка (только клетки, отмеченные как основные в маске подчастей детали) цветом 0,7 от основного и полупрозрачные кубы (0,5; 0,5; 0,7; 0,2) и (0,5; 0,5; 0,3; 0,2). Рамка юнита: половина 0,25 × 0,25 × 0,9 м, центр на 0,9 м над полом. Рамка вейпоинта: 0,05 × 0,05 × 0,75, поднята на 0,75. Рамка вложенного шаблона: вертикальные рёбра высотой 1,1 × 2,5 м, поднята на 0,05 м (`SUBTEMPL_DHEIGHT`).

### Формулы
- Тайл под курсором: t = −(z₀ − (этаж·2,5 + h_рельефа_в_центре)) / d_z; точка = (x₀ + t·d_x, y₀ + t·d_y). Если |d_z| < ε — (−1, −1).
- Высота точки луча над точкой O на плане: t = (a·b)/(a·a), где a — горизонтальная проекция направления, b = O − начало луча; z = z₀ + d_z·t.
- `CheckPos(рамка, смещение, размер)`: смещение зажимается в [−(min рамки)+ε; 0,625·размер − (max рамки)−ε] по каждой оси.
- Центрирование камеры на выделении («center»): якорь = центр рамки (с поправкой на высоту рельефа), дистанция = 3 + радиус сферы рамки / tg(π/8).

### Особые случаи и прихваты
- CapsLock — это «привязка к тайлу» (`TileAlign` читает состояние переключателя CapsLock, а не нажатие клавиши); Ctrl — дискретный поворот 45° и добавление к выделению; Shift — поворот; Z — перенос по высоте; Alt — свободная камера (щелчки и обновление выделения игнорируются).
- Удалённый фрагмент здания остаётся в массиве с ID детали −1, иначе сломались бы userID остальных фрагментов (они — индексы массива).
- Перенос объекта пишет в базу на каждое отпускание; перенос фрагмента — сериализует файл постройки; перенос вейпоинта — файл вейпоинта; лестницы правятся в памяти и сохраняются вместе с постройкой.
- Ошибка оригинала: в `CLadderSel` проверка типа написана как присваивание (`type = BT_LADDER`), поэтому всегда истинна — безвредно.
- Ошибка оригинала: отмена поворота юнита (`CUnitSel::Cancel`) пишет в базу x вместо y (передаётся `ptPos.x` дважды).
- Перемещение лестницы и её удаление не попадают в историю отмены.
- Рамочное выделение не выбирает вейпоинты (цикл пустой) и выбирает пятна на стенах без учёта этажа.

### Что нужно от движка-носителя
Луч-пиккинг по всем объектам редактора с 32-битной меткой; сортировка попаданий с приоритетом активного слоя; «гизмо» переноса с режимами плоскость/высота, квантованием по тайлу (0,625 м) и по четверти этажа (0,625 м), с зажимом в границы зоны; поворот вокруг общего центра с шагом 90° для деталей здания и 45° по модификатору для остальных.

## 5. Буфер обмена: копирование и вставка между этажами и зонами

### Назначение
Копировать часть зоны (стены, полы, объекты, юнитов, вложенные шаблоны, пятна рельефа) на другой этаж той же зоны, в другую зону и в новый шаблон.

### Данные
Буфер — собственный формат буфера обмена Windows `"A5_WYSIWYG_DATA"`; содержимое сериализуется структурой: активный этаж в момент копирования (целая часть); минимальный этаж выделения (начальное значение 10); полные копии фрагментов здания (со всеми материалами, флагами, списком пятен); **ID** записей объектов (`FinalElements`); полные копии пятен рельефа; пятна на стенах; полные копии лестниц; **ID** записей юнитов; **ID** записей прямоугольников вложенных шаблонов. Минимальный этаж обновляется при добавлении фрагмента (пол(z)), объекта, юнита и шаблона (их этаж).

### Алгоритм
1. Копирование («copy»): каждый выделенный добавляет себя в буфер; буфер записывается в буфер обмена Windows с активным этажом = пол(активный этаж) и очищается.
2. Вставка («paste») одной группой отмены:
   1. Δэтаж = активный этаж сейчас − активный этаж при копировании.
   2. Фрагменты: если в буфере есть фрагменты — размеры информации о постройке ставятся равными размерам шаблона; массивы карты комнат и подвала подгоняются под размер; каждому фрагменту — новый ID, z += Δэтаж; стены (деталь глубины 0) — в массив стен, остальные — в массив сплошных (с проверкой, что слой фрагмента виден — иначе событие «обновить список слоёв»); отмена «вставка»; min/max этаж постройки расширяется на этаж + 0,5 (целая часть).
   3. Объекты: для каждого ID — новая запись `FinalElements` в целевом варианте с тем же объектом; все дополнительные свойства копируются через шесть менеджеров объектов (обычный, масштабируемый, взрыв, проход, дверь/окно, мина); позиция та же, этаж + Δэтаж, `fDZ` и поворот те же.
   4. Пятна рельефа — новые записи (`TerrainSpots`) с той же позицией (этаж не сдвигается).
   5. Пятна на стенах и лестницы **не вставляются** (функция вставки пятен пуста, функции вставки лестниц нет).
   6. Вложенные шаблоны — новая запись прямоугольника с тем же шаблоном, этаж + Δэтаж; юниты — новая запись `Units` с тем же монстром, этаж + Δэтаж.
3. Вставленное становится выделением и переносится: целевая точка — тайл под курсором на этаже «минимальный этаж выделения» из буфера (если он не задан — активный этаж). С выравниванием по левому верхнему углу: смещение = цель − левый верхний угол рамки (min x, max y). Если у выделенных есть дискретность сдвига — смещение округляется до тайлов **отбрасыванием** (x → целое(x), y → целое(y − 0,5)). Затем зажим в карту и для каждого выделенного «начать — протащить — завершить» (пятна сдвигаются напрямую). Постройка сериализуется, сцена обновляется полностью.
4. Вставка в новый шаблон («template_paste», раздел 16): курсор считается недействительным (−1, −1); цель = левый верхний угол такой, чтобы рамка выделения стояла по центру шаблона: x = 0,5·(W − ширина рамки в тайлах), y = H − 0,5·(H − высота рамки в тайлах), × 0,625; смещение всегда округляется как выше.

### Особые случаи и прихваты
- Объекты, юниты и шаблоны копируются ссылкой на ID исходной записи: если исходник удалить до вставки, он не вставится.
- Буфер — системный, поэтому вставка работает между зонами и даже между двумя копиями редактора на одной машине.
- Δэтаж считается от активного этажа, а не от этажа выделения: скопировав со 2-го этажа при активном 0, при вставке на активном 1 получите сдвиг всех этажей на +1.
- Пятна на стенах и лестницы в буфер попадают, но при вставке теряются.

### Что нужно от движка-носителя
Сериализуемый буфер «кусок зоны» с относительными координатами и сдвигом этажа; создание новых записей с копированием всех свойств исходных.

## 6. Стены: цепочка рисования, слияние, нарезка на детали, внутренняя сторона, переворот

### Назначение
Рисовать стены здания «ломаной» по сетке, с автоматической нарезкой на стандартные детали (ConstructionParts) и правильной ориентацией внутренней стороны. Стены можно рисовать в двух местах: в 2D-виде шаблона (слой «Walls», основной способ) и в 3D-окне заливкой прямоугольника (`A_FILL`) или поштучно.

### Данные
- Деталь стены — запись `ConstructionParts` с `SizeY = 0` (глубина 0 = «стена»; любая деталь с `SizeY > 0` — «сплошная» или пол). `SizeX` — длина в «строительных клетках» по 2 тайла (1,25 м), `SizeZ` — высота в этажах, `Thickness` — толщина, `UserColor` — цвет в 2D-виде. Выбор не-стены в слое стен отвергается («Only wall can be selected»).
- Фрагмент стены (`SBuildFragment`): ID детали, `nSubBlockID` = хеш подблока `GetPartHashID(1+k, 1, 1)` = (1+k)<<7 | 1<<10 | 1<<13 (k — номер 2-тайлового куска вдоль детали, с нуля), позиция (x, y в тайлах; z в этажах; полуэтаж = +0,5), поворот (0…3 = 0°/90°/180°/270°), слой (`MakeFragmentID(тип, индекс)` = тип << 16 | индекс), флаги встроенного объекта (`OF_OPEN` = 1 — дверь/окно открыты), 8 слотов материалов, список ID пятен, сквозной ID.
- Ориентация по умолчанию (поворот 0): деталь лежит вдоль +X от своей точки, **внутренняя сторона смотрит в +Y**. Вектор протяжки подблока для поворотов 0/90/180/270: (2,0), (0,2), (−2,0), (0,−2) тайла.
- План стен этажа (`CWallsPlan`): хеш «(x, y, поворот) → фрагмент» по всем фрагментам стен с целой частью z = этаж.

### Алгоритм (2D-вид, слой «Walls»)
1. Нажатие левой кнопки: мышь захватывается, курсор ограничивается прямоугольником шаблона (+1 пиксель слева, справа и снизу). Цепочка начинается с узла сетки под курсором (целые координаты тайла).
2. Каждое движение мыши (`WallMove`): точка переводится в узел сетки; новая вершина цепочки появляется, только если сдвиг от последней вершины **кратен длине детали в тайлах** L = 2·`SizeX` (размер кисти слоя, `SBrush.nSizeX`) по одной из осей (`CrossNearestBorder`): сначала проверяется X (если x ≠ x_посл и (x_посл − x) делится на длину — точка прижимается к y_посл, ход горизонтальный), иначе Y (аналогично, x прижимается к x_посл). Так цепочка всегда идёт **только по осям** и шагами, кратными длине детали.
3. Откат: если новая вершина совпадает с предпоследней вершиной цепочки — последняя вершина удаляется (ведение мыши назад «стирает» цепочку). Иначе вершина добавляется.
4. Escape или правая кнопка — отмена, цепочка выбрасывается. Цепочка рисуется XOR-линией толщиной 2 пикселя цвета (150, 155, 0).
5. Отпускание левой кнопки (`WallEnd`, нужно ≥ 2 вершин): слияние коллинеарных: начало = v0, конец = v1; для каждой следующей вершины vi — если она на одной прямой с (начало, конец) (векторное произведение (конец − начало) × (vi − начало) = 0), конец = vi; иначе отрезок (начало, конец) выдаётся, начало = конец, конец = vi. В конце выдаётся последний отрезок. Все отрезки передаются в `AddWalls(деталь, отрезки)`.
6. Нарезка отрезка (`PlaceWall`), длина детали в тайлах L = 2·SizeX:
   1. Число деталей n = округлить(|конец − начало|) / L (целочисленное деление: хвост короче детали отбрасывается).
   2. Шаг d = (конец − начало) / n. Если у шага отрицательная компонента — начало и конец меняются местами, шаг берётся по модулю (детали всегда раскладываются в положительном направлении осей).
   3. Поворот и сдвиг первой детали (`WallPosition`, по **исходному** направлению рисования): горизонталь справа налево (x_конец < x_начало) — поворот 0°, сдвиг 0; горизонталь слева направо — поворот 180°, сдвиг (L, 0); вертикаль сверху вниз (y_начало > y_конец) — поворот 90°, сдвиг 0; снизу вверх — поворот 270°, сдвиг (0, L). Итог: **внутренняя сторона всегда справа по ходу рисования** — чтобы стены смотрели внутрь, дом обводят по часовой стрелке.
   4. Для j = 0…n−1: начало детали = (начало + сдвиг) + j·d; деталь режется на SizeX фрагментов-подблоков: фрагмент k имеет позицию начало_детали + k·(вектор протяжки поворота) и `nSubBlockID = GetPartHashID(1+k, 1, 1)`. Каждый фрагмент кладётся в план (хеш по (x, y, поворот) — повторное рисование поверх перезаписывает) и в массив стен информации о постройке.
7. После всех отрезков — сохранение «расстановки» (`Save`: карта комнат пересобирается, информация о постройке сериализуется в файл, раздел 19).

**Выбор и правка стен в 2D.** Щелчок выбирает ближайшую стену: расстояние от точки до отрезка фрагмента (проекция t ∈ (0; 1) — до прямой, иначе до ближайшего конца), не дальше `MAX_SELECTION_DIST` = 1 тайл; деталь выбранной стены показывается в дереве. Рамкой выбираются стены, у которых оба конца строго внутри рамки. Правая кнопка — меню: «Flip» и «Delete» (если выделение пусто — берётся стена под курсором).
- **Удаление** (2D): фрагмент ищется по полному совпадению (деталь, подблок, позиция, поворот, слой) и вынимается из массива стен; план и файл постройки обновляются.
- **Переворот** («вывернуть наизнанку», `Flip`): копия фрагмента; фрагмент удаляется; позиция сдвигается на вектор протяжки (на другой конец 2-тайлового куска); поворот меняется на противоположный (0↔180, 90↔270); фрагмент добавляется вновь. Отрезок остаётся на месте, внутренняя сторона меняется.

**Отрисовка в 2D.** Толщина пера = ширина стены в пикселях (не меньше 1). Внутренняя сторона показывается штриховкой, смещённой вправо от направления фрагмента (при ширине 1 — пунктир сдвинутой линией, иначе прямоугольник шириной в толщину стены со штриховкой «крест-накрест»); сама линия — цветом `UserColor` детали (кэшируется; при «неактивном» слое — серым, среднее трёх каналов).

### Алгоритм (3D-окно)
1. **Поштучно**: в режиме «выделение» при пустом выделении щелчок без протаскивания (рамка < 0,05 м) ставит выбранную деталь активного слоя (`AddObject`): позиция = тайл под курсором на активном этаже с зажимом рамки детали в карту (`CheckTilePos`), поворот — активный (комбобокс 0/90/180/270 на панели), этаж — активный (полуэтаж для «промежуточных» слоёв: +0,5).
2. **Заливка прямоугольником** (Ctrl + протащить по пустому выделению, `A_FILL`): углы — тайлы нажатия и отпускания. Для стены: шаг = 2·SizeX тайла; число деталей по X: nX = целое(|Δx| / шаг), по Y: nY = целое(|Δy| / шаг) (**по Y тоже делится на шаг X** — для стен глубина 0); угол = старт + знак·n·шаг; прямоугольник обрезается в [0; размер шаблона]. Затем обводка против часовой стрелки с внутренней стороной внутрь: низ — поворот 0, от (minx, miny) шагом (2,0); верх — поворот 180, от (maxx, maxy) шагом (−2,0), только если nY > 0; правая сторона — поворот 90, от (maxx, miny) шагом (0,2); левая — поворот 270, от (minx, maxy) шагом (0,−2), только если nX > 0. Каждая сторона: nX (или nY) деталей по SizeX подблоков. Во время протаскивания показывается предпросмотр моделями детали и пунктирная рамка цвета (1; 1; 0,7).
3. Вставка детали (`AddFragment`): позиция зажимается в карту и делится на 0,625 (тайлы); если деталь «сплошная» (SizeY ≠ 0) — один фрагмент в массив сплошных с хешем 0, отмена «вставка», обновление куска сетки здания в точке (позиция + повёрнутый вектор (1,1)) на высоте z·4+1, min/max этаж = этаж + 0,5 + SizeZ (целое); если стена — SizeX фрагментов шагом повёрнутого (2,0) с хешами (1+k, 1, 1), каждый со своей отменой (одной группой). Новый слой, которого нет среди видимых, вызывает пересборку списка слоёв.

### Формулы
- `GetPartHashID(x, y, z)` = z<<13 | y<<10 | x<<7; «нераздроблённая деталь» — младшие 7 бит = 0; первый подблок = `GetPartHashID(1,1,1)` = 9344.
- Ключ хеша стены в 2D: ((поворот / 90) << 30) + (y << 15) + x — поскольку поворот хранится кодом 0…3, деление на 90 всегда даёт 0 (поворот в хеш-функцию фактически не входит, но участвует в сравнении ключей).

### Константы

| имя | значение | смысл | источник |
|---|---|---|---|
| `MAX_SELECTION_DIST` | 1,0 тайла | радиус выбора стены в 2D | `WallsLayer.cpp` |
| `WALL_MAX_LEN` | 7 | максимальная длина детали (в клетках), движок | `BuildingInfo.h` |
| строительная клетка | 2 тайла = 1,25 м | единица `SizeX/SizeY` | код |
| цвет цепочки | RGB(150,155,0), XOR, 2 px | | `WallsLayer.cpp` |

### Особые случаи и прихваты
- Внутренняя сторона стены — справа по ходу рисования (в 2D) и «внутрь прямоугольника» при 3D-заливке; хранится не флагом, а поворотом фрагмента (+Y детали — внутрь).
- Длина отрезка, не кратная длине детали, молча укорачивается (целочисленное деление).
- Выделение и удаление в 2D работают с отдельными 2-тайловыми фрагментами, а не с деталями целиком.
- Повторное рисование по тому же месту с тем же поворотом в 2D-плане перезаписывает запись хеша, но в массив информации о постройке фрагмент добавляется ещё раз — дубликат (чистка дубликатов при сохранении не делается, не подтверждено, что игра их игнорирует).
- 3D-заливка стен считает число деталей по Y делением на шаг X (у стены глубина 0 — делить на неё нельзя).
- У фрагмента есть конструктор, обнуляющий только ID; при рисовании стен в 2D не заполняются слой (`nFragmentID`) и флаги объекта (`nObjectFlags`), при постановке в 3D — флаги объекта. Поэтому код «выделить всё» и рамки считает фрагмент «без слоя», если его номер слоя −1 **или больше 100** (в отладочной сборке мусор = 0xCCCCCCCC → номер слоя 52428). Что именно оказывалось в этих полях в релизной сборке — не подтверждено.

### Что нужно от движка-носителя
Сетка 0,625 м с «строительной клеткой» 1,25 м; модульные детали стен, ориентированные «внутрь» по +Y; инструмент ломаной по осям с откатом и слиянием коллинеарных отрезков.

## 7. Полы и сплошные заливки (полуэтажи, слои)

### Назначение
Покрывать этаж плитами перекрытий, ставить «сплошные» блоки (крыши, лестничные марши, колонны, ступени и т. п.), в том числе на полуэтаже, и раскладывать их по независимым слоям.

### Данные
- Четыре типа слоёв постройки (числа совпадают с `EFloorType`, «не менять порядок»): `LID_FLOORS` = 0 (перекрытия), `LID_FLOORS_INTERM` = 1 (промежуточные перекрытия на полэтажа выше), `LID_SOLIDS` = 2 (сплошные), `LID_SOLIDS_INTERM` = 3 (промежуточные сплошные). У каждого типа может быть несколько пронумерованных слоёв (индекс 0, 1, 2…; имя «Floors1» и т. п.). ID слоя = тип << 16 | индекс; он же записывается в каждый фрагмент (`nFragmentID`).
- Деталь пола/сплошного — `ConstructionParts` с `SizeY > 0`; клетка рисования = (2·SizeX) × (2·SizeY) тайлов (поворот в размере клетки 2D-вида **не учитывается** — всегда как при 0°).
- План пола (`CFloorPlan`, на каждый (тип, этаж, слой)): карта W×H «клетка → (ID детали, индекс в списке)» и списки клеток по деталям; удалённая клетка помечается x = −1.
- Этаж фрагмента: целый этаж; для промежуточных типов — этаж + 0,5.
- Группы слоёв (`SLayerGroup` = список ID слоёв + список этажей): слои одной группы при сборке здания клиппятся как один слой, а перечисленные этажи сводятся к общему этажу клиппинга (сам механизм — «Мир 2 — Здания и разрушение.md»).

### Алгоритм (2D-вид)
1. Нажатие (режимы «выделение» или «стирание»): мышь захватывается, курсор ограничивается шаблоном. Первая клетка = (целое(x), целое(y)) под курсором; если клетка не помещается в шаблон (x + ширина клетки > W или y + высота > H) — отказ.
2. При движении новая клетка добавляется, если смещение от последней добавленной кратно размеру клетки по обеим осям (|dx| mod ширина = 0 и |dy| mod высота = 0, хотя бы одно ненулевое) и клетка помещается в шаблон. Получается «штамп» по решётке, привязанной к первой клетке. Клетки сразу рисуются штриховкой цвета детали (стирание — белым, ID −10). Escape/правая кнопка — отмена.
3. Отпускание: в режиме стирания — `DeleteCells`, иначе `AddCells`:
   - `AddCells`: для каждой клетки внутри шаблона — если в ней уже эта же деталь, пропуск; если другая — старая помечается удалённой и делается попытка убрать её фрагмент из информации о постройке (см. прихват); клетка записывается; в массив сплошных добавляется фрагмент (позиция клетки, этаж/полуэтаж, активный поворот, слой, хеш подблока 0). Затем сохранение.
   - `DeleteCells`: для каждой занятой клетки фрагмент ищется по полному совпадению и вынимается из массива сплошных; клетка освобождается; сохранение.
4. При наведении в режиме «выделение» рисуется XOR-рамка размера клетки (подсказка кисти).
5. Рамкой выделяются все клетки рамки; Delete удаляет фрагменты в выделенных клетках.

**Связывание слоёв** (флажок «link» у слоя в списке): если слой — активный, ничего не делать; иначе слой удаляется из своей группы и добавляется в группу активного слоя (если у активного группы нет — создаётся из двух). **Связывание этажей** (флажки этажей −2…4 на панели слоёв): этажи записываются в группу активного слоя (или создаётся новая группа из одного слоя). Группы сохраняются в информацию о постройке; при сохранении удаляются пустые группы и группы из одного слоя без этажей.

### Алгоритм (3D-окно)
Поштучная постановка и заливка прямоугольником — как в разделе 6, но для сплошной детали: заливка кладёт решётку деталей с шагом (2·SizeX, 2·SizeY) по прямоугольнику, обрезанному в шаблон, в активном повороте; число деталей по Y считается делением на шаг X, а цикл идёт с шагом Y (для неквадратных деталей прямоугольник округляется по X-шагу). Для деталей с поворотом 90/180/270 точка привязки сдвигается: 90° → (2·SizeY, 0), 180° → (2·SizeX, 2·SizeY), 270° → (0, 2·SizeX) тайлов (поворот вокруг угла клетки).

### Особые случаи и прихваты
- Полуэтаж — это не отдельный этаж, а z = этаж + 0,5 у фрагментов промежуточных слоёв; активный этаж в 3D автоматически получает +0,5, если активен промежуточный слой.
- «Сплошные» фрагменты без собственной геометрии (детали-«пустышки», например, для разметки) в 3D рисуются полупрозрачными кубами (0,6; 0,6; 0,65; 0,6) размером SizeX·1,25 × SizeY·1,25 × SizeZ·2,5 м с userID `BT_GEOMETRY|индекс` — их можно выбрать и двигать.
- Ошибка оригинала в 2D: при закрашивании клетки другой деталью удаление старого фрагмента ищет фрагмент с ID **новой** детали, поэтому не находит; старый фрагмент остаётся в данных (два фрагмента в одной клетке), пропадает только из 2D-плана текущего сеанса.
- Слои «Solids» и «Intermediate solids» по умолчанию скрыты (в списке слоёв создаются невидимыми).

### Что нужно от движка-носителя
Слои построек с ID (тип, номер), видимость по слоям, полуэтажи (+1,25 м), групповой клиппинг слоёв.

## 8. Комнаты

### Назначение
Разметить помещения этажа: номер комнаты нужен игре для звука, освещения и поведения ИИ внутри здания (потребители — другие спецификации).

### Данные
- Таблица `RoomParams` (база): ID (счётчик), `VariantID`, `Floor`, `RoomID` (номер комнаты внутри (вариант, этаж)), `UserColor` (цвет в редакторе).
- В информации о постройке — `roomMap`: по массиву байтов на каждый этаж от `nMinFloor` до `nMaxFloor`, размер (W+2) × (H+2) — по краю добавлена полоса в 1 тайл; значение клетки (x+1, y+1) = номер комнаты, 0 — вне комнат.

### Алгоритм
1. Кисть слоя «Rooms» выбирается в диалоге списка комнат активного этажа (элементы окрашены цветом комнаты). Кнопка «новая комната»: номер = MAX(RoomID) по (вариант, этаж) + 1, если комнат нет — 1; запись в `RoomParams` с цветом RGB(0,0,0). Кнопка цвета — стандартный выбор цвета, запись `UserColor`.
2. Рисование — тем же механизмом, что полы (раздел 7), клеткой 1 × 1 тайл; фрагменты в массив сплошных не пишутся.
3. При каждом сохранении расстановки (`Save`) карта комнат для всех этажей от min до max пересобирается из планов комнат: массив обнуляется (и при необходимости расширяется до (W+2)×(H+2)), каждая живая клетка (x, y) пишет номер комнаты в [y+1][x+1].

### Особые случаи и прихваты
- Номер комнаты — байт; нумерация своя на каждом этаже.
- Число этажей карты комнат = max − min + 1; при сохранении постройки массив пересоздаётся (с потерей содержимого), если число этажей изменилось (`FixRoomMapSize`).

### Что нужно от движка-носителя
Растровая разметка помещений по тайлам на каждый этаж.

## 9. Подвалы и маски дыр

### Назначение
Отметить тайлы, где рельеф под зданием «вынимается» (подвал), чтобы этажи ниже 0 были видны и проходимы. Дыры в рельефе с собственными стенами — раздел 14.

### Данные
`cellar` — двумерный булев массив W × H в информации о постройке (истина = дыра). В 2D-виде он редактируется как картинка: цвет подвала RGB(100, 75, 60), «пусто» RGB(255, 230, 215).

### Алгоритм
1. При открытии варианта массив читается; если он меньше шаблона — пересоздаётся нулевым.
2. Слой «Cellar» в 2D: нажатие и протаскивание с зажатой левой кнопкой ставят пиксели кистью размера пера: перо 1 — один тайл под курсором; перо 2 — квадрат 2×2 с углом (x − 0,5, y − 0,5); перо 3 — квадрат 5×5 с углом (x − 2, y − 2). Режим «стирание» ставит «пусто». Режим «заливка» — заливка области (flood fill) от тайла под курсором.
3. При сохранении картинка переводится обратно в массив: всё, что не «пусто», — дыра; запись в информацию о постройке и сериализация.
4. При сериализации постройки `FixCellarSize` подгоняет массив к размеру шаблона с сохранением пересекающейся части.

### Константы

| имя | значение | смысл | источник |
|---|---|---|---|
| `CELLAR_COLOR` | RGB(100,75,60) | тайл подвала | `CellarLayer.cpp` |
| `WHITE_COLOR` | RGB(255,230,215) | тайл без подвала | `CellarLayer.cpp` |
| перья | 1×1, 2×2, 5×5 тайлов | размер кисти | `CellarLayer.cpp` |

### Что нужно от движка-носителя
Маска «вырезать рельеф» по тайлам под зданием (см. «Карта 1»).

## 10. Лестницы

### Назначение
Поставить вертикальную лестницу (по которой лезут бойцы) в здание или на рельеф.

### Данные
`SLadder` в информации о постройке: `nID` (из счётчика `nMaxLadderID`), позиция `SDiscretePos` (x, y — тайлы, z — начальный этаж; поворот 0…3), `nHeight` — высота в ступенях по `F_LADDER_STEP` = 0,625 м (комментарий в коде говорит «в этажах», но рисуется и считается ступенями), `fBeginHeight`/`fEndHeight` — высоты начала и конца, `eDir` — сторона, с которой лезут (вперёд/назад/влево/вправо).

### Алгоритм
1. Контекстное меню 3D-окна → «New Ladder»: точка под курсором на плоскости активного этажа, переведённая в систему мира без подъёма рельефа и в тайлы; новая лестница: ID = следующий, высота 4 ступени (2,5 м = один этаж), x, y = точка (дробные), z = активный этаж, поворот = активный поворот панели. Постройка сериализуется, лестницы перерисовываются.
2. В 3D лестница показывается равнобедренной призмой высотой `nHeight` × 0,625 м и шириной 0,625 м цвета (0,2; 0,51; 0,8), с userID `BT_LADDER|ID`. Рамка выбора: от (0; +0,3125) до (0,3125; −0,3125) в локальных осях лестницы, по высоте от этажа до этажа + высота.
3. Перенос — всегда по целым тайлам (см. раздел 4), поворот — кратно 90°.
4. Двойной щелчок — диалог с числом ступеней; при изменении — сериализация постройки и обновление лестниц.
5. При сериализации лестницы с ID ≤ 0 выбрасываются.

### Особые случаи и прихваты
- Лестницы не попадают в историю отмены, а при вставке из буфера теряются (раздел 5).
- Проходимость по лестнице и «вход на лестницу» считаются в «ИИ 1 — Сетка и проходимость.md».

### Что нужно от движка-носителя
Объект «лестница» с высотой в ступенях 0,625 м и направлением подъёма.

## 11. Двери и окна как детали; переключатель «открыто»

### Назначение
Код поддерживает два способа сделать дверь или окно:
- **деталь со встроенным объектом**: у детали стены `ConstructionParts.Object` указывает на объект (со стадиями разрушения и анимациями), и объект живёт внутри фрагмента;
- **проём-деталь + отдельный объект**: деталь стены с вырезом (папки `Doors`/`Windows` дерева деталей, например «TownDoor01/d02_br», «TownWindow01/d02_br») плюс полотно/створка — обычный объект `FinalElements`, ссылающийся на объект с дверью (таблица `Doors`: объект, звуки открытия и закрытия).
В базе ноября 2003 г. встроенный объект есть только у 7 деталей (все — части печей «Stove00»); двери и окна сделаны вторым способом (194 записи `Doors`). Отдельно стоящие ворота, сундуки и т. п. — тоже объекты.

### Данные
- Деталь со встроенным объектом: обычный фрагмент (раздел 6) + `nObjectFlags` фрагмента; бит `OF_OPEN` = 0x1 — «изначально открыто».
- Объект на карте: запись `FinalElements` с полями `OpenObject` («открыто»), `Lightmap` (освещение лайтмапой или обычное), `Grenade` и `Power` (растяжка на двери — у объектов с дверью), `ObjectPhase` (стадия разрушения).

### Алгоритм
1. Проём ставится как любая стена: выбрать деталь-проём в дереве деталей и нарисовать/поставить (раздел 6); полотно — перетащить объект двери/окна в проём (раздел 15) и повернуть.
2. Двойной щелчок по фрагменту в 3D открывает диалог фрагмента — только если у детали есть встроенный объект (`pObject`); диалог содержит флажок «открыто»; ОК ставит/снимает `OF_OPEN` и сериализует постройку.
3. Двойной щелчок по объекту карты (`FinalElements`) переключает **превью** «открыть/закрыть»: если у модели объекта есть скелет, объект — дверь (`pDoor`) и у скелета есть анимации `ACTIVATE` и `DEACTIVATE`, проигрывается соответствующая анимация с текущего момента (с запоминанием финальной позы). В базу это не пишется.
4. Флаг `bOpen` объекта и выбор освещения (лайтмапа/обычное) меняются в диалоге объекта (`CObjectDlg`) и пишутся сразу в `FinalElements`.
5. Стадия разрушения объекта, с которой он появится (`nObjectPhase` записи), выбирается в инспекторе; модель в 3D берётся по этой стадии.

### Особые случаи и прихваты
- Объект без модели (предмет-«слот улики» `RPGItems` ID 188, «взрыв» ID 189, предметы без модели) рисуется сферой радиусом 0,3125 м: обычный — (0,7; 0,7; 0,9), слот улики — (1; 0,5; 0,6), взрыв — (0,77; 0,55; 0,1).
- Объекты-«взрывы» (предмет 189, со свойствами «мощность» и «радиус») — авторские разрушения, применяемые при загрузке карты (см. «Карта 1»); в редакторе показ разрушения от них отключён (вызов закомментирован).

### Что нужно от движка-носителя
Модульные детали стен с проёмами и отдельные интерактивные объекты дверей/окон с флагом начального состояния (по желанию — встроенный объект в детали); превью анимации открытия в редакторе.

## 12. Пятна на стенах и наборы материалов

### Назначение
Раскрашивать стены и плиты здания материалами (по сторонам), быстро применять «наборы» из четырёх материалов, накладывать проецируемые пятна-декали (грязь, трещины, плакаты) на выбранные фрагменты здания и на рельеф.

### Данные
- У каждого фрагмента 8 слотов материалов (`N_CONSTRUCTION_MATERIALS` = 8); слоты 0…3 — первая геометрия детали, 4…7 (`N_FIRST_GEOMMATERIALS` = 4) — вторая геометрия. Слот — «смешанный материал»: список слоёв `SRawMaterialApply` {проекция (NORMAL, PROJECTION_X/Y/Z), ID шаблона материала `TMaterials`, масштаб, сдвиг (x, y), поворот}. Пустой слот = материал детали по умолчанию (`pDefMaterials`).
- Активный материал (в пользовательских настройках) — 6 наборов: набор 1 (`MSET_FIRST`) = один материал с масштабом/сдвигом/поворотом с панели «Material»; наборы 2…6 = по 4 материала. Наборы хранятся в реестре в разделе `Materials`, ключи `MaterialSet_<набор>_<индекс>` = ID шаблона материала.
- Пятно на здании (`SProjectedSpot`): начало (угол), нормаль, размер (м), поворот (градусы, вокруг нормали), ID материала, ID пятна (счётчик `nMaxSpotID`), маска материалов (бит n = «на геометрию с материалом n не накладывать»). Пятно хранится в информации о постройке, а **привязка к фрагментам** — списком ID пятен в каждом фрагменте.
- Пятно на рельефе — запись `TerrainSpots` (ID, `VariantID`, `MaterialID` → таблица `Spots`, позиция (м), размер (м), поворот, `Priority`, `Layer`).
- userID пятна: `BT_TEXSPOT << 24 | (ручка << 16 | тип << 14 | индекс)`; тип 0 — на здании (индекс = ID пятна), 1 — на рельефе (индекс = номер в списке пятен варианта); ручки: углы (нижний-левый, нижний-правый, верхний-правый, верхний-левый) и центр.

### Алгоритм
**Покраска (режим «Brush», `EM_MATERIAL`).** Нажатие левой кнопки без модификаторов на фрагмент здания, далее каждый кадр, пока кнопка зажата и нет Ctrl/Alt/Shift, — покраска фрагмента под курсором:
1. Слот: для второй геометрии — 4; для стены нормаль поверхности переводится в локальные оси фрагмента (обратный поворот); если |n_y| — наибольшая компонента: слот 1 при n_y > 0 (внутренняя сторона, +Y), иначе слот 0 (наружная); иначе слот 3 (торцы и верх). Для сплошной/пола: если |n_z| наибольшая — слот 0 при n_z > 0 (верх), 1 (низ); иначе 0.
2. Один материал: слот заменяется списком из одного слоя (если он уже такой — ничего). Набор из 4: слоты база…база+3 (база 0 или 4) заменяются по одному слою.
3. При изменении — отмена «смена фрагмента» (снимок до/после); перестройка показа здания; при отпускании кнопки — сериализация постройки.

**Пипетка** (`EM_SELECTMATERIAL`, временный режим на стеке режимов): щелчок по фрагменту берёт материал: для набора 1 — слоя слота под курсором (или материал детали по умолчанию, переведённый в его шаблон с проекцией NORMAL); для наборов 2…6 — все 4 слота первой геометрии. Затем режим возвращается к предыдущему.

**Новое пятно на здании.** Контекстное меню (правая кнопка без перетаскивания) → «New Building Spot...» (доступно, если выделены фрагменты): выбор материала в дереве `Materials` → пятно 1 × 1 м с нормалью поверхности под курсором (точка пересечения сохранена в момент открытия меню и переведена в систему без подъёма рельефа), центрированное на точке, поворот 0, следующий ID; пятно привязывается ко **всем выделенным фрагментам** (ID добавляется в их списки, куски сетки здания перестраиваются), постройка сериализуется.

**Правка пятна.** В 3D пятно рисуется рамкой с крестом (цвет (0,3; 1; 0,7)), кубиками 0,25 м в углах (выбираемые ручки) и жёлтым кубом в центре, на 6 мм над поверхностью. Перетаскивание: курсорный луч пересекается с плоскостью пятна; с CapsLock точка привязывается к узлу тайла по тем осям, вдоль которых нормаль ≈ 0; угловая ручка тянет свой угол (противоположный неподвижен, размер пересчитывается), центр — переносит. Поворот (Shift) — вокруг центра пятна на угол перетаскивания. Двойной щелчок — диалог: 4 флажка «накладывать на материал 0…3» (маска) и кнопка «выбрать фрагменты пятна». Удаление ставит ID материала −1 (выбрасывается при сохранении). Команды: «Set building spot fragments» — снять пятно со всех фрагментов и привязать к выделенным; «select_spot_fragments» — выделить фрагменты пятна (стены — с битом 0x40000000).

**Пятна на рельефе.** «New Terrain Spot...»: выбор записи в дереве `Spots`; позиция = ближайший узел тайла к точке пересечения курсорного луча с плоскостью z = 0 (не с рельефом!); нормаль (0,0,1); размер = размер текстуры материала пятна × 0,625 · 8 / 256 м (т. е. 32 пикселя на тайл: текстура 256×256 → 5 × 5 м); поворот 0; приоритет = максимальный приоритет пятен варианта + 1; слой = индекс активного слоя пятен (если активен слой `LID_SPOTS`), иначе 0. Перетаскивание/поворот как у пятна на здании, но всегда относительно точки нажатия; при отпускании — запись в `TerrainSpots` и отмена; перерисовывается прямоугольник старого и нового положения. «topmost_spot» — поднять приоритет выделенного пятна на максимум + 1.

### Константы

| имя | значение | смысл | источник |
|---|---|---|---|
| `N_CONSTRUCTION_MATERIALS` | 8 | слотов на фрагмент | `DataConst.h` |
| `N_FIRST_GEOMMATERIALS` | 4 | первый слот второй геометрии | `DataConst.h` |
| `N_MATERIALSET_SIZE` | 4 | материалов в наборе | `MEUserSettings.h` |
| наборов | 6 | 1 одиночный + 5 четвёрок | `UserSettingsSetup.h` |
| новое пятно на здании | 1 × 1 м | | `IWysiwyg.cpp` |
| масштаб пятна рельефа | 0,625·8/256 м на пиксель | | `IWysiwyg.cpp` |
| подъём рисования пятна | 0,005–0,006 м | против z-конфликта | `wEditor.cpp`, `WysiwygSpotSel.cpp` |

### Особые случаи и прихваты
- Внутренняя/наружная сторона стены для покраски определяется по знаку локальной нормали Y — та же ось, что и «внутрь» при рисовании стен.
- Пятно на здании видно только на тех фрагментах, к которым его привязали; иначе декаль «не ложится».
- Пятна на рельефе ставятся по плоскости z = 0, а не по поверхности рельефа (на холмах точка смещается).

### Что нужно от движка-носителя
Многослотовые материалы на модульных деталях (сторона внутрь/наружу/торец), декали-проекции с маской по материалам и явной привязкой к набору мешей; приоритет наложения декалей рельефа.

## 13. Правка 3D-фрагментов, редактор деталей и виртуальные связи

### Назначение
Деталь здания (`ConstructionParts`) — модуль из одной-двух геометрий с AI-геометрией, разбитой на «куски» (pieces) по ячейкам 0,625 м; куски нужны для разрушения и расчёта устойчивости (схема связей «кусок—сосед»). Редактор позволяет: править фрагменты здания поштучно в 3D (каждый 2-тайловый подблок стены — отдельный фрагмент), задавать маску подчастей детали и вручную дополнять связи кусков «виртуальными» кусками.

### Данные
- Хеш куска внутри детали: `GetPartHashID(px, py, pz)` | `GetPieceHashID(x, y, z)`, где хеш части = pz<<13 | py<<10 | px<<7 (номер строительной клетки внутри детали, с 1), хеш куска = z<<4 | y<<2 | x (номер ячейки 0,625 м внутри клетки, с 1; x, y — 2 бита, z — 3 бита). Клетка 1,25 × 1,25 × 2,5 м делится на куски 2 × 2 × 4 по 0,625 м («WALL_HEIGHT/4 == FP_GRID_STEP»).
- Связи куска (`juncs`): до 6 направлений (+X, +Y, +Z, −X, −Y, −Z) к соседним ячейкам; признак «связь с землёй» для нижнего уровня.
- `AIGeometries.PiecesInfo` — строка дополнительных (виртуальных) кусков: «хеш,маска;хеш,маска…», маска: +X = 1, +Y = 2, +Z = 4, −X = 8, −Y = 16, −Z = 32. В базе 11 AI-геометрий с такой строкой, например «Roof» (ID 2457), «Plain1» (ID 360), «out0» (ID 368: `10538,63`).
- `ConstructionParts.SubPartMask` — маска «основных» клеток детали (редактор `DT_SUBPARTS`); по ней в 3D рисуется «основная» рамка выделения фрагмента.

### Алгоритм
1. **Фрагмент в 3D**: щелчок по стене выбирает подблок (2 тайла), а не деталь целиком; рамкой можно выбрать все подблоки. Перенос и поворот — раздел 4; при любом изменении перестраиваются только затронутые куски сетки здания: для каждой клетки детали — узел (повёрнутый) и его 8 соседей на высоте z·4+1 (`FindPoints2Update`).
2. **Автоматические связи кусков** (при «обновить данные» AI-геометрии, раздел 19): для каждого куска — охватывающий ящик его вершин; опорная точка p = (x−1, y−1, z−1)·0,625; допуск 0,25·0,625 = 0,156 м. Если min.z не выше p.z − 0,625 + допуск — связь вниз (−Z; «земля», если z−1 = 0); min.x — связь −X; min.y — −Y (обе «земля», если z = 0); max.z не ниже p.z + 0,625 − допуск — связь вверх (+Z, никогда не «земля»); max.x — +X; max.y — +Y. То есть кусок связан с соседом, если его геометрия доходит до общей грани ячейки.
3. **Редактор кусков** (`DT_GEOMETRYPIECES`, кнопка у свойства `PiecesInfo` AI-геометрии): таблица кусков — номер, хеш, PartX/Y/Z, X/Y/Z, шесть флажков связей. Куски из файла AI-геометрии показываются только для чтения; виртуальные (в квадратных скобках) — редактируемые: Insert — добавить (диалог: часть X/Y/Z, кусок X/Y/Z, 6 флажков), двойной щелчок — изменить, Delete — удалить. ОК собирает строку виртуальных кусков и записывает в `PiecesInfo`. Игра при импорте разбирает строку в «дополнительные связи» (`additionalLinks`) — использование в схеме здания описано в «Мир 2».
4. **Диалог фрагмента** (двойной щелчок по фрагменту с встроенным объектом): флажок «открыто» (раздел 11).

### Константы

| имя | значение | смысл | источник |
|---|---|---|---|
| ячейка куска | 0,625 м по всем осям | 2×2×4 куска на клетку | `ExportGeometry.cpp` |
| допуск связи | 0,25·0,625 м | касание грани ячейки | `ExportGeometry.cpp` |
| маска связей | +X 1, +Y 2, +Z 4, −X 8, −Y 16, −Z 32 | `PiecesInfo` | `PiecesInfoView.cpp` |

### Особые случаи и прихваты
- Постобработка связей между соседними кусками (поиск «пропущенных» связей через ячейку по Z) написана, но закомментирована — работают только связи по касанию граней.
- Ошибка в закомментированном коде (`i == end && i->second > 0`) — не исполняется.

### Что нужно от движка-носителя
Разбиение коллизии модульных деталей на ячейки 0,625 м с графом связей и возможностью ручного добавления виртуальных узлов/связей.

## 14. Рельеф: сферическая кисть высот, тайлы и трава, пятна, дыры, альфа-карта

### Назначение
Лепить высоты, раскладывать типы тайлов (текстуры), траву, цветовую карту, дыры с подпорными стенками и альфа-карту смешивания вложенного рельефа. Рельеф каждого варианта шаблона хранится отдельным файлом.

### Данные
- Файл `<каталог экспорта>\Terrain\<ID варианта>` — сериализованный `CMETerrainInfo`: информация о рельефе `STerrainInfo` (ширина, высота шаблона в тайлах; `typeMap` — байт типа тайла на узел; `heightMap` — 16-битная высота на узел в единицах 1/64 м (`FP_TERRAIN_H_SCALE`); дыры; слои травы; цветовая карта DWORD; пятна; счётчик ID слоёв травы, начинается с 1; карта звуков шагов; средний цвет), альфа-карта (16 бит на узел), диапазон высот `fMinH`/`fMaxH` (м) для 2D-представления. Все карты — (W+1) × (H+1) узлов.
- Слой травы `SGrassLayer`: ID записи травы (`Grass`), карта плотности (байт на узел), максимальная плотность (≤ 32), цветовая карта травы, список отдельных «пучков» (точки в тайлах), ID слоя.
- Дыра `STerrainHole`: высота дна (в единицах 1/64 м), видимость, многоугольник (точки в тайлах).
- Новый рельеф (`CreateTerrain`): min 0, max 1 м, размеры шаблона, остальное пусто; новый слой тайлов заливается типом 11 (`TRANSPARENT_TILE`).

### Алгоритм: 3D-окно
Активный слой рельефа (`LID_HEIGHTS`, `LID_TILES`, `LID_GRASS`, `LID_ALPHA`) в режиме «выделение» перехватывает левую кнопку; точка — пересечение луча только с рельефом.
1. **Сферическая кисть высот** (`CSphereHeightMap`). При нажатии: центр = узел (округление) под курсором; требуется 0 < x < ширина карты высот, 0 < y < высота (край недоступен); снимается копия карты высот. При каждом движении мыши — смещение курсора от точки нажатия в пикселях (dx, dy):
   - прирост высоты Δh = −0,02·dy м (вверх — поднять), в единицах карты Δu = Δh·64;
   - радиус r = 0,03·|dx| тайла.
   - Если ни Δh, ни r (при r ≥ 1) не изменились — ничего. Иначе карта высот восстанавливается из копии (правка всегда считается от исходного состояния, а не накапливается).
   - r > 1 и |Δu| > 0,01: «сферическая шапка»: R = (r² + Δh²) / (2·Δh) (сфера через край круга и вершину высоты Δh над центром); z0 = |Δh| − |R|; для каждого узла (x, y) в квадрате [центр ± ceil(r)], обрезанном картой, на расстоянии d ≤ r от центра: δ = z0 + √(R² − d²); новая высота = исходная + знак(Δh)·64·max(0, δ), не меньше 0. Обновляемый прямоугольник — квадрат, расширенный на 1 узел.
   - r ≤ 1: меняется только центральный узел: исходная + Δu, не меньше 0; обновляется ±1 тайл.
   - Инвалидируется объединение текущего и прошлого прямоугольника (геометрия; при отпускании — пересчёт AI-карты); при отпускании отмена хранит старую и новую карты высот целиком плюс суммарный прямоугольник; файл рельефа сериализуется. Esc («deselect») откатывает к копии.
2. **Тайлы**: кисть-круг радиусом 0,3 / 0,7 / 3,0 м (перья 1/2/3); радиус в узлах n = округлить(радиус / 0,625) = 0 / 1 / 5; при n < 1 красится один узел, иначе все узлы с (dx² + dy² ≤ n²). Значение — ID выбранного тайла в дереве `TerrainTiles`. Изменённые узлы пишутся в отмену; инвалидируется текстура ±1 тайл.
3. **Трава** (слой травы номер k): тот же круг, значение плотности = параметр `ME_GRASS_DENSITY` = 255 / max_плотность × текущая плотность кисти; Ctrl + щелчок добавляет одиночный пучок в точку (в тайлах); режим «стирание» обнуляет плотность в круге и удаляет пучки ближе радиуса кисти. Курсор кисти — окружность (6 сегментов на четверть) над узлом, для стирания — полупрозрачный цилиндр (0,9; 0,4; 0,35; 0,8).
4. Изменения рельефа в мире применяются частично (раздел 1, п. 9); пока кнопка зажата и не включён `ME_INSTANT_TERRAIN`, перестройка откладывается до отпускания.

### Алгоритм: 2D-вид
1. Слои рельефа (`Texture`, `Height map`, `Alpha`, `Terrain holes`, `Grass "<имя>"` + её цветовая карта, `Terrain color map`, `Terrain spots`) добавляются в список слоёв командой «добавить слой»; карта альфа добавляется вместе с картой высот; одиночные слои нельзя добавить дважды. Добавление тайлов/высот/травы сразу сохраняет рельеф.
2. **Карта высот как картинка**: значения переводятся в оттенок серого: серый = 255·(h − min)/(max − min); обратно h = min + серый·(max − min)/255. Кисть-маска (стиль «косинус», радиус 1…128, по умолчанию 10) красит текущей высотой; диалог кисти задаёт min (−100…100 м), max, текущую высоту (ползунок 0…100) и флаг «тиснение» (при нём протаскивание не рисует). Импорт/экспорт BMP (32 бита, имя `<ID варианта>_<имя слоя>.bmp`; «экспорт всего» пишет высоты, тайлы, альфу и цветовую карту).
3. **Тайлы в 2D**: перья 1×1, 2×2, 5×5 тайла, заливка области, стирание = тип 11; щелчок показывает тип тайла под курсором в дереве.
4. **Альфа-карта**: 0…255 серого ↔ 0…65535; кисть как у высот, min/max заблокированы (0…1).
5. **Трава**: плотность 0…255 как картинка; диалог кисти — выбор записи `Grass` и максимальной плотности (≤ 32).
6. **Цветовая карта**: перья шириной 1/3/5 пикселей, цвет — стандартный диалог; у цветовой карты травы масштаб картинки 2.
7. **Дыры**: правое меню «New hole» — диалог (радиус, число сегментов, высота дна в м) создаёт правильный многоугольник вокруг точки; узлы многоугольника перетаскиваются мышью (выбор дыры показывает её свойства в инспекторе); «Delete hole», «Hole height...». Видимость дыр в 3D — параметр `ME_TERRAIN_SHOWHOLES`.
8. Сохранение рельефа (`WriteTerrMap`): при закрытии вида, смене шаблона и по уведомлению слоёв все слои собираются обратно в `CMETerrainInfo` (тайлы, высоты с min/max, дыры, альфа, цветовая карта, слои травы — новым слоям выдаётся ID из счётчика), отдельно маска подвала уходит в постройку; файл рельефа записывается.

### Особые случаи и прихваты
- Профиль сферической кисти смешивает единицы: радиус и расстояния — в тайлах, высота — в метрах; поэтому шапка вытянута по горизонтали в 1,6 раза относительно «настоящей» сферы. Вершина при этом поднимается ровно на Δh.
- Кисть высот работает от снимка: можно «водить» мышью вперёд-назад, подбирая радиус и высоту, — результат зависит только от текущего смещения курсора.
- Узлы на нулевой строке/столбце сферической кистью не выбираются как центр.
- Высоты ниже 0 обрезаются нулём (беззнаковая карта).

### Что нужно от движка-носителя
Ландшафт с узлами 0,625 м, 16-битной высотой, побайтовой картой типов, картами травы с плотностью и отдельными пучками, цветовой картой, полигональными дырами со стенками; частичная перестройка по прямоугольнику.

## 15. Размещение объектов, юнитов, вейпоинтов, маршрутов, камер и света

### Назначение
Расставить на зоне объекты (мебель, деревья, ящики, двери-объекты, мины, «взрывы»), предметы, юнитов, вейпоинты с маршрутами, сохранить камеры (для сценария и роликов) и источники света.

### Данные
- `FinalElements`: `ModelID` → `PlacableObjects` (обёртка: либо объект `ObjectTemplates.PlacableID`, либо предмет `RPGItems` с «объектом размещения»), `VariantID`, `PosX`/`PosY` (дробные **тайлы**), `Floor`, `DeltaZ` (м), `Rotation` (градусы), `ScaleX/Y/Z`, `OpenObject`, `Lightmap`, `ObjectPhase`, свет (`PointLight` — цвет RGB, `LightPosX/Y/Z`, `LightRadius`, `LightFlareRadius`, `LightFlareTexture`, `LightParam`, `FlarePosX/Y/Z`), свойства взрыва/прохода/двери/мины (раздел 18). В базе 64 581 строка.
- `Units`: `MonsterID` → `RPGPers`, `PosX`/`PosY` (**целые** тайлы), `Floor`, `Rotation`, логика и прочее (раздел 18). 4854 строки.
- Вейпоинт = запись `Waypoints` (`UserName` = путь имени в дереве имён, `VariantID`, `NameID` → `WaypointNames`, `Is3DPoint`) + файл `<каталог экспорта>\Waypoints\<ID>`: позиция (x, y в тайлах; z — добавка в м), этаж, поворот, список команд (тип: поза/ждать/направление; время; поза ползком/присев/шагом/бегом; направление из 8 или «нет»). 2306 записей, 1207 имён.
- Маршрут юнита — файл `Units\<ID юнита>` или, если у юнита есть группа (`Units.Group` → `UnitGroups`), `Groups\<ID группы>`: список маршрутов, каждый — список **ID имён** вейпоинтов.
- Камера — запись `Cameras` (`AnchorX/Y/Z`, `Distance`, `Yaw`, `Pitch`, `Roll`, `FOV`).

### Алгоритм
1. **Перетаскивание из дерева в 3D-окно** (принимаются деревья: шаблоны, объекты, предметы, персонажи, пятна, детали, имена вейпоинтов). Во время перетаскивания под курсором (тайл на плоскости активного этажа, поднятой на рельеф) рисуется предпросмотр: модель объекта (предмет без модели — сфера; см. раздел 11), полупрозрачный ящик шаблона W·0,625 × H·0,625 × 2,75 м цвета (0,68; 0,87; 1; 0,2), модель персонажа (повёрнута на 90°), куб размера пятна с его материалом, деталь в активном повороте (или ящик без геометрии), красный флажок вейпоинта.
2. **Бросок объекта/предмета**: новая запись `FinalElements` в варианте; позиция = точка под курсором в тайлах (дробная), этаж = активный, поворот 0, `DeltaZ` = «начальный подъём»: 0,1 м, если низ AI-геометрии объекта не выше 0,05 м **и** в клетке здания (x/2, y/2) на этом этаже есть хоть один фрагмент (стоит на плите), иначе 0. Если у нулевой модели объекта есть точечный свет — его цвет (×255, RGB), позиция, радиус, радиус и текстура блика, позиция блика копируются в запись. Отмена «вставка»; объект становится выделенным.
3. **Бросок персонажа**: запись `Units` (монстр = персонаж), позиция — тайл под курсором, этаж активный, поворот 0.
4. **Бросок шаблона**: запись `Rects` (раздел 16). **Бросок пятна** — запись `TerrainSpots` в точке под курсором с размером по текстуре (раздел 12). **Бросок детали** — как постановка детали (раздел 6; если активный слой не строительный — в слой «Floors» 0). **Бросок имени вейпоинта** — новый вейпоинт с этим именем в точке под курсором.
5. **Через контекстное меню**: «New Waypoint...» — диалог выбора имени (и папки) → запись + пустой файл вейпоинта → позиция = точка под курсором на плоскости активного этажа (x, y — дробные тайлы), этаж — активный. (Пункт «New Object...» в меню закомментирован; команда «new_object» работает от выбранного в слое объектов.)
6. **Маршрут**: выделить юнита и вейпоинты (Ctrl+щелчки) → «Set route»: первый маршрут юнита (или его группы) := имена выделенных вейпоинтов в порядке выделения; при сохранении имена, которых уже нет в дереве имён, выбрасываются. «View unit route» — выделить юнита и по одному вейпоинту варианта на каждое имя маршрута. Двойной щелчок по юниту — окно маршрутов (`CRouteDlg`); по вейпоинту — окно команд вейпоинта.
7. **Камеры**: «Save Camera position» — выбрать запись в дереве камер, записать в неё текущие якорь, дистанцию, рыскание, тангаж, крен и FOV; «Restore Camera position» — поставить камеру из записи; «Animate Camera position...» — список (камера, время перехода в мс; первой по умолчанию 0, следующим 1000) → камера линейно интерполирует якорь, дистанцию, углы и FOV между последовательными записями. Команда «camera_info» пишет текущую камеру в поля камеры активного элемента: для предметов — `[Slot|Ammo]Camera*` (иконки инвентаря), для персонажей — `Camera*`/`FaceGenCamera*`, для шаблона — в запись камеры, выбранную в слое камер.
8. **Свет**: освещение 3D-окна редактора задаётся в настройках («Preferences → Light»), хранится в реестре: цвета света, амбиента (по умолчанию серый 0x80808080), тумана (0xA5B2A5A5), блеска, «пара», тени, фона, амбиента земли; направление света (0,1; 0,2; −1); начало (10; 10; 0); старт и дистанция тумана; параметры пара (шум 0,8, скорость 0,05, время смены 5, высота 5, плотность 1); небо (кубическая текстура ID 1). Цвет направленного света = свет − амбиент (не меньше 0). Игровое освещение зоны — свойство варианта `DefaultLight` (дерево AmbientLights, по умолчанию 102). Точечный свет объекта правится в инспекторе (группа свойств «PointLight»).

### Особые случаи и прихваты
- Объект может стоять в дробной позиции тайла; юнит — только в целой.
- «Начальный подъём» 0,1 м — костыль против проваливания мебели в плиту пола при постановке в здание.
- При создании вейпоинта переданный этаж игнорируется — берётся активный этаж (целая часть).
- Ошибка оригинала: в подсчёте подъёма для предмета используется модель из поля класса, а не только что созданная (`pModel->pGeometry` вместо локальной) — для предметов подъём может считаться по чужой модели.
- Ошибка оригинала: при запуске анимации камеры исходный FOV кладётся в локальную переменную, а поле класса остаётся прежним (интерполяция FOV начинается со старого значения).

### Что нужно от движка-носителя
Перетаскивание ассета из браузера в вид с предпросмотром; привязка к тайлу/этажу; вейпоинты как именованные точки с командами; маршрут как список имён; сохранённые камеры с интерполяцией.

## 16. Шаблоны и подшаблоны: вставка, закрепление варианта, шаблон из выделения

### Назначение
Зона Silent Storm собирается из вложенных шаблонов: шаблон (прямоугольник W × H тайлов) имеет варианты; вариант содержит свой рельеф, постройку, объекты, юнитов, вейпоинты и прямоугольники вложенных шаблонов, у каждого из которых при сборке выбирается вариант (случайно с весом и по флагам). Редактор позволяет вкладывать, двигать, поворачивать вложенные шаблоны, закреплять вариант и выносить часть зоны в новый шаблон. Сама сборка — «Карта 1».

### Данные
- `Templates`: `ID`, `UserName`, `FolderID` (→ `TemplateTypes`), `Width`, `Height` (тайлы), `MEUserColor`. 2666 записей.
- `TemplVariants`: `ID`, `TemplateID`, `Grid`, `RndWeight`, `Flags`, `DefaultLight`, `ColorMap`, `ScriptID`, `Border`, `AmbientMusic`, `CombatMusic`, `HMBlendType`, `DiplomacyID`, `ShowTerrain`, `NoAttack`, `MinCutFloor`, `MaxCutFloor`, `Weather`, `ExitBorder`. 4726 записей.
- `Rects` (вложенный шаблон в варианте): `ID`, `VariantID`, `TemplateLink`, `Rotation` (градусы), `Floor`, `CenterX`/`CenterY` (**центр в тайлах**), `Width`/`Height` (размер вложенного шаблона в тайлах, копируется при вставке), `DeltaZ` (м), `Params` (имена атрибутов через `;`). 19 684 записи. В памяти движка центр переводится в **угол** в метрах: угол = центр·0,625 + R(поворот)·(−W/2, −H/2)·0,625 (поворот против часовой); редактор при записи делает обратное.
- «Пин» вложенного шаблона (`nPinID`) — **не хранится в базе**: это ID варианта, выбранного для показа в текущем сеансе.

### Алгоритм
1. **Вставка вложенного шаблона**: перетащить шаблон из дерева в 3D-окно (или в 2D-слой «Sub templates»). Создаётся запись `Rects` с `TemplateLink`, `Width`/`Height` = размеры шаблона; угол прямоугольника = точка под курсором (м), этаж = активный, `DeltaZ` = 0, поворот 0; записывается центр (обратное преобразование). Отмена «вставка». Вставка шаблона в самого себя в 2D запрещена (тот же ID шаблона); при перетаскивании в 3D такой проверки нет.
2. **Показ в 3D**: для каждой записи `Rects` варианта — вариант вложенного шаблона: если пин задан — он, иначе случайный по весам (`GetRnd`) и запоминается как пин. Затем строится карта вложенного шаблона до глубины «Subtemplate depth» (настройка, из реестра `TemplateDepth`) теми же функциями сборки, что в игре (`BuildMapEditMap`): объекты, юниты, постройки вложенного варианта рисуются, рельеф вкладывается в рельеф зоны (с альфа-картой и режимом смешивания `HMBlendType` — «Карта 1»). Поверх — полупрозрачный ящик W·0,625 × H·0,625 × (2,5 + случайно 0…0,25) м цвета (0,58; 0,77; 0,95) с прозрачностью `ME_SUBTEMPLATE_ALPHA` и каркасом (0,4; 0,6; 0,7); случайная добавка высоты нужна, чтобы ящики соседних шаблонов не мерцали. Пикируется только ящик (userID `BT_SUBTEMPLATE|ID записи`), и только если шаблон не выше плоскости отсечения этажей.
3. **Перенос/поворот** — раздел 4; при переносе здания и предметы вложенного шаблона двигаются «на лету» (перестройка их позиции относительно точки создания), высота каждого здания берётся по рельефу в его точке; занятый прямоугольник (+1 тайл по краям) старого и нового положения отправляется на перестройку рельефа; при отпускании кнопки рельеф зоны пересобирается. Сменился шаблон в записи или режим выравнивания по рельефу — карта вложенного шаблона строится заново.
4. **Двойной щелчок по вложенному шаблону** — вопрос «Do you really want to load the selected map ?» и переход к этому шаблону в дереве.
5. **Закрепление варианта**: (а) редактор `DT_PARAMS` свойства `Params` в инспекторе открывает список атрибутов (таблица `Attributes`) с «+»/«−»; выбранные имена пишутся через `;` — при сборке вложенный шаблон выбирает только варианты, удовлетворяющие этим флагам (своим `Flags` в окне `PARAMS_VIEW`); (б) показ закрепляется пином на сеанс; при создании мира с «сбросом пинов» (каждое открытие варианта) пины выбираются заново — та же выборка используется и для рельефа, чтобы рельеф совпадал с показанным вариантом.
6. **Варианты шаблона**: «New variant» — новая строка `TemplVariants` с умолчаниями (раздел 18), переимпорт базы; «Copy variant» — новый вариант + копия всех свойств варианта + копия содержимого (`CPlacement::CopyFrom`: прямоугольники вложенных шаблонов с поворотом и позицией; юниты с поворотом; объекты с дополнительными свойствами четырёх менеджеров (обычный, масштабируемый, взрыв, проход); старые «взрывы»; файл рельефа целиком; постройка целиком — стены, сплошные, карта комнат, пятна, лестницы, подвал, группы слоёв; пятна рельефа; вейпоинты — новые записи + копии файлов); «Delete variant» — с подтверждением удаляет строку варианта.
7. **Новый шаблон из выделения** («New template from selection» в контекстном меню 3D-окна):
   1. Рамка выделения → размеры: nX = 1 + ceil(2·полуширина / 0,625), nY = 1 + ceil(2·полувысота / 0,625).
   2. Диалог «новый шаблон» (папка — папка текущего шаблона, имя, ширина = nX, высота = nY — можно изменить) → новая запись `Templates` (сервер даёт ID) + первый вариант с умолчаниями; в запись шаблона пишутся ширина и высота.
   3. Выделение копируется в буфер обмена (с активным этажом = пол(активный этаж)) — **исходная зона не меняется**.
   4. Таблицы шаблонов и вариантов в движке обновляются; открывается WYSIWYG-интерфейс нового варианта с той же камерой; в него автоматически вставляется буфер («template_paste»): содержимое ставится по центру нового шаблона (раздел 5, п. 4); дерево переключается на новый шаблон; камера сбрасывается на обзор шаблона.
8. **2D-вид вложенных шаблонов** (слой «Sub templates»): прямоугольники с именем шаблона, повёрнутым по шаблону; внутри — контуры вложенных в него шаблонов до глубины `TemplateDepth`; Shift + тащить по выделенному — поворот с шагом 45°, Ctrl + щелчок — снять/добавить выделение, тащить — перенос всех выделенных; при постановке/повороте прямоугольник сдвигается внутрь шаблона (ближайшая допустимая позиция; не влезающий по размеру — отказ).

### Формулы
- Угол ↔ центр: угол = центр·0,625 + R(θ)·(−0,5·W·0,625; −0,5·H·0,625), R(θ) — поворот против часовой стрелки на θ градусов.
- Центр рамки шаблона в 3D (для высоты рельефа): угол + R(θ)·(0,5·W·0,625; 0,5·H·0,625).

### Особые случаи и прихваты
- Пин вложенного шаблона живёт только в памяти: каждый раз открывая зону, дизайнер может увидеть другой вариант вложенного шаблона (если флаги не ограничивают выбор) — это и есть «случайность», которую увидит игрок.
- Ящик вложенного шаблона имеет случайную добавку высоты 0…0,25 м.
- При копировании варианта (`CopyFrom`) объекты, двери и мины теряют свойства менеджеров «дверь/окно» и «мина» (копируются только 4 из 6 групп), цикл по этажам идёт от −10 до 9 (этаж 10 не копируется), а у старых «взрывов» позиция переносится до проверки успешности вставки.

### Что нужно от движка-носителя
Префабы с вариантами, весами и флагами-атрибутами; вложенные префабы с поворотом на произвольный угол и смещением по этажу/высоте; превью выбранного варианта прямо в редакторе; создание нового префаба из выделения с центровкой.

## 17. Отмена и повтор

### Назначение
Неограниченная по глубине история правок WYSIWYG-окна (3D): перенос/поворот/вставка/удаление объектов, юнитов, вложенных шаблонов, пятен рельефа, фрагментов здания, покраска материалами, кисти рельефа (тайлы, трава, пучки, высоты). 2D-вид и инспектор свойств в историю не пишут.

### Данные
- История — вектор команд с «текущей позицией»; первым элементом при создании мира кладётся пустая команда-ограничитель. Добавление новой команды отрезает «хвост» повтора.
- Стек открытых групп (`BeginUndoList`/`EndUndoList`); команда, пришедшая при открытой группе, попадает в верхнюю группу; закрытая группа кладётся в историю (или в объемлющую группу) одной командой, если она не пустая и не помечена «пропустить». Группы вложенные.
- Команда (`CWysiwygUndo`) одного из видов: `UA_CHANGE_POS` (снимки «до» и «после»), `UA_INSERT` (снимок вставленного), `UA_DELETE` (снимок удалённого).
- Разновидности: фрагмент здания (снимок `SBuildFragment` целиком, поиск по постоянному `nID` фрагмента, а не по индексу); записи базы — объект (`FinalElements` + все дополнительные свойства шести менеджеров), юнит (`Units`), вложенный шаблон (`Rects`), пятно рельефа (`TerrainSpots`); рельеф — списки изменённых узлов типа тайла (x, y, старое, новое), плотности травы, вставленных и удалённых пучков, плюс для кисти высот — вся старая и новая карта высот и прямоугольник обновления.
- Общий список всех живых команд с записями базы (`dbundolist`) — для перенумерации ID.

### Алгоритм
1. **Отмена** («undo»): взять команду в текущей позиции и сдвинуть позицию назад; выполнить её отмену (группа — в обратном порядке подкоманд); если отмена не удалась — стереть всю историю **до** текущей позиции (дальше назад отменять нельзя). Затем выполнить накопленные «пост-обработки» и разослать событие «deselect» (выделение снимается, незавершённая операция кисти рельефа отменяется). Повторный вход во время выполнения блокируется флагом.
2. **Повтор** («redo»): сдвинуть позицию вперёд, выполнить повтор подкоманд в прямом порядке; при неудаче — стереть хвост истории.
3. Семантика видов: смена позиции — записать снимок «до» (отмена) или «после» (повтор); вставка — отмена удаляет, повтор вставляет снимок; удаление — наоборот.
4. **Фрагменты здания**: поиск по `nID` в массиве стен или сплошных (по признаку «стена» = глубина детали 0); вставка — в конец массива (индексы, а значит и userID, меняются); удаление — вынимание из массива. Пост-обработка (одна на всю группу): сериализовать постройку в файл и перестроить все куски здания.
5. **Записи базы**: удаление записи помечает ID в команде отрицательным; повторная вставка создаёт новую запись (новый ID), копирует позицию, «открыто», лайтмапу, масштаб и все дополнительные свойства, после чего **во всех остальных командах того же типа**, ссылавшихся на старый ID, он заменяется новым — чтобы дальнейшие отмены/повторы попадали в новую запись. После — точечное обновление объекта в мире.
6. **Рельеф**: отмена записывает старые значения узлов в обратном порядке (повтор — новые), считает охватывающий прямоугольник и инвалидирует текстуру/траву/геометрию только в нём; для пучков травы — удалить вставленные/вернуть удалённые.
7. **Сброс истории**: при каждом создании WYSIWYG-мира (открытие варианта, переключение режима WYSIWYG, создание шаблона из выделения) история очищается.
8. Группы создаются: при отпускании кнопки после переноса (все выделенные), при клавиатурном переносе/повороте (от начала до конца), при вставке из буфера, удалении выделения, заливке прямоугольником, вставке детали стены (её подблоки).

### Особые случаи и прихваты
- Не попадают в историю: лестницы, вейпоинты, пятна на стенах (их перенос/удаление), флаги «открыто» фрагментов, правки в 2D-виде (стены, полы, комнаты, подвал, высоты 2D), правки через инспектор.
- Кисть высот хранит в отмене две полные копии карты высот (дорого по памяти, но просто).
- Отменённое удаление фрагмента возвращает его в конец массива — порядок фрагментов в файле постройки после серии отмен отличается от исходного.

### Что нужно от движка-носителя
Транзакционная история команд с группами и «пост-обработкой» (одна пересборка на группу); стабильные ID сущностей (или перенумерация ссылок в истории при пересоздании).

## 18. Инспектор свойств и деревья базы данных

### Назначение
Весь контент игры (модели, материалы, детали, объекты, персонажи, оружие, звуки, шаблоны карт…) редактируется как записи таблиц базы через одинаковый интерфейс: дерево папок + список свойств. Схема каждого дерева задана декларативно в коде; свойства размещённых на карте экземпляров — отдельными «менеджерами объектов».

### Данные
**Описание дерева** (`SResTree`): номер дерева, имя вкладки, имя корня, менеджер записей `CItemsMgr(номер, таблица папок, таблица записей[, таблица вариантов])`, обработчик выбора (какое окно показать), обработчик экспорта из исходников (Maya/текстуры/звуки/XLS), обработчик «обновить данные из исходника», флаги видимости и «скрыть дерево». Для каждого свойства: тип значения (целое, дробное, строка, логическое), вид редактора (`DT_DEC`, `DT_HEX`, `DT_STR`, `DT_BOOL`, `DT_BROWSE` — путь к файлу с префиксом каталога, `DT_COMBO` — список строк, `DT_COLOR`, `DT_RELATION` — ссылка на запись другого дерева, `DT_SUBPARTS` — маска подчастей детали, `DT_RELLIST` — список экземпляров, `DT_PARAMS` — набор атрибутов, `DT_GEOMETRYPIECES` — редактор кусков AI-геометрии, `DT_CUSTOM`), значение по умолчанию, «только чтение», группа, подсказка. Имя свойства = имя столбца таблицы.
- В коде описано 79 деревьев (`ResDescription.cpp`); в базе 105 таблиц папок `*Tree` (все одного вида: `ID`, `FolderName`, `ParentID`, `UserColor`) и отдельная таблица папок шаблонов `TemplateTypes` (та же структура, 607 строк). Корень папок — запись с именем «root» (показывается пустой). У таблиц записей есть `ID`, `UserName`, `FolderID`, `MEUserColor` (цвет записи в дереве).
- **Элементы «с вариантами»** (`bUniTemplate`, третья таблица): Templates → `TemplVariants`, Models → `ModelTemplates`/`Models`, Materials, Effects, AmbientLights, RndSounds (`SoundVariants`), Objects (`ObjectTemplates`/`Objects`), ConstructionParts (`ConstructionPartTemplates`/`ConstructionParts`). У каждого варианта — `TemplateID` (ссылка на элемент), `RndWeight` (вес случайного выбора) и `Flags`.
- **Флаги вариантов** (`TemplVariants.Flags`): строка «наборы через `;`, номера атрибутов (таблица `Attributes`) через `,`»; у варианта может быть несколько наборов. Окно `PARAMS_VIEW` показывает матрицу «атрибуты × (вариант, набор)» с «+»/«−»; щелчок переключает и сразу пишет строку. У вложенного шаблона на карте (`Rects.Params`) — **имена** атрибутов через `;` (редактор `DT_PARAMS`): требование к варианту вложенного шаблона, т. е. способ «закрепить» вариант (раздел 16).
- **Менеджеры свойств размещённых экземпляров** (`ObjDescription.cpp`), по типу выделенного:

| тип | таблица | свойства |
|---|---|---|
| юнит | `Units` | `MonsterID`→Pers, `Name`, `PosX`, `PosY`, `Floor`, `Rotation`, `ClueSlot`, `ClueInventorySlot`, `Player`, `RelativeLevel`, `Group`→UnitGroups, `Pose` (Stand/Crouch/Crawl), `Logic` (Guard/Sentry/Roaming/Fear), `RoamingRadius`, `FearUseToHit` (объявлено дважды), `GuardAnimation`→Animations |

| вейпоинт | `Waypoints` | `NameID`→WaypointNames |

### Алгоритм
1. **Загрузка дерева** — лениво при первом обращении: таблица папок целиком, затем записи (ID, папка, имя, цвет). При чтении папок у каждой строки делается «пустая» запись (`SetData`) — побочный эффект, не меняющий данных.
2. **Свойства записи** (`GetPropList`): создаётся копия шаблона свойств, читается одна строка (для элементов с вариантами — строка варианта; если вариант не указан — первый). Если запись не была в списке (создана другим пользователем), она подгружается по ID.
3. **Правка свойства в инспекторе** пишет в базу **немедленно**: значение ставится, строка записи/варианта открывается и обновляется целиком (все свойства шаблона). Связь (`DT_RELATION`) можно задать и перетаскиванием записи из дерева на инспектор: ищется первое свойство, связанное с таблицей перетаскиваемого дерева (среди активной группы); «пустое» значение даёт NULL. Исключение: текстура, брошенная на материал, идёт в `BumpID`, если формат текстуры «normals», иначе в `TextureID`.
4. **Множественное выделение на карте**: свойства каждого выделенного собираются своими менеджерами; показывается **пересечение** (`Intersect`) — только общие свойства; правка применяется ко всем. Всегда добавляются `MapID` (только чтение) и `SelectionX/Y/Z` — центр рамки выделения; правка этих полей переносит выделение (событие «move_selection»). Для фрагментов здания — `ConstructionPartID` (ссылка), для лестниц — «Ladder», для прочего — `Floor` (только чтение) и `Rotation`.
5. **Создание записи** (`AddItem`): до двух попыток вставки; в таблицу записей вставляется строка с временным значением (`UserName` = «New Item», для вариантов `Flags` = ''), ID выдаёт сервер (столбец-счётчик), затем строка открывается и заполняется: папка, имя, значения по умолчанию свойств, цвет 0. Для элементов с вариантами сразу создаётся первый вариант (строка в таблице вариантов с `TemplateID` и умолчаниями).
6. **Удаление записи** — удаление строки; удаление папки — только строки папки (вложенные записи становятся «потерянными»).
7. Старый путь выдачи ID — «скопировать строку с максимальным ID и дать ID = MAX(ID)+1; пустая таблица → 1» (`InsertCopyMax`) — в коде есть, но для таблиц карт закомментирован; номера комнат (`RoomID`) по-прежнему считаются как MAX+1 в пределах (вариант, этаж) (раздел 8), ID фрагментов/пятен/лестниц — счётчиками в файле постройки (начиная с 1; если счётчик ≤ 0 или > 100000 — сброс на 1, «для старых шаблонов»).
8. **«Сохранить всё»** (`OnFileSaveall`) вызывается почти на каждое действие (смена элемента, вставка, перетаскивание): дописывает отложенные изменения шаблонов (имя, папка, размеры), устаревших «конечных элементов» и всех деревьев (`UpdateModified`).
9. **История** «назад/вперёд» по выбранным элементам (пары дерево+запись), повторный выбор той же записи в историю не пишется.
10. **Обновление игровой базы в редакторе** («Update game», «Roll», «Make current»): сохранить всё → переимпортировать базу в движок (`NDatabase::Import`, `BuildMapLinks`) → пересобрать вид. «Make current» дополнительно закрывает все ресурсы рендера и копирует «последнюю версию» данных (`CopyLastVersion`).

### Особые случаи и прихваты
- Вставка строки делается не SQL-командой `INSERT`, а добавлением строки в открытый набор с одним заполненным «левым» столбцом; ID возвращается обратным чтением.
- Ошибка оригинала: удаление варианта убирает ID из **копии** списка вариантов — в памяти вариант остаётся до перечитывания.
- У юнита свойство `FearUseToHit` объявлено дважды.
- Связи «Model0…4» у объектов — это пять стадий разрушения (контейнеры моделей).

### Что нужно от движка-носителя
Табличная база контента с деревом папок, вариантами записей и весами; универсальный инспектор свойств с типами-редакторами и ссылками между таблицами; пересечение свойств при множественном выделении.

## 19. Проверка и запекание при сохранении

### Назначение
Редактор не имеет единой кнопки «Сохранить зону»: каждая правка сразу уходит в базу или в бинарный файл в каталоге экспорта (`<каталог экспорта>` = реестр `REG_EXPORT_DST`, по умолчанию `W:\complete\`; исходники — `REG_EXPORT_SRC`, по умолчанию `W:\Art\ForComplete\`). «Запекание» — это проверка и чистка при каждой сериализации плюс отдельные операции пересчёта ресурсов.

### Данные — что куда пишется

| данные | куда | когда |
|---|---|---|
| шаблон, вариант, вложенный шаблон, объект, юнит, пятно рельефа, вейпоинт (запись), комната, камера, свойства любых записей | таблицы базы (`Templates`, `TemplVariants`, `Rects`, `FinalElements`, `Units`, `TerrainSpots`, `Waypoints`, `RoomParams`, `Cameras`, …) | немедленно при правке |
| постройка (фрагменты, карта комнат, пятна на здании, лестницы, подвал, группы слоёв, счётчики ID) | файл `Buildings\<ID варианта>` | после каждого изменения постройки (`SerializeBuilding`) |
| рельеф (карты, дыры, трава, альфа, min/max) | файл `Terrain\<ID варианта>` | при отпускании кисти в 3D, при закрытии 2D-вида/смене шаблона, по уведомлению слоёв 2D |
| вейпоинт (позиция, этаж, поворот, команды) | файл `Waypoints\<ID>` | при создании, переносе, правке команд; удаление — удаление файла |
| маршрут юнита | `Units\<ID юнита>` или `Groups\<ID группы>` | «Set route» |
| геометрия модели | `Geometries\<ID>` (+ `Binds\`, `Locators\`) | экспорт из Maya |
| AI-геометрия | `AIGeometries\<ID>` (+ `AIBinds\`) | экспорт из Maya + пересчёт |
| коллизия дверей/окон по стадиям | `AIBSPTrees\<ID двери>` | «обновить данные» дерева дверей |
| текстуры | `Textures\<ID>` (+ `Textures\<ID + 0x01000000>` — несжатая копия для DXT) | экспорт текстур |
| скелеты, анимации, эффекты, свет, звуки, шрифты, головы | `Skeletons\`, `Animations\`, `Effects\`, `Lights\`, звуки по ID, … | соответствующий экспорт |

### Алгоритм
1. **Сериализация постройки** (`SerializeBuilding`): размеры = размеры шаблона (если нет ни одного фрагмента — 0 × 0); min/max этаж сбрасываются в 0 и пересчитываются по фрагментам (диапазон всегда включает этаж 0). Чистка:
   - фрагменты с ID детали ≤ 0 (удалённые) или несуществующей деталью, а также с позицией вне [0; W] × [0; H] (включительно) — выбрасываются; фрагменту без ID выдаётся следующий; если счётчик ID фрагментов не больше максимального ID — счётчик = max + 1 (с утверждением-предупреждением);
   - из материалов фрагментов выбрасываются слои с несуществующими шаблонами материалов;
   - пятна на здании с несуществующим материалом (в т. ч. удалённые, ID −1) — выбрасываются;
   - группы слоёв пустые или из одного слоя без этажей — выбрасываются;
   - лестницы с ID ≤ 0 — выбрасываются;
   - карта комнат приводится к (max−min+1) этажам по (W+2)×(H+2) (при несовпадении числа этажей — пересоздаётся пустой);
   - маска подвала подгоняется к W × H с сохранением пересечения.
   Затем файл перезаписывается целиком.
2. **Маршруты**: при записи из маршрута выбрасываются имена вейпоинтов, которых больше нет в дереве имён.
3. **Экспорт AI-геометрии + пересчёт** (`AIGeometryUpdateDBData` и `UpdateAIGeometryInfo`): прочитать файл AI-геометрии (точки, треугольники, куски, сферы масс); построить список рёбер и проверить замкнутость (при незамкнутой геометрии — предупреждение «Non closed AI geometry!» в просмотрщике); объём всей геометрии → свойство `Volume` записи; для каждого куска: объём, BSP-деревья для каждой замкнутой оболочки куска, связи (раздел 13); BSP-деревья для замкнутых оболочек всей геометрии; файл перезаписывается (блоки: точки, треугольники, куски, сферы, деревья).
4. **Коллизия дверей и окон по стадиям разрушения** (`DoorsUpdateDBData`): для каждой записи `Doors` и каждой из 5 стадий разрушения объекта двери (модели 0…4): если у модели стадии есть скелет и AI-геометрия — AI-геометрия скиннится по первому кадру анимации `ACTIVATE` (вариант «открыто») и по первому кадру `DEACTIVATE` («закрыто»), для каждого куска берётся первое BSP-дерево; в файл `AIBSPTrees\<ID>` пишутся два набора: открытые (блок 1) и закрытые (блок 2), по 5 стадий.
5. **Пересчёт данных геометрии** (`GeometryUpdateDBData`): по 4 частям модели (по материалам) — размер = 2 × максимальная полуширина ящиков, центр = среднее центров непустых частей → `SizeX/Y/Z`, `CenterX/Y/Z` записи `Geometries`. Для частиц — центр и полуразмеры ящика; для текстур — ширина, высота, средний цвет из заголовка файла.
6. **Анализ данных** (меню Tools → Analyse): набор проверок с журналом: наличие исходников анимаций, геометрий, AI-геометрий, текстур, эффектов, звуков реплик; типы текстур материалов (запрещены «Transparent»/«TransparentAdd» в текстуре/бампе/блеске/зеркале материала), текстуры частиц и интерфейса; «мусорные» текстуры и звуки (файлы без записей — с предложением удалить). Проверка «скелет геометрии = скелет AI-геометрии» есть, но выключена.
7. **«Make current»**: закрыть ресурсы рендера и выполнить `<каталог экспорта>\makeCurrent.bat` (копирование последней версии данных), затем переимпорт базы.

### Константы

| имя | значение | смысл | источник |
|---|---|---|---|
| `REG_EXPORT_SRC` по умолчанию | `W:\Art\ForComplete\` | исходники | `Export.cpp` |
| `REG_EXPORT_DST` по умолчанию | `W:\complete\` | каталог данных игры | `Export.cpp` |
| флаг несжатой копии текстуры | 0x01000000 | ID файла дубля DXT | `Export.cpp` |
| стадий разрушения | 5 | `N_DESTROY_STAGES` | `DataConst.h` |

### Особые случаи и прихваты
- Чистка удалённых фрагментов при сериализации меняет индексы фрагментов в памяти — поэтому после удаления редактор пересоздаёт главное здание и снимает выделение.
- Фрагменты на правой/верхней границе (x = W или y = H) ещё допустимы; за ней — молча удаляются.
- Нет проверки перекрытия фрагментов и дубликатов.

### Что нужно от движка-носителя
Конвейер «исходник → бинарный ресурс по ID» с проверкой дат; пересчёт производных данных (объёмы, BSP, ящики) при импорте; хранение зоны в двух видах: записи базы + бинарные файлы постройки и рельефа.

## 20. Экспорт из Maya

### Назначение
Модели, AI-геометрия, скелеты, анимации, частицы и источники света делаются в Maya; редактор формирует MEL-скрипт и запускает Maya в пакетном режиме с плагином экспорта `A5ExportModel`.

### Алгоритм
1. Для выбранных записей дерева (список ID) — для геометрий записи сначала сортируются группами по одинаковому исходному файлу (`SrcName`), чтобы открывать каждый `.mb` один раз.
2. Временный файл `%TEMP%\maya.mel`: первая строка — `loadPlugin "W:\Tools\A5ExportModel.mll"`; далее по записи:
   - **проверка дат**: исходник `<источник>\Models\<SrcName>` должен существовать (иначе окно ошибки); экспорт нужен, если результата нет, исходник новее результата или включён «принудительный экспорт»;
   - если исходник отличается от предыдущего — `file -o -f "<исходник>"; triangulateAll;`;
   - **геометрия**: предварительно `sysFile -del` для четырёх файлов `Geometries\<(i<<16)+ID>`, i = 0…3 (части по материалам); выделить корневой узел `RootJoint`; `file -es -f -typ "A5ExportModel" -op "mesh=1;binds_path=<данные>\Binds\;eff_path=<данные>\Locators\" "<данные>\Geometries\<ID>"`;
   - **AI-геометрия**: `select -ne <RootJoint>`; опции `ai_mesh=1;binds_path=<данные>\AIBinds\;` → `AIGeometries\<ID>`;
   - **скелет**: открыть файл, выделить корень, опции `skeleton=1;scale=<MSRFormat>;` → `Skeletons\<ID>`;
   - **анимация**: открыть файл скелета, `loadClip "<исходник анимации>" "<PersName>"` (и второй клип `SrcName2`/`PersName2`, если задан), выделить корень скелета, опции `animation=1;fps=<FPS>;start=<StartFrame>;end=<EndFrame>;all_frames=<DefaultFrames>;scale=<MSRFormat>;` → `Animations\<ID>`;
   - **частицы**: выбрать все множества объектов с префиксом `ExportPrefix`, опция `particles=1;` → `Effects\<ID>`;
   - **свет**: выделить узел `SelectNode`, опция `light=1;` → `Lights\<ID>`.
3. Если реестр `REG_EXPORT_GUI` = 1 — в конец скрипта добавляется `quit -a;` и Maya запускается с интерфейсом; иначе с `-batch`. Командная строка: `start /min /wait maya.exe [-batch] -script "<скрипт>" -log <данные>\Logs\maya.log`. После завершения показывается окно с журналом (с возможностью скрыть предупреждения). Если ни одна запись не требовала экспорта — сообщение «нечего экспортировать».
4. После экспорта — пересчёт производных данных (раздел 19) и переимпорт соответствующей таблицы в движок.
5. Прочие экспортёры: текстуры — пакетный файл `texture_export.bat` с вызовами `w:\tools\texconv -t<тип> -f<формат> -m<мипы> -a<адресация> -s<MappingSize/BumpGain>` (для DXT — вторая несжатая копия 8888); звуки — копирование файлов; шрифты; головы и последовательности голов — `w:\tools\lsconverter.exe`.

### Особые случаи и прихваты
- Выгрузка нескольких записей из одного `.mb` открывает его один раз (сортировка по исходнику).
- Пути в MEL удваивают обратные слеши (`MakeDoubleSlash`).
- Ошибка оригинала: экспорт света обновляет в движке таблицу анимаций вместо таблицы света.

### Что нужно от движка-носителя
Для UE5 — штатный импорт FBX; от этого раздела нужна только идея «экспорт по ID с проверкой дат и пересчётом производных данных».

## 21. Импорт сценариев, диалогов и реплик из Excel (кратко)

### Назначение
Тексты сценария, диалоги и реплики бойцов писали сценаристы в таблицах Excel; редактор переносит их в базу через ODBC-драйвер Excel (`Provider=MSDASQL.1; DSN=Excel Files; DBQ=<файл>; DriverId=790`). Логика сценария и реплик — в «Кампания 1/2» и «Мир 1»; здесь только способ импорта.

### Алгоритм
1. **Улики сценария** (кнопка экспорта дерева Scenario): файл = `<источник>\<SrcXLSName записи>`; лист `ScenarioClues$`. Строка с непустым кодом улики начинает новую улику: ищется улика по (сценарий, код); если её описание (строка `Strings`, с заменой апострофов) отличается от ячейки — строка обновляется; счётчик целей сбрасывается. Следующие строки с непустым «ObjectiveAction» — цели 1 и 2 улики (не более двух): обновляется описание цели. Обратная операция (`CreateScenarioXLS`) выгружает улики в новую таблицу.
2. **Реплики бойца** (меню File → Export acks): выбрать `.xls` и персонажа; лист `General on game zone$`; столбцы: условие, описание условия, параметр, фраза 1, интонация 1, вероятность 1, фраза 2, интонация 2, вероятность 2. Пропускаются строки без условия или без обеих фраз; «N/A» и «N/A.» считаются пустой фразой. Для каждой строки создаются/обновляются записи `AckInfos` (строка текста, звук, «кто говорит», интонация), последовательности `AckSeqs`, условия `AckConditions`; имя реплик строится по персонажу; учитывается `MaxAck` персонажа; изменения журналируются (`AcksInserted`, `AcksDeleted`). Итог — «Exported N records».
3. **Диалоги** (экспорт дерева Dialogs): лист с именем диалога; строки — код персонажа (герой по умолчанию по стороне/голосу или конкретный персонаж), фраза; формируется последовательность `DialogSeqs` (вставка/удаление записей с журналом `DialogAcksInserted`/`DialogAcksDeleted`). Есть проверки «мусора»: последовательностей, записей реплик и строк без ссылок.

### Что нужно от движка-носителя
Импорт таблиц (CSV/XLSX) в строковые таблицы и записи реплик с журналом изменений; в UE5 — DataTable/StringTable.

## 22. Совместное редактирование: предупреждение

### Назначение
Несколько дизайнеров работали с одной базой на сервере. Редактор не блокирует зону, а лишь предупреждает, что тот же вариант уже открыт на другой рабочей станции.

### Данные
Таблица `SharedMaps`: `PlacementID` (ID варианта), `ComputerName`, `ID` (счётчик), `Time` (строка `ctime`, например «Wed Sep 24 19:13:14 2003»). В базе ноября 2003 г. осталось 398 строк — «хвосты» незакрытых сеансов.

### Алгоритм
1. При запуске каждый редактор слушает TCP-порт 16115.
2. Открытие варианта шаблона (`OpenPlacement`): прочитать все строки `SharedMaps` с этим вариантом. Для каждой: если имя компьютера совпадает со своим или соединиться с этим компьютером на порт 16115 не удалось — строка считается устаревшей и удаляется. Иначе отправить ID варианта текстом (с завершающим нулём) и прочитать ответ: «true» — владелец подтверждён, иначе строка удаляется.
3. Отвечающая сторона: прочитать число; если её активный элемент — шаблон и открыт именно этот вариант — ответ «true», иначе «false».
4. Если подтверждённые владельцы есть — окно «This map is opened on workstations:» со списком имён (кроме своего). Редактирование не запрещается.
5. Затем добавляется своя строка (вариант, имя компьютера, текущее время). Закрытие варианта, переход к другому элементу и выход из редактора удаляют свою строку (по варианту и имени компьютера).

### Особые случаи и прихваты
- Для проверки всех строк используется **один** сокет: после первого успешного соединения следующие `Connect` на нём же не проходят, и остальные владельцы считаются устаревшими и стираются из таблицы — предупреждение показывает не больше одного удалённого владельца.
- Отвечающая сторона при неподходящем варианте отправляет «false» и сразу «true» (нет выхода после первого ответа); спрашивающий читает первую строку буфера, поэтому работает правильно лишь благодаря тому, что «false» приходит первым.
- Две копии редактора на одной машине друг друга не видят (свои строки удаляются как устаревшие).
- Строки остаются в таблице при аварийном завершении — их подчищает следующий открывший.

### Что нужно от движка-носителя
Для современного редактора достаточно мягкой блокировки зоны (запись «кто открыл» + проверка живости владельца) или системы контроля версий над файлами зон.

## 23. Клавиши редактора (секция mapeditor)

### Назначение и правила
Файл `Complete\cfg\input.cfg` (сгенерирован инструментом «S^2»). Привязки до первой директивы `bindsection` действуют во всех секциях, привязки секции — только в ней; редактор при каждом событии ставит секцию `mapeditor`. Если одна комбинация является надмножеством другой (Ctrl+C и C), более длинная блокирует более короткую. Команда с «+»/«−» — ось (знак направления); «!» — событие отпускания. Ниже — всё, что действует в 3D-окне редактора. Обработчики — `IWysiwyg.cpp` (WYSIWYG) и `iMapEditor.cpp` (просмотрщик); команды без клавиши вызываются из меню через очередь событий (раздел 1).

## 24. Минимальный современный редактор: приоритетный список функций

Цель — чтобы дизайнер мог собрать зону «как в Silent Storm» (рельеф + модульные здания + объекты + юниты + вложенные шаблоны со случайными вариантами) на движке-носителе (UE5: режим редактора/плагин). Приоритет 1 — без этого зону не собрать; 2 — без этого работа очень медленная; 3 — удобства и вспомогательное.

### Приоритет 1 — обязательно
1. **Модель данных зоны**: шаблон W × H тайлов (0,625 м) с вариантами (вес `RndWeight`, флаги-атрибуты); содержимое варианта: рельеф (узлы (W+1)×(H+1)), постройка (фрагменты: деталь, подблок, x/y в тайлах, z в этажах с полуэтажами, поворот 0–3, слой, флаги, 8 слотов материалов, пятна, ID), объекты (дробные тайлы, этаж, `DeltaZ`, поворот, масштаб, стадия разрушения, «открыто»), юниты (целые тайлы, этаж, поворот, логика/поза/группа), вложенные шаблоны (центр в тайлах, поворот на любой угол, этаж, `DeltaZ`, атрибуты-требования), вейпоинты с командами, маршруты, пятна рельефа (приоритет, слой), комнаты, маска подвала, лестницы.
2. **3D-вид с этажами**: плоскость отсечения этажей (всё выше скрыто), активный этаж = рабочая плоскость (2,5 м на этаж), полуэтаж для промежуточных слоёв.
3. **Строительные инструменты**: ломаная стен по осям с шагом длины детали, откатом и слиянием коллинеарных отрезков; автоматический поворот «внутрь справа»; нарезка на детали и 2-тайловые подблоки; переворот стороны; заливка прямоугольником (контур стен внутрь, решётка плит); поштучная постановка с активным поворотом и предпросмотром.
4. **Выделение и трансформации**: пиккинг с приоритетом активного слоя (вложенный шаблон — внутренний первым), Ctrl-добавление, рамка по активному этажу, «выделить всё видимое»; перенос с привязкой к тайлу (по умолчанию для деталей — всегда), по высоте четвертями этажа, зажим в границы зоны; поворот 90° для деталей/лестниц и свободный/45° для остальных; удаление.
5. **Палитра ассетов + перетаскивание** в вид с предпросмотром: детали, объекты, предметы, персонажи, шаблоны, пятна, имена вейпоинтов.
6. **Рельеф**: кисть высоты (сферическая шапка от снимка, раздел 14), покраска типов тайлов кругом, трава (плотность + пучки), дыры-многоугольники с высотой дна, маска подвала.
7. **Материалы**: покраска сторон детали (внутрь/наружу/торец/верх/низ по нормали), набор из 4 материалов, пипетка.
8. **Вложенные шаблоны**: вставка, перенос/поворот, показ выбранного варианта с вложенным рельефом и зданиями, атрибуты-требования к варианту; «новый шаблон из выделения» с центровкой.
9. **Отмена/повтор** для всех правок 3D-вида (группы, стабильные ID).
10. **Сохранение и проверка**: чистка удалённых/некорректных фрагментов, пятен, групп слоёв, лестниц; приведение карт комнат и подвала к размеру; запись постройки и рельефа.
11. **Инспектор свойств** выбранного (пересечение свойств при множественном выборе; координаты центра выделения как редактируемые поля).

### Приоритет 2 — важно для скорости
12. Буфер обмена между этажами и зонами (сдвиг этажа = разница активных этажей).
13. Пятна-декали на здании с явной привязкой к фрагментам и маской материалов; пятна на рельефе с приоритетом «наверх».
14. Слои построек (несколько слоёв перекрытий/сплошных), видимость слоёв, связывание слоёв и этажей для клиппинга.
15. Лестницы (высота в ступенях 0,625 м, поворот).
16. Маршруты юнитов по именам вейпоинтов; команды вейпоинтов (поза, ожидание, направление).
17. Сохранённые камеры и анимация камеры по списку (линейная интерполяция, время в мс).
18. Режим «собрать как в игре» (случайные варианты, полная сборка) и запуск миссии из редактора.
19. Предупреждение о совместном открытии зоны (или блокировка через систему версий).

### Приоритет 3 — вспомогательное
20. 2D-план зоны (стены, полы, комнаты, рельеф как картинки) — в UE5 можно заменить видом сверху.
21. Редактор кусков AI-геометрии и виртуальных связей (для разрушаемости — если она переносится, см. «Мир 2»).
22. Импорт/экспорт карт рельефа в изображения; импорт текстов из таблиц.
23. Просмотрщики ассетов (модель, материал, анимация с маркерами выстрела, объект по стадиям, AI-геометрия).
24. Анализ данных (наличие исходников, типы текстур, «мусорные» файлы).

### Чего не повторять
Двойную запись (база + бинарные файлы по ID варианта), ID-индексы фрагментов в выделении, неинициализированные поля фрагментов, потерю лестниц и пятен на стенах при вставке, отсутствие отмены для 2D-правок — см. «Все прихваты списком».

## Все прихваты списком

1. Игровой цикл редактора делает шаг на каждый второй вызов простоя MFC (`RENDER_DELAY` = 1); активен только при фокусе 3D-окна (или всегда при «Realtime preview», если активно 3D-окно).
2. Зона с хотя бы одним фрагментом постройки поднимается целиком на высоту рельефа в центре шаблона; зона без построек кладёт каждый объект на рельеф в его точке; флаг пересчитывается каждый кадр.
3. Сетка здания в редакторе создаётся на W+2 × H+2 и на 10 этажей шире фактического диапазона — чтобы не пересоздавать её при правке.
4. Начальная камера: l = целое(0,625·max(W,H)), высота = 4 + (l >> 1)/tg 17,5°, не меньше 5; тангаж −89°.
5. Диалоги из контекстного меню открываются через таймер 10 мс (иначе «глюки»); само меню — через 100 мс после правой кнопки, движение мыши его отменяет (правое перетаскивание — камера).
6. Опция перекраски системных цветов Windows по формуле sRGB→линейный (f ≤ 0,1047 → f/4).
7. Перенос объекта разрешается только через 0,2 с после его выбора; двойной щелчок — < 0,4 с и только по уже выделенному.
8. CapsLock (состояние переключателя) = привязка к тайлу; Shift = поворот; Z = высота; Ctrl = добавить к выделению / поворот 45° / заливка прямоугольником при пустом выделении; Alt = камера, щелчки игнорируются.
9. Первый клавиатурный шаг с CapsLock = 0,8 тайла (гарантированный переход в соседний тайл); поворот мышью −0,7°/пиксель по вертикали; клавиатурный поворот 20°/шаг (клавиша не назначена).
10. Если в выделении есть фрагмент здания, вся группа двигается по целым тайлам и поворачивается кратно 90°.
11. Этаж любого переносимого объекта ограничен сверху 4; фрагмент за один перенос — тоже.
12. Этаж вложенного шаблона меняется с гистерезисом: `DeltaZ` ≥ 1,26 м — вверх, < −1,24 м — вниз.
13. Удаление фрагмента в 3D — «надгробие» (ID детали −1), чтобы не сбить индексы-userID; чистка — при сериализации; после неё здание пересоздаётся, выделение снимается.
14. Удаление в 2D вынимает фрагмент сразу; отменённое удаление в 3D возвращает фрагмент в конец массива.
15. userID фрагмента стены = индекс | 0x40000000; второй геометрии — бит 0x20000000.
16. Рамка выбирает строго внутри, только на этаже пол(активного); вейпоинты рамкой не выбираются; пятна на стенах — без учёта этажа.
17. «Выделить всё» не берёт пятна на стенах, но берёт фрагменты «без слоя» (−1 или номер > 100 — следствие неинициализированного поля).
18. Поля `nFragmentID`/`nObjectFlags` фрагмента не инициализируются при рисовании стен в 2D (а `nObjectFlags` — и в 3D).
19. Внутренняя сторона стены — справа по ходу рисования (обводить по часовой стрелке); хранится поворотом (локальная +Y — внутрь).
20. Вершины цепочки стен появляются только с шагом 2·SizeX тайлов; ведение назад до предпоследней вершины стирает последнюю; хвост отрезка короче детали отбрасывается.
21. Повторное рисование стены поверх существующей в 2D создаёт дубликат в данных.
22. Закраска клетки пола другой деталью в 2D не удаляет старый фрагмент (поиск ведётся по ID новой детали).
23. Размер клетки пола в 2D не учитывает поворот детали; 3D-заливка считает число деталей по Y делением на шаг X.
24. Сплошные детали без геометрии — полупрозрачные кубы (0,6; 0,6; 0,65; 0,6), их можно выбирать.
25. Объект без модели — сфера 0,3125 м: обычная (0,7; 0,7; 0,9), слот улики (предмет 188) — (1; 0,5; 0,6), «взрыв» (предмет 189) — (0,77; 0,55; 0,1); разрушения от «взрывов» в редакторе не показываются.
26. Новый объект, стоящий на основании (низ AI-геометрии ≤ 0,05 м), в клетке с фрагментами здания поднимается на 0,1 м; у предметов подъём считается по чужой модели (ошибка).
27. Точечный свет нулевой модели объекта копируется в запись объекта при постановке.
28. Двойной щелчок по двери/окну-объекту проигрывает анимацию открытия/закрытия только для показа; флаг «открыто» — в отдельном диалоге/свойстве.
29. Сферическая кисть высот считает от снимка, смешивает тайлы (по горизонтали) и метры (по высоте), не трогает нулевые строку/столбец; высота ≥ 0.
30. Кисть тайлов/травы: радиусы 0,3/0,7/3,0 м → 0/1/5 узлов.
31. Пятно рельефа ставится по плоскости z = 0, размер 32 пикселя текстуры на тайл; новое — поверх всех (приоритет max+1).
32. Пятно на здании видно только на явно привязанных фрагментах; удаление = материал −1.
33. Пин варианта вложенного шаблона живёт только в памяти сеанса; рельеф строится по тому же пину.
34. Ящик вложенного шаблона получает случайную высоту 2,5…2,75 м (от мерцания соседних ящиков).
35. Поворот вложенного шаблона не нормализуется (в базе есть 360, 450, 630, −90).
36. Атрибуты-требования вложенных шаблонов (`Rects.Params`) в базе 2003 г. не заданы ни разу (0 из 19 684); флаги вариантов есть у 10 вариантов, часть ссылается на несуществующие атрибуты 2, 3, 4.
37. Буфер обмена: объекты, юниты, шаблоны копируются ссылкой на ID исходной записи; пятна на стенах и лестницы при вставке теряются; сдвиг этажа = разница активных этажей.
38. Вставка в новый шаблон центрирует выделение и округляет сдвиг отбрасыванием (x → целое(x), y → целое(y − 0,5)).
39. Новый шаблон из выделения: размер = 1 + ceil(размер рамки / 0,625); исходная зона не меняется.
40. Копия варианта теряет свойства «дверь/окно» и «мина» объектов, не копирует этаж 10, двигает «старые взрывы» до проверки вставки.
41. Удаление варианта не убирает его из списка вариантов в памяти (удаление из копии).
42. Лестницы, вейпоинты, пятна на стенах, флаги фрагментов, все 2D-правки и правки инспектора — вне истории отмены.
43. Неудачная отмена стирает всю более старую историю; неудачный повтор — хвост; история сбрасывается при каждом создании WYSIWYG-мира.
44. При повторной вставке удалённой записи базы её новый ID подставляется во все команды истории того же типа.
45. Кисть высот хранит в истории две полные копии карты высот.
46. Новые записи создаются вставкой строки с «левым» значением (`UserName` = «New Item», `Flags` = '', `Floor` = 0) и чтением ID, выданного сервером; путь «MAX(ID)+1» остался в коде, но отключён.
47. Номер комнаты = MAX(RoomID)+1 в пределах (вариант, этаж); карта комнат пересоздаётся пустой, если изменилось число этажей постройки.
48. Счётчики ID фрагментов/пятен/лестниц > 100000 сбрасываются в 1 («для старых шаблонов»).
49. При сериализации постройки выбрасываются фрагменты вне [0; W] × [0; H] (граница включительно), с ID детали ≤ 0 или несуществующей деталью, слои материалов с несуществующим шаблоном, пятна с несуществующим материалом, пустые группы слоёв, лестницы с ID ≤ 0.
50. Совместное редактирование: один сокет на все проверки (видно не больше одного удалённого владельца, остальные строки стираются); ответ «false» и «true» подряд; две копии на одной машине не видят друг друга.
51. `GridInterval` = 0 зацикливает рисование сетки; сетка рисуется с многократными повторами линий.
52. Space назначен двум командам (`topmost_spot`, `next_phase`) в разных интерфейсах; общая привязка Ctrl+C = `exitgame` в редакторе не обрабатывается.
53. Анимация камеры: исходный FOV пишется в локальную переменную, поле класса не обновляется.
54. Экспорт света из Maya обновляет в движке таблицу анимаций вместо света; в режиме Maya с интерфейсом в скрипт добавляется `quit -a`.
55. Хеш стены в 2D-плане делит код поворота (0…3) на 90 — поворот в хеш не входит.
56. Режим `EM_GEOMETRY` есть на панели, но в 3D не обрабатывается.
57. Свойство юнита `FearUseToHit` объявлено дважды.
58. Ошибки: `type = BT_LADDER` (присваивание вместо сравнения), отмена поворота юнита пишет x вместо y.
59. Связи кусков AI-геометрии ставятся по касанию граней ячейки 0,625 м с допуском 0,156 м; поиск «пропущенных» связей закомментирован.
60. Коллизия дверей в двух состояниях — по первому кадру анимаций `ACTIVATE` и `DEACTIVATE` для каждой из 5 стадий разрушения.
61. Для DXT-текстур экспорт делает вторую несжатую копию с ID | 0x01000000.
62. Создание вейпоинта игнорирует переданный этаж и берёт активный.
63. Пипетка материала — временный режим со стеком глубины 1.
64. Лестницы не попадают в принудительное выделение («выделить всё», дополнение рамкой) — список лестниц собирается, но не обрабатывается.
65. Рамочное выделение пятен на стенах сравнивает их начало в метрах с рамкой в тайлах.
66. Вложенный шаблон можно перетащить в самого себя в 3D (проверка есть только в 2D).
67. Двери и окна в данных 2003 г. — проём-деталь + отдельный объект; встроенный в деталь объект есть только у 7 частей печей.

## Примеры

### Пример 1. Дом 8 × 6 клеток с дверью и двумя окнами

Исходные данные: вариант V шаблона 24 × 20 тайлов (15 × 12,5 м), активный этаж 0. Дом 8 × 6 строительных клеток = 16 × 12 тайлов = 10 × 7,5 м, юго-западный угол в тайле (4; 4), северо-восточный — (20; 16). Детали из базы:

| роль | шаблон детали (ID, имя, папка) | вариант | размер X×Y×Z, толщина | геометрия | материалы по умолчанию (слот 0, 1, 2, срез) |
|---|---|---|---|---|---|
| стена | 59 «02br» (Doors/Door01/Wall) | 206 | 2×0×1, 0,2 | 483 «d02br» | 373 Brick01, 373 Brick01, 1385 WallTop, 364 Brick |
| проём двери | 644 «d02_br» (Doors/TownDoor01) | 1744 | 2×0×1, 0,2 | 2213 «do2_br» | 373, 373, 1385, 364 |
| проём окна | 620 «d02_br» (Windows/TownWindow01) | 1626 | 2×0×1, 0,2 | 2266 «do2_br» | 373, 373, 1385, 364 |
| пол | 29 «Floor_wh01» (Floors) | 59…62 (4 варианта, вес 1) | 1×1×1, 0,1 | — | — |

Длина детали стены L = 2·2 = 4 тайла (2,5 м); плита пола — клетка 2 × 2 тайла.

1. **Стены (2D-вид, слой Walls, кисть 59).** Нажать в узле (4; 4) и вести по часовой стрелке: вверх до (4; 16), вправо до (20; 16), вниз до (20; 4), влево до (4; 4). Вершины цепочки появляются каждые 4 тайла; после слияния — 4 отрезка:
   - A (4;4)→(4;16), вверх, 12/4 = 3 детали, поворот 270° (код 3), сдвиг (0; 4): начала деталей (4;8), (4;12), (4;16); подблоки шагом (0; −2): (4;8)#9344, (4;6)#9472, (4;12), (4;10), (4;16), (4;14);
   - B (4;16)→(20;16), вправо, 4 детали, поворот 180° (код 2), сдвиг (4; 0): начала (8;16), (12;16), (16;16), (20;16); подблоки шагом (−2; 0): (8;16), (6;16), (12;16), (10;16), (16;16), (14;16), (20;16), (18;16);
   - C (20;16)→(20;4), вниз: концы меняются местами, начало (20;4), 3 детали, поворот 90° (код 1), сдвиг 0: подблоки шагом (0; 2): (20;4), (20;6), (20;8), (20;10), (20;12), (20;14);
   - D (20;4)→(4;4), влево: начало (4;4), 4 детали, поворот 0, подблоки шагом (2; 0): (4;4), (6;4), … (18;4).
   Итого 28 фрагментов стены, z = 0, деталь 59, хеши 9344 (первый подблок) и 9472 (второй). Внутренняя сторона у всех — внутрь дома. Постройка сразу сериализуется; ID фрагментов выдаются по порядку массива: 1…28 (A — 1…6, B — 7…14, C — 15…20, D — 21…28).
2. **Дверь.** Рамкой выделить на южной стене подблоки (12;4) и (14;4) (оба конца каждого строго внутри рамки, например (11,5; 3,5)–(16,5; 4,5)), правое меню → Delete: фрагменты 25 и 26 вынимаются. Кисть 644, провести цепочку (16;4)→(12;4) (влево, чтобы внутренняя сторона осталась внутри): 1 деталь, поворот 0, подблоки (12;4)#9344 и (14;4)#9472, ID 29, 30. Дверное полотно: в 3D-окне перетащить из дерева объектов «TownDoor01» (`ObjectTemplates` 999 → `PlacableObjects` 1169) в проём → строка `FinalElements`: `ModelID` 1169, `VariantID` V, `PosX`/`PosY` — дробные тайлы точки броска (≈ 14,0; 4,0), `Floor` 0, `DeltaZ` 0 или 0,1 (если низ AI-геометрии ≤ 0,05 м и в клетке есть фрагменты — не подтверждено для этой модели), `Rotation` 0; при необходимости R (90°) или Shift+тащить (Ctrl — шаг 45°).
3. **Окна.** На северной стене удалить подблоки (8;16), (6;16) [ID 7, 8] и (16;16), (14;16) [ID 11, 12]. Кисть 620, цепочки (4;16)→(8;16) и (12;16)→(16;16) (вправо): по 1 детали, поворот 180°, подблоки (8;16)#9344, (6;16)#9472 и (16;16)#9344, (14;16)#9472, ID 31…34. Створки: перетащить «TownWindow01» (`ObjectTemplates` 1004 → `PlacableObjects` 1178) в каждый проём — ещё 2 строки `FinalElements`.
4. **Пол.** Слой «Floors» (номер 0), кисть 29. Нажать точно в тайле (4; 4) и провести по площади до (18; 14): клетки добавляются по решётке с шагом 2 тайла — 8 × 6 = 48 клеток → 48 сплошных фрагментов: деталь 29, подблок 0, позиции (4…18 шаг 2; 4…14 шаг 2; 0), поворот 0, слой 0. Вариант плиты (59…62) выберет игра случайно по весу.
5. **(По желанию) потолок/второй этаж** — активный этаж 1, та же заливка: ещё 48 фрагментов с z = 1.
6. **Покраска** (3D, режим Brush, набор 1 = материал): щёлкать по внутренней стороне стен — слот 1 фрагмента (локальная нормаль +Y) получает один слой материала; наружная сторона — слот 0.

Результат: файл `Buildings\V` — 28 фрагментов стен (22 × деталь 59, 2 × 644, 4 × 620), 48 (96) сплошных, размеры 24 × 20, этажи 0…0 (0…1), карта комнат на 1 (2) этаж по 26 × 22, маска подвала 24 × 20 (пустая), счётчик ID фрагментов > 34+48. В базе — 3 новые строки `FinalElements` (с отменой «вставка» в истории 3D); правки 2D (стены, пол) в историю отмены не попадают.

### Пример 2. Отмена переноса стены

Продолжение примера 1, 3D-окно. Фрагмент ID 17 — первый подблок средней детали восточной стены: позиция (20; 8; 0), поворот 90° (код 1), хеш 9344. После удалений в шаге 2–3 (вынуты ID 25, 26 после него и 7, 8, 11, 12 перед ним) его индекс в массиве стен = 12, userID = 0x40000000 | 12.

1. Щелчок по стене: пиккинг возвращает здание с userID 0x4000000C → выделение `CFragmentSel` (рамка 0,2 × 1,25 × 2,5 м + основная рамка).
2. Через ≥ 0,2 с тянуть мышью вправо на 2 тайла при включённом CapsLock. Плоскость переноса — на высоте центра рамки (1,25 м = 0,5 этажа) + высота рельефа в центре шаблона. Смещение округляется до тайлов (у фрагмента дискретность 1): (1,25; 0) м; зажим в карту не срабатывает.
3. Отпустить: смещение в тайлах = целое(1,25/0,625) = 2, по высоте 0 → позиция (22; 8; 0); перестраиваются куски сетки здания вокруг старой и новой клетки; в открытую группу отмены кладётся «смена позиции» {до: копия фрагмента с (20;8), после: (22;8), ID 17}; группа закрывается и уходит в историю; постройка сериализуется в `Buildings\V`, AI-карта синхронизируется. Второй подблок детали (20; 10) остаётся на месте — в стене образуется разрыв (переносится подблок, а не деталь; для переноса детали целиком нужно выделить оба подблока).
4. Ctrl+Z: команда в текущей позиции истории — эта группа; позиция сдвигается назад; подкоманды выполняются в обратном порядке: фрагмент ID 17 ищется по `nID` в массиве стен (деталь 59 имеет глубину 0 → «стена»), ему возвращается снимок «до» целиком (позиция (20; 8; 0), поворот, материалы, пятна). Пост-обработка: сериализация `Buildings\V` и перестройка всех кусков здания; затем «deselect» — выделение снято.
5. Ctrl+Shift+Z: позиция сдвигается вперёд, тому же фрагменту присваивается снимок «после» (22; 8; 0), снова сериализация и перестройка.

### Пример 3. Новый шаблон из выделения и вложение в другую зону

1. В зоне V (пример 1) на этаже 0 протянуть рамку (`EM_SELECT`, пустое выделение, без Ctrl) вокруг дома: выбираются 28 фрагментов стен, 48 плит пола и 3 объекта (их позиции внутри рамки и этаж 0).
2. Рамка выделения: стены дают ±0,1 м от осевых линий (половина толщины 0,2): x ∈ [4·0,625 − 0,1; 20·0,625 + 0,1] = [2,4; 12,6], y ∈ [2,4; 10,1] (северная стена при повороте 180° даёт [9,9; 10,1]); плиты и объекты внутри (принято, что AI-рамки створок не выходят за стены — не подтверждено). Размер: 10,2 × 7,7 м.
3. Правое меню → «New template from selection»: nX = 1 + ceil(10,2/0,625) = 1 + ceil(16,32) = 18, nY = 1 + ceil(7,7/0,625) = 1 + ceil(12,32) = 14. Диалог предлагает папку текущего шаблона, имя (например «House8x6») и 18 × 14. ОК → строка `Templates` (ID = T от сервера, `Width` 18, `Height` 14) и строка `TemplVariants` (ID = V2, `TemplateID` T, умолчания: `Grid` 0, `RndWeight` 1, `DefaultLight` 102 «All», `ShowTerrain` 1, `Border` 15, `HMBlendType` 'Normal', `Weather` 'Sunny').
4. Выделение копируется в буфер (активный этаж 0); открывается WYSIWYG варианта V2 с той же камерой и сразу выполняется вставка в новый шаблон:
   - фрагменты получают новые ID 1…76 в новой постройке (размеры 18 × 14), этаж + 0;
   - объекты — 3 новые строки `FinalElements` в V2 с копией всех свойств;
   - перенос для центровки: цель (x, y) = (0,5·(18 − 16,32); 14 − 0,5·(14 − 12,32)) тайлов = (0,84; 13,16) → (0,525; 8,225) м; левый верхний угол рамки (2,4; 10,1) м; сдвиг (−1,875; −1,875) м = (−3,0; −3,0) тайла → (целое(−3,0); целое(−3,5)) = (−3; −3) тайла.
   - Итог: стены дома по линиям x = 1 и 17, y = 1 и 13 тайлов; пол (1…15; 1…11); объекты сдвинуты на 3 тайла. Исходная зона V не изменилась. Дерево переключается на T/V2, камера сбрасывается на обзор шаблона.
5. Открыть зону Z (например, деревню) и перетащить «House8x6» из дерева шаблонов в 3D-окно, отпустив над точкой (20,0; 15,0) м на этаже 0 → строка `Rects`: `VariantID` Z, `TemplateLink` T, `Width` 18, `Height` 14, `Floor` 0, `DeltaZ` 0, `Rotation` 0, центр = (20/0,625 + 9; 15/0,625 + 7) = (41; 31) тайла. Отмена «вставка». В 3D показывается единственный вариант V2 (пин), его рельеф вкладывается в рельеф Z, поверх — голубой ящик 11,25 × 8,75 × (2,5…2,75) м.
6. Клавиша R поворачивает выделенный вложенный шаблон на 90° вокруг его центра (угол сдвигается так, чтобы центр остался на месте); при записи — `Rotation` 90, центр (41; 31) без изменений.
7. Чтобы в будущем выбирать между несколькими вариантами дома (например, днём и ночью), у шаблона T добавляют варианты («New variant»/«Copy variant»), в окне PARAMS отмечают атрибуты (Day = 6, Night = 5), а у вложения в зоне Z в свойстве `Params` указывают имя атрибута («Day») — при сборке будет выбран вариант с этим флагом.

## Отклонения реконструкции от оригинала

Пометок `[FORK]` в исходниках MapEdit нет. Известные отличия:

1. **Версия исходников.** По `reconstruction\FORK.md`, MapEdit в репозитории — «потомок Jan03» (январская ветка 2003 г.), т. е. **старше** релизного `MapEdit.exe` (ноябрь 2003 г., рядом с которым лежит база `A5GAME`). Всё описанное — поведение январского кода; функции и исправления, появившиеся до ноября, могут отсутствовать, а схема базы ноября 2003 г. содержит столбцы, которых этот код не знает (редактор не ссылается на `TemplVariants.NoAttack`, `MinCutFloor`, `MaxCutFloor`, `Weather`, `ExitBorder`, на `FinalElements.KeyID`, `LockHardness`, `IsLocked`, `RPGChestID`, `LightShadow` и на `Waypoints.Is3DPoint`, хотя игровой импорт `DBFormat` их читает — значит, в релизном редакторе были свойства/инструменты для них: замки и ключи на объектах, сундуки, погода, границы выхода, пределы отсечения этажей, 3D-вейпоинты).
2. **Не собирается.** MapEdit исключён из сборки реконструкции (нужны MFC, Stingray Objective Toolkit, LifeMode SDK); ни одно утверждение этого документа не проверено запуском.
3. **Подгонка к API нового движка** (комментарии на английском с отсылками «retail @0x…»): вызов `CBuildingGrid::Setup(W+2, H+2, min−10, max+10, VNULL2)` — в «ритейле» без параметра преобразования; `Explode(MakeTransform(VNULL3), …)` — преобразование сетки здания теперь передаётся параметром (редакторская сетка стоит в начале координат); размеры прямоугольников рамки иконок и киношных полос «запечены» в `CRectLayout` вместо масштаба раскладки; в мире редактора добавлена заглушка `GetPocket()` («мир редактора не переносит стратегический карман»). По смыслу поведение не меняют.
4. **Механическая переделка проверок типов**: около 40 мест вида «`CDynamicCast<T> p(x); if (p) …`» вместо прежних цепочек `dynamic_cast` в условиях (выбор класса выделенного объекта, маска выделения, сбор выделения). Порядок проверок сохранён; влияние на поведение не подтверждено, но не ожидается.
5. **Данные.** Исследовалась не SQL-база сервера, а её перенос в SQLite (`tools\mdf2sqlite.py`: 283 таблицы, 268 540 строк; против `Complete\game.db` расходятся 49 значений). Признак «столбец-счётчик» у `ID` (на котором держится выдача ID при вставке) в `_mdf_columns` не отражён — что `ID` был IDENTITY на сервере, выведено из кода вставки, не из схемы.
