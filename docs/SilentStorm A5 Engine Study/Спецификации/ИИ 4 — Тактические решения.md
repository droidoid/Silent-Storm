# ИИ 4 — Тактические решения в бою

Источник: `reconstruction/Main` (aiCommander, aiLogic, aiCombatLogic, aiChoosePlace, aiActionPlaceSource, aiActions, aiSnipeAction, aiHeavyGunAction, aiLootAction, aiWeapon, aiInventory, aiDecision, aiJob, aiUnit, aiUnitState, aistate, AILog, RPGGame, RPGToHit) и база `A5GAME.sqlite`. Код не вставляется; формулы и пороги даны точно. Там, где реконструкция сама помечает место как собственное исправление или допущение, это вынесено в раздел «Отклонения реконструкции от оригинала».

## Суть

У каждой стороны, которой управляет компьютер, есть один «командир». Он не строит общего плана: он по очереди берёт своих бойцов (следующим становится ближайший к предыдущему) и даёт каждому думать самостоятельно. Думает боец так: (1) собирает список клеток, куда он может встать за ограниченное число очков действия (ОД) — своя клетка, клетки вдоль пути к врагу, узкая «фланговая» дуга, — каждая в двух позах: стоя и сидя; (2) для каждого возможного действия (выстрел, граната, ракета, нож, перезарядка, подбор, рукопашная, станковый пулемёт, снайперский режим, панцеркляйн…) выбирает из этих клеток лучшую; (3) идёт сверху вниз по жёстко заданному списку правил и исполняет первое действие, которое выполнимо. Оценки «полезности» как таковой нет — есть порядок правил и компараторы клеток. Свою защищённость от врага ИИ в этом слое не считает вообще: клетка оценивается только по собственному шансу попадания и по остатку ОД. Оружие и режим огня выбираются перебором «оружие × режим» по ожидаемому урону за весь остаток ОД. Таблицы `aiUtilityTables*` в базе пусты — правила зашиты в код.

## Термины и единицы

| Термин | Значение |
|---|---|
| Сегмент мира | Один шаг симуляции, 50 мс (`DW_SEGMENT_TIME`) |
| ОД (AP) | Очки действия. У ИИ-бойца есть «зеркало» ОД/здоровья (плановая копия) и «живые» значения на сервере юнита |
| Клетка (тайл) | Узел сетки пути, шаг сетки 0,625 м (`FP_GRID_STEP`). Расстояния «в метрах» — мировые единицы; «в клетках» = метры / 0,625 |
| CP | Опорная точка юнита (control point), по ней меряются все дистанции |
| Место (`SPlaceWithAP`) | Клетка + слой + поза + направление и число ОД, которое останется у бойца по прибытии |
| Поза клетки | 2-битная категория: 0 лёжа, 1 сидя, 2 стоя, 3 «неактивная» (лазание, лестница и т. п.) |
| Поза перемещения | WALK, RUN, CROUCH, CRAWL — «желаемая поза» при движении |
| Логика | Объект поведения бойца (атака, оборона, охрана, отступление, после боя); создаётся слоем реакций (см. чужую спецификацию) |
| Действие | Один из 19 классов (выстрел, граната…) с тремя операциями: «можно ли из места», «какое из двух мест лучше», «записать в журнал» |
| Журнал | Список записей плана; при добавлении запись сразу меняет плановое состояние (зеркала ОД, патронов, инвентаря), затем разворачивается в команды мира |
| Враг (`pEnemy`) | Выбранная цель бойца из его личного списка подтверждённых врагов |
| Подозреваемый (`pPossibleEnemy`) | Ближайший из «возможных» врагов (потерянных из виду/услышанных) |
| Группа врагов | Скопление врагов в радиусе 1,5 м, строится для гранат и ракет |
| ПК | Панцеркляйн (экзоскелет) |
| СП | Станковое орудие/пулемёт (в коде HG, «cannon») |
| HL | Часть тела: ANY (−1), HEAD, BODY, руки, ноги |
| RT / TB | Режим реального времени / пошаговый режим |

## 1. Командир: цикл, очерёдность, троттлинг

### Назначение
Раз в сегмент выдавать в мир не более одной команды от ИИ; раз в три сегмента — принимать одно новое решение (запустить «думание» одного бойца или забрать у его логики одну команду); вовремя заканчивать ход; не дать ИИ зависнуть.

### Данные
- Список своих бойцов (`units`) и кэш «юнит мира → ИИ-обёртка».
- Счётчик `nAILag` (0…2).
- Очередь исходящих команд: список команд, защёлка «в этом сегменте команда уже выдана», счётчик `nNonFreezeCounter`.
- Очередь реакций, ждущих обновления (обрабатывается по одной).
- Трекер обхода: рабочая копия списка бойцов, текущий боец, игрок.
- Множество логик, уже объявивших «мой ход окончен» (сбрасывается в начале хода).
- Общее состояние стороны (`SAIState`): мир, игрок, списки «союзники»/«враги», группы врагов, текущий боец/враг.
- Глобальный флаг запрета ИИ `game_noai`.

### Алгоритм

**Каждый сегмент мира (`Segment`)**
1. Снять защёлку «команда выдана».
2. `nAILag += 1`. Если `nAILag > 2`: обнулить, пересобрать состояние стороны (п. 2) и выполнить «ИИ-сегмент»:
   1. Если ИИ запрещён или идёт скриптовая сцена — выйти.
   2. Каждому своему боеспособному бойцу под управлением ИИ дать тик восприятия (обновление личного списка угроз и выбор цели, п. 10).
   3. В TB, если сейчас не ход этой стороны, — выйти.
   4. Для каждого бойца, у которого состояние угроз изменилось: выбросить из очереди команд все его команды, отменить его текущую команду мира, поставить его реакцию в очередь (без дублей).
   5. В TB, если идёт анимация действия, — выйти.
   6. Снять с очереди реакций ОДНУ (первую) и обновить её (она выбирает/меняет логику бойца). Реакция мёртвого/небоеспособного пропускается.

**Генерация команды (`GenerateCommand`, вызывается миром каждый сегмент)**
1. Если у менеджера заданий есть задания высшего приоритета (расчёт проходимости/путей) — ничего не делать.
2. TB: если идёт анимация действия — выйти. RT: обнулить все анти-зависательные счётчики (общий и у каждого бойца).
3. Взять из очереди первую команду (не более одной за сегмент — защёлка). Если взяли: проверить выполнимость (см. «Проверка CheckCanDo»); если можно — отдать миру. Выйти в любом случае.
4. Если ИИ запрещён: в TB — закончить ход. Выйти.
5. Если очередь команд не пуста, или защёлка стоит, или `nAILag > 0` — выйти. (То есть новые решения принимаются только в сегмент, когда `nAILag` только что сброшен, — раз в 3 сегмента = 150 мс.)
6. Снять завершившиеся логики у всех своих боеспособных бойцов (боец сообщает реакции «логика кончилась», состояние помечается изменённым).
7. Если не скриптовая сцена: если очередь реакций не пуста — выйти; если у кого-то из бойцов состояние угроз помечено изменённым — выйти (сначала пусть отработают реакции).
8. TB: если «конец хода» (см. ниже) — закончить ход и выйти.
9. Выбор бойца: проверить текущего (жив, мой игрок, боеспособен), иначе перейти к следующему. Если текущего нет — заново заполнить рабочую копию полным списком и взять следующего. Пока у текущего «нет работы» — брать следующего. Если никого — выйти.
10. TB: если боец сменился — послать интерфейсу подсказку «сейчас будет ходить этот ИИ-юнит» (камера).
11. Записать в общее состояние «текущий боец» и «текущий враг» (личная цель бойца).
12. Взять активную логику бойца. Нет логики — выйти. Логика сейчас думает — выйти (ждать).
13. Если логике «нужно думать»: запустить думание, но только если сейчас НИКТО из своих бойцов не думает (одновременно думает один). Иначе — забрать у логики одну команду; если это команда юнита, юнит активен в мире и боеспособен: поставить её в очередь и сразу за ней поставить команду «продолжить» (Continue) для того же юнита. Если сама команда — «пустышка-продолжение» (keepalive), второй Continue не ставится.
14. RT: перейти к следующему бойцу (в RT каждый сегмент решений — новый боец; в TB боец остаётся текущим, пока у него есть работа).

**Следующий боец (`Next`)**
1. Выбросить с начала рабочей копии всех «негодных» (мёртв, чужой игрок, небоеспособен).
2. Если копия пуста — текущего нет.
3. Если прежний текущий ещё существует — новым становится ближайший к нему по прямой (по CP) из рабочей копии; иначе — первый в копии. Сравнение строгое, начальный лучший результат 65535, при равенстве побеждает более ранний в списке.
4. Выбранный удаляется из рабочей копии (каждый ходит один раз за круг).

**«Есть работа» у бойца**: логика существует, не на паузе, и (в TB) логика не объявила конец своего хода. Исключение: боец в «неактивной» позе, стоящий на месте в простое маршрута, без команды и без действия, пропускается.

**Конец хода стороны (TB)**: не RT и не идёт анимация; если сработал анти-зависательный порог — конец хода принудительно; иначе конец, когда у каждого своего боеспособного, активного в мире бойца (кроме помеченных «без ИИ» и кроме пропускаемых «неактивных») логика либо отсутствует, либо на паузе, либо объявила конец хода. Ответ «да, конец» по логике запоминается до начала следующего хода.

**Закончить ход**: очистить очередь, поставить команду «конец хода», обнулить счётчики.

**Проверка CheckCanDo** (перед отдачей команды миру): для команд-обёрток «установить команду юниту», кроме Continue, спросить юнит «могу ли я это». Если код результата хуже порога (в коде реконструкции сравнение `> UCR_NO_TARGET`, т. е. > 3; комментарий ссылается на литерал «> 4» в оригинале — см. «Не установлено») — команда отбрасывается, логика этого бойца помечается «ход окончен», в отладочный вывод пишется «AI error : unit can't do command!».

### Константы

| Имя | Значение | Смысл |
|---|---|---|
| `DW_SEGMENT_TIME` | 50 мс | Длина сегмента мира |
| порог `nAILag` | > 2 | ИИ-сегмент и новые решения — каждый 3-й сегмент |
| команд за сегмент | 1 | Защёлка очереди |
| думающих одновременно | 1 | На всю сторону |
| порог счётчика команд | > 5000 | Принудительный конец хода |
| вес счётчика бойца | ×200 | `общий + счётчик_бойца×200 > 5000` → конец хода |
| начальная «бесконечность» дистанции | 65535 | При поиске ближайшего |

### Особые случаи и прихваты
- Счётчик команд растёт на 1 при каждой постановке в очередь (в том числе для «мёртвой»/пустой команды и для каждого Continue). Счётчик бойца растёт при каждой смене логики и при каждой установке реакции. Один боец, у которого логика сменилась 26 раз без единой команды, уже завершает ход всей стороны. В RT счётчики обнуляются каждый вызов генерации, т. е. порог действует только в TB.
- При изменении угроз у бойца его уже запланированные команды выбрасываются и текущая команда мира отменяется — ИИ мгновенно «передумывает».
- Пока идёт расчёт путей (задания высшего приоритета), командир вообще не трогает ни очередь, ни логики.
- Командир игрока-человека — тот же класс, но генерирует команды только во время скриптовых сцен.
- При передаче управления стороне вызывается Lua-функция `OnStartTurn(идентификатор игрока)`.
- Блокировки объектов (`LockObject`) в реконструкции есть, но в оригинале такого поля нет (см. отклонения).

### Что нужно от движка-носителя
Сегментный тик; признаки «RT/TB», «идёт анимация действия», «идёт скриптовая сцена», «чей ход», «юнит активен в ходе»; очередь команд мира с командами «установить команду юниту», «продолжить», «отменить», «конец хода»; проверка выполнимости команды юнитом с кодом результата; подсказка интерфейсу о ходящем юните.

## 2. Общее состояние стороны и группы врагов

### Назначение
Раз в 3 сегмента (а также в начале хода и при передаче управления) пересобрать списки «не враги» и «враги» и группы врагов для гранат/ракет.

### Алгоритм
1. «Союзники» = все боеспособные юниты мира, чей игрок НЕ враг данной стороне (включая нейтральных и юнитов человека); «враги» = все боеспособные юниты мира, чей игрок враг. Берутся ВСЕ юниты мира, а не только видимые.
2. Каждому своему бойцу проставить ссылку на это состояние.
3. Построить группы врагов. Идём по врагам в порядке списка мира; для каждого врага E:
   1. Для каждой уже существующей группы: если квадрат расстояния от E до центра группы < 2,25 (т. е. < 1,5 м) — добавить E в группу.
   2. Создать новую группу из одного E (центр = позиция E).
4. Добавление в группу пересчитывает центр по формуле с числом членов ДО вставки `n`: если `n = 0` — центр = позиция; иначе `центр = (центр × (n − 1) + позиция) / n`. Следствие: при добавлении второго члена центр целиком перескакивает на него, первый член группы в центре не участвует никогда.
5. Для каждой группы `fNearestAlly` = минимум расстояний от центра группы до каждого «не врага» (начальное значение 65535). В число «не врагов» входит и сам бросающий.

### Константы

| Имя | Значение | Смысл |
|---|---|---|
| радиус группы | 1,5 м (сравнение квадрата с 2,25) | Склейка врагов в группу |
| начальное `fNearestAlly` | 65535 | «Своих рядом нет» |

### Особые случаи и прихваты
- Групп всегда не меньше, чем врагов: у каждого врага есть «своя» группа, плюс он входит во все более ранние группы поблизости. Группы пересекаются.
- Группы строятся по точным текущим позициям всех врагов на карте независимо от видимости — это знание, которого у игрока нет.
- В начале хода дополнительно запоминаются суммы здоровья «союзников» и «врагов» (в текущих правилах не используются).
- В состоянии есть неиспользуемый в бою метод «опасный атакуемый враг» (ближайшие ±1,5 м, затем тот, кто сам лучше всего попадает по бойцу) — наследие прежней схемы.

### Что нужно от движка-носителя
Перечень всех юнитов мира, признак боеспособности, дипломатия «игрок–игрок», точные позиции.

## 3. Базовая логика: выдача команд и защита от зацикливания

### Назначение
Общий механизм любой логики: очередь команд, «точка интереса» для камеры, пауза, детектор топтания на месте.

### Алгоритм выдачи одной команды (`GetCommand`)
1. Нельзя, если логика на паузе или юнит сейчас выполняет действие.
2. **Keepalive**: если на сервере юнита уже установлена команда и (RT, либо в TB юниту хватает ОД её начать) — проверить зацикливание и вернуть команду «продолжить». Это имеет приоритет над собственной очередью логики.
3. Если очередь пуста — попросить логику сгенерировать команды (для боевой логики: развернуть журнал в команды и очистить журнал).
4. Если очередь всё ещё пуста — вернуть «ничего». Иначе снять первую команду, проверить зацикливание, вернуть.

### Детектор зацикливания
Хранит последнее «место + живые ОД» и счётчик повторов.
1. Текущее место считается «тем же», если совпадает по маске `0x1feffff` (клетка и слой; поза, направление и бит движения игнорируются) И совпадают живые ОД сервера.
2. То же → счётчик +1; иначе запомнить новое и обнулить счётчик.
3. Счётчик ≥ 31: вывести « AI : fatal cycling detected : logic canceled », пометить логику завершённой.
4. Иначе, если счётчик > 15: с вероятностью 25 % (младшие 2 бита случайного числа равны 0) отменить текущую команду юнита и заново выставить зеркалу ОД только что прочитанное значение.

### Прочее
- Логика считается завершённой только когда у сервера юнита нет установленной команды (завершение откладывается).
- «Точка интереса» берётся из команд: конец пути, точка взгляда, цель выстрела по объекту, точка выстрела по клетке, орудие. Один раз найденная, не сбрасывается последующими командами.
- Базовый «конец хода логики»: в TB во время исполнения — нет; завершена или на паузе — да; иначе «да», если юнит не активен/небоеспособен или (не выполняет действие И имеет команду И ему не хватает ОД её продолжить).

### Константы

| Имя | Значение | Смысл |
|---|---|---|
| маска «то же место» | `0x1feffff` | Клетка+слой |
| мягкий порог | > 15 повторов | 25 % шанс отмены команды за каждую выдачу |
| жёсткий порог | ≥ 31 повтор | Логика отменяется |

### Что нужно от движка-носителя
«Юнит выполняет действие», «у юнита установлена команда», «хватает ли ОД начать установленную команду», генератор случайных чисел.

## 4. Менеджер заданий (кванты думания)

### Назначение
Размазать тяжёлые вычисления ИИ по кадрам: каждое задание делает по одному маленькому шагу за вызов.

### Алгоритм (один сегмент мира)
1. Если заданий нет или все либо «простаивают», либо ждут — выйти.
2. Засечь время. Пока список не пуст и прошло меньше `0,010 с − накопленный перерасход`: взять задание по круговому указателю; если оно не завершено, не простаивает и не ждёт — выполнить один шаг; если после шага завершилось — уведомить и пометить к удалению (вместе с дочерними). Сдвинуть указатель; дойдя до конца — вычистить помеченные и начать с начала.
3. Перерасход `+= затраченное − 0,010`, но не более 0,200 с.

«Ждёт» = есть задания высшего приоритета, а это не из них; либо оно само ждёт другое, ещё не завершённое, задание.

### Константы

| Имя | Значение | Смысл |
|---|---|---|
| `F_AI_TIME_TO_THINK` | 0,010 с | Бюджет на сегмент |
| `F_AI_MAX_OVERRUN_TIME` | 0,200 с | Потолок накопленного перерасхода |

### Особые случаи
Боевая логика как задание «простаивает», если логика недействительна, или идёт скриптовая сцена, или у бойца есть несделанные команды.

### Что нужно от движка-носителя
Точный таймер.

## 5. Боевая логика: когда думать и конвейер одного раздумья

### Назначение
Общий для пяти боевых логик двигатель: решить, пора ли думать, прогнать конвейер «синхронизация → места → выбор мест → решение», выдать команды.

### Данные
Журнал; список источников мест; задание выбора мест (с резервом ОД); стадия конвейера (INIT, PLACESOURCE, ACTION, THINK, FINISHED); индекс подготавливаемого источника; снимок ОД `nUnitLastAP`.

### Когда нужно думать (`IsNeedToThink`)
Все условия сразу: логика действительна (боец, сервер, мир живы, боец боеспособен); `CanSkip` ложно; боец не выполняет действие; нет команд к исполнению (на сервере нет команды, очередь логики пуста, журнал пуст); логика ещё не думает; и: в RT — всегда, в TB — только если живые ОД бойца отличаются от снимка `nUnitLastAP`.

### Запуск (`Think`)
1. «Остановить думание»: снять оба задания с менеджера, очистить очередь команд и журнал, обнулить индекс источника, **снять снимок живых ОД**, стадия = FINISHED.
2. Если `CanSkip` или логика недействительна — выйти.
3. Стадия = INIT, задание добавить в менеджер.

### Конвейер (по одной стадии за шаг задания)
1. **INIT**: синхронизировать бойца — перечитать ОД/здоровье в зеркала, позицию, занятое орудие, **заново построить ИИ-инвентарь из настоящего**, и синхронизировать зеркала всех подтверждённых врагов бойца.
2. **PLACESOURCE**: подготовить ОДИН источник мест за шаг; когда все подготовлены — дальше.
3. **ACTION**: сбросить задание выбора мест (у всех действий очищаются кэши оценок), добавить его в менеджер и ждать его завершения.
4. **THINK**: вызвать `MakeDecision` конкретной логики; стадия = FINISHED; задание завершено.

### Задание выбора мест (один шаг)
Идёт по действиям в порядке их регистрации:
1. Если действие «не может выполняться» (боец недействителен) — к следующему действию.
2. Первый шаг для действия: взять места из привязанного источника; отфильтровать по резерву ОД: место остаётся, только если `ОД_места > резерв`, и тогда `ОД_места −= резерв`. (При резерве 0 отбрасываются места с ОД ≤ 0.)
3. Последующие шаги: взять одно место. Если поза клетки «лёжа» или «неактивная» — пропустить. Иначе, если действие выполнимо из этого места и (лучшего ещё нет или политика говорит «кандидат лучше текущего лучшего») — запомнить как лучшее.
4. Места кончились — к следующему действию; действия кончились — задание завершено.

Политики «лучше»: для атаки/обороны/охраны/после боя — компаратор самого действия (п. 8); для отступления — лучше то место, где ОСТАЁТСЯ МЕНЬШЕ ОД (дальше убежал), действие игнорируется.

Так как сравнения строгие, при равенстве побеждает место, встретившееся раньше: своя клетка стоя → своя клетка сидя → клетки пути от ближних к дальним (стоя, затем сидя) → фланговые.

### Исполнение выбранного действия (`DoAction`)
1. Взять лучшее место действия. `цена_хода = max(0, зеркало_ОД − ОД_места)`; записать «потратить ОД» на эту величину.
2. Если место отличается от текущего по маске `0xc1feffff` (клетка, слой И поза) — записать «переместиться» с желаемой позой движения RUN (WALK, если боец в ПК).
3. Вызвать запись действия в журнал.

Запись «переместиться» разворачивается в две команды: «желаемая поза» и «путь в место, с использованием позы места» (т. е. боец бежит и по прибытии принимает позу места — стоя или сидя).

### Конец хода боевой логики (TB)
«Да», если: логика недействительна; `CanSkip`; завершена; сервер недействителен; юнит не активен в мире. «Нет», если: выполняет действие; не TB; думает. Иначе «нет», только если (есть команды к исполнению ИЛИ ОД изменились с последнего раздумья) И (у сервера нет команды ИЛИ хватает ОД её начать); в остальных случаях «да».

Следствие (главный предохранитель): если раздумье не породило ни одной команды, ОД не изменились — боец больше не думает и его ход окончен. Если команды исполнились и ОД изменились — он думает ещё раз. Так крутится цикл «подумал → сделал → подумал» до исчерпания ОД.

### Новый ход
По событию «новый ход игрока» каждая боевая логика останавливает думание; если ход начался у владельца бойца — снимок ОД обнуляется (гарантированно новое раздумье).

### Константы

| Имя | Значение | Смысл |
|---|---|---|
| маска сравнения места в `DoAction` | `0xc1feffff` | Клетка+слой+поза |
| резерв ОД | 0 (атака, охрана, после боя, отступление); у обороны — число, переданное реакцией («ОД на возврат в укрытие») | Сколько ОД нельзя тратить |

### Что нужно от движка-носителя
Событие «новый ход игрока»; живые ОД юнита; команды «желаемая поза», «путь».

## 6. Источники мест-кандидатов

### Общая процедура «добавить обе позы» (`AddAllPoses(клетка, цена_хода, бюджет)`)
1. Если у бойца есть живой враг — вычислить направление «с этой клетки на врага» (квантованное) и проставить его обоим вариантам.
2. `цена_стоя = цена_хода + ОД(смена позы из позы клетки в «идти»)`. Если `цена_стоя ≤ бюджет` и клетка проходима в позе «стоя» — добавить место (стоя, `зеркало_ОД − цена_стоя`).
3. `цена_сидя = цена_хода + ОД(смена позы из позы клетки в «сидеть»)`. Если боец «может сидеть» и `цена_сидя ≤ бюджет` и (вариант «стоя» уже добавлен ИЛИ клетка проходима сидя) — добавить место (сидя, `зеркало_ОД − цена_сидя`).
4. Вернуть «полностью достижима» = `цена_стоя ≤ бюджет` И (не может сидеть ИЛИ `цена_сидя ≤ бюджет`).

Проходимость: клетка не «непроходима» и не «нельзя лечь»; занятость/блокировка засчитывается, только если клетку держит ДРУГОЙ юнит (своя блокировка не мешает).

Лежачая поза не предлагается никогда.

### 6.1. Источник «атака» (стрельба, граната, ракета, нож; у охраны ещё рукопашная)
Параметры: бюджет хода `nMaxAP` (обычная атака — **14 ОД**, охрана — максимум ОД бойца), флаг проверки огня по своим (включён), область (только у охраны).

1. **Своя клетка**: если проверка огня по своим выключена или текущая позиция не опасна для своих — добавить обе позы с ценой 0.
2. **Вдоль пути к врагу**: найти путь от своей клетки к клетке врага (неточный путь разрешён, чужие юниты игнорируются). Идти по точкам, накапливая цену хода (сумма ОД за каждый шаг по типу шага и текущей позе):
   - накопленная цена > бюджета — стоп;
   - пропустить точку, если её поза «неактивная», или это своя клетка, или (есть область и точка вне области);
   - если точка опасна для своих — пропустить (но идти дальше);
   - добавить обе позы; если вернулось «не полностью достижима» — стоп.
3. **Фланговая волна**: бюджет волны `min(nMaxAP, 8)` ОД. Залить все достижимые клетки в этом бюджете (без проверок «самоубийственных» клеток и без учёта временных блокировок юнитами). Для каждой: пропустить «неактивные», свою клетку, клетки вне области; вычислить единичный вектор «боец → клетка» и «боец → враг» в плоскости; оставить клетку, только если `|cos угла| ≤ 0,1737` (направление в пределах ±10° от перпендикуляра к оси на врага); пропустить опасные для своих; добавить обе позы с ценой из таблицы волны и бюджетом `nMaxAP`.

### 6.2. Источник «текущее место» (перезарядка, лечение, подбор, «уйти из неактивной позы», снайперские, СП, ПК)
1. Если боец НЕ в «неактивной» позе: добавить свою клетку в обеих позах, цена 0, без ограничения бюджета.
2. Если в «неактивной» (на лестнице и т. п.): найти ближайшие клетки в пределах **15 ОД** при движении RUN (WALK в ПК); из незаблокированных выбрать самую дешёвую (клетка «по направлению взгляда» получает бонус −100000 к цене, но из-за ошибки он практически никогда не срабатывает — см. прихваты); добавить её в обеих позах.

### 6.3. Источник «рядом с врагом» (рукопашная в логике атаки)
1. Получить «кольцо» клеток, с которых можно ударить врага в ближнем бою.
2. Найти путь к кольцу (сам враг не препятствие, чужие юниты игнорируются, неточный путь разрешён), при расчёте поза движения RUN (WALK в ПК).
3. Добавить ОДНО место — последнюю точку пути — с `ОД = зеркало_ОД − цена всего пути` (в позе точки пути, без варианта «сидя», без поворота к врагу). ОД может быть отрицательным — тогда место отсеет фильтр резерва.

### 6.4. Источник «к точке» (отступление)
Бюджет **25 ОД**. Своя клетка (обе позы, цена 0), затем точки пути к точке отступления, пока накопленная цена ≤ бюджета; пропускаются своя клетка и «неактивные»; проверки огня по своим нет; обход не прерывается на «не полностью достижимой».

### 6.5. Источник «одно место» (оборона)
1. Если удерживаемое место опасно для своих (проверка первым огнестрельным) — мест нет.
2. Цена хода до места считается как путь в позе CROUCH (недостижимо → 65535).
3. Режим «стоя»: обе позы на этом месте без ограничения бюджета. Режим «сидя»: одно место с `ОД = максимум_ОД − цена_хода`.

### 6.6. Область охраны
Множество клеток, достижимых из центра за заданный радиус в ОД при заданной позе движения; хранятся только клетки с позой не «лёжа» и не «неактивная», ключ — поза+слой+y+x (без направления). Если центр «неактивный» или непроходим — область не строится.

### Константы

| Имя | Значение | Смысл |
|---|---|---|
| бюджет хода атаки | 14 ОД | Насколько далеко боец готов сместиться ради выстрела |
| бюджет фланговой волны | min(бюджет, 8) ОД | |
| фланговый допуск | `|cos| ≤ 0,1737` (sin 10°) | Только клетки «вбок» |
| поиск выхода из неактивной позы | 15 ОД | |
| бюджет отступления | 25 ОД | |
| бонус «по взгляду» | −100000 | Фактически мёртв |
| «без ограничения» | 0xffff | |

### Особые случаи и прихваты
- Путь к врагу прокладывается к его точной текущей клетке.
- Клетка, полученная и по пути, и фланговой волной, окажется в списке дважды с разными ОД; при этом кэш оценок действия ключуется только клеткой/позой/направлением (без ОД), поэтому вторая копия получит оценку первой.
- Ошибка оригинала (сохранена): «клетка по направлению взгляда» сравнивает номер направления (0…7) с углом в радианах — совпадает только при нуле.
- Ошибка оригинала (сохранена): при поиске выхода из неактивной позы «лучшая цена» инициализируется числом, которое всегда меньше порога проверки, поэтому процедура добавления вызывается даже без кандидатов (на заведомо неверной клетке; та отсеивается проверкой проходимости).
- Ошибка оригинала (сохранена): источники «рядом с врагом» и «к точке» временно меняют желаемую позу юнита и НЕ восстанавливают её при раннем выходе (нет кольца/нет пути).
- Ошибка оригинала (сохранена): при построении области охраны проверка проходимости в цикле смотрит на центр, а не на клетку.

### Что нужно от движка-носителя
Поиск пути с флагами «неточный путь», «игнорировать юнитов», «игнорировать конкретного»; заливка «все клетки в N ОД» с таблицей цен; цена шага по типу шага и позе; цена смены позы; проходимость клетки по позе и «кто держит клетку»; кольцо клеток рукопашной вокруг цели; квантованное направление «клетка → точка».

## 7. Отсев мест из-за огня по своим

### Алгоритм (`IsPosDangerousForAllies(позиция, оружие)`)
1. Нет бойца/состояния/живого боеспособного врага → «опасно».
2. Оружие недействительно → «не опасно». (Оружие — «первое огнестрельное»: то, что в руках, если это не ракетница, иначе первое огнестрельное по порядку инвентаря.)
3. Создать описание атаки оружием; пусто → «опасно».
4. Построить ИИ-растр лучей (п. 12) из точки ствола при данной позиции в сторону врага, часть тела BODY.
5. Собрать все объекты, которые может задеть этот набор лучей (попавшие и «шальные»).
6. Если среди них есть любой боеспособный «не враг» (включая нейтральных и юнитов человека), кроме самого бойца, — «опасно».

Применяется: своя клетка, клетки пути и фланга источника «атака»; место источника «одно место». Не применяется к источникам «текущее место», «рядом с врагом», «к точке». Для гранат и ракет отдельные правила расстояний (п. 9.3, 9.4).

## 8. Сравнение двух мест

| Действие | «Место 1 лучше места 2», если |
|---|---|
| Выстрел | Порог = 20 (в ПК = 5). Если шанс попадания хотя бы одного из мест < порога → лучше то, где шанс строго больше. Иначе (оба ≥ порога) → лучше то, где ОД строго больше (меньше идти) |
| Лечение | Сидя лучше, чем не сидя; при равенстве — больше ОД |
| Начало снайпинга | Место 1 сидя, а место 2 нет → лучше; иначе — больше ОД |
| Все остальные (граната, ракета, нож, перезарядка, рукопашная, подбор, «двинуться», СП, ПК, прочие снайперские) | Строго больше ОД |
| Любое в логике отступления | Строго МЕНЬШЕ ОД |

Шанс попадания места для выстрела — это шанс лучшей пары «оружие×режим» при ОД этого места; место, с которого нельзя сделать ни одного выстрела, имеет шанс 0.

Поведенческое следствие: если с места, где боец стоит, шанс ≥ 20 %, он не сдвинется (стоять дешевле всего). Если < 20 % — пойдёт туда, где шанс выше, но только в пределах 14 ОД и только туда, где после хода ещё хватит ОД на выстрел. Сесть он предпочтёт, лишь если сидя шанс выше, а «стоя» не дотягивает до порога, либо если он уже сидит.

## 9. Действия: условия выполнимости и запись в журнал

Общее: «выполнимо из места» вычисляется для пары (позиция места, ОД места). При исполнении действие пересчитывает свои данные для «текущего места» бойца (текущая позиция + зеркало ОД, уже уменьшенное на цену хода) и пишет записи в журнал. Каждая запись сразу меняет плановое состояние.

### 9.1. Выстрел
**Выполнимо**, если: есть боец и враг; перебор оружия (п. 11) дал оружие; у оружия в текущем магазине есть патроны (пустой магазин — нельзя, даже если есть запасной: сначала сработает правило перезарядки); шанс попадания > 0.
Дополнительно вычисляется «убьёт наверняка» = `здоровье_врага × 2,5 < качество`, где качество — ожидаемый урон за весь остаток ОД (п. 11). Бюджет выстрелов = ОД места. Часть тела — ANY.

**Запись**:
1. Если оружие не в руках — «сменить оружие» (команды: старое из слота в рюкзак; упорядочить рюкзак; новое из рюкзака в слот 1; сделать слот активным).
2. «Сменить режим огня» на выбранный (при добавлении записи режим реально выставляется на предмете оружия).
3. Вычислить параметры одного «нажатия» (п. 11.3). Пока не требуется перезарядка, число пуль > 0 и цена нажатия ≤ остатка бюджета: записать «выстрел по юниту (враг, ANY)», «потратить ОД» на цену нажатия, «потратить патроны» (зеркало магазина), уменьшить бюджет, пересчитать параметры.

Команда выстрела — «стрелять по объекту (цель, часть тела)».

### 9.2. Перезарядка
**Выполнимо**, если поза места не «неактивная»; найдено оружие для перезарядки — ПЕРВОЕ по порядку инвентаря огнестрельное (включая ракетницы), у которого текущий магазин не полон (по собственной вместимости магазина) и есть запасной магазин (его наполненность не проверяется); цена перезарядки этого оружия (с перками) ≤ ОД места.
**Запись**: сменить оружие (если не в руках), «перезарядить» (в плане: запасной магазин становится текущим), потратить ОД.

### 9.3. Граната
**Выполнимо**, если: есть граната (та, что в руках, иначе первая по порядку инвентаря); цена броска (по позе места) ≤ ОД места; найдена подходящая группа врагов.
Подходящая группа: непустая; **радиус осколков гранаты строго меньше `fNearestAlly` группы** (в базе у всех гранат радиус 5,0 — т. е. ни один «не враг», включая самого бросающего, не ближе 5 м к центру группы); проверка мира «можно бросить из этой позиции в центр группы» успешна (баллистика по силе броска + проверка траектории на столкновения; видимость цели не проверяется).
Из подходящих выбирается ближайшая к месту по квадрату расстояния до центра; при точном равенстве — более многочисленная; иначе остаётся более ранняя.
Вычисляется «плохое состояние группы» = максимум по членам группы их зеркала **ОД** ≤ 15 (константа названа «плохое здоровье», но читается ОД).
**Запись**: пока есть граната и бюджет ≥ цены броска: сменить оружие (если не в руках), «бросить гранату в точку» (центр группы, запомненный один раз), потратить ОД; в плане граната удаляется из инвентаря, руки пустеют; взять следующую «лучшую» гранату. То есть за одно решение боец кидает столько гранат, на сколько хватает ОД, все в одну точку.
Команда — «стрелять по клетке/точке».

### 9.4. Ракета
**Выполнимо**, если: есть ракетница (в руках или первая по порядку); в ней есть заряд; цена выстрела ≤ ОД места; найдена подходящая группа.
Подходящая группа: `fNearestAlly > 3,0` м и группа непуста; проверка мира «можно пустить ракету в точку» успешна: дистанция в клетках ≥ 3 и меньше максимальной для ракетницы, и трасса до точки свободна. Сначала пробуется центр группы; при неудаче — точка «центр, поднятый на 0,6 м и сдвинутый на 1,7 м в сторону стрелка».
Выбор группы — как у гранаты.
**Запись**: сменить оружие, режим огня «навскидку», «выстрел по точке», потратить ОД — один выстрел.

### 9.5. Бросок ножа
**Выполнимо**, если есть враг; есть метательное оружие (лучшее по среднему урону `(мин+макс)/2`, строго больше; при равенстве — более раннее); цена броска ≤ ОД места; проверка мира «можно метнуть в CP врага» успешна.
**Запись**: сменить оружие, потратить ОД, «бросок ножа» (команда «стрелять по объекту», ANY); в плане нож удаляется из инвентаря.

### 9.6. Рукопашная
**Выполнимо**, если есть враг; есть оружие ближнего боя (лучшее по среднему урону; «голые руки» есть у каждого — добавляются в ИИ-инвентарь безусловно); цена удара ≤ ОД места; CP врага в пределах досягаемости от места (`F_MELEE_DISTANCE = 0,625·√2 + 0,01 ≈ 0,894 м` в плане, плюс проверка по высоте в движке).
**Запись**: сменить оружие, потратить ОД, «удар» — команда «стрелять по объекту» с частью тела HEAD.

### 9.7. Подбор предметов
Место игнорируется — всё считается от текущей позиции.
**Выполнимо**, если:
1. Среди известных игроку объектов-предметов на земле есть «нужные» (п. 13); для каждого запоминается, что выбросить (вместе с запасными магазинами выбрасываемого оружия).
2. Из нужных остаются лежащие не дальше **4,0 м** и те, для которых мир разрешает перенос «земля → рюкзак».
3. Из них выбирается самый нужный по типу: огнестрельное > магазин > граната > ближнего боя/метательное > аптечка (первый найденный данного типа).
4. Есть клетки, с которых можно дотянуться до предмета (досягаемость человека 0,625 м), и путь к ним.
5. Все прочие нужные предметы, до которых можно дотянуться с конечной точки пути (0,625 м), берутся заодно.
**Запись**: «выбросить» всё, что мешает (команды: предмет в руку, из руки на землю, упорядочить рюкзак); «подобрать» (команды: желаемая поза, упорядочить, перенос земля → рюкзак); затем то же для попутных предметов, с повторной проверкой «нужен ли» на уже обновлённом плановом инвентаре. Желаемая поза: в логиках атаки/охраны — RUN, после боя — WALK; в ПК — WALK.

### 9.8. Лечение
**Выполнимо**, если: есть аптечка (в руках или первая по порядку); `здоровье ≤ 0,3 × максимум`; враг не ближе 4,0 м (или врага нет); цена применения аптечки ≤ ОД места; мир разрешает первую помощь самому себе из этого места.
**Запись**: сменить «оружие» на аптечку, «лечить» (себя), потратить ОД. Лечит только себя.

### 9.9. «Двинуться» (уйти из неактивной позы)
**Выполнимо**, если клетка места отличается от текущей клетки бойца (маска `0x1feffff`). Собственной записи нет — всё делает общий ход `DoAction`. Привязано к источнику «текущее место», который даёт чужую клетку только бойцу в неактивной позе; в логике отступления привязано к источнику «к точке» и тогда означает «бежать к точке».

### 9.10. Снайперский режим (4 действия)
Условие дистанции `CanSnipe`: есть враг; `расстояние_до_врага × 1,6 ≥ 15` (т. е. ≥ 15 клеток) и расстояние до подозреваемого `× 1,6 ≥ 10` (≥ 10 клеток; нет подозреваемого — условие выполнено).
Условие «могу попасть по цели снайпинга»: боец в режиме снайпинга, цель жива, настоящий (игровой, не упрощённый) шанс попадания по сохранённой цели и части тела > 0.

- **Начать снайпинг** — выполнимо, если: ещё не в режиме; есть оружие для снайпинга (первое по порядку огнестрельное, поддерживающее режим «снайперский», с непустым магазином); `CanSnipe`; шанс (ИИ-оценка, п. 12, из позы места, повернувшись к врагу) по ANY > 0; если шанс по HEAD > 0 — целиться в голову; **«зона поражения»**: взять все клетки, куда враг может добежать за 4 ОД (RUN), и убедиться, что из места видна КАЖДАЯ из них (дальность зрения и угол обзора бойца); хоть одна не видна — нельзя. Запись: сменить оружие, режим «снайперский», «начать снайпинг по цели/части тела».
- **Копить ОД** — выполнимо, если в режиме, могу попасть, накоплено меньше пула; копится `min(пул − накоплено, текущие ОД бойца)` > 0 (от места не зависит). Команда «накопить всё».
- **Снайперский выстрел** — выполнимо, если в режиме и могу попасть. Запись: «выстрел по сохранённой цели», ANY.
- **Отменить снайпинг** — выполнимо, если в режиме и (нарушено `CanSnipe` ИЛИ не могу попасть). Команда «отмена».

### 9.11. Станковое орудие (3 действия)
«Орудие рабочее» = не сломано и есть боезапас. «Орудие пригодно из места» = рабочее; расстояние место–орудие ≤ **10 м**; враг дальше **5 м** от орудия, подозреваемый дальше **3 м**; боец может дойти (путь к подходам орудия при RUN, сумма ОД шагов + ОД «подойти к орудию» ≤ ОД места). «Враг поражаем» = текущая цель бойца входит в список известных врагов (подозреваемые + подтверждённые), по которым орудие может стрелять (точка прицеливания — тело; ответ «нужна перезарядка» обрывает перебор).

- **Сесть за орудие** — не за орудием; среди всех орудий мира выбрать ближайшее к месту из незанятых, пригодных, с поражаемым врагом. Команды: желаемая поза RUN, «использовать орудие».
- **Стрелять из орудия** — за орудием, оно рабочее, пригодно, враг поражаем. Запись: выставить орудию режим огня № 4 (длинная очередь), «выстрел по цели», ANY.
- **Слезть** — за орудием, и НЕ (рабочее И пригодно И враг поражаем). Запись: «покинуть орудие» и трата 1 ОД напрямую у юнита.

### 9.12. Панцеркляйн (3 действия)
- **Вылезти** — боец в ПК и здоровье костюма < 1. Команда «выйти из ПК».
- **Надеть** — боец не в ПК; кандидаты: пустые костюмы с ненулевым здоровьем (в первую очередь), затем занятые костюмы, чей пилот небоеспособен; первый кандидат со здоровьем > 0, до которого боец может добраться и «взять» (проверка мира при желаемой позе RUN). Запись: «переместиться» на собственную позицию с позой RUN (нормализация позы) и «надеть ПК».
- **Таран («террор»)** — боец в ПК, здоровье костюма ≤ 25 % максимума; выбрать ближайшую по квадрату расстояния группу врагов; если до её центра ещё ≥ 1,0 (квадрат расстояния) — идти шагом (WALK) в ближайшую к центру группы проходимую позицию.

## 10. Выбор цели

### Данные
У бойца три списка с запомненными позициями: подтверждённые враги, возможные враги, союзники (заполняются событиями восприятия — чужая спецификация). В начале хода: все боеспособные враги из списка видимости юнита переводятся в подтверждённые; подтверждённые, пропавшие из видимости, — в возможные.

### Алгоритм выбора врага (вызывается, когда список подтверждённых изменился)
1. **Ближайшая «кучка»**: `fBest = 4095`. Для каждого боеспособного подтверждённого врага с расстоянием `d` до бойца: если `|d − fBest| ≥ 1,5`: если `d < fBest` — кучка = {этот враг}, `fBest = d`; иначе игнорировать. Если `|d − fBest| < 1,5` — добавить в кучку (`fBest` при этом не меняется).
2. **Лучший по попаданию**: для каждого из кучки вычислить максимальный шанс попадания лучшей парой «оружие×режим» с текущей позиции при текущих ОД (п. 11). Выбрать врага со строго большим шансом; первый кандидат выигрывает у «пустого» выбора (поэтому при всех нулях цель — первый в кучке).
3. Если цель сменилась — пометить состояние изменённым (это отменит текущие команды бойца и перезапустит реакцию).

Подозреваемый и «союзник, зовущий на помощь» — просто ближайшие по прямой из своих списков; смена любого тоже помечает состояние.

### Испуг
Проверяется каждый тик, один раз: если есть цель, боец не в ПК, и (здоровье < 50 % максимума ИЛИ подтверждённых врагов больше двух), и в радиусе 9,0 м нет ни одного другого боеспособного «не врага» — боец помечается испуганным (далее решает реакция страха — чужая спецификация).

### Константы

| Имя | Значение | Смысл |
|---|---|---|
| ширина кучки | 1,5 м | |
| начальное расстояние | 4095 | |
| испуг: здоровье | < 50 % | |
| испуг: число врагов | > 2 | |
| испуг: «свой рядом» | < 9,0 м | |

### Особые случаи
- Цель называется «самый опасный», но опасность врага не оценивается: это «ближайший, по кому лучше попадаю».
- Позиции врагов всегда берутся живые (точные), а не запомненные.
- Гранаты и ракеты выбирают цель независимо — по группам (п. 2), а не по `pEnemy`.

## 11. Выбор оружия и режима огня

### 11.1. Перебор (`GetBestFireArms(позиция, цель, ОД)`)
1. Начальное «качество» = −65535, шанс = 0.
2. Для каждого огнестрельного оружия ИИ-инвентаря (ракетницы исключены), по порядку инвентаря:
   1. Вычислить «укрытие цели» из данной позиции для этого оружия, часть тела ANY (п. 12); далее оно используется как целое число.
   2. Для каждого режима по порядку: навскидку, прицельный, тщательный, короткая очередь, длинная очередь (снайперский не перебирается): пропустить, если оружие его не поддерживает или режим у бойца временно запрещён (запреты выставляет реакция обороны); вычислить качество и максимальный шанс (11.2).
   3. Если качество строго больше лучшего — запомнить оружие, режим, укрытие и шанс ЭТОЙ пары.
3. Вернуть лучшее оружие (или «нет»).

При равенстве качества выигрывает более раннее оружие и более ранний режим. Предпочтения оружию в руках нет; цена смены оружия не учитывается (смена предметов стоит 0 ОД по таблице).

### 11.2. Качество пары «оружие×режим» = ожидаемый урон за остаток ОД
1. Временно выставить оружию проверяемый режим.
2. `урон_пули = (мин_урон + макс_урон) / 2` (целое).
3. `цена_первой_пули`: `ОД_выстрела(режим) + ОД_подготовки` где `ОД_выстрела` = базовая цена выстрела оружия, плюс «ОД прицеливания» оружия для прицельного и тщательного, с перками-скидками, минимум 1; `ОД_подготовки` — цена «вскинуть оружие» по типу оружия **в руках** (1…8). Для **тщательного** режима цена первой пули = `max(все_оставшиеся_ОД, ОД_выстрела)` (подготовка не прибавляется, выстрел съедает всё).
4. `пуль_за_нажатие`: одиночные режимы — 1; короткая очередь — `скорострельность / 6`; длинная — сколько влезет: счётчик `n = 0`, `остаток = ОД − цена_первой_пули`; пока `остаток ≥ 0`: `n += 1`, `остаток −= цена_доп_пули`.
5. `цена_доп_пули` = `максимум_ОД_бойца / скорострельность` (целое, с перком-скидкой, минимум 1).
6. **Число пуль за остаток ОД** (симуляция с перезарядками): запомнить патроны текущего и всех запасных магазинов. Пока `ОД > 0`:
   - если в магазине есть патроны: если `ОД < цена_первой_пули` — стоп; выпустить `min(патроны, пуль_за_нажатие)` пуль: первая стоит `цена_первой_пули`, остальные `цена_доп_пули`; если после вычитания `ОД < 0` — прервать очередь (эта пуля не считается); иначе пуля засчитана;
   - если магазин опустел: `ОД −= цена_перезарядки`; если `ОД ≤ 0` — стоп; взять следующий магазин; нет магазинов — стоп.
7. `доп_ОД` (только тщательный) = `max(0, ОД − ОД_выстрела)`.
8. Для каждой засчитанной пули `n = 0…`: шанс = ИИ-расчёт попадания (п. 12) с номером пули в очереди `n mod пуль_за_нажатие` и `доп_ОД`; `макс_шанс = max(...)`; `качество += шанс / 100 × урон_пули` (накопление в целом числе — дробная часть отбрасывается на каждом шаге).
9. Вернуть режим оружия на место.

Следствия:
- Если остатка ОД не хватает ни на одну пулю, шанс = 0 и место считается «нестреляемым». Это и есть механизм «оставь ОД на выстрел».
- Тщательный выстрел всегда один и сжигает все ОД; его бонус: `+ОД прицеливания` и `+⌊1,5 × доп_ОД⌋` к сумме слагаемых попадания, плюс `доп_ОД / 3` к навыку. Он выигрывает у «навскидку», когда на второй выстрел навскидку ОД не хватает или когда прибавка точности перевешивает число выстрелов.
- Симуляция учитывает перезарядки (качество может включать выстрелы после смены магазина), хотя само действие «выстрел» при пустом текущем магазине невыполнимо.

### 11.3. Параметры одного нажатия при записи
Для выставленного режима, при доступных ОД `A`:
1. Текущий магазин пуст и запасного нет, либо нет цели → нули.
2. Магазин пуст → `цена = ОД перезарядки`, берётся число патронов запасного, флаг «нужна перезарядка» (цикл записи на этом останавливается).
3. `пуль = min(патроны, пуль_за_нажатие(A − цена))`.
4. Тщательный: `доп_ОД = A − ОД_выстрела − цена`.
5. Первая пуля: `цена += цена_первой_пули(A − цена)`; каждая следующая: `+= цена_доп_пули`.

### 11.4. Прочие «лучшие» предметы
- Граната, ракетница, аптечка: предмет в руках, если он этого типа; иначе ПЕРВЫЙ такого типа по порядку инвентаря. Свойства не сравниваются.
- Нож/оружие ближнего боя: максимальный средний урон, строго; предпочтения «в руках» нет.
- «Первое огнестрельное» (для проверки огня по своим): то, что в руках (если не ракетница), иначе первое.
- Оружие для снайпинга: первое по порядку с режимом «снайперский» и непустым магазином.

### 11.5. Порядок ИИ-инвентаря
Сначала предметы рюкзака (только магазины и то, что можно вложить в первый оружейный слот), затем предметы слотов экипировки по номеру слота. Сначала создаются обёртки не-магазинов, потом магазины раскладываются по подходящему оружию (первому по порядку, которое их принимает), в конце безусловно добавляется врождённое «оружие по умолчанию» (кулаки). Инвентарь перестраивается заново при каждом раздумье.

## 12. Какие числа видит ИИ: укрытие цели и шанс попадания

### 12.1. Укрытие цели для ИИ (`GetCoverForAIUnit`)
1. Точка начала — точка ствола бойца при оцениваемой позиции (не глаза).
2. Строится проективная сетка лучей на весь корпус цели: половина сетки **8** (для игрока — 20, и у игрока есть ещё вторая, грубая сетка 5 — у ИИ её нет). Половина ширины поля `min(1,0; дистанция_в_плане × tg(π/8))`, половина высоты 1,0 (в метрах, с масштабом проекции); дальность проекции `max(0,1; дистанция + 2)`; дальность пуль `min(дистанция + 1, максимум трассы)`. Трассировка учитывает укрытия и объекты, блокирующие ствол; «разрушаемые фрагменты» в ИИ-режиме не учитываются. Минимальная «чистая» дистанция от ствола — 1,0.
3. `укрытие = 100 × (число пробивающих лучей / число лучей, попавших в цель) × ((сумма остаточной пробивной силы / число пробивающих) / пробивная_сила_атаки)`.
4. Нет лучей в цель → 0. Все лучи заблокированы → неопределённое число (деление на ноль); вызывающие трактуют «не больше нуля» как 0.

Итог: «укрытие» — это доля видимого силуэта цели (0…100), взвешенная потерей пробивной силы. Высокое значение = цель открыта.

### 12.2. ИИ-расчёт шанса попадания
Входы: стрелок, оцениваемая позиция (поза и CP), цель (её живая позиция), укрытие, часть тела (ANY), номер пули в очереди, оружие, доп. ОД.
Отличия от расчёта для игрока:
- **Площадь силуэта цели = 1** всегда (поза и ракурс цели не учитываются).
- **Штраф за движение цели = 0**.
- **Освещённость = полная** (1,1,1); учитывается только флаг «ночь» (×0,9 без перка ночного зрения).
- «Первый раунд боя» = нет (коэффициент 1).
- Накопленные снайперские ОД = 0.
- «Удар в спину» = нет.

Формула:
- `дист` = целое от `|CP_места − CP_цели| / 0,625`, минимум 1.
- `навык` = навык стрельбы с перками типа оружия; для тщательного `+ max(0, доп_ОД + штраф_движения) / 3`; для пули очереди `n > 0`: `max(навык × (навык_очередей/140)^n, ⌊60 × навык_очередей / 140⌋ % × навык) × отдача / 100`; всё умножается на штраф ранений.
- `D1 = навык × (макс_дальность − мин_дальность) / 140 + мин_дальность`.
- `D2 = clamp(100 × cos³(дист / D1) + 2; 2; 100)`; если `дист > 2 × D1` — `D2 = 0`.
- `SMove = min(пройдено_в_прошлом_ходу, 10) × штраф_движения_типа_оружия` (коэффициент отрицательный; 0 с перком).
- `RS = min(повторов_действия, 5) × 2`.
- `Stance` = бонус типа оружия за позу места (сидя/лёжа).
- `AllAdd = SMove + RS + Stance + D2 + привыкание_к_оружию + качество_оружия` `[+ ОД прицеливания` для прицельного/тщательного`]` `[+ ⌊SMove⌋ + ⌊1,5 × доп_ОД⌋` для тщательного`]`.
- `AllMult = max(0, AllAdd × свет × 1)`.
- `k = (оптика + 1) × 100 / (дист + оптика)`; `CA = ((100 − k) × (укрытие/100) + k) / 100` (с поправками перков цели и, если включены «прицельные попадания», множителем части тела — для ANY он 1).
- `защита = аура_уклонения_цели + неуязвимость_цели / 10`.
- `шанс = clamp(AllMult × CA + перк_тщательного + аура_стрелка − защита − погода(5 при непогоде); 2; 100)`, усечение до целого. Если `укрытие ≤ 0` — шанс 0.

Важное следствие: при ненулевом укрытии шанс никогда не меньше 2 — «линия огня есть» ⇒ выстрел выполним, сколь угодно далёкий.

## 13. Что ИИ подбирает и что выбрасывает

«Нужен ли предмет» (в скобках — что назначается «на выброс»):
1. Не магазин и нельзя вложить в первый оружейный слот → не нужен.
2. Граната → нужна, пока гранат ≤ 3.
3. Метательное → пока метательных ≤ 3. Ближнего боя → пока таких ≤ 1 (кулаки считаются).
4. Магазин → если есть подходящее оружие и у него меньше 4 запасных магазинов.
5. Аптечка → если аптечек нет.
6. Огнестрельное: сломанное — никогда. Ракетница → пока ракетниц < 2.
7. Остальное огнестрельное сравнивается по «типу хвата» (пистолет / винтовка / ПП / пулемёт), сравнение «моё хуже» = `AIRating моего < AIRating найденного`:
   - Пистолет: есть свой пистолет → брать, если свой хуже (свой на выброс); нет — брать.
   - Винтовка: есть своя → (своя на выброс) если своя — FG-42 (запись № 21) → не брать; если найденная FG-42 → брать; если своя с оптикой → брать только если своя хуже И найденная тоже с оптикой; если своя без оптики, а найденная с оптикой → брать; иначе брать, если своя хуже. Своей винтовки нет: если есть ПП или пулемёт → не брать; иначе брать.
   - ПП: есть свой → брать, если хуже (свой на выброс); нет своего: есть винтовка или пулемёт → не брать; иначе брать.
   - Пулемёт: есть свой → брать, если хуже (свой на выброс); нет: если есть ПП — он на выброс; брать, если нет винтовки.
   - Прочие типы хвата — никогда.
Выбрасывается оружие вместе со всеми своими запасными магазинами.

## 14. Правила выбора действия

### 14.1. Механизм
Каждое правило = (действие, обязательные признаки, обычные признаки). Признак — булева переменная с «желаемым» значением: истинность 1, если совпало, иначе 0. Истинность правила = `min(минимум обязательных, среднее обычных)` (нет обычных → 1).
Обход по порядку: `лучшее = ничего`, `планка = 1`. Для правила с истинностью `f`: если `f` строго больше лучшей — запомнить; если при этом `f > планка × 0,5` — немедленно вернуть это действие. После каждого правила `планка ×= 0,5`.
На практике: побеждает ПЕРВОЕ правило с ненулевой истинностью. Единственное правило с дробной истинностью — граната: `среднее(«выстрел НЕ убьёт наверняка», «группа в плохом состоянии»)` = 0, 0,5 или 1; на его позициях в списках 0,5 всегда выше планки. Значит граната бросается, если она выполнима И (выстрел не гарантирует убийство ИЛИ группа «в плохом состоянии»); не бросается, только когда выстрел убивает наверняка и группа «бодра».

Перед правилами для каждого действия берётся его оценка в его лучшем месте (нет лучшего места → «невыполнимо»).

### 14.2. Логика атаки (обычный бой)

| 3 | Таран в ПК | текущее |

| 5 | Сесть за орудие | текущее |
| 6 | Стрелять из орудия | текущее |

`CanSkip` (пропуск хода): боец боеспособен и живые ОД ≤ 5.

### 14.3. Логика охраны
Источники: «атака» с областью охраны и бюджетом = максимум ОД бойца; «текущее место». Рукопашная привязана к источнику «атака». Тарана нет.
Порядок: вылезти из ПК > надеть ПК > отменить снайпинг > копить ОД > снайперский выстрел > начать снайпинг > слезть с орудия > сесть за орудие > стрелять из орудия > **выстрел** > ракета > граната (те же два признака) > нож > перезарядка > подбор > **лечение** > рукопашная > «двинуться».
`CanSkip`: как в атаке (ОД ≤ 5).

### 14.4. Логика обороны (удержание места)
Источник: «одно место» (режим «стоя»), резерв ОД = переданное реакцией число. Действия: выстрел > ракета > граната (два признака) > перезарядка. Если ничего не выбрано — логика завершается целиком. `CanSkip` — никогда.

### 14.5. Логика отступления
Источник: «к точке» (25 ОД), политика мест «меньше ОД — лучше». Сначала проверка прибытия: расстояние от живой позиции бойца до точки < 0,5 → логика завершена. Иначе: выстрел > ракета > граната (два признака) > нож > перезарядка > рукопашная > «двинуться». Не завершается, пока не дошёл. `CanSkip`: ОД ≤ 5.

### 14.6. Логика «после боя»
Источник: «текущее место». Правила: перезарядка > лечение > подбор (только если логика создана с разрешением подбора; поза WALK) > «двинуться». Если ничего не выбрано и «ОД обновлялись» (у владельца начинался новый ход, либо мир в RT) — логика завершается. В TB это даёт логике прожить ещё один ход. `CanSkip` — никогда.

### 14.7. Когда какая логика (интерфейс со слоем реакций)
Подробности — в спецификации реакций. Для обычной реакции: есть подозреваемый и нет врага → «проверить место» (бегом к ТЕКУЩЕЙ позиции подозреваемого); есть враг → логика атаки (существующая не пересоздаётся); враг пропал, союзник зовёт → бегом к союзнику; был бой и врагов нет → «после боя» с подбором; боя не было → без логики (маршрут/простой).

## 15. Позы, укрытия, скрытность

- Кандидаты есть только «стоя» и «сидя». Лёжа боевые логики не ложатся (места с позой «лёжа» отбрасываются).
- Перемещение — бегом (в ПК шагом); поза места принимается по прибытии.
- Собственная защищённость места от врага не оценивается; «укрытие» в расчётах — это видимость ЦЕЛИ. Занятие укрытий и «выглядывание» делает реакция обороны через логику обороны (резерв ОД на возврат).
- Сидя выбирается, когда: (а) это даёт больший шанс при шансе ниже порога 20; (б) боец уже сидит (тогда «сидя» дешевле); (в) лечение и начало снайпинга явно предпочитают «сидя».
- Запись «спрятаться» (команда скрытности, 14 ОД) существует, но ни одно из 19 действий её не создаёт. Вероятность скрытности бойца (`HideProbability`) используется маршрутными логиками (чужая спецификация).

Их схема (таблица → строки с полем «действие» → элементы «колонка, мин., лучшее, макс., неважно») в точности повторяет устройство признака правила (лучшее значение, минимум, максимум) — это задел под задание правил данными, которым игра не пользуется: все правила зашиты в код, и в коде обращений к этим таблицам нет.

## 17. Отладка и журналирование

- Консольная переменная `game_noai` — полностью отключает ИИ (в TB сторона сразу заканчивает ход).
- Отладочные сообщения: «AI error : unit can't do command! [ result = N ]»; « AI : fatal cycling detected : logic canceled ».
- Отладочные дампы: инвентарь бойца (число огнестрельных и их запасных магазинов, ракетниц, гранат); стек управления бойца; состояние менеджера заданий (сколько заданий, сколько высшего приоритета); позиции юнитов списка.
- Расчёт попадания умеет печатать все слагаемые в лог RPG.
- Признак-чит юнита «без ИИ» исключает его из ожидания конца хода.

## Все прихваты ИИ списком

1. ИИ принимает решения раз в 3 сегмента (150 мс); в сегмент уходит максимум одна команда.
2. Одновременно думает только один боец стороны.
3. В TB боец ходит, пока у него есть работа; следующий — ближайший к нему по прямой из ещё не ходивших.
4. После каждой команды в очередь автоматически ставится «продолжить».
5. Команда, которую юнит выполнить не может, выбрасывается, а логика бойца помечается «ход окончен».
6. Общий предохранитель: больше 5000 поставленных команд за ход — принудительный конец хода.
7. Смена логики/реакции бойца весит 200 «команд»: ~25 смен без действий — конец хода стороны.
8. Топтание на месте с теми же ОД: с 16-го повтора — 25 % шанс отмены команды, на 31-м логика убивается.
9. В TB боец думает снова, только если его ОД изменились с прошлого раздумья; пустое раздумье = конец его хода.
10. Чтобы обойти п. 9, «слезть с орудия» принудительно тратит 1 ОД.
11. Начало хода обнуляет снимок ОД — гарантированное раздумье.
12. Бюджет думания — 10 мс на сегмент с компенсацией перерасхода до 0,2 с; по одному месту/источнику за шаг.
13. Пока считаются пути, командир ИИ полностью замирает.
14. При любом изменении угроз план бойца стирается, текущая команда отменяется.
15. Группы врагов строятся по ВСЕМ врагам карты, включая невидимых, по точным позициям.
16. Гранату можно бросить в группу, которую никто не видит: проверяются только баллистика и расстояние до своих.
17. Центр группы считается с ошибкой: второй добавленный полностью заменяет центр, первый член не учитывается никогда.
18. Группы пересекаются; у каждого врага есть собственная группа.
19. «Свои рядом с группой» включают самого бросающего, нейтральных и юнитов человека.
20. Граната: никого из «не врагов» ближе радиуса осколков (5 м) к центру; ракета: ближе 3 м.
21. Ракета не пускается ближе 3 клеток; при неудаче пробуется точка чуть выше и ближе к стрелку.
22. «Плохое здоровье группы» на деле проверяет ОД врагов (≤ 15).
23. Граната не бросается, только если выстрел убивает наверняка И группа «бодра».
24. За одно решение бросаются все гранаты, на которые хватает ОД, в одну и ту же точку.
25. «Убьёт наверняка» = здоровье врага × 2,5 < ожидаемого урона; ИИ знает точное здоровье врага.
26. ИИ знает точные ОД врагов.
27. Путь к врагу и поворот к нему строятся по его точной текущей позиции; «подозреваемого» тоже ищут по текущей позиции.
28. Цель — не самый опасный, а ближайший (±1,5 м) с лучшим собственным шансом попадания.
29. Кучка ближайших считается относительно первого найденного ближайшего, а не истинного минимума.
30. Ради выстрела боец отходит не дальше 14 ОД; фланговый манёвр — не дальше 8 ОД и только строго вбок (±10°).
31. Обход пути обрывается на первой клетке, где не хватает бюджета на «сесть».
32. Шанс ≥ 20 % (в ПК ≥ 5 %) — «достаточно»: дальше важна только экономия ОД, боец стоит на месте.
33. Место без ОД на выстрел имеет шанс 0 — так ИИ резервирует ОД на выстрел.
34. Минимальный шанс 2 % при любой линии огня: ИИ стреляет на любую дистанцию.
35. ИИ не оценивает, насколько сам открыт врагу.
36. ИИ не ложится.
37. ИИ считает попадание с упрощениями в свою пользу: силуэт цели всегда полный, движение цели не штрафует, освещённость полная.
38. ИИ-растр укрытия грубее игрового (8 против 20 + дополнительная сетка) и не видит разрушаемых фрагментов.
39. Проверка огня по своим — растром лучей первого огнестрельного оружия по корпусу; под защитой и нейтральные, и юниты человека.
40. Если врага нет, своя клетка в источнике «атака» считается «опасной» и не добавляется.
41. Выбор оружия — полный перебор «оружие × режим» по ожидаемому урону за остаток ОД; оружие в руках не имеет преимущества, смена бесплатна.
42. Тщательный выстрел сжигает все ОД и не платит «подготовку»; каждый лишний ОД даёт +1,5 к шансу.
43. Цена «подготовки» берётся по оружию в руках, а не по оцениваемому.
44. Ожидаемый урон копится в целом числе — дробь теряется на каждой пуле.
45. Оценка урона включает выстрелы после перезарядки, но стрелять с пустым магазином нельзя — сначала правило перезарядки.
46. Запись «сменить режим огня» меняет режим на настоящем предмете уже в момент планирования.
47. Перезаряжается первое по порядку оружие с неполным магазином и запасным; запасной может быть пуст.
48. Перезарядка стоит ниже выстрела и ножа: ИИ дозаряжает неполный магазин всякий раз, когда стрелять нечем/не по кому.
49. Гранаты, ракетницы и аптечки не выбираются по качеству: «что в руках, иначе первое».
50. У каждого есть «кулаки»: рукопашная доступна всегда, если до врага можно добежать и хватит ОД на удар.
51. Удар в ближнем бою всегда «в голову»; бросок ножа и выстрел — «куда попадёт».
52. В логике атаки ИИ никогда не лечится; лечится в охране и после боя, только себя, при здоровье ≤ 30 % и враге дальше 4 м.
53. Подбор стоит выше рукопашной: боец скорее поднимет оружие в 4 м, чем побежит драться.
54. FG-42 никогда не выбрасывается и всегда подбирается; винтовку с оптикой меняют только на лучшую с оптикой.
55. Запас: гранат до 4, метательных до 4, магазинов до 4 на ствол, аптечка одна, ракетниц две.
56. Снайпер начинает «выцеливание», только если видит все клетки, куда цель добежит за 4 ОД, а враг не ближе 15 клеток (подозреваемый — 10).
57. Снайпинг отменяется, как только враг подошёл ближе или цель стало нельзя поразить.
58. За станковый пулемёт садятся, если он в 10 м, враг дальше 5 м от него и его можно достать; выбирается ближайшее орудие.
59. Из орудия стреляют длинной очередью.
60. В ПК при здоровье костюма ≤ 25 % — идти шагом в гущу ближайшей группы врагов; при сломанном костюме — вылезти; бесхозный костюм — надеть (в том числе с небоеспособным пилотом).
61. Действие «двинуться» в атаке работает только как выход из лазания: с обычной клетки оно невыполнимо, отдельного «просто подойти к врагу» в логике атаки нет.
62. При отступлении лучшим считается место, куда уходит больше ОД, но стрельба по пути остаётся в приоритете.
63. Логика «после боя» живёт лишний ход, чтобы дозарядиться и собрать трофеи со свежими ОД.
64. Кэш оценок действия ключуется местом без ОД: дубликат клетки с другой ценой получает чужую оценку.
65. При равенстве побеждает более раннее: своя клетка стоя.
66. Инвентарь ИИ перестраивается заново при каждом раздумье.
67. Отрицательная трата ОД в плане превращается в трату 1 ОД.
68. Испуг: ранен ниже половины или врагов больше двух и никого своего в 9 м (ПК не пугается).
69. Таблицы полезности в базе пусты; сложность меняет только ОД, здоровье, уровень и вероятности.
70. Мёртвые/сохранённые ошибки оригинала: бонус «по взгляду», всегда-истинная проверка лучшей цены, невосстановленная желаемая поза, проверка проходимости центра вместо клетки.

## Пример

Во всех примерах величины, зависящие от чужих подсистем (цена шага, цена смены позы, выдача калькулятора попадания), приняты условно и помечены «(усл.)».

### Пример 1. Стрелок с винтовкой, враг виден в 12 клетках, 30 ОД

Дано: винтовка Мосина 1891/30 (цена выстрела 21, прицеливание 8, режимы: навскидку, прицельный, тщательный), тип «винтовка» (подготовка 6, бонус сидя +2). Боец стоит, в магазине 5 патронов. Шаг бегом 2 ОД (усл.), «сесть» 4 ОД (усл.), «встать из стоя» 0.

1. **Места (источник «атака», бюджет 14)**:
   - своя клетка: стоя (30 ОД), сидя (26 ОД);
   - путь к врагу, шаг k: стоя `30 − 2k`, сидя `30 − 2k − 4`. k = 1…5 — обе позы (сидя: цена 6…14 ≤ 14); k = 6 — стоя (цена 12) добавлено, сидя (16 > 14) нет ⇒ «не полностью достижима» ⇒ обход пути прекращён;
   - фланг: клетки не дальше 8 ОД (до 4 шагов), направление на которые в пределах 80°…100° от оси на врага; обе позы каждой.
2. **Оценка выстрела по местам**. Цена первой пули: навскидку 21 + 6 = 27; прицельный 29 + 6 = 35; тщательный `max(ОД, 29)`.
   - Своя, стоя, 30 ОД: навскидку — 1 пуля (остаток 3); прицельный — 0 пуль; тщательный — 1 пуля, доп. ОД = 1. Пусть калькулятор даёт 31 % навскидку (усл.); тщательный = 31 + 8 (прицеливание) + ⌊1,5⌋ = 40 % (усл., до умножения на коэффициент укрытия примерно так). Урон пули 25 (усл.): качество 7 против 10 ⇒ выбран тщательный, шанс 40.
   - Своя, сидя, 26 ОД: 26 < 27 и 26 < 29 ⇒ 0 пуль, шанс 0 — невыполнимо.
   - k = 1, стоя, 28 ОД: навскидку 1 пуля (шанс ≈ 32); тщательный — нельзя (28 < 29). Шанс 32.
   - Все остальные места: ОД ≤ 26 ⇒ невыполнимо.
3. **Сравнение**: своя-стоя (40 %, 30 ОД) против k = 1 (32 %, 28 ОД): оба ≥ 20 ⇒ лучше то, где больше ОД ⇒ своя клетка.
4. **Правила атаки**: 1–10 невыполнимы (нет ПК, орудий, оптики); ракеты и гранаты нет; выстрел выполним ⇒ выбран.
5. **Запись**: трата 0 ОД на ход; место совпадает с текущим — перемещения нет; режим «тщательный»; параметры нажатия при 30 ОД: 1 пуля, цена `max(30, 29) = 30` ⇒ «выстрел по врагу», «−30 ОД», «−1 патрон»; при 0 ОД следующее нажатие стоит 29 > 0 — стоп.
6. **Команды**: «режим огня: тщательный», «стрелять по объекту (враг, куда попадёт)»; после каждой — «продолжить». По одной в сегмент.
7. После выстрела ОД = 0 ≤ 5 ⇒ `CanSkip` ⇒ ход бойца окончен.

Вариант: если бы на своей клетке калькулятор давал 12 %, а на k = 1 — 14 %, то (оба < 20) выигрывает больший шанс: боец пробежит одну клетку (2 ОД) и выстрелит навскидку с 28 ОД.

### Пример 2. Гранатомётчик: три врага кучей в 10 клетках, 40 ОД

Дано: у бойца две гранаты (радиус осколков 5,0), ПП. Враги A, B, C стоят в пределах 1 м друг от друга на расстоянии 6,25 м; союзник бойца — в 8 м от врагов.

1. **Группы** (порядок A, B, C): A → группа Г1{A}, центр A. B: до центра Г1 < 1,5 м ⇒ Г1{A,B}, центр прыгает в B; новая Г2{B}. C: Г1 ⇒ {A,B,C}, центр = середина B и C; Г2 ⇒ {B,C}, центр = C; новая Г3{C}. `fNearestAlly`: для всех трёх ≈ 6,2 м (сам бросающий ближе союзника).
2. **Граната по местам**: цена броска 20. На своей клетке (40 ОД): радиус 5,0 < 6,2 — да; бросок в центр возможен по баллистике — группа годится. Ближайшая по расстоянию до центра — допустим Г1 (3 врага). Клетки пути ближе к врагу дают `fNearestAlly` тот же (он считается от позиции юнита в мире, не от места) — безопасность от места не зависит. Все выполнимые места сравниваются по ОД ⇒ своя клетка, стоя, 40 ОД.
3. **Выстрел**: пусть ПП даёт длинной очередью качество 48 (усл.); здоровье цели 60 ⇒ `60 × 2,5 = 150 < 48` ложно ⇒ «не убьёт наверняка».
4. **Правило гранаты**: обязательное «выполнима» = 1; обычные: «не убьёт наверняка» = 1, «плохое состояние» (максимум ОД врагов ≤ 15?) — пусть у врагов по 60 ОД ⇒ 0; среднее 0,5. Планка к 12-му правилу давно ниже 0,5 ⇒ граната выбрана (правило 12 стоит выше выстрела — 13).
5. **Запись**: бюджет 40: «сменить оружие» на гранату, «бросить в центр Г1», −20; вторая граната: «сменить оружие», «бросить в ту же точку», −20; бюджет 0 — стоп.
6. Если бы союзник стоял в 4 м от врагов — все три группы отпали бы (5,0 < 4,0 ложно), граната невыполнима, боец стрелял бы из ПП. Если бы сам боец был в 7 клетках (4,4 м) — граната тоже невыполнима с любого места: ИИ не отходит назад ради броска.

### Пример 3. Врага не достать: пустой магазин, затем нет линии огня

Дано: автоматчик, 50 ОД, в магазине 0 патронов, есть запасной магазин; враг виден в 8 клетках.

1. Выстрел: лучшая пара найдётся (симуляция учитывает перезарядку), но текущий магазин пуст ⇒ невыполнимо на всех местах. Гранат, ножей нет.
2. Правило 15 «перезарядка»: поза обычная; первое оружие с неполным магазином и запасным — ПП; цена перезарядки 17 ≤ 50 ⇒ выполнимо, место — своя клетка стоя.
3. Запись: «перезарядить», −17 ОД. Команда «перезарядить», затем «продолжить».
4. ОД изменились (33 ≠ 50) ⇒ новое раздумье: теперь выстрел выполним ⇒ обычный выбор места и режима (пример 1).

Продолжение: враг зашёл за стену, но остался в списке подтверждённых; у бойца 33 ОД, магазин полон.
1. На всех местах в 14 ОД укрытие цели 0 ⇒ шанс 0 ⇒ выстрел невыполним.
2. Перезарядка: магазин полон ⇒ нет. Подбор: рядом пусто ⇒ нет.
3. Рукопашная: путь к кольцу вокруг врага стоит, скажем, 40 ОД ⇒ ОД места −7 ⇒ место отброшено фильтром ⇒ невыполнимо. (Если бы путь стоил 20, а удар кулаком 10 — боец побежал бы бить: 13 ≥ 10.)
4. «Двинуться»: место = своя клетка ⇒ невыполнимо.
5. Ни одно правило не сработало ⇒ команд нет ⇒ ОД не изменились ⇒ ход бойца окончен. Дальнейшее (перевод врага в «подозреваемые» в начале хода и поход «проверить место») — дело слоя реакций.

## Отклонения реконструкции от оригинала

Отмечены самой реконструкцией (комментарии об исправлениях, допущениях, [FORK]):

1. **Прицельный выстрел в голову не перенесён.** В оригинале действие «выстрел» целится в голову, когда шанс > 50 и некая метрика бойца > 5,0 (два неопознанных виртуальных вызова). В реконструкции всегда «куда попадёт».
2. **«Может сидеть»** в процедуре добавления поз определено как «боец не в неактивной позе» — это вывод по смещению виртуальной функции; тот же слот в других местах трактуется как «боец в ПК». Вероятно, в оригинале ПК не предлагается поза «сидя».
3. **Проходимость своей клетки**: реконструкция пропускает клетку, заблокированную самим бойцом (исправление от 2026-07-10); способ проверки отличается от оригинального (там «состояние клетки» + «владелец»).
4. **Реакция умершего бойца** в очереди реакций пропускается (исправление «оригинальной ошибки»).
5. **Снайперский выстрел и накопление ОД** дополнительно требуют ненулевого настоящего шанса попадания; оригинал для выстрела проверял только «в режиме снайпинга». Начало снайпинга оценивается из позы места с поворотом к цели и выбранным снайперским оружием.
6. **Цена ракеты** берётся как цена выстрела оружия (в оригинале — отдельный код действия).
7. **Кольцо рукопашной** строится генератором, центрированным на враге; удвоение досягаемости зависит от ПК врага, а не бойца. Досягаемость удара проверяется по центру врага, а не по точке его коллайдера.
8. **Цена удара/броска ножа** запрашивается без длины оружия (двухаргументная форма).
9. **Поиск пути** в источниках «атака» и «к точке» идёт с флагами по умолчанию; оригинал использовал флаг «учитывать направление».
10. **Ракетница** в реконструкции — подкласс огнестрельного оружия (в оригинале — «сестра»); исключение ракетниц из перебора сделано по флагу базы.
11. **Трата ОД в плане**: отрицательная цена превращается в 1 ОД; цена выстрела и перезарядки имеет пол 1; скидка перка на перезарядку исправлена (платится 70 %, а не 30 %) — это меняет числа, которые видит ИИ.
12. **Признак «под управлением ИИ»** вычисляется динамически по текущему игроку юнита.
13. **Блокировки объектов, флаг «ход ИИ», стек «управлений» (`IAIControl`), список `CAIPlayer`** — остатки ранней версии, в оригинальном командире их нет; на решения не влияют.
14. **Пропуск бойца в неактивной позе** на стационарном простое маршрута (`ShouldYieldInactiveUnit`) — добавление реконструкции.
15. **Позиция бойца** для действий всегда читается с сервера юнита; плановая копия позиции (которую меняет запись «переместиться») при оценках не используется. Следствие: при исполнении действие пересчитывается от ещё не изменённой позиции (см. «Не установлено», п. 2).
16. **Источник «текущее место»** восстановлен в полной форме (с поиском выхода из неактивной позы); источник «атака» не вызывает отдельную проверку «можно ли вообще поразить с клетки» (дальность+сектор), полагаясь на оценку действия.
17. Порядок полей/сериализация, ID классов — вне предмета спецификации.

Неиспользуемые файлы (в сборку не входят или мертвы):
- `aiAction.*`, `aiAttackAction.*`, `aiCompoundAction.*` — прежняя (январь 2003) схема: логика-задание с двумя подзаданиями («найти хорошие места» вдоль пути к врагу в бюджете **12 ОД**, «выбрать место для действий») и всего тремя действиями — выстрел, граната, ракета; перезарядка — особый случай до выбора; порядок ракета > граната > выстрел; если ничего — «идти к врагу пригнувшись»; пропуск хода при ОД ≤ 20; компараторы мест с предпочтением меньшей дистанции до врага. Действия ссылались на общее состояние, а не на бойца.
- `aiCriterion.*` — целиком закомментирован: взвешенные критерии «попадание», «спрятаться», «урон» с кусочно-линейными шкалами и порогом «шанс ≥ 20 — стоять, иначе бежать вперёд». Отсюда происходит порог 20.
- `aiMoveAction.*` — компилируется, но из него используются только две вспомогательные функции «клетка → позиция»; оба задания внутри — из прежней схемы.
- `aiCombatStubs.cpp` — пустая заглушка.
- `aiPlayer.*`, `aiControl.h` — списочные обёртки и интерфейс «управления» прежней схемы.

## Не установлено

1. **Порог в проверке выполнимости команды**: код сравнивает с «нет цели» (3), комментарий говорит о литерале «> 4» в оригинале. Различие: пропускается ли «не хватает ОД» (4). Не подтверждено.
2. **От какой позиции действие пересчитывается при исполнении.** В реконструкции — от живой позиции бойца, а ОД — уже за вычетом хода. Если выстрел возможен только с нового места, то в этом раздумье запишется лишь перемещение, а выстрел — после него, в следующем раздумье (ОД изменятся). Так ли было в оригинале (или оценка шла от плановой позиции, и ход с выстрелом уходили одной пачкой) — не подтверждено.
3. Условие и метрика прицельного выстрела в голову (п. 1 отклонений).
4. Истинный смысл «может сидеть» (ПК или неактивная поза).
5. Порядок вызовов «сегмент командира» и «генерация команды» внутри одного сегмента мира и точное место вызова генерации — не прослежено.
6. Цены шага и смены позы (`pose_move_coeff` = 2, `pose_switch_coeff` = 4, `rotate` = 2 в `RPGAPs`) и их формулы — в спецификации перемещения; в примерах приняты условно.
7. Насколько свежи зеркала ОД/здоровья врагов, не входящих в личный список бойца (для «плохого состояния группы»), — зависит от того, чей командир и когда их синхронизирует; не прослежено.
8. Поведение при неопределённом значении укрытия (все лучи заблокированы) после приведения к целому в переборе оружия — зависит от платформы; в оригинале, по комментарию, возвращалось число с плавающей точкой.
9. Используется ли где-либо запомненная сумма здоровья сторон на начало хода и «нанесённый за ход урон» — в текущих правилах нет; возможно, остаток схемы критериев.
10. Точное содержание проверок мира «можно бросить гранату/метнуть нож/взять костюм/оказать помощь» — в спецификациях соответствующих подсистем; здесь использован только их ответ.
11. Режим огня орудия № 4 принят как «длинная очередь» по порядку перечисления режимов; для орудий без этого режима поведение не проверено.
