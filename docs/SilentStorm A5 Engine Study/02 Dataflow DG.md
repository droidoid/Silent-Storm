# Dataflow-ядро `DG.H`

← [[00 Главная]]

Самая необычная часть движка: граф ленивых вычислений с версиями. Определён в `Main/DG.H` и `Main/DG.CPP`.

## Устройство

- **`CVersioningBase`** — база узла. Хранит `nFrameCalced` (кадр последнего пересчёта) и `nVersion`.
  - `NeedUpdate()` — виртуальная: нужно ли пересчитать.
  - `Recalc()` — виртуальная: сам пересчёт.
  - `Updated()` — поднять версию вручную, когда значение изменилось.
- **`CFuncBase<T>`**, **`CPtrFuncBase<T>`** — узлы, хранящие значение типа `T`.
- **`CHoldedFuncBase`** — вариант с очередью удержания: кэширует результат со случайным сроком жизни.
- **`DEFINE_DG_CONSTANT_NODE`** — узлы-константы с ручной установкой, например `CCTime` в `Main/Time.h`.
- **`CDGPtr<T>`** — ребро зависимости. `Refresh()` тянет обновление и возвращает, изменилась ли версия.

## Как работает пересчёт

1. Потребитель вызывает `Refresh()` на своих входах.
2. Узел пересчитывается **не чаще одного раза за кадр**: сравнивается `nFrameCalced` с глобальным `nDGCurrentFrame`.
3. Типичная реализация: `NeedUpdate(){ return pA.Refresh() | pB.Refresh(); }`.
4. Кадр графа сдвигает `MarkNewDGFrame()`. Вызывается на каждый сегмент мира и на каждый кадр UI (`Main/GView.cpp`, `Main/GSceneInternal.cpp`).

Это pull-модель: ничего не считается, пока результат никому не нужен.

## Где используется

`CFuncBase` / `CDGPtr` встречаются примерно в 35 заголовках `Main`:

- части сцены и комбайнеры буферов — [[03 Сцена и рендер]];
- источники света — [[04 Свет и тени]];
- аниматор скелета `CSkeletonAnimator` — [[08 Анимация]];
- головы LifeStudio — [[09 Лица LifeStudio]];
- частицы;
- звук: `SoundEffect` принимает `CFuncBase<STime>` и `CFuncBase<CVec3>`.

## Почему это интересно

Готовая идея для нодового движка: версии вместо флагов «грязно», покадровый кэш, зависимости как типизированные указатели. См. [[20 Что можно взять]].
