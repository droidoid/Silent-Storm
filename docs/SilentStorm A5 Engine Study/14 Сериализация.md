# Сериализация и сохранения

← [[00 Главная]]

Один механизм обслуживает всё: ассеты, `game.db`, заголовки паков, сохранения.

## `CStructureSaver` — `FileIO/BasicChunk1.h/.cpp`

- Пишет вложенные чанки с идентификаторами типа `char`. Чанк 0 зарезервирован под систему.
- Объект реализует `int operator&(CStructureSaver &f)` с вызовами `f.Add(id, &поле)`. Один метод и на запись, и на чтение.
- Шаблоны покрывают `string`, `vector`, `list`, `hash_map`, `CArray2D`; простые POD пишутся сырыми байтами.
- Указатели отслеживаются: хэш объектов плюс фабрика классов, регистрация — `REGISTER_SAVELOAD_CLASS(0xNNNNNNNN, Класс)`.
- Общие кэши (`CBasicShare`, `Misc/BasicShare.h`) сохраняются через `SerializeShared`.
- Интерфейса `IBinSaver` в этом снапшоте нет.

## Генерация кода

- Поля класса обрамляются пустыми макросами `ZDATA` / `ZEND` (есть также `ZDATA_`, `ZSKIP`).
- Тело `operator&` между ними дописывает макрос IDE: `Soft/serialize.dsm` (VC6) и проект `Soft/Serialize7` (VS .NET).

## Сохранение игры

- Точки входа: `CICSave::Exec` в `Main/iMain.cpp`, `Main/iSaveManager.cpp`, `SaveWorld` в `Main/iMission.cpp`.
- Сохраняется **полный граф объектов**, без отдельного формата «состояния».
- `game.sav`: заголовок `SSaveFileHeader` (магическое число `0x818B9F21`, скриншот), затем стек интерфейсов и общие кэши.
- Каждая зона — отдельный файл `<id зоны>.sav` с миром.
- Слоты — папки `save\<профиль>\<слот>\`, копируются из `temp` и обратно.
- Ссылки на записи базы хранятся только как id (`CDBPtr::operator&`).
- Состояние Lua вместе с потоками тоже сериализуется — см. [[15 Скрипты Lua]].
