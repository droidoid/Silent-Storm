# Каталог технических решений Silent Storm: ИИ, навигация, пространственные запросы

Составлен по чтению кода `Main` (четыре параллельных прохода по файлам, ключевые константы перепроверены); ничего не собиралось и не запускалось. Расстояния в метрах, тайл = 0.625 м. Три расхождения со старыми заметками:

- **BSP не используется игрой.** В релизном коде столкновения идут через воксельные битовые сетки `CPrecalcSpheres`; BSP строит только экспортёр редактора.
- **Слоёв на этаж 3, а не 4** (`N_MAX_LAYERS_PER_FLOOR = 3`).
- **`aiCompoundAction` / `aiAttackAction` / `aiAction` — мёртвый старый дизайн.** Они не входят в сборку; живая схема — `CAICombatLogic` с правилами.

## A. Навигация

**1. Тайловая сетка: группы, этажи, слои**
- **Задача:** дискретная модель проходимого пространства для многоэтажных разрушаемых зданий.
- **Как работает:** карта состоит из нескольких групп `CLayersGroup`: ландшафт и «альтернативные сетки» зданий, повёрнутые на произвольный угол. Группа — до 256×256 тайлов, 8 этажей × 3 слоя (этажи могут быть отрицательными), всего до 256 слоёв. `STile` занимает 16 байт: 4 маски по 8 направлений (лёжа, присед, стоя, перелезание), высота u16 (0..25 м), этаж, флаги поз, смещение центра ±0.208 м (9 вариантов), блокировки, индекс двери. Дополнительные слои создаются лениво, когда в колонке больше одной поверхности.
- **Данные:** геометрия уровня, прямоугольники групп и точки лестниц от редактора. Сама сетка печётся в рантайме (загрузка готовой сетки из карты не подтверждена).
- **Связи:** питает 2–8, 17, 20.
- **От хоста:** только математика и сериализация.
- **Оценка:** приём стандартный, но повёрнутые подсетки и слои специфичны. ~3300 строк, лифтится вместе с 2.
- **Файлы:** `aiGrid.h/.cpp`, `Grid.h`, `aiPosition.h`.

**2. Запекание проходимости по позам**
- **Задача:** получить из произвольной геометрии высоты, допустимые позы и ходы.
- **Как работает:**
  - Вертикальные лучи 3×3 на тайл (шаг 0.208 м) дают списки твёрдых интервалов; верх интервала — поверхность. Зазор меньше 0.718 м поверхность отбрасывает.
  - Поза в точке проверяется сферами R = 0.31 на трёх высотах.
  - Ход — протяжка сферы к соседу при перепаде < 0.55 м (диагональ < 0.778): лёжа на h+0.41, присед h+0.975, стоя h+1.59.
  - Тайлам хуже «стоя» подбирается одно из 8 смещений центра.
- **Данные:** AI-карта (11), пакетная трассировка (13), воксельные коллайдеры (9).
- **Связи:** заполняет 1; вызывается из 4.
- **От хоста:** вертикальные лучи со всеми интервалами и sweep сферы по собственной геометрии.
- **Оценка:** отличительное решение (автогенерация навигации без ручной разметки). ~2100 строк; зависит от геометрического бэкенда.
- **Файлы:** `aiPassCalcer.cpp`, `aiMovesCalcer.cpp`, `aiPMConst.h`.

**3. Кромки, перелезание, прыжки, лестницы, двери**
- **Задача:** нестандартные переходы — окна, заборы, уступы, лестницы, двери, стыки сеток.
- **Как работает:**
  - Тайл-кромка (`INACTIVE`) — место, где опоры под 3×3 сэмплами нет, но выше (шаг 0.1 до 2.8 м) помещаются две сферы.
  - Перелезание — «HC-ход» по 4 осевым направлениям при перепаде 0.55..2.8 м; четыре класса высоты (<1, <1.5, <2, остальное).
  - Лестницы задаются данными (низ, направление, высота). Ступень годна, если сфера 0.1 касается геометрии с флагом «часть лестницы». Сломанная лестница делится на две половины.
  - Дверь (`SFlipper`) хранит две маски ходов (открыта/закрыта); блокирует только то, что задевает обе её позы.
  - Межсеточные переходы: уклон ≤ 30°, уровень связи 1..3. Совпадающие тайлы разных слоёв связаны бесплатным переходом.
- **Данные:** точки лестниц, двери с двумя наборами коллизий.
- **Связи:** 2, 5, 6.
- **От хоста:** как в 2.
- **Оценка:** отличительное; размазано по `aiPassCalcer` / `aiMovesCalcer` / `aiGrid`, отдельно не вынимается.
- **Файлы:** `aiPassCalcer.cpp`, `aiMovesCalcer.cpp`, `aiDoorCollider.h`, `aiGrid.cpp`.

**4. Инкрементальный пересчёт после разрушений**
- **Задача:** обновлять навигацию при изменении геометрии без фризов.
- **Как работает:** единица — квадрат 8×8 тайлов с уровнем готовности 0/1/2 (грязно / позы / ходы). На каждом квадрате висит трекер AI-карты (z 0..25 м, маска «блокер прохода»). `OnChange` сбрасывает уровень и ставит задачу пересчёта квадрата; одна задача на группу затем перекрашивает зоны. Пока она не закончена, `FindPath` возвращает «нет пути». Вне задач квадраты досчитываются лениво при обращении.
- **Данные:** события AI-карты.
- **Связи:** 11 → 2 → 6; планировщик 16.
- **От хоста:** уведомления об изменении геометрии с AABB.
- **Оценка:** отличительное и ключевое для разрушаемости. ~300 строк поверх 1–2.
- **Файлы:** `aiGrid.cpp`, `aiPassCalcJob.cpp`, `aiColourer.cpp`.

**5. Пространство состояний и генератор ходов**
- **Задача:** граф поиска с позами, направлениями и стоимостями в очках действия (AP).
- **Как работает:** `SPathPlace` — 32 бита: x, y, слой, направление (3 бита), поза (2), флаги moving / final / integral. Ступень лестницы и точка полёта кодируются теми же полями. Стоя и в приседе направление всегда 0 (повороты бесплатны); лёжа оно значимо, ползти можно только вперёд (±45° в движении), поворот проверяет, что тело помещается. Ходы: шаг, диагональ, смена позы, climb 1–4, прыжок, три лестничных, нулевой переход между слоями. Стоимость хода берётся из таблицы AP от правил игры (каждая < 16), плюс 1 за чужой зарезервированный путь.
- **Данные:** таблица стоимостей действий.
- **Связи:** 1, 6, 7.
- **От хоста:** ничего.
- **Оценка:** отличительное (поза в состоянии). ~1100 строк, самодостаточно.
- **Файлы:** `aiMoves.cpp`, `aiMovesEnumerator.h`, `aiPosition.h`.

**6. Волновой поиск пути и конвейер FindPath**
- **Задача:** дешёвый по AP путь и карта достижимости.
- **Как работает:**
  - Дейкстра без эвристики с кольцевой очередью из 17 корзин (макс. стоимость хода 16); таблица «место → родитель, стоимость» в хеше.
  - Конвейер: применить блокировки → отфильтровать цели → обновить зоны → при лимите ≥ 40 ограничить поиск коридором зон (7) → восстановить путь, вставить остановки-повороты и действия открытия/закрытия дверей.
  - Если в пути есть двери или кромки (штраф 10 за каждую) — повторный поиск без них, побеждает более дешёвый.
  - Затем улучшение стрейфом и сглаживание: углы заменяются брезенхемоподобным чередованием шагов с проверкой проходимости.
  - Частичный путь: ближайший посещённый узел, отказ при d² > 5.
  - Заливка без цели (`aiMultiMoves`) даёт все места в пределах бюджета AP.
- **Данные:** 1, 5, 7, 8.
- **Связи:** используется 18–21 и игроком.
- **От хоста:** ничего. Код нереентерабелен (статические таблицы).
- **Оценка:** стандартная техника в аккуратной обвязке. ~1700 строк.
- **Файлы:** `aiWaveSearch.h`, `aiPath.cpp`, `aiWayConstraints.h`, `aiSmoothPath.cpp`, `aiMultiMoves.cpp`.

**7. Иерархия зон-«цветов»**
- **Задача:** быстро отвечать «достижимо ли» и сужать тонкий поиск.
- **Как работает:** слой режется на блоки 8×8; связная компонента внутри блока — зона (≤ 64 тайлов) с центром. Строятся два графа: только стоячие ходы и любые. Вес ребра — расстояние до центров плюс шаг (2/3 для прямого/диагонали, ×2 присед, ×3 лёжа, ×5 перелезание). Лестницы — псевдозоны. Занятые тайлы и запертые двери рвут связи. `CalcBestWays` — Дейкстра по зонам с кэшем по источнику; вокруг каждой зоны маршрута помечаются блоки 3×3 — это разрешённый коридор. Перекраска инкрементальная, по списку затронутых прямоугольников.
- **Данные:** 1.
- **Связи:** 4, 6.
- **От хоста:** ничего.
- **Оценка:** аналог HPA*, сделан рано и по-своему. ~1700 строк, самодостаточно относительно сетки.
- **Файлы:** `aiColourer.cpp/.h`, `aiSimpleWaveSearch.h`, `aiMapProxy.h`.

**8. Блокировки тайлов и поиск ближайшего места**
- **Задача:** учёт занятых клеток и постановка юнита в ближайшую свободную.
- **Как работает:** след юнита — тайл и его копии в других слоях. Лежащий или панцеркляйн занимает ещё тайлы спереди и сзади (при диагонали +4 ортогональных); на лестнице — 4 ступени. На время поиска действуют блокировки только «учитываемых» юнитов. Ближайшее место ищется сферами с радиусом 1 м и шагом +2 м до 15. При потере опоры — радиус 3 м, точки выше исходной запрещены, результат «переместить / упасть / отказ».
- **Данные:** позиции юнитов.
- **Связи:** 6, 7, 20.
- **От хоста:** ничего.
- **Оценка:** стандартное. ~300 строк.
- **Файлы:** `aiLocker.cpp`, `aiNearestPosition.cpp`, `aiGrid.cpp`.

## B. Геометрия и запросы

**9. AI-геометрия и воксельные «предрасчётные сферы»**
- **Задача:** отдельная от графики коллизионная модель с быстрым тестом «поместится ли сфера юнита».
- **Как работает:** объект состоит из кусков (точки, рёберный меш с проверкой замкнутости, объём, стыки с признаком «земля») и масс-сфер. Для куска печётся битовая сетка с шагом 0.1 м (32 слоя по Z в одном int, выше — стопка блоков). Бит равен 1, если сфера R = 0.31 в центре вокселя касается треугольника. Статическая сфера проверяется одним битом, движущаяся — выборкой вдоль отрезка с шагом 0.1. Двери хранят наборы «открыто/закрыто» по стадиям разрушения. Скиннинг кусков для юнитов считается на CPU.
- **Данные:** ресурсы `AIGeometries`, `AIBSPTrees` (имя историческое), экспорт редактора.
- **Связи:** 2, 11, 14.
- **От хоста:** шаг запекания в редакторе (или на лету), матрицы скелета.
- **Оценка:** отличительное (радиус вшит в данные). ~800 строк.
- **Файлы:** `aiObject.*`, `aiObjectLoader.*`, `PrecalcCollider.h`, `aiCollider.*`.

**10. BSP-дерево твёрдого тела (в релизе не используется)**
- **Задача:** столкновение сферы/луча с замкнутым мешем — предшественник п. 9.
- **Как работает:** листья «твёрдо/пусто»; сечения закрываются крышками. Разделитель выбирается по числу полигонов: >25 — осевая бисекция, 6..25 — плоскость через ребро с ценой (пересечённые·3 + дисбаланс), ≤5 — плоскость полигона. В твёрдых листьях добавляются скошенные плоскости на острых рёбрах. Запросы: статическая и движущаяся сфера (с точкой и плоскостью удара), луч. Эпсилон 0.01.
- **Данные:** замкнутый меш.
- **Связи:** в игровом коде вызовов построения нет, только экспорт в `MapEdit`.
- **От хоста:** ничего.
- **Оценка:** стандартная техника, 1800 строк, полностью автономна; для переноса необязательна.
- **Файлы:** `BSPTree.cpp`, `BSPtree.h`, `BSPCollider.h`.

**11. AI-карта: рыхлое октодерево с трекерами изменений**
- **Задача:** единый реестр коллизионных оболочек и рассылка «здесь изменилось».
- **Как работает:** корень 1024 м от (−128, −128, −128), минимальный узел 4 м, объект опускается по центру, пока помещается; дети создаются лениво, лимита ёмкости нет. Оболочка несёт источник (объект, броня, этаж, битовые флаги: юнит, террейн, зрение, блокер прохода/оружия/предметов, укрытие, лестница, состояние двери). Дверь — две оболочки, активна одна. `Sync` перемещает динамические оболочки, копит AABB и маску изменений и оповещает трекеры; пустые узлы чистятся каждый 256-й вызов.
- **Данные:** 9, объекты мира.
- **Связи:** основа для 2, 4, 12–15, 17, 19.
- **От хоста:** события появления/удаления/движения объектов.
- **Оценка:** стандартная структура, ценность в трекерах. ~1600 строк.
- **Файлы:** `aiMap.*`, `ocTree.h`, `wTSFlags.h`.

**12. Трассировка луча с интервалами входа/выхода**
- **Задача:** узнать для выстрела всё, сквозь что прошёл луч, и толщину каждого тела.
- **Как работает:** вершины оболочки проецируются в 2D-систему двух плоскостей луча; для каждого ребра один раз считается знак, три совпавших знака дают вход или выход. Входы и выходы сортируются и спариваются по индексу; незамкнутому террейну достраивается ±1e10. Фильтр — маска флагов, набор этажей, активная поза двери. Результат — интервалы {t и нормаль входа, выхода, источник, id куска}, отсортированные по входу; плотность берётся из брони источника.
- **Данные:** 11.
- **Связи:** баллистика, 19, проверки видимости.
- **От хоста:** ничего сверх своей геометрии (стандартный raycast «первое попадание» не подходит).
- **Оценка:** отличительное, основа пробития. ~300 строк.
- **Файлы:** `aiTrace.*`, `aiInterval.*`.

**13. Пакетная трассировка растеризацией**
- **Задача:** дёшево получить тысячи параллельных или перспективных лучей.
- **Как работает:** программный растеризатор рисует треугольники в сетку «пикселей». Лицевые грани дают входы, обратные — выходы; на пиксель хранится отсортированный список интервалов из пула. Варианты: воксельный куб с id объектов для взрывов (три ортопрохода) и куб зрения с битами «поверхность/твёрдое» и заливкой внутренности.
- **Данные:** 11.
- **Связи:** 2, 17, 19, взрывы.
- **От хоста:** ничего (CPU-растеризатор свой).
- **Оценка:** отличительное. ~1000 строк.
- **Файлы:** `aiRender.*`, `aiVoxelRender.*`, `aiVision.cpp`.

**14. Физический коллайдер обломков и рэгдолла**
- **Задача:** столкновения движущихся сфер с точной геометрией.
- **Как работает:** на запрос собирается временный «суп треугольников» в иерархической сетке (до 6 уровней, ячейка 2·max(R, |v|)). Тесты: движущаяся сфера–треугольник, отрезок–треугольник через координаты Плюккера, статическая сфера–треугольник. Скольжение — до 9 итераций: дойти до контакта, спроецировать остаток скорости, трение 0.4 от нормальной составляющей; на пологом террейне полная остановка. Стекло при контакте разбивается и пропускает.
- **Данные:** 11.
- **Связи:** обломки, гранаты, рэгдолл.
- **От хоста:** можно заменить физикой движка.
- **Оценка:** стандартное. ~900 строк.
- **Файлы:** `phCollider.*`, `SuperCollider.*`, `VolumeContainer.*`.

**15. Сторож устойчивости**
- **Задача:** ронять объекты, трупы, обломки и мины, когда исчезла опора.
- **Как работает:** графа опор нет. При регистрации объект запоминает оболочки-«ловцы», пересекающие его bound. Трекеры в сетке (до 16×16×8 ячеек) ловят изменения; если ловец пропал — объект перепроверяется. Объект устойчив, если опоры касается больше половины масс-сфер (все, если их меньше 4). Труп падает, обломок будится, мина без опоры взрывается.
- **Данные:** масс-сферы моделей.
- **Связи:** 11, разрушаемость.
- **От хоста:** события геометрии.
- **Оценка:** простое, но характерное. ~500 строк.
- **Файлы:** `aiStability.*`.

## C. Восприятие

**16. Планировщик задач ИИ с бюджетом времени**
- **Задача:** размазывать тяжёлые расчёты по кадрам.
- **Как работает:** бюджет 10 мс на сегмент мира минус накопленный перерасход (до 0.2 с). Задачи обходятся по кругу, по одному кванту; есть зависимости «ждать задачу» и высокий приоритет (пересчёт сетки), блокирующий остальных и выдачу команд.
- **Данные / связи:** обслуживает 4 и 20.
- **От хоста:** таймер.
- **Оценка:** стандартное, 230 строк, автономно.
- **Файлы:** `aiJob.*`.

**17. Воксельное зрение**
- **Задача:** кто кого видит, с учётом травы, стёкол и ночи.
- **Как работает:**
  - Воксель = четверть тайла; кубы 32³ с битами «твёрдо» и «прозрачно», считаются лениво и пересчитываются при изменении геометрии.
  - Дальность 20 м, поле зрения 180°; ночью множитель 0.666.
  - Проверка — 9 лучей (центр ± 0.2), нужно больше 3 прошедших. Луч идёт 3D-Брезенхемом, твёрдое обрывает, прозрачное тратит бюджет.
  - У цели 2–3 контрольные точки по позе. Результаты кэшируются (до 30000 записей).
  - Спрятанный враг раскрывается броском: 45 − (44/30)·дистанция в тайлах + Spot − Stealth.
  - Зрение игрока — объединение по юнитам плюс постоянная память трупов и объектов; тайловой карты тумана нет.
- **Данные:** 11, 13, навыки и перки.

**18. Слух и память угроз**
- **Задача:** превращать звуки и косвенные признаки в знание ИИ.
- **Как работает:**
  - Звук имеет радиус (по типу тайла, × глушитель). Громкий слышен детерминированно в радиусе, зависящем от Spot. Тихий — броском (база + Spot − Stealth + дистанционный член, потолок 95).
  - У юнита три набора: видимые враги, «возможные» враги, союзники, звавшие на помощь, плюс известные трупы. Затухания и числовой угрозы нет.
  - «Возможного» врага порождают: пуля ближе 2.5 м, граната (метатель ближе 30 м), союзник в 5 м увидел врага, увиденный труп (его убийца).
  - Цель — лучший шанс попадания среди врагов в пределах 1.5 м от ближайшего.
  - Испуг: HP < 50 % или врагов больше 2, и нет своих ближе 9 м.
- **Данные:** звуковые константы из БД (значения в коде не заданы).
- **Связи:** 17 → 20, 21.
- **От хоста:** шина игровых событий.
- **Оценка:** стандартное. ~900 строк.
- **Файлы:** `aiThreatTracker.cpp`, `aiUnitState.cpp`, `aiEvent.cpp`, `RPGUnitMission.cpp`.

**19. Укрытие как доля пробивающих лучей**
- **Задача:** оценить, насколько цель доступна огню из точки.
- **Как работает:** из дульной точки на корпус цели строится проективная сетка лучей (полуразмер 8 для ИИ, 20 для игрока; окно ±1 м). Луч относится к одному из классов: упёрся рядом / мимо / дошёл. По интервалам п. 12 пробивная способность уменьшается на толщину × плотность. Для ИИ итог = 100 × доля пробивших × средний остаток пробития. Те же лучи дают список объектов и союзников под огнём. Замечено: если попавшие лучи есть, но ни один не пробил, получается 0/0.
- **Данные:** 12, 13, броня и материалы.

## D. Тактика

**20. Командир и боевая логика на списке приоритетов**
- **Задача:** выбрать действие юнита за ход.
- **Как работает:**
  - Командир думает каждый 3-й сегмент, выдаёт не более одной команды за сегмент; думает один юнит за раз. Следующий юнит — ближайший к предыдущему.
  - Защиты: лимит 5000 команд; антицикл (15 повторов → 25 % отмены, 31 → стоп).
  - Логика думает квантами: синхронизация → источники мест → выбор места для каждого действия → решение.
  - Места атаки: свой тайл, тайлы вдоль пути к врагу в бюджете 14 AP, фланговые в пределах 8 AP (±10° от перпендикуляра). Позы — стоя и присед; места, откуда выстрел заденет своих, отбрасываются.
  - Сравнение мест: шанс попадания до порога 20 (5 в панцеркляйне), дальше остаток AP. Собственное укрытие не учитывается.
  - Решение — нечёткие правила, фактически булевы, то есть строгий порядок: панцеркляйн, станковое оружие, снайпинг, ракета, граната, выстрел, нож, перезарядка, лут, рукопашная, сближение.
  - Оружие и режим огня: максимум Σ(шанс × средний урон) по пулям, которые успеваются за AP.
  - Группы врагов (кластер 1.5 м) используются для гранат и ракет. Фокусировки огня и формаций в бою нет.
- **Данные:** правила (AP, шанс попадания), 6, 17–19; параметры сложности (`nHideProbability`, `nAssassinProbability`, `bAICheckCorpses`).
- **Связи:** 21, 22.
- **От хоста:** ничего; нужен слой правил игры.
- **Оценка:** архитектура стандартная, наполнение специфично. ~7000 строк, сильно связано с RPG-правилами.
- **Файлы:** `aiCommander.cpp`, `aiCombatLogic.cpp`, `aiActions.cpp`, `aiActionPlaceSource.cpp`, `aiWeapon.cpp`.

**21. Реакции — автомат режимов поведения**
- **Задача:** переключать юнита между боем, охраной, бегством, засадой.
- **Как работает:** у юнита одна реакция; её `Update` вызывается при изменении состояния (FIFO, одна за сегмент) и ставит логику либо заменяет саму себя.
  - **Normal:** испуг → 40 % тревога, иначе отступление; далее проверка подозреваемого, атака, помощь союзнику, действия после боя.
  - **Guard:** зона вокруг поста по AP-радиусу.
  - **Defence** (пистолет/ПП): танец «укрытие ↔ огневая точка»; укрытие — клетка в 18 AP, которую враг не видит.
  - **Assassin:** спрятаться и ползти в точку, где шанс быть услышанным < 15.
  - **Fear, Script.**
  - Тревога: добежать до союзника и передать врага всем своим в 5 м.
- **Данные:** `eLogic` юнита на карте.
- **Связи:** 18, 20, 22.
- **От хоста:** скриптовый движок.
- **Оценка:** стандартный FSM. ~1700 строк.
- **Файлы:** `aiReactions.cpp`, `aiGuardReaction.cpp`, `aiDefenceReaction.cpp`, `aiAssassinReaction.cpp`, `aiFearReaction.cpp`.

**22. Маршруты, вейпоинты, task-команды, журнал плана**
- **Задача:** патрули, скриптовые перемещения и исполнение планов.
- **Как работает:**
  - Вейпоинт — именованная точка с командами POSE / WAIT / DIR. Маршрут разворачивается в шаги (Goto, поза, направление, ожидание) и крутится по кругу; пинг-понга нет.
  - Бой ставит маршрут на паузу с откатом к последнему Goto.
  - Группы: клетки строя вокруг центра (≤ 2 м) и барьер Sync на каждом вейпоинте.
  - Готовые фабрики: осмотр, блуждание, проверка позиции, обход с фланга (точка у 1/3 пути, остановка перед дверью или лестницей).
  - `CAILog` — не текстовый лог, а журнал записей плана с Commit / RollBack над копией юнита, разворачиваемый в команды мира.
  - Lua задаёт логику юнита, маршруты, телепорт и хук `OnUnitNeedCommand`.
- **Данные:** вейпоинты и маршруты из редактора, Lua.
- **Связи:** 6, 20, 21.
- **От хоста:** скрипты, очередь команд юнита.
- **Оценка:** стандартное. ~3500 строк.
- **Файлы:** `aiRouteLogic.cpp`, `aiRouteMisc.cpp`, `aiTaskCommand.cpp`, `aiWaypoint.*`, `AILog.*`.

**Мелочи вне каталога:**
- `PolyUtils` — 2D булевы операции над полигонами с дырками (привязка к сетке 1/4096); используется для дыр в террейне.
- `aiHeight` — локальная карта высот вокруг юнита с билинейной выборкой.
- `DiscretePos` — дискретная постановка объектов (поворот кратно 90° + отражение), к путям не относится.
- Отладка скудная: `GetNetworkFragment` (узлы и связи 16×16 вокруг точки), консольные дампы, `OutputDebugString`. Экранных отладочных видов ИИ нет.
