# Каталог технических решений Silent Storm: правила игры и структура кампании

Основа — `Main/RPG*`, `sc*`, `iChapterMap*`, `iGlobalMap*`, `rpgGlobal*` и записи `DBFormat`. Боевую часть я читал сам; сценарий, карты, магазин, медали, дипломатию и подсказки разбирал вспомогательный агент, его выводы я не перепроверял. ## A. Персонаж

**1. Навыки с модификаторами (`CDynamicSkill`)**
- **Задача:** единое представление 17 параметров персонажа.
- **Как работает:** значение = база от статов + часть от опыта, затем `×Πmul + Σadd` по списку живых модификаторов. Модификатор — объект, чьё время жизни равно времени эффекта (ранение, перк, панцеркляйн). Базы: VP = 10·(STR+5); AP = 36+2·DEX; стрельба = 20+DEX; ближний бой = STR+2·DEX; метание и очереди = 2·STR+DEX; снайпер = 2·DEX+INT; скрытность = 5+2·DEX; наблюдательность = 5+2·INT; медицина и инженерия = DEX+2·INT; уклонение (IC) = 5; перехват = 25.
- **Данные:** `RPGBaseValues` (статы, стартовый опыт), `RPGClasses.skills` (потолки по классу).
- **Связи:** всё остальное в разделах A–D.
- **От движка:** ничего.
- **Оценка:** стандарт жанра, реализация аккуратная; ~400 строк, автономно.
- **Файлы:** `RPGUnit.h/.cpp`, `DataRPG.h`.

**2. Рост: опыт, уровень, обучение использованием**
- **Задача:** прокачка без ручного распределения очков.
- **Как работает:** потолок навыка = `ln(1+0,02·XP)·cap/(20·0,4762)`; уровень считается той же функцией с классовым cap. Каждое применение навыка добавляет `clamp(остаток·k/rate[skill]; 1e-5; 0,1)` и заодно качает связанный стат (STR, DEX или INT). Получаемый опыт умножается на `1+0,05·INT`. Опыт за врага = `(XP(L+1)−XP(L))/участников(1..6)/8,1`. ИИ-юнитам уровень задаётся напрямую (`SetXPLevel`).
- **Данные:** `RPGBaseValues` запись 63 (скорости обучения), `RPGClasses`.
- **Связи:** 1, 3, 21.
- **От движка:** ничего.
- **Оценка:** отличительное сочетание «потолок от опыта + рост от использования»; ~150 строк.
- **Файлы:** `RPGUnit.cpp`.

**3. Дерево перков**
- **Задача:** классовые способности.
- **Как работает:** ориентированный граф; узел = перк и до 3 родителей, взять можно при всех взятых родителях. Одно очко за уровень. У перка 3 float-параметра. Эффекты не описаны данными: код в ~90 местах спрашивает `HasPerk(id, &p1, &p2, &p3)` по числовому id. ИИ берёт случайные доступные перки.
- **Данные:** `Perks`, `PerkTreeNodes`, `RPGClasses.nPerkTreeID`.
- **Связи:** почти все формулы ниже.
- **От движка:** ничего.
- **Оценка:** структура стандартная, эффекты жёстко в коде; ~300 строк плюс вкрапления повсюду.
- **Файлы:** `rpgPerk.cpp`, `rpgPerkConstants.h`, `DataPerk.h`.

**4. Стоимость действий в ОД**
- **Задача:** цена каждого действия.
- **Как работает:** один `switch`.
  - Шаг: `(RUN−поза+1)·2`, диагональ ×1,5, перенос тела ×1,5 и ×2,25.
  - Смена позы 4 за ступень; поворот 2 (лёжа 4); прятаться 14; прыжок 10; лазание 10/12/14/15; дверь 4; ловушка и разминирование 30.
  - Вход в панцеркляйн 10, выход 6.
  - Выстрел = `nShotAP` (+`nTargetingAP` для прицельного и тщательного).
  - Очередь = `maxAP/nRoF` (похоже, за пулю — не подтверждено).
  - Удар = `maxAP−(maxAP−minAP)·skill/140`.
  - Лечение, мина, отмычка — из записи предмета.
- **Данные:** `RPGAP` (id 5, 9–13), `RPGWeapons`, `RPGWeaponTypes.nPrepareCost`, перки-скидки.
- **Связи:** 1, 3, 12.
- **От движка:** ничего.
- **Оценка:** стандарт; ~150 строк; наполовину в коде.
- **Файлы:** `RPGUnitMission.cpp` (`GetActionAP`), `RPGUnit.cpp`.

## B. Стрельба и урон

**5. Сетка лучей укрытия (`CCoverInfo`)**
- **Задача:** оценить видимую и пробиваемую долю цели, заготовить траектории.
- **Как работает:** из дула строится проективная сетка лучей: подробная (полусторона 20) в окне 2×2 вокруг цели и грубая (полусторона 5) шире, до конуса tan(π/8). ИИ использует одну сетку с полустороной 8. Каждый луч несёт отсортированный список пересечений. Классы лучей: `obst` (помеха ближе минимальной дистанции), `loose` (мимо цели), `hit`. Для `hit` запас пробития `nK` уменьшается на толщину×плотность преград; союзник на пути отменяет луч. Укрытие % = доля пробивающих `hit`-лучей × средний остаток `nK` / исходный.
- **Данные:** `RPGArmors` → `RPGMaterials.fDensity`, флаги трассировки.
- **Связи:** 6, 7, 8, ИИ.
- **От движка:** пакетная трассировка сетки лучей с упорядоченными интервалами вход/выход и материалом; у объектов — метки частей тела.
- **Оценка:** отличительное, ядро боя; ~500 строк; зависит от трассировщика.
- **Файлы:** `RPGGame.cpp`, `RPGCover.h`, `RPGBullet.cpp`.

**6. Вероятность попадания**
- **Задача:** процент для интерфейса и броска.
- **Как работает:** иерархия калькуляторов (юнит, тайл, граната, нож, ракета, ИИ).
  - `Add` = D2 + поза + пристрелка (`2·min(повторы, max)`) + качество + привыкание к оружию + `nTargetingAP` (прицельный/тщательный) + `1,5·доп.ОД` (тщательный/снайперский) + штраф за свой ход − боковое смещение цели.
  - `D1 = skill·(max−min)/140+min`; `D2 = clamp(100·cos³(dist/D1)+2; 2; 100)`, ноль за 2·D1.
  - `ToHit = Add·свет·коэф.первого хода·CA − IC цели/fICModifier ± ауры − 5 (погода)`, итог 2..100. Свет = `0,5·(1+|освещ|/√3)`, ночью ×0,9.
  - `CA = ((100−k)·укрытие·площадь + k)/100`, `k = (s+1)·100/(dist+s)`, s = 20 (оптика 100): вблизи укрытие почти не влияет.
  - Площадь цели — перекрытие 1–3 кругов R = 0,25 по позе; голова ×0,2.
  - Навык × штраф здоровья (1/0,9/0,75/0,5). Пуля n очереди: `max(skill·(burst/140)^n; стабилизация)·отдача/100`.
  - Ближний бой: `(0,5·Δнавыков+бонус+70)·доступные зоны·здоровье`, в спину ×1,5.
- **Данные:** `RPGToHit` (≈30 констант), `RPGWeapons`, `RPGWeaponTypes` (бонусы поз, штраф движения), сложность.
- **Связи:** 1, 3, 5, 7.
- **От движка:** освещённость (сейчас заглушка 1,1,1), флаги ночи и погоды.
- **Оценка:** отличительная формула; ~1000 строк; чистая логика.
- **Файлы:** `RPGToHit.cpp`, `RPGUnitMission.cpp`.

**7. Бросок и выбор луча (разброс)**
- **Задача:** превратить процент в физическую траекторию.
- **Как работает:** бросок 0..100, отличающийся от предыдущего минимум на 6; `fHit = ToHit/бросок`. При `fHit ≥ 1` рулетка по пробивающим `hit`-лучам с весом cos² к центру цели. Иначе `loose`-лучи сортируются по отклонению, вес = `(fHit − |n/N − fHit|·dev)²`: чем ближе к успеху, тем ближе промах. Пуля-промах трассируется честно, по пути для каждого юнита заново считается шанс. Для очереди `nRoF/6` пуль, шанс считается на каждую.
- **Данные:** нет.
- **Связи:** 5, 6, 8.
- **От движка:** генератор случайных чисел, трассировка.
- **Оценка:** отличительное; ~200 строк.
- **Файлы:** `RPGGame.cpp` (`RealPeekRay`, `CheckToHit`), `RPGBullet.cpp`.

**8. Порция атаки и пробитие материалов**
- **Задача:** единая модель урона по людям, объектам и стенам.
- **Как работает:** `CAttackPortion` = `{nK, тип урона, min/max, шанс и тяжесть крита, шанс оглушения, флаги}`. Пуля: `nK = нач.скорость·fUnitWeight`; урон = `ammo.nDmgMin·DamageMod(Max)/100`. Таблица `[тип урона][класс DR материала]`: >0 повреждает, 0 останавливает, <0 пролетает насквозь. После тела `nK −= толщина·плотность`, при ≤0 стоп. Урон = `rand(min,max)+min(nK/10−порог, 0)`, × коэффициенты, по телу × множитель сложности. Рикошет — по углу и вероятности материала.
- **Данные:** `RPGDmgToArmor` (12 классов), `RPGMaterials`, `RPGAmmo`, `RPGArmors`.
- **Связи:** 5, 9, 10, 11, 13.
- **От движка:** материал на каждом коллайдере, интервалы пересечения.
- **Оценка:** отличительное, компактное; ~400 строк.
- **Файлы:** `RPGAttackMech.cpp`, `RPGBullet.cpp`, `RPGItemSet.cpp`.

**9. Урон по человеку, потеря сознания, смерть**
- **Задача:** последствия попадания.
- **Как работает:** множитель зоны: голова 1,5; тело 1; рука 0,7; нога 0,85; плюс бонус крита. Проверка IC: с шансом IC% урон снижается на IC%. «Перевязанные» VP — отдельный пул, поглощает урон пропорционально и считается за половину в штрафах. Оглушение: `база·clamp((0,5−здоровье)·2,5; 0; 1)`. Смерть при `VP ≤ −коэф.сложности·maxVP`, между 0 и порогом юнит без сознания. Падение: 3 броска `rand(0; (h−2,8)·50/4)`.
- **Данные:** `Difficulty`, `RPGAmmo.nUnconsciousProbability`.
- **Связи:** 8, 10, 14, 21.
- **От движка:** зона попадания от коллайдера.
- **Оценка:** запас отрицательных VP и пул перевязки отличительны; ~200 строк.
- **Файлы:** `RPGUnitMission.cpp` (`ProcessAttack`).

**10. Критические ранения**
- **Задача:** долговременные эффекты ран.
- **Как работает:** шанс = `10·(попаданий по цели за ход+1) + 0,4·снайпер`. Тяжесть = `снайпер/4 + Σ(уровень × d20)`, потолок 300 (меняется скриптом). По зоне (голова, торс, руки, ноги) строится шкала: записи сортируются по `nWeight`, занимают отрезки `nRange`; тяжесть — индекс в шкале. Бонус урона = `тяжесть/300 × (голова 2; торс 1,5; руки 0,5)`. 15 типов, включая смерть, слепоту, глухоту, кровотечение, потерю оружия, случайный выстрел. Одинаковые сливаются по максимуму; лекарство может приостановить на N ходов. Кровотечение за ход = `value + 0,1·(maxVP/2−VP)`. Общий штраф ран (ОД, перехват, боевые навыки ×0,95…0,5) на порогах 75/50/25 % здоровья.
- **Данные:** `RPGCriticals`.
- **Связи:** 1, 9, 14, 12.
- **От движка:** ничего (эффекты «уронил оружие» исполняет мир).
- **Оценка:** шкала тяжести отличительна; ~900 строк; автономно.
- **Файлы:** `RPGCritical.cpp`, `RPGAllCriticals.h`, `RPGUnitMission.cpp`.

**11. Разрушаемые объекты и здания**
- **Задача:** урон по неживому.
- **Как работает:** объект: VP из модели, N стадий, стадия = доля потерянных VP; у каждой стадии своя броня, избыточный урон переходит на следующую. Здание: id коллайдера декодируется в координаты куска, вызывается `DamageSpot(кусок, урон)`. Обрушение — вне моей области.
- **Данные:** `Objects` (модели стадий), `RPGMaterials.nVP/nThreshold`.
- **Связи:** 8, 13.
- **От движка:** система разрушаемой сетки здания.
- **Оценка:** обёртка тонкая (~150 строк), ценность в самой системе разрушения.
- **Файлы:** `RPGObject.cpp`, `RPGBuilding.cpp`.

**12. Панцеркляйны**
- **Задача:** силовая броня как оболочка поверх пилота.
- **Как работает:** отдельные VP и броня. Рикошет с шансом `nRicochetProb`. С шансом `(1−critResist)·крит` урон проходит к пилоту ослабленным. Иначе страдает корпус, `nK −= 1590`, остаток идёт в человека. При 0 VP — статус «сломан». Навыки пилота смещаются таблицей `pChangeValues`, шаг дороже на `nAddMoveAP`, ближний бой `nK` = 1600. 10 флагов разрешённых типов оружия, регенерация, множитель слуха. Слоты рук переезжают между инвентарями.
- **Данные:** `Panzerkleins`.
- **Связи:** 1, 4, 8, 15.
- **От движка:** смена модели и анимаций.
- **Оценка:** отличительное; ~250 строк, размазано.
- **Файлы:** `RPGUnitMission.cpp`, `RPGInventory.cpp`, `DataRPG.h`.

**13. Гранаты, взрывы, метание**
- **Задача:** оружие по площади.
- **Как работает:** скорость броска = `(база+(STR+skill/18)·coefSTR)·вес^0,74/(вес/1000)`, дальность = v²/g. Взрыв — `nWaveNumber` волн по воксельному объёму; урон min..max × коэффициент объёма; по конструкциям × `(волны−текущая+1)·fStructureDamageCoeff`. Инженерные заряды масштабируются разницей навыка и требования. Брошенный нож застревает или отскакивает по классу DR.
- **Данные:** `RPGGrenades`, `RPGEngGrenades`, `RPGToHit`.
- **Связи:** 8, 11, 17.
- **От движка:** баллистика тела, воксельная заливка объёма.
- **Оценка:** волновой взрыв отличителен. Осколки не читал — не подтверждено.
- **Файлы:** `RPGToHit.cpp`, `wExplTracker.cpp`, `RPGBullet.cpp`.

**14. Медицина**
- **Задача:** лечение в бою и между миссиями.
- **Как работает:** аптечка — заряды с эффектом (обычный, только криты, снять штрафы, стимулятор, остановить кровь, ремонт панцеркляйна). Потолок лечения = `250/140·skill` «перевязанных» VP; ОД = `VP/skill·60`. Лечатся криты с `DC ≤ 300/140·skill`. Стимуляторы: при Σ(1/длительность) > 1 — передозировка и потеря сознания. После миссии и на отдыхе пул = `skill·coef·1,786`, навык = лучший медик + `coef·среднее остальных`.
- **Данные:** `RPGFirstAids`, `Difficulty`.
- **Связи:** 9, 10, 21.
- **От движка:** ничего.
- **Оценка:** отличительно (два пула VP); ~250 строк.
- **Файлы:** `RPGUnit.cpp`, `RPGUnitMission.cpp`, `rpgGlobal.cpp`.

## C. Восприятие и ход

**15. Воксельная видимость**
- **Задача:** кто кого видит.
- **Как работает:** мир разбит на кубы 32³ вокселей (шаг = тайл/4), сетка 32×32×4. В каждом — битовые маски «непрозрачно» и «полупрозрачно»; трава добавляет 6 полупрозрачных вокселей. Куб пересчитывается лениво при изменении геометрии. Линия — 3D-Брезенхем; полупрозрачность расходует бюджет `−186·ln(dist/range)`. Юнит = 1–3 куба по позе; куб виден, если видны ≥4 из 9 точек. Дальность 30/27/25 тайлов (стоя/сидя/лёжа), растёт с перепадом высоты, сектор 180°. Кэш на 30 000 запросов.
- **Данные:** почти всё в коде; множитель видимости задаётся скриптом.
- **Связи:** 6 (удар в спину), 16, 19, ИИ.
- **От движка:** воксельная растеризация коллизий с флагом прозрачности и уведомления об изменениях.
- **Оценка:** отличительное; ~650 строк; автономно.
- **Файлы:** `RPGVision.cpp`, `RPGGame.cpp`.

**16. Слух и скрытность**
- **Задача:** обнаружение без видимости.
- **Как работает:** громкий звук слышен детерминированно в радиусе `R0+(R−R0)·spot/140`. Тихий — с шансом `base+(spot+(R0−dist)·k−stealth)·100/140`, не выше 95; скрытность источника множит на `fHideCoeff`. Раскрытие спрятавшегося: `45−1,47·dist+spot−stealth`. У ИИ собственный шанс прятаться из сложности.
- **Данные:** `RPGAISoundConstants`, `AISounds`, `RPGWeapons.fSilencer`.
- **Связи:** 15, ИИ.
- **От движка:** события звука с позицией.
- **Оценка:** стандарт; ~100 строк. Кто и когда вызывает проверку раскрытия — не подтверждено.
- **Файлы:** `RPGUnitMission.cpp`.

**17. Перехват хода**
- **Задача:** реакция в чужой ход.
- **Как работает:** `P = база(взаимная видимость / со спины / после промаха) + Δнавыков перехвата − fAPReduction·(maxAP−AP)`, 5..95; ноль при `AP ≤ nMinInterruptAP`. Возвращается запас `P − бросок`, стороны сравниваются.
- **Данные:** `RPGInterruptsConstants`.
- **Связи:** стек ходов (заметка 11), 15.
- **От движка:** ничего.
- **Оценка:** стандарт (как в Jagged Alliance 2); ~40 строк.
- **Файлы:** `RPGUnitMission.cpp`.

## D. Предметы

**18. Инвентарь, обоймы, магазин, сундуки**
- **Задача:** хранение и оборот предметов.
- **Как работает:** рюкзак — сетка 7×13 с размещением «первое подходящее»; автоукладка сортирует по `max(w,h)+w·h`. Два слота рук, один активный. Обойма = контейнер патронов; совместимость по `nAmmoGroup`, тип патрона — «цвет»; перезарядка доливает из нескольких обойм. Аптечки, инструменты, отмычки — контейнеры зарядов. Магазин: 8 сеток 10×13; ассортимент по стороне и `nRating ≤ уровень` (макс. сложность открытых зон), количество растёт с уровнем. Сундук: шаблон → взвешенный выбор варианта по уровню и флагам → список предмет×количество с фильтром сложности.
