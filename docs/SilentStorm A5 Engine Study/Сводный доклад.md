# Движок Silent Storm (A5): сводный доклад

Пути без префикса — относительно `Soft/Andy/Jan03/a5dll/`.

## Главное

- Монолитный игровой движок: почти весь код (рендер, ИИ, мир, RPG, UI) — одна DLL `Main`; границы «движок/игра» нет.
- Самое необычное — **dataflow-ядро** `Main/DG.H`: ленивые версионируемые узлы-функции, на которых построены сцена, свет, анимация, частицы, звук.
- Разрушаемость — не физика, а **инженерный расчёт**: решётка прочности узлов + граф «стержни–узлы» с устойчивостью и изгибающими моментами.
- Весь контент, включая карты, живёт в **SQL-базе** (130 таблиц); ресурсы — файлы с именем = числовой id записи.
- Единая сериализация `CStructureSaver` обслуживает ассеты, `game.db`, паки и сохранения (включая состояние Lua).
- Стартовая карта неточна: код использует **Direct3D 9 API** (шейдеры DX8-класса), решение — формата VS .NET 2002 (7.00), а `OpenDynamix` — это сторонний ODE, который игрой не вызывается.

## 1. Архитектура

- `Game/Main.cpp` (`WinMain`): ресурсы → `NDatabase::Serialize(game.db)` → `NGfx::Init3D`, `NSound::InitSound`, `NInput::InitInput` → `cfg\autoexec.cfg` → цикл `PumpMessages` + `NMainLoop::StepApp`.
- Стек интерфейсов и очередь команд (`CICLoad`, `CICSave`…) — `Main/iMain.cpp`; миссия `IMission` со стейт-машиной `IState` — `Main/iMission.h`, `Main/iGameStates.h`.
- Мир тикает фиксированными сегментами по 50 мс: `CWorld::UpdateWorld` → `Segment()` — `Main/wMain.cpp`.
- Объектная модель: `CObjectBase` с двумя счётчиками, `CPtr` (слабая ссылка) и `CObj` (владение), `IsValid()` — `Misc/Basic2.h`.
- Консоль, переменные, конфиги — `MiscDll/Commands.cpp` (`NGlobal`); шина событий — `Misc/EventsBase.h`.
- Dataflow: `CVersioningBase` (`NeedUpdate/Recalc/Updated`), `CFuncBase<T>`, `CDGPtr<T>::Refresh()`, пересчёт не чаще раза за кадр (`MarkNewDGFrame`) — `Main/DG.H`.

## 2. Сцена и рендер

- Сцена `CGScene` — свободное октодерево `CVolumeNode` с корзинами по материалам; `Main/GSceneInternal.cpp`, `Main/OcTree.h`. Порталов нет; отсечение — программный иерархический Z-буфер `CHZBuffer` (`Main/GShadowVolume.cpp`).
- Батчинг: части сливаются в общие буферы (`Main/GCombiner.h`); рендер — список операций `CRenderCmdList` (~90 `ERenderOperation`), сортируемый по проходу/цели/состоянию (`Main/GRenderExecute.cpp`).
- Шейдеры: макроассемблер `Main/GfxShaders.txt` (vs.1.1, ps.1.1/1.4 + блоки RS/TSS как fixed-function fallback) → `ShaderCompiler/ShaderCompiler.cpp` → байт-код в `GfxShaders.cpp`. Пути по железу — `ERenderPath` (`Main/GRenderModes.h`).
- Свет (`Main/GRenderLight.cpp`): солнце — shadow map; точечные — стенсильные теневые объёмы; лайтмапы считаются на GPU инкрементально (`Main/GLightmapCalc.cpp`); динамике — ambient-куб по 6 осям.
- LOD геометрии не найден (только LOD лайтмапов, `Main/GGeometry.h`).
- Частицы — запечённые ключи из Maya (`Main/GParticleFormat.h`, `Main/GParticles.h`); декали — клиппинг треугольников цели (`Main/GDecalGeometry.cpp`).

## 3. Разрушаемость и физика

- Здание = 3D-решётка байтов прочности `CBuildingGrid::net` (4 слоя на этаж) — `Main/BuildingGrid.h`; видимые куски стен прячутся, когда их узел разрушен (`Main/MakeBuilding.cpp`, `Main/wBuilding.cpp`).
- Урон: `DamageSpot`, `Explode` (затухание ~1/d²) — `Main/BuildingGrid.cpp`; взрывная волна гранат идёт по вокселям 0,2 м — `Main/wExplTracker.cpp` (её связь с узлами зданий не подтверждена).
- Обрушение: `CBuildingSchema::Recalc` = `ComputeStability` (опора снизу вверх) → `FindFree` (висящие группы) → `ComputeMoments` (нагрузка и момент против пределов материала) — `Main/BuildingSchema.cpp`, `Main/rod.h`, `Main/RodJunction.h`.
- Обломки и гранаты — собственное твёрдое тело из сфер `CASphereSet`; рэгдолл — Verlet-частицы и палки `CParticleSkeleton` — `Main/GAnimParticles.h`, `Main/wDebris.cpp`.
- `OpenDynamix/` — ODE Рассела Смита (LGPL, `OpenDynamix/step.cpp`); вызовов из `Main` нет.
- Баллистика: прямой луч без гравитации, пробитие = мощность минус толщина×плотность — `Main/RPGGame.cpp` (`ProcessRangedAttackPortion`), трассировка `Main/aiTrace.h`.

## 4. Анимация

- Скелет `SBone`, клип `CFileAnimationInfo` — `Main/GAnimFormat.h`; поза — `Main/GSkeleton.h`.
- Блендинг — дерево узлов `CAnimator` произвольной глубины: `CASequence`, `CAInterpolator`, `CAAdder` (аддитив), `CAIK2Chain`, `CASmartAimer` — `Main/GAnimation.h`; корень — dataflow-узел `CSkeletonAnimator`.
- Скиннинг на CPU, до 4 весов, есть MMX-путь — `Main/GCombiner.cpp`.
- Экспорт: транслятор Maya `A5ExportModel/A5ExportModel.cpp` (mesh, skin, ai_mesh, skeleton, animation, particles, light) пишет чанковые файлы с именем-id.
- Лица: `LSConverter/LSConverter.cpp` конвертирует головы LifeStudio (GDP); в игре `CHeadAnimator` вызывает закрытый LifeStudioHeadAPI — `Main/LSHead.cpp`. Липсинк по звуку не подтверждён.

## 5. ИИ

- AI-геометрия: выпуклые куски с BSP-деревьями, отдельные деревья для стадий разрушения и дверей — `Main/aiObject.h`, `Main/BSPtree.h`.
- Путь: Дейкстра с корзинами (не A*) по состояниям «тайл, слой, направление, поза» — `Main/aiWaveSearch.h`, `Main/aiPosition.h`; до 8 этажей (`Main/aiGrid.h`); иерархия через зоны — `Main/aiPath.cpp`.
- Вейпоинты — скриптуемые патрульные точки (`Main/aiWaypoint.h`).
- Тактика — жёсткие приоритеты: `CAILogicAttack::MakeDecision` (перезарядка → ракета → граната → выстрел → сближение), выбор позиции по укрытию — `Main/aiCompoundAction.cpp`, `Main/aiTacticalCommander.cpp`.
- Пошаговость: `CTBSWorld` со стеком перехватов, без перехватов — реальное время — `Main/wTurnBased.h`; шанс перехвата — `Main/RPGUnitMission.cpp`.
- Зрение: 20 м, ≥4 из 9 лучей — `Main/RPGVision.cpp`.

## 6. Данные и контент

- База — единственный источник истины: 130 таблиц (`REGISTER_DATABASE_CLASS`), маппинг ручной (`Import()` + `ImportField`) — `DBFormat/DataFormat.cpp`, `ADOImport/BasicDB.h`.
- `DataImport/DataImport.cpp`: SQL → `game.db` (дамп всех таблиц через `CStructureSaver`); `ADOFake/BasicDBfake.cpp` — заглушка без ADO.
- Ресурс = `Complete/<Тип>/<id>`; сначала ищется в `<Тип>.res` — `Main/GResource.cpp`. Пак: сигнатура + файлы + таблица id→смещение — `FileIO/FilesPackage.cpp`. Сигнатура готовых `.res` в `Complete/` с кодом не совпадает — совместимость не подтверждена.
- Текстуры: `TexConv/main.cpp` (MMP/DDS, DXT), `TexMipStrip/`.
- Сериализация: `operator&(CStructureSaver&)` c чанками и отслеживанием указателей — `FileIO/BasicChunk1.h`; тела генерирует макрос IDE `Soft/serialize.dsm` по маркерам `ZDATA/ZEND`.
- Сохранение — полный граф объектов: `game.sav` + `<зона>.sav` — `Main/iMain.cpp`, `Main/iSaveManager.cpp`.

## 7. Скрипты

- Lua 4.0 с потоками и сериализуемым состоянием — `Script/Script.cpp`, `Script/lsaver.cpp`.
- Привязки (~юниты, группы, камера, диалоги, сценарий, UI) — `Main/ScriptFunctions.cpp`, `Main/script*.cpp`.
- На Lua: триггеры миссий, катсцены, сценарные события (`Complete/Scripts/TriggersManager.l`); обратные вызовы `OnOpenObject`, `OnTalk`.
- В C++: ИИ, бой, RPG-правила, UI, разрушаемость.

## 8. Редактор карт

- MFC MDI + Stingray Toolkit + Scintilla — `MapEdit/StdAfx.h`.
- Умеет: рельеф, конструктор зданий (стены, полы, комнаты, подвалы), объекты, юниты, маршруты, Lua, сценарии, UI — `MapEdit/WallsLayer*`, `MapEdit/Wysiwyg*`.
- Встраивает тот же рендер и цикл интерфейсов: `MapEdit/GameView.cpp`, `MapEdit/iMapEditor.cpp`, ветки `#ifdef _MAPEDIT`. Как именно линкуется `Main` — не подтверждено.
- Карта — записи в БД; редактор пишет в SQL напрямую (`MapEdit/db.cpp`) и запускает Maya в batch-режиме для экспорта (`MapEdit/Export.cpp`), генерирует AI-BSP (`MapEdit/ExportGeometry.cpp`).

## 9. Инфраструктура

- Память: подмена `operator new`, 16 пулов степеней двойки в зарезервированных 512 МБ — `MemoryMngrDll/FastPow2Alloc.cpp`.
- Файлы: потоки `CDataStream` — `FileIO/`.
- Ввод: DirectInput8 с именованными биндами — `Input/Bind.h`.
- Звук: обёртка FMOD 3 — `FModSound/FMSound.cpp`, сцена — `Main/Sound.cpp`. Заглушки нет: SDK FMOD отсутствует, есть только `bin/fmod.dll`.
- Bink в исходниках не упоминается вовсе.

## 10. Состояние

- Все 1457 файлов из `.vcproj` на месте, но сборка «как есть» невозможна: нет DirectX 9 SDK, FMOD SDK, LifeStudioHeadAPI, s3tc, Maya SDK; пути `W:\`, `C:\AW\` зашиты.
- В репозитории есть STLport 4.5.2 (`Soft/SDK/stlport`), Lua, zlib, libpng, Scintilla.
- `Soft/Andy/Oct02/src` — только `Main` (~146 тыс. строк); в Jan03 добавлены Lua-привязки, перки, сохранения, декали, `wVision`; редактор вынесен в `MapEdit`.
- `Soft/Monster` — ранний прототип на VC6/DX8 (~14 тыс. строк), не параллельная ветка.
- `Soft/Andy/Apr03/p2pa7` — отдельный UDP/P2P-стенд, в игру не интегрирован; May03/Jun03 — по 3–4 файла (тени, физика); *Gold — только бинарники.

## Схема связей

```
Game.exe ─→ Main.dll ─→ FileIO (потоки, .res, CStructureSaver)
   │           ├─→ DBFormat ─→ ADOImport | ADOFake ─→ game.db / SQL
   │           ├─→ Script (Lua) ─→ Complete/Scripts
   │           ├─→ Input, FModSound, MiscDll, MemoryMngrDll
   │           └─→ LifeStudioHeadAPI (закрыт)
MapEdit.exe ─→ Main (тот же рендер) ─→ SQL напрямую ─→ maya.exe + A5ExportModel
Maya ─→ A5ExportModel ─→ Complete/<Тип>/<id> ─→ PkgBuilder ─→ <Тип>.res
SQL ─→ DataImport ─→ game.db
GfxShaders.txt ─→ ShaderCompiler ─→ GfxShaders.cpp ─→ Main
Внутри Main: i* (UI) ─→ w* (мир) ─→ RPG*, ai*, Build* ─→ G* (сцена) ─→ Gfx* (D3D9)
```

## Что здесь можно взять

- **Dataflow-ядро `DG.H`** — готовая идея pull-графа с версиями и покадровым кэшем; прямо переносится в нодовый движок.
- **Разрушаемость**: решётка прочности + граф устойчивости с моментами — дёшево, детерминированно, хорошо параметризуется процедурно.
- **Пайплайн «id записи = имя файла»** и batch-экспорт из DCC по команде редактора — простая основа для воспроизводимой сборки ассетов.
- **Дерево аниматоров** как dataflow-узлы; шейдеры как данные с компиляцией на этапе сборки.
- **Сериализация графа объектов** вместе с состоянием скриптов.
- Безнадёжно устарело: ps1.x-шейдеры и render paths под GeForce2/3, CPU-скиннинг с MMX, стенсильные тени, жёсткая привязка к MS SQL/ADO и MFC, аллокатор на фиксированном адресе, Lua 4.0, макросы VS для генерации кода.
