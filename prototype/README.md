# Прототип для выбора движка

← [Документация](../docs/README.md) · [Выбор движка](<../docs/SilentStorm A5 Engine Study/23 Выбор движка.md>) · [Спецификация зданий](<../docs/SilentStorm A5 Engine Study/Спецификации/Мир 2 — Здания и разрушение.md>)

## Зачем

Прототип отвечает на вопросы из раздела «Что решает прототип» в [сравнении движков](<../docs/SilentStorm A5 Engine Study/23 Выбор движка.md>): сколько стоит убрать сотню кусков здания за один шаг и нарисовать его заново, как ведёт себя свет, пока здание осыпается, во что обходится инструмент «стена по сетке» и как быстро проверяется правка в коде. Рабочая гипотеза — Unreal Engine 5 (принята 13.11.2026).

## Как устроено

| Часть | Что это | Состояние |
|---|---|---|
| `core/` | Ядро на C++ без движка: здание, урон, лучи, обрушение. Тот же код потом собирается внутри проекта Unreal | готово, проверено тестами |
| `ue5/` | Проект Unreal: показ кусков, свет, сценарии замеров | не начат |
| `results/` | Результаты замеров, по файлу на прогон | замеры ядра на сервере |

Где что работает:

- **Сервер сборки** (этот репозиторий, видеокарты нет) — код, сборка, тесты, замеры без картинки.
- **Машина владельца** (RTX 3090) — всё, где нужна картинка: свет, время кадра, редактор Unreal.
- Изменения в обе стороны — **только через git**: сервер отправляет код, машина владельца забирает его, собирает, запускает и отправляет результаты в `results/`.

## Ядро: что уже есть

Ядро повторяет устройство зданий оригинала по [спецификации «Мир 2»](<../docs/SilentStorm A5 Engine Study/Спецификации/Мир 2 — Здания и разрушение.md>):

- **Решётка прочности.** Трёхмерная сетка с шагом 0,625 м по всем осям, 4 плоскости на этаж высотой 2,5 м. В каждом узле — один кусок и один байт прочности: 0 — пусто, 1–253 — прочность, 254 — «подвал» (стоит на земле, неуязвим), 255 — неразрушимо.
- **Прочность куска** по формуле оригинала: ⌈2 · VP · объём⌉, где VP — из таблицы материалов (кирпич 650, дерево, камень и бетон 400), но не больше 253. Пример: прямой кусок кирпичной стены 0,625 × 0,25 × 0,625 м получает 127.
- **Урон.** `DamageSpot` — единственное место, где убывает прочность, с теми же правилами, что в оригинале. Взрыв по решётке — по формуле оригинала: при мощности 50 и меньше ничего не происходит, задета только сфера половинного радиуса, урон — P · min(1, 1/d²).
- **Луч сквозь здание.** Возвращает все куски на пути с точками входа и выхода, по порядку — это нужно выстрелу сквозь преграды.
- **Обрушение.** Кусок падает, если ни одна цепочка соседних кусков не связывает его с опорой. Это второй проход статики оригинала («поиск свободных»).
- **Отчёт за шаг мира:** разрушенные куски (с пылью и звуком), оторвавшиеся куски (падают тихо), «части» для перерисовки. Часть — как в оригинале: один этаж над квадратом 2 × 2 узла; при разрушении узла помечаются 27 частей вокруг.
- **Тестовое здание.** Генератор коробки с комнатами: наружные стены из кирпича, внутренние из дерева, окна, двери, плиты на каждом этаже и крыша. Для каждой комнаты — точка, где повесить лампу. Данные оригинала не нужны.

### Чем ядро пока отличается от оригинала

- Куски — прямоугольные коробки внутри своей ячейки решётки. В оригинале это нарезанные заранее меши неправильной формы.
- Из статики есть только второй проход. Нет первого (пролёт держится между двумя противоположными опорами) и третьего (вес стекает к опорам, перегруженные стыки ломаются). Поэтому висящая консоль пока не обрушается, пока она хоть как-то связана с опорой.
- Взрыв меряет расстояние до центра узла. Оригинал берёт точки, смещённые от узлов, и пропускает последний ряд (спецификация «Мир 2», раздел 6.3).
- Прочность выше 255 в оригинале переполняется байтом (263 превращается в 7) — здесь не повторено.
- Стены не подрезаются заново, когда рядом что-то разрушено.

Для выбора движка этого достаточно: ядро даёт нужную нагрузку — сколько кусков исчезает и отрывается за шаг. Полная статика из «Мира 2» — отдельная работа при переносе.

## Замеры ядра на сервере (13.11.2026)

Ryzen 7 9700X, один поток, сборка Release. Полный вывод — [results/core-server-2026-11-13.txt](results/core-server-2026-11-13.txt).

| | Малое здание | Большое здание |
|---|---|---|
| Размер | 25 × 20 м, 3 этажа | 50 × 40 м, 5 этажей |
| Кусков | 7 226 | 38 190 |
| Комнат (ламп) | 30 | 50 |
| Граната (P = 1000, R = 10 м): разрушено кусков за шаг | в среднем 116, до 288 | в среднем 194, до 365 |
| Проверка обрушения за шаг | 0,05 мс, не больше 0,14 мс | 0,39 мс, не больше 0,49 мс |
| Обрушение половины здания | 2 861 кусок за 0,19 мс | 16 295 кусков за 0,86 мс |
| Луч со всеми попаданиями | 0,6 мкс | 1,5 мкс |

Вывод: ядро не будет узким местом. Шаг мира в оригинале — 50 мс, а ядро тратит на него меньше миллисекунды даже в большом здании. Главный вопрос — во что движку обойдётся убрать и заново нарисовать столько кусков за шаг: до 365 при гранате и 16 тысяч при крупном обрушении. Это и будет мерить слой Unreal.

На машине владельца процессор (Xeon E5-2699 v3, 2014 год) заметно медленнее в один поток, поэтому там цифры будут хуже. Как запас прочности это даже полезно.

## Как собрать и проверить

Нужны CMake и Visual Studio 2022 или её Build Tools с компилятором C++.

```
cmake -S prototype/core -B C:/build/ssproto -G "Visual Studio 17 2022" -A x64
cmake --build C:/build/ssproto --config Release
C:/build/ssproto/Release/ssproto_tests.exe
C:/build/ssproto/Release/ssproto_bench.exe
```

Тесты сверяют луч и выборку по сфере с перебором всех кусков, проверяют правила урона, формулу взрыва, обрушение, пометку частей и повторяемость. Сейчас все 56 проверок проходят, в том числе в отладочной сборке.

## Что дальше

1. **Слой Unreal** (`ue5/`): плагин, который собирает ядро и показывает куски двумя способами — экземплярами, по одному на кусок, и сшитыми мешами по частям, как в оригинале. Свет — лампы в комнатах, полностью динамический.
2. **Сценарии замеров**: граната за шагом, сотня кусков за шаг, обрушение половины здания. Время кадра и шага пишется в файл, плюс снимки экрана.
3. **Запуск на машине владельца**: забрать изменения из git, запустить один скрипт. Скрипт собирает проект, прогоняет сценарии без участия человека и кладёт результаты в `results/`, их остаётся закоммитить и отправить.

## Что нужно установить

**На машине владельца (RTX 3090):**

- Unreal Engine 5, актуальная версия 5.x, через Epic Games Launcher: только Windows, без отладочных символов и примеров — около 50–60 ГБ. Нужны учётная запись Epic и принятие лицензии.
- Visual Studio 2022 с набором «Разработка игр на C++» — для сборки проекта.
- Git и Git LFS.
- Место: движок, Visual Studio и кэш шейдеров вместе занимают порядка 80 ГБ, так что 100 ГБ впритык.

**На сервере:** Unreal Engine 5 той же версии. Здесь он не рисует, только собирает: так код проверяется на сборку до отправки, а не у вас после неё. Ставить тоже вам — нужны учётная запись Epic и права администратора.
